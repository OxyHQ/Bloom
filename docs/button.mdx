# Button

```tsx
import { Button } from '@oxy.so/bloom/button';
import { RiAddLine } from '@oxy.so/bloom/icons';

<Button tone="action" appearance="solid" onPress={save}>Save</Button>
<Button tone="neutral" appearance="subtle" onPress={cancel}>Cancel</Button>
<Button tone="danger" onPress={remove}>Delete</Button>
<Button tone="action" icon={RiAddLine} accessibilityLabel="Add item" onPress={add} />
<Button tone="action" leadingIcon={RiAddLine} size="lg">Add item</Button>
<Button href="/help" tone="accent" appearance="plain">Read the guide</Button>
```

`size` (`xs`, `sm`, `md`, `lg`) and `tone` inherit from `BloomScope`; defaults are `md` and `accent`. `appearance` defaults to `solid`. Appearance controls fill and border, independently of semantic tone. Filled accent and status buttons retain Bloom’s subtle vertical gradient: ramp 500 → 600 at rest, 400 → 500 on hover and 600 → 700 when pressed. Native SVG and web CSS paint the same stops; `support` and `action` preserve their authored semantic fill/foreground pairs; neutral solid buttons retain a gentle gradient between the shared secondary and tertiary surfaces. Outline, subtle and plain appearances use their semantic flat fills.

The Color roles prototype assigns `accent` to identity and links, `support` to contextual emphasis, and `action` to the main CTA. Use `tone="action"` for a task’s Create/Send/Save button and keep secondary controls neutral. `tone="support" appearance="subtle"` can emphasize a related option when that distinction has meaning; it is not a replacement for every secondary button. All eight tones remain available through the shared contract.

An `icon` without children makes a square action. Labelled actions use `leadingIcon` and `trailingIcon`, each an icon component receiving width, height and fill. `leading` and `trailing` are custom content slots.

`loading` blocks activation while preserving the mounted label's width. `disabled` also blocks activation. A control drawing no text needs `accessibilityLabel`. Native touch targets retain the padding around compact visuals; web has real button, anchor and form semantics (`type="submit"` or `"reset"`). Activation is always `onPress`.

The pressable is the parent's layout child: `className` and `style` are applied there, without an extra wrapper. Web styles flatten RN style arrays and register their interaction CSS using constructed stylesheets. `asChild` composes an existing web link; disabled state guards the composed handler.

`CloseButton` remains a semantic dismiss control with a required accessible name and sizes `xs | sm | md | lg`.

See [Component contract](./appearance.mdx) for inheritance and [Migration](./coherent-system-migration.mdx) for the clean API cut.

## Compatibility

The shared `size`, `tone` and `appearance` vocabulary coexists with the previously published family props. Explicit shared props take precedence over legacy spellings; existing size and state callbacks remain supported. New code should prefer the shared vocabulary.
