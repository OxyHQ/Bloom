# AiChat

`AiChat` composes an AI workspace with navigation, conversation and context panels, the thread and image generation. `AppShell panelLayout` owns the frame and responsive panel layout; the exported `AiChatShell` adapts its existing props to that API. For a ready-made transcript + composer + history rail, use [`AgentChat`](./agent-chat.mdx); [Building AI interfaces](./ai-overview.mdx) says which to choose. The shell and container publish their actual base fills without adding a material rim to the workspace; transparent layouts inherit their enclosing surface and arbitrary background slots remain caller-owned.

The AI Chat template declares AppShell panelLayout directly; AiChatShell is a
compatibility adapter for existing consumers, with no second panel API.

The pieces of the AI chat and AI image generation screens. Everything is data and callbacks — no model, transport or storage. The full screens are composed in Storybook under `Templates/AI Chat` and `Templates/AI Image Generation`.

| Export | What it is |
| --- | --- |
| `AiChatShell` | Compatibility adapter to AppShell navigation, conversation and resizable context panels |
| `AiChatMobileHeader` | The in-container header below `xl` (menu button, title, panel button), wired to the shell |
| `AiChatHeader` | A header with a title node of yours centred between the shell's menu and panel buttons, at every width |
| `AiChatResizeHandle` | Shared accessible resize separator, also used by AppShell panelLayout |
| `AiChatContainer` | The chat card: breadcrumb header, thread, composer slot, `AgentThinking` while working |
| `AiChatThread` | The bottom-anchored, self-following scroll of turns — with the follow, upward pagination and `ref` a host with history needs |
| `AiChatUserMessage` / `AiChatAssistantMessage` | The turns, with the staggered blur-in |
| `AiChatMessageLine`, `AiChatBulletList`, `AiChatBullet`, `AiChatStrong`, `AiChatLinkChip` | A reply's blocks and inline runs |
| `AiChatFeedbackRow` | Like / dislike / copy with tooltips, plus your own `actions`, as one pill cut into segments |
| `AiChatImageGeneration` | An image generating: dot wave, split-flap countdown, radial reveal, feedback and toast |
| `AiChatCodePanel` | Changes / Browser panel: uncommitted-changes card and a numbered code view |
| `AiChatGalleryPanel` | Gallery / Styles panel: masonry wall of generations that expand in place |

It composes Bloom's own families: `Sidebar` (with `tree` and `plan`), `ComposerPill` + `ComposerStatusBar` inside `ComposerLoader`, `CodeBlock` / `CodeLines`, `AgentProgress`, `AgentThinking`, `Tabs` (pill), `Breadcrumb`, `Tooltip`, `Button`.

```tsx
import { AppShell } from '@oxy.so/bloom/app-shell';
import { Screen, ScreenScrollView } from '@oxy.so/bloom/screen';
import { PageHeader } from '@oxy.so/bloom/page-header';
import { PageFooter } from '@oxy.so/bloom/page-footer';
import { ComposerPill } from '@oxy.so/bloom/composer-panel';
import { AiChatUserMessage, AiChatAssistantMessage, AiChatCodePanel } from '@oxy.so/bloom/ai-chat';

<AppShell contentMaxWidth="none" panelLayout={{
  mode: 'split', flow: 'bounded', activePanel,
  panels: [
    { id: 'navigation', width: 260, hideBelow: 1024, content: navigation },
    { id: 'conversation', minWidth: 320, content: (
      <Screen scroll="auto" bottomBarKeyboardBehavior="visible"
        header={<PageHeader title={conversationName} actions={conversationActions} />}
        bottomBar={<PageFooter><ComposerPill value={draft} onValueChange={setDraft}
          busy={working} onSubmit={send} onStop={stop} /></PageFooter>}
      >
        <ScreenScrollView>
          <AiChatUserMessage>update our colour tokens for dark mode</AiChatUserMessage>
          <AiChatAssistantMessage>Done — the tokens are wired.</AiChatAssistantMessage>
        </ScreenScrollView>
      </Screen>
    ) },
    { id: 'context', width: 410, minWidth: 320, maxWidth: 560,
      hideBelow: 1280, content: <AiChatCodePanel width="100%" code={file} language="tsx" /> },
  ],
}} />
```

Give AppShell a sized parent for a bounded workspace. Select compact panels
through `activePanel`; their header back actions return to conversation.
Existing AiChatShell integrations can retain their sidebar/panel props through
the compatibility adapter.

## Shell

New compositions declare the workspace through `AppShell panelLayout`. Keep stable
IDs for `navigation`, `conversation` and `context`, and let the shell resolve
`hideBelow`, panel minima and resizing against its measured container. A split
with enough room shows all eligible panels; compact layouts show `activePanel`.
A menu or context action selects that panel. In `AiChatShell` navigation is a
`drawer="reveal"` drawer beneath the retained conversation, and below `xl` the
context panel is a floating side sheet named by `panelLabel` (its own header,
such as `AiChatCodePanel`'s, carries the title and the close action).

The conversation declares its own chrome and viewport:

```tsx
<AppShell gutter={12} contentMaxWidth="none" panelLayout={{
  mode: 'split', flow: 'bounded', activePanel,
  panels: [
    { id: 'navigation', width: 260, hideBelow: 1024, content: navigation },
    { id: 'conversation', minWidth: 320, scroll: 'content', content: (
      <Screen scroll="auto" bottomBarKeyboardBehavior="visible"
        header={<PageHeader title={conversationName} actions={conversationActions} />}
        bottomBar={<PageFooter><ComposerPill {...composer} /></PageFooter>}
      >
        <ScreenScrollView>{turns}</ScreenScrollView>
      </Screen>
    ) },
    { id: 'context', width: 410, minWidth: 320, maxWidth: 560,
      hideBelow: 1280, resizable: true, scroll: 'content', content: context },
  ],
}} />
```

The shell supplies panel framing and independent scopes. Content declares
`Screen scroll="auto"`, `header` and `bottomBar`; `ScreenScrollView` reuses the
existing web viewport. Native retains its list. Do not wrap descriptor content
in another `AppShellPanel`, paint another frame, or put an existing list inside
`scroll="panel"`. Host controls shared by a panel's routes belong in descriptor
`headerActions`, which PageHeader composes with the route's own actions.

`AiChatShell` preserves `sidebar`, `mobileSidebar`, `panel`, width and controlled
open props as adapters. `navOpen` / `panelOpen` select navigation / context in
compact layouts; closing returns to conversation. `panel` receives the width
selected by the shared engine. Resize limits remain 320–560px by default, with
410px as the resting context width. `sidebarCollapsed` and explicit sidebar
width overrides remain host preferences. `navSwipeEnabled` is retained for API
compatibility; the shell no longer installs a private swipe recognizer.

Hidden panels retain their mounted content and state after first presentation.
The shared engine makes them inert, inaccessible and inactive. Keep descriptor
IDs and the content tree stable: resizing, selecting another compact panel or
switching flow must not create another copy of the conversation or editor.
`useAppShellPanel()` exposes actual `visible` and `active` state so background
scroll writers and observers can suspend themselves.

`useAiChatShell()` remains the compatibility context for `AiChatHeader` and
`AiChatMobileHeader`: `openNav`, `closeNav`, `openPanel`, `navPresented`,
`compact`, `navCollapsed`, `sidebarCollapsed`, `hasNav`, `hasPanel` and
`documentScroll`. Its selection follows the modular panels. These helpers do
not create drawers, backdrops or a second layout engine. Compact selected
panels retain the shared interaction hook for focus entry/containment, Escape,
Android back and opener restoration.
Both header helpers compose PageHeader and its floating button islands; a
centered avatar/name node participates in the header's measured height.

`scroll="container"` maps to a bounded panel layout. `scroll="document"` maps
to document flow on web, while native keeps native scrolling. Shared Screen
chrome and viewport APIs should own new routes; the container/thread adapters
below preserve their public composition and transport-free behavior. Native
`safeArea` remains an opt-in for all four device edges at the shell; inner PageHeaders use
`safeArea={false}` when the shell already owns those edges.

`background` stays a decorative layer below the workspace. `surface={false}`
allows the enclosing host's paint to show through; a chat-specific background
belongs on its container. Preserve the actual parent fill when composing
transparent or custom backgrounds.

### Recorded hazards from the retired shell

The previous centered identity header had a 48px minimum, 12px horizontal/top
padding and 40px side slots. PageHeader now measures its central title in flow
with a 56px minimum, so larger avatars and system fonts grow the row.

The previous private layout used a 12px outer frame, navigation at 1024px with
a 16px workspace gap, and context at 1280px with a 12px gap. Its 20px separator
strip revealed a 15×25px grip (radius 4, three 1×13px lines); keyboard nudges
were 16px. The shared panel engine now owns resizing and keyboard behavior.

The former context drawer measured `min(410px, 100% - 12px)`, had 12px padding,
a 40px header and a 40% black backdrop, and travelled for 300ms. The former
navigation drawer was 272px wide (12px vertical padding, 6px start padding):
it moved the workspace 272px, rounded it to 32px, scaled navigation from 94%
and settled over 325ms with `cubic-bezier(0.42, 0, 0.58, 1)`. The close veil
was 10% black / 5% white. These are retired geometry measurements, not
parameters to reproduce in a panel adapter.

The retired swipe recognizer admitted only one real web touch from the first
24px, after 12px travel and a horizontal:vertical ratio of at least 2; halfway
travel or 0.3px/ms settled it open. It never claimed mouse selection, vertical
scrolling, diagonals, a pinch or a horizontal gesture that began inside the
conversation, and did not set `touch-action`. Preserve those content gestures
by leaving the adapter free of shell-owned swipe handlers. Reduced motion
belonged to settling, not direct finger tracking.

A hidden mounted subtree needs more than opacity or pointer events: remove it
from the accessibility tree and the web tab order. The former veil needed
`tabIndex={-1}` because RNW Pressable overwrites `focusable={false}` with a Tab
stop. Compact panels have no veil. Actual modal surfaces still need their own
focus entry, Tab containment, Escape/Android-back ordering and opener restoration;
portaled menus/dialogs above them must receive dismissal first.

## Container and thread

AiChatContainer adapts its props to Screen. PageHeader renders its optional
breadcrumb and real actions; PageFooter contains AgentThinking (infinity) while
`working` and the `composer`. AppShell supplies the panel frame, corners and
surface. The container declares no second card radius or private header/footer
positioning. Its background slot remains decorative and cannot intercept input.

`project` is **optional**: a chat that belongs to nothing draws its own crumb alone, with no folder glyph and no empty crumb.

The container publishes its painted surface through Bloom’s surface context, so nested sheet composers and sticky controls follow the panel fill. A transparent container inherits its parent’s fill.

`background` is a layer filling the container, drawn **above its own surface and below every turn, header and composer**, clipped to the radius and never interactive — a host's wallpaper, gradient or animated field goes here rather than behind the container, and nothing has to reach into it. An opaque node needs nothing else; add `surface={false}` when the node is translucent and should show what the container is sitting on instead of background-secondary.

The thread scrolls with a thin scrollbar, px 16 / pt 16, turns 12 apart, and is **bottom-anchored**: a short exchange sits just above the composer. It follows the newest content with a smooth scroll whenever it grows — that is the default, and every prop below is off unless asked for.

| Prop | Type | Default | Description |
|---|---|---|---|
| `autoFollow` | `boolean` | `true` | Follow the newest turn as the content grows. |
| `followAnimated` | `boolean` | `true` | `false` for a follow that must not be seen travelling. |
| `followThreshold` | `number` | — | Follow only from within this many px of the bottom, measured **before** the growth. Omit and every growth follows. A follow still on its way counts as at the bottom, so growths landing before its scroll event keep following; a scroll **up** ends it. A growth that is not followed calls `onScroll` with the unchanged offset and the new content size, so a jump-to-latest button hears that the end moved away. |
| `onStartReached` | `() => void` | — | The reader came near the **top**. A chat pages upward, so this — not `onEndReached` — is its pagination signal. Once per approach; it re-arms when the reader leaves the zone. |
| `onStartReachedThreshold` | `number` | `300` | How near the top, px. |
| `maintainStartPosition` | `boolean` | `false` | The growth that answers an `onStartReached` is added to the offset, so a page landing **above** the reader does not move the turn they are on. Inert without `onStartReached` — the thread only anchors growth it asked for. |
| `onScroll` / `scrollEventThrottle` | | `16` | The thread observer receives the raw event when requested. Screen keeps its own shared chrome and restoration metrics. |
| `ref` | `AiChatThreadHandle` | — | `scrollToEnd({ animated })`, `scrollToOffset({ offset, animated })`, `getScrollView()`. |

**Not there:** virtualization and `scrollToIndex`. The thread uses ScreenScrollView, so a long history is fully mounted, and a host jumping to a cursor measures that turn's row (`onLayout`) and calls `scrollToOffset`. `maintainStartPosition` is the web-safe half of React Native's `maintainVisibleContentPosition`, which react-native-web ignores.

**Hazard (web):** react-native-web gives every view `min-height: 0`, so the usual `flexGrow: 1` + `justifyContent: 'flex-end'` content container stays the viewport's height and its children overflow it instead of scrolling — and `onContentSizeChange` never sees the growth. The thread floors its container at `minHeight: '100%'` on web instead.

### Screen chrome and compatibility insets

Both container modes use Screen's header and bottomBar slots. The default
reserves measured header clearance; `floatingChrome` sets
`headerPlacement="overlay"`, allowing content to extend underneath the header.
PageHeader and PageFooter own their shared scrims. The thread keeps its own
16px top, 12px bottom and horizontal padding, while Screen reserves chrome
once at the viewport owner. Native does not add footer height to the list's
content a second time. Chat Screens set `bottomBarKeyboardBehavior="visible"`
so focusing the native prompt keeps the composer visible above the keyboard.

`useAiChatChromeInsets()` adapts Screen's current clearances for custom children.
Overlay headers report zero top clearance. A growing composer resizes the
viewport: a reader at its end stays at the end without an animated follow;
a reader midway keeps their offset. An ordinary new turn retains the thread's
follow behavior. ScreenScrollView forwards the same imperative handle to the
native list or existing web viewport, avoiding a second scroller.

Compact navigation and context panels retain an interaction adapter for focus,
Escape and Android back. While the selected panel is alone, focus enters it,
Tab/Shift+Tab stay inside, and dismissal restores the opener when possible.
This adapter supplies no layout, width, backdrop or swipe gesture. Portaled
menus and dialogs still take dismissal priority.

### Document scroll

Under `<AiChatShell scroll="document">`, AppShell uses document flow on web.
Screen and PageHeader/PageFooter supply the shared sticky chrome; the
conversation grows the page, and ScreenScrollView reuses the document owner.
Native continues using its native viewport. The shell supplies the panel's
framing instead of adding a second ContentPanel inside AiChatContainer.

Thread following, upward pagination and the ref continue through the shared
owner. A host can inspect that owner with `useScreenViewport()` rather than
assuming window scroll or creating another restoration binding. A hidden panel
must not save or reset scroll state. Retained panel IDs and route keys keep
restoration scoped to the correct conversation and destination.

The host must allow document growth: an ancestor scroll container changes
which element owns the page. Expo/RNW resets such as `html, body { height: 100%;
overflow: hidden }` or an absolutely positioned web Stack screen can pin the
page to one viewport. Document hosts use flow-preserving routes and explicit
scroll restoration. Bounded hosts keep the root height chain instead; do not
apply document-height overrides to an embedded bounded workspace.

### Recorded container hazards

The retired container had a 24px card radius and private breadcrumb spacing
(16px horizontal/top, 8px action gap), footer spacing (10px horizontal/bottom,
12px top, 10px gap), and independent absolute chrome. Its 16px scroll ramp
covered the full header plus a 55% tail: a 60px header produced a 93px ramp.
Compressing the ramp into the final tenth made the fade read as a slab. These
measurements remain recorded; PageHeader now owns that ramp directly.

The former AgentChat frosting was a white/black 20% wash with 20px backdrop
blur. It made a rectangular band. Scrims must use the actual painted parent
fill; fixed background-secondary over a darker host also made a lighter band.
Custom background slots do not reveal their painted pixel color to the theme.

The old inset contract put `header + 16px` and footer heights into list
padding and iOS indicator insets. Reapplying those values under Screen would
reserve chrome twice. A 40px composer growth or 20px header growth is geometry,
not a new message: never turn it into an animated follow. Native now reports
the reduced viewport rather than another 40px of message content.

The former document wrapper used `100dvh`, a 12px sticky gutter, `overflow:
clip` and its own framed ContentPanel with `overlayInset=12`. Clipped backdrop
input and nested clipping/scroll containers can invalidate an otherwise green
markup check. A conversation must remain below shared chrome even if a turn
contains its own z-index. Thread row offsets and host cursor-jump offsets must
refer to the same viewport coordinate space; browser scroll anchoring must not
also compensate growth already handled by `maintainStartPosition`.

## Turns

- **User** — pushed right with a 6px bleed past the column, as wide as its text up to half the column + 6; radius 16, background-primary, px 12 / py 11, shadow-card.
- **User actions** — `actions` draws the feedback row's buttons under the card, 8 below and right-aligned, as one pill cut into 28×42 segments 2px apart (copy, edit). On a web pointer (`@media (hover: hover)`) they fade in over 150ms while the turn is hovered or holds focus — opacity only, so they stay in the tab order and the accessibility tree, and tabbing into one reveals the row. Native and touch web always show them.
- **Assistant** — full width, blocks 8 apart, with `AiChatFeedbackRow` last (`feedback={false}` drops it).
- **Blocks** — `AiChatMessageLine` (body-regular; `tone="secondary"` for status lines; `block` for a card), `AiChatBulletList` (a 5px disc in a 21px indent, items 8 apart), `AiChatStrong` (body-medium), `AiChatLinkChip` (inline, radius 8, px 4 / py 3, accent-100 with a 16px link glyph and caption-2-medium accent-500). A bare string child becomes a line; any other element a block line.
- **Motion** — a turn fades in over 400ms while its blocks rise 6px, un-blur 6px (web) and fade in, 500ms `cubic-bezier(0.25, 0.1, 0.25, 1)`, 180ms apart; a bullet list staggers its own items from its slot. `animate={false}` mounts settled (history), as does reduced motion.

## Feedback row

28px squares 6 apart: radius 8, p 6, background-tertiary, background-secondary-hover on hover with the 16px glyph deepening to icon-primary. Each has a `sm` tooltip above after 200ms (keyboard focus raises it too; a press does not). Copy swaps the glyph for a check (blur, 75% scale, fade, 200ms) and holds the tooltip open reading "Copied!" for 1.6s, then dismisses it even if the pointer is still there.

The confirmation follows the copy, not the press. `onCopy` returns `AiChatCopyResult` (`void | boolean | Promise<void | boolean>`): a handler returning nothing or `true` confirms at once, as before; a promise confirms when it resolves (only the latest press's); `false`, a throw or a rejection confirms nothing — a blocked clipboard is not a "Copied!".

`actions` (on the row, or through `AiChatAssistantMessage`'s `feedbackProps`) appends buttons after copy on the same surface:

```ts
interface AiChatTurnAction {
  key: string;                // React key; `${testID}-${key}` names the button
  label: string;              // accessible name and tooltip
  icon: AiChatIconComponent;  // RiVolumeUpLine, not <RiVolumeUpLine />
  onPress: () => void;
  active?: boolean;           // a toggle: hover surface + primary glyph, aria-pressed
  disabled?: boolean;         // 50% opacity, disabled, aria-disabled
}
```

Leave `active` undefined for a plain button: `false` is a toggle that is off, announced "not pressed". `AiChatUserMessage` takes the same `actions`.

```tsx
<AiChatAssistantMessage
  feedbackProps={{
    onCopy: () => Clipboard.setStringAsync(text),
    actions: [
      { key: 'speak', label: 'Read aloud', icon: RiVolumeUpLine, onPress: toggleSpeech, active: speaking },
      { key: 'regenerate', label: 'Regenerate', icon: RiRefreshLine, onPress: regenerate, disabled: busy },
    ],
  }}>
  {reply}
</AiChatAssistantMessage>
```

## Image generation

- The frame unfolds from 0 to 250 tall (550ms `cubic-bezier(0.22, 1, 0.36, 1)`) while it fades in and un-blurs, pushing the thread up instead of popping in.
- A 200×250 card (radius 16, background-primary, shadow-card): on web a canvas of 9px-spaced dots swelling and brightening as rings ripple out from the centre (icon-primary on a ring, icon-quaternary elsewhere, faded at the edges); native draws the still field. Along the bottom, "Generating image" shimmers against a **split-flap countdown** of whole seconds — each digit an 11-wide card whose old top half falls (150ms ease-in to −90°) as the new bottom half rises with a small slap past 0° (230ms, 150ms late).
- It lands after `duration` (4000) — or when a controlled `ready` turns true — firing `onGenerated` once. The status fades out (300ms); on web the artwork is revealed through a radial mask feathered 26% wide sweeping from the centre to 132% while it fades in and un-blurs 10px (1550ms, a registered `@property`); native fades it in.
- The feedback row rises in under it; like and dislike raise a toast over the image's bottom edge (radius 8, neutral-950 @80% with an 8px backdrop blur, body-2-medium white) that rises 8px in and out (420ms) and leaves after 2.2s.

## Panels

Both share a shell: `width` wide, full height, pt 8, gap 10, and a 30-tall header of pill tabs with actions on the right.

- **Code** — Changes (∞) / Browser (globe) with terminal / expand / sidebar glyphs (16px, 8 apart). A summary strip framed on three sides by a 1px background-secondary line (radius 10 on top): "N Uncomitted changes" (body-2-medium secondary), `+156` / `-23` (body-regular success-700 / negative-600) and, only with `onUndo`, an undo glyph; each changed file tucks 7px up under it (radius 10, background-secondary, py 4 / pr 5 / pl 6: a 16px mark, the path with its additions, a `status` chip). Then the code as `CodeLines` at `md`, soft-wrapping, scrolling with a thin scrollbar. The Browser tab shows `browser` or a placeholder; `browser={null}` drops the tab.
- **Gallery** — Gallery (an 18px glyph, optically matching the 20px sparkle) / Styles (the tab shows `stylePresets` or a placeholder; `stylePresets={null}` drops it), with 18px actions on 2px padding (radius 6, primary-hover, tooltips). The wall is explicit balanced columns 8 apart — always filling the shortest — so an insertion only moves its own column; `generated` images are pinned to the head of the first. Tiles (radius 10, background-secondary, the artwork covering them at its `aspectRatio`) cascade in top-left → bottom-right (fade + 8px blur over 400ms, scale from 95% over 550ms, 130ms × order late; a generated tile only fades). Hovering lifts the image 3% and fades in a scrim (neutral-950 40% → clear → 55%) with frosted download / more actions (22px, neutral-950 @45%, 65% hovered, 4px blur; each drawn only with its `onDownload` / `onMore`) and the prompt (body-2-regular, two lines). Pressing a tile lifts it into a full-width row above the wall (body-medium prompt, p 10, a minimize action); on web it morphs between the two boxes by FLIP (550ms, 600ms for the enlarged tile) while its neighbours glide, painting above the wall in flight, and the scroller jumps to the top first.

## Known gaps

- **Native:** no dot-wave animation (a still field), no radial mask (a fade), no gallery morph (the tile moves instantly), and the gallery's hover scrim shows only on the enlarged tile. The resize grip works by pan but only appears while dragging.
- **The frosted chips** are blur + tint + sheen + rim.
- **Effort at Max** has no flame / starfield flourish (see `composer-panel`).
- The gallery re-baselines rather than animating when the panel's own width changes during a resize drag.

### Custom chat header

`AiChatHeader` composes PageHeader with a centered title node, such as an
AgentProfile identifying the conversation. It shows at every width; the title
is in flow and determines the row's height above the shared 56px minimum.
Measured action widths reserve room for the navigation and context islands.
Outside AiChatShell it renders its title alone. AiChatMobileHeader is the
string-titled compatibility header for compact shell layouts.

`AiChatContainer` can receive a `header` such as Bloom's `PageHeader` with the
application's real actions. Omit `title` and `project` to omit its breadcrumb;
without breadcrumb or action handlers no extra header row is reserved. Share
and more controls render only when `onShare` and `onMore` are supplied. This
keeps applications without public sharing from presenting a dead share action.

### Panels without a backend

A panel control renders only when it can act. The summary's undo glyph needs
`onUndo`, a tile's download and more actions need `onDownload` and `onMore`,
and the header `actions` are the caller's list (pass `[]` for none: the defaults
carry no handlers). A host with no browser preview or no style presets passes
`browser={null}` or `stylePresets={null}` and the tab is gone, so the panel
never presents a preview or a style editor that does not exist.

### Language

Every default name and label (the feedback row, the panels, the default panel actions and `panelLabel`, the shell's panel navigation buttons, the image countdown) is localised via `BloomProvider locale`; each `labels` key still wins.

### Panel keyboard ownership

Compact workspace panels are destinations selected by their header controls.
Their PageHeader back action returns to the conversation; retained hidden
tracks leave the accessibility tree and web tab order through AppShell. A
compact panel has no backdrop; its retained interaction adapter owns focus
entry, Tab containment, Escape and Android back while it is selected alone. Controlled
hosts keep `navOpen` / `panelOpen` synchronized through their change callbacks.

The interaction contract also applies to actual modal surfaces:
Escape/Android back must yield to a portaled menu or dialog above it, fields
need `overlay/modal-keyboard.ts` because RNW can stop their keydown propagation,
and focus returns to the opener when supported. Native accessibility focus on
entry does not imply automatic return to an arbitrary opener without its trigger
ref. These hazards remain recorded for modal consumers; hook-only Android tests
do not establish behavior of the modular workspace or verify a device runtime.

`AiChatContainer.actions` composes real menu triggers or other chat actions in
the breadcrumb action row, replacing the default share/more controls. Use it
with `AiChatMobileHeader` to preserve the template layout without a second toolbar.

## Selection

Content is selectable and the interface is not. Every control takes no selection on web (Bloom's base rule, adopted by the theme provider); the breadcrumb and the web-search trail are navigation and activity, so their text is not selectable either. A reply's lines are content — `AiChatMessageLine` is selectable by default — and a status line passes `selectable={false}`.

### User bubble styling

`AiChatUserMessage bubbleStyle` addresses the painted bubble; `style` continues
to address the full-width turn. Pass a style or a function of the measured
column width. The function receives 0 before the first layout and is reevaluated
when the column resizes. Use the same padding longhands as the base style:

```tsx
<AiChatUserMessage
  bubbleStyle={width => ({
    maxWidth: width > 0 ? Math.max(0, width - 112) : '100%',
    marginInlineEnd: 0,
    borderRadius: 24,
    paddingLeft: 16,
    paddingRight: 16,
    paddingTop: 12,
    paddingBottom: 12,
  })}
>
  Show items for a weekend trip
</AiChatUserMessage>
```

The default half-column limit, 16px radius and 6px end-edge bleed are unchanged.
The end-edge bleed follows the inherited direction on both platforms.

Conversation turns and the composer share a centered 768px maximum reading
width. The panel keeps its own full layout track; narrow viewports use the
available width. The shared internal chat layout style supplies this measure.
