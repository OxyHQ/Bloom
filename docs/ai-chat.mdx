# AiChat

The pieces of the AI chat and AI image generation screens. Everything is data and callbacks — no model, transport or storage. The full screens are composed in Storybook under `Templates/AI Chat` and `Templates/AI Image Generation`.

| Export | What it is |
| --- | --- |
| `AiChatShell` | The page frame: sidebar, chat container, resizable right panel, and the phone / tablet drawers |
| `AiChatMobileHeader` | The in-container header below `xl` (menu button, title, panel button), wired to the shell |
| `AiChatResizeHandle` | The grip on the chat's right edge |
| `AiChatContainer` | The chat card: breadcrumb header, thread, composer slot, `AgentThinking` while working |
| `AiChatThread` | The bottom-anchored, self-following scroll of turns — with the follow, upward pagination and `ref` a host with history needs |
| `AiChatUserMessage` / `AiChatAssistantMessage` | The turns, with the staggered blur-in |
| `AiChatMessageLine`, `AiChatBulletList`, `AiChatBullet`, `AiChatStrong`, `AiChatLinkChip` | A reply's blocks and inline runs |
| `AiChatFeedbackRow` | Like / dislike / copy with tooltips, plus your own `actions` |
| `AiChatImageGeneration` | An image generating: dot wave, split-flap countdown, radial reveal, feedback and toast |
| `AiChatCodePanel` | Changes / Browser panel: uncommitted-changes card and a numbered code view |
| `AiChatGalleryPanel` | Gallery / Styles panel: masonry wall of generations that expand in place |

It composes Bloom's own families: `Sidebar` (with `tree` and `plan`), `ComposerPill` + `ComposerStatusBar` inside `ComposerLoader`, `CodeBlock` / `CodeLines`, `AgentProgress`, `AgentThinking`, `Tabs` (pill), `Breadcrumb`, `Tooltip`, `Button`.

```tsx
import { AiChatShell, AiChatContainer, AiChatMobileHeader, AiChatThread, AiChatUserMessage, AiChatAssistantMessage, AiChatCodePanel } from '@oxy.so/bloom/ai-chat';

<AiChatShell
  sidebar={<Sidebar {...rail} />}
  sidebarCollapsed={railOnly}
  mobileSidebar={<Sidebar {...rail} mobile flat />}
  panelLabel="Code"
  panel={(width) => <AiChatCodePanel width={width} code={file} language="tsx" />}>
  <AiChatContainer
    project="vibl coding project"
    title="coding scenario"
    header={<AiChatMobileHeader title="Agentic chat" />}
    working={working}
    background={<YourOwnField />}
    composer={
      <ComposerLoader active={working}>
        <ComposerPill surface={false} glass={working} busy={working} disabled={working} onStop={stop} />
      </ComposerLoader>
    }>
    <AiChatThread>
      <AiChatUserMessage>update our colour tokens for dark mode</AiChatUserMessage>
      <AiChatAssistantMessage>Done — the tokens are wired.</AiChatAssistantMessage>
    </AiChatThread>
  </AiChatContainer>
</AiChatShell>
```

Give the shell a sized parent — it fills it.

## Shell

- **lg and up** (1024): the floating `sidebar` in flow, 16 from the workspace, inside a 12px frame on background-full.
- **xl and up** (1280): the `panel` 12 right of the chat at its width (410, dragged within 320–560). The grip is a 20px strip straddling the chat's edge; hovering it reveals a 15×25 grip (radius 4, border, background-primary, shadow-xs, three 1×13 icon-quaternary lines) that follows the pointer along the edge and stays while dragging. Dragging right widens the chat. With keyboard focus, ←/→ nudge by 16.
- **below xl** the panel is a right drawer — min(410, 100% − 12) wide, background-full, p 12, shadow-sidebar, a 40-tall header with the panel name and a close button — over a 40% black backdrop, sliding 300ms. `panel` receives `'100%'` there.
- **below lg** the `mobileSidebar` rests under the workspace (272 wide, py 12 / pl 6). Opening it slides the whole workspace 272 right and rounds it to 32 while the sidebar scales from 94% and fades in (325ms `cubic-bezier(0.42, 0, 0.58, 1)`); a 10% black / 5% white veil over the workspace closes it. Opening one drawer closes the other.
- **The nav drawer swipes** — dragging in from the left edge opens it and dragging the open drawer back closes it, the drawer following the finger and settling on release by distance (halfway) or by a flick (0.3 px/ms), whichever the release says first. `navSwipeEnabled` (default **`true`**) turns it off: a drawer that cannot be swiped has one way to open on touch, which is what a host migrating off `expo-router`'s `Drawer` loses, so it is on unless a host says otherwise.

  It is armed only where there IS a drawer — below `lg`, and only with a `mobileSidebar`. An opening drag has to start within **24px of the left edge**, travel 12px, and be **twice as horizontal as vertical** before it is claimed: a vertical drag stays the thread's scroll and a horizontal drag anywhere but the edge stays the content's, so a carousel or a scrolling code block inside the chat keeps its gestures. Once the drawer is open the closing drag may start anywhere, because the veil is over all of it by then. On **web only a real touch** is claimed — a mouse drag from the edge is left alone so a selection that starts there survives — and nothing sets `touch-action`, which would have taken horizontal panning away from every scroller inside the workspace.
- `navOpen` / `panelOpen` are controllable. Reduced motion snaps: the drag itself still tracks the finger 1:1 (it is direct manipulation, not an animation), and only the settle at the end of it jumps rather than travels.
- **A collapsible rail** — `sidebarCollapsed` publishes the state while the sidebar owns its width and transition. `sidebarWidth` and `collapsedSidebarWidth` are explicit column overrides only; omit them for a Bloom `Sidebar` so its FAB, insets and collapse animation determine the actual width. The shell does not clip that sidebar into a fixed 56px lane.
- **`background` and `surface`** — `background` is any node, drawn above the shell's own background-full and below the sidebar, workspace and drawers; it is never interactive. The workspace paints background-full too, so pass `surface={false}` with it (that drops both) or the layer is covered exactly where the chat sits. When the layer belongs to the chat rather than the page, put it on `AiChatContainer` instead, which is the nearer slot and needs no opt-out.
- **`scroll`** — what scrolls the page, `AppShell`'s contract. `container` (the default) fills the parent and the conversation scrolls inside the card. **`document`** (web) grows the page and lets the browser scroll it — the page's scrollbar, scroll restoration, the mobile address bar collapsing and `window.scrollTo` behave as on any page. See [Document scroll](#document-scroll). Native has no document and treats it as `container`.
- **What the shell publishes** — `useAiChatShell()` returns the shell's state to any descendant: `compact`, `navCollapsed`, `sidebarCollapsed`, `hasNav` / `hasPanel`, `documentScroll`, `openNav` / `closeNav` / `openPanel`, and **`navPresented`**.

  Below `lg` a closed drawer stays **mounted** — it is translated offscreen, not removed. The shell takes it out of reach itself: while closed, the nav drawer and the panel drawer are `aria-hidden` and `pointerEvents="none"`, `inert` on web (so their controls leave the tab order too) and hidden from VoiceOver/TalkBack on native. A host does not wrap `mobileSidebar` in a gate of its own; `navPresented` is there for anything else that has to know whether the nav is on screen.

## Container and thread

Radius 24 on background-secondary: the breadcrumb header (px 16 / pt 16, share and more glyphs 8 apart, deepening to black / white on hover), the thread, then the footer (px 10 / pt 12 / pb 10, gap 10) with `AgentThinking` (infinity) while `working` and the `composer`.

`project` is **optional**: a chat that belongs to nothing draws its own crumb alone, with no folder glyph and no empty crumb.

`background` is a layer filling the container, drawn **above its own surface and below every turn, header and composer**, clipped to the radius and never interactive — a host's wallpaper, gradient or animated field goes here rather than behind the container, and nothing has to reach into it. An opaque node needs nothing else; add `surface={false}` when the node is translucent and should show what the container is sitting on instead of background-secondary.

The thread scrolls with a thin scrollbar, px 16 / pt 16, turns 12 apart, and is **bottom-anchored**: a short exchange sits just above the composer. It follows the newest content with a smooth scroll whenever it grows — that is the default, and every prop below is off unless asked for.

| Prop | Type | Default | Description |
|---|---|---|---|
| `autoFollow` | `boolean` | `true` | Follow the newest turn as the content grows. |
| `followAnimated` | `boolean` | `true` | `false` for a follow that must not be seen travelling. |
| `followThreshold` | `number` | — | Follow only from within this many px of the bottom, measured **before** the growth. Omit and every growth follows. |
| `onStartReached` | `() => void` | — | The reader came near the **top**. A chat pages upward, so this — not `onEndReached` — is its pagination signal. Once per approach; it re-arms when the reader leaves the zone. |
| `onStartReachedThreshold` | `number` | `300` | How near the top, px. |
| `maintainStartPosition` | `boolean` | `false` | The growth that answers an `onStartReached` is added to the offset, so a page landing **above** the reader does not move the turn they are on. Inert without `onStartReached` — the thread only anchors growth it asked for. |
| `onScroll` / `scrollEventThrottle` | | `16` | The raw event. Nothing is attached at all unless something is listening. |
| `ref` | `AiChatThreadHandle` | — | `scrollToEnd({ animated })`, `scrollToOffset({ offset, animated })`, `getScrollView()`. |

**Not there:** virtualization and `scrollToIndex`. The thread is a `ScrollView`, so a long history is fully mounted, and a host jumping to a cursor measures that turn's row (`onLayout`) and calls `scrollToOffset`. `maintainStartPosition` is the web-safe half of React Native's `maintainVisibleContentPosition`, which react-native-web ignores.

**Hazard (web):** react-native-web gives every view `min-height: 0`, so the usual `flexGrow: 1` + `justifyContent: 'flex-end'` content container stays the viewport's height and its children overflow it instead of scrolling — and `onContentSizeChange` never sees the growth. The thread floors its container at `minHeight: '100%'` on web instead.

### Floating chrome

`<AiChatContainer floatingChrome>` keeps every part and changes the geometry: the conversation fills the **whole card** and scrolls **behind** the header and **behind** the composer. Use it when the transcript is the screen — a full-height chat where two opaque bands would each take a strip of it, or where a `background` layer should run edge to edge under everything. Leave it off (the default, and what the AI Chat template uses) for the stacked layout above.

| Layer | Geometry |
|---|---|
| card | unchanged: radius 24, background-secondary (or `surface={false}`), clipped; `background` still fills it under everything |
| `children` | fill the card's full height — nothing is in flow above or below them |
| header block | the `header` slot (`AiChatMobileHeader`) + the breadcrumb row, absolute at the top, transparent — no band of its own |
| footer block | `AgentThinking` + `composer`, absolute at the bottom, px 10 / pt 12 / pb 10, gap 10 — **no band of its own**: the transcript passes behind the composer and stays in sight around it |
| top fade | the page-header edge scrim in the card surface, opaque at the top edge, ending 55% of the header block's height below it; fades in over the first **16px** scrolled (the gap it closes) |

Both blocks are `pointerEvents="box-none"`, so the transcript under their empty space still scrolls and takes clicks. The fade is decorative (hidden from assistive tech) and exists **only while turns are actually under the header**. Nothing is painted behind the composer: its own card is what covers the turns under it, as the conversation slides past on either side.

**Insets.** The container measures both blocks (`onLayout`) and hands the heights to its children through context. An `AiChatThread` pads its **content** by them — pt = header block + 16, pb = footer block — and sets matching iOS `scrollIndicatorInsets`, so at rest the first and last turns sit exactly where the stacked layout puts them relative to the chrome, and in motion pass under it. The `ScrollView` stays the only scroller; `autoFollow`, `followThreshold`, `onStartReached`, `maintainStartPosition` and the ref work unchanged. A resize that is **exactly** the chrome's (the composer growing, `AgentThinking` appearing, the header measuring in on mount) is not a new turn: a reader at the end stays at the end without an animated follow, and a reader mid-thread keeps their turn in place. Any other child reads the same numbers from `useAiChatChromeInsets()` (`{ top, bottom }`, or `null` outside a floating container) to keep an empty state or a scroller of its own clear of the chrome.

**Why a fade, not a frost.** `AgentChat` frosts its overlaid header (white/black 20%, a 20px backdrop blur on web) once the transcript reaches it. Here the chrome has no band, and a frosted rectangle is one: it ends at its own bottom edge, and that edge is a line across the transcript. A one-colour opacity ramp is identical on native and web and needs no blur.

**Limits.** The fade is background-secondary. With `surface={false}` there is no known colour to fade to, so the header floats **without** it. Over an opaque `background` layer the fade is the card surface, not the layer.

### Document scroll

Under `<AiChatShell scroll="document">` (web) the **document** is the scroller, the way every framed Oxy web page scrolls. The chat keeps every part; what moves is the page.

| Part | Geometry |
|---|---|
| shell | at least one screen (`100dvh`) and grows with the chat; `overflow: clip`, never `hidden`, so it is not a scroll container |
| sidebar, panel | sticky rails, `top: 12`, one screen tall less the gutter above and below |
| drawers, backdrop, shell `background` | `position: fixed`, so they cover the screen, not the page |
| card | a [`ContentPanel`](/docs/bloom/main/content-panel), `framed` at the shell's gutter (`overlayInset` 12, `maskColor` the shell's background-full, background-secondary as its surface, `chrome="none"` — the template's card has no edge): its sticky mask and radius keep the card framed at the screen's edges while the conversation scrolls under them, as on any framed Oxy web page. It grows with the conversation, one screen tall at the least; the chrome always floats (`floatingChrome` is implied) |
| header block | sticky in the flow at `top: 12`, with the same fade while turns run under it |
| footer block | sticky in the flow at `bottom: 12`, no band — the conversation passes behind the composer |
| container `background` | a screen-sized layer with the panel's geometry, under the turns: a wallpaper stays put while the conversation moves over it |
| conversation | one stacking layer (`zIndex: 0`) under the header and the composer: a turn's own z-indexes (a search log, a progress card, a date header) never climb over the chrome |
| thread | a plain view, no scroller: bottom-anchored, px 16 / pt 16, turns 12 apart |

The thread keeps its props and its handle. It follows through the window, opens at its newest turn (the page is shared with whatever route was on it before), fires `onStartReached` near the top and holds a landed page still. Offsets stay in **the thread's own frame**: `0` is the thread's top, so a row's `onLayout` y is still a `scrollToOffset` target, and `contentSize` runs to the **end of the page**, so `contentSize − offset − viewport` is still the distance left to scroll. `getScrollView()` returns `null`. The browser's scroll anchoring is off inside the thread — it would move the page for growth the thread already accounts for, and only in some browsers.

At rest the chrome is in the flow and covers nothing, so `useAiChatChromeInsets()` is `{ top: 0, bottom: 0 }`.

**The host's part.** Nothing between the shell and the document may be a scroll container:

- Expo / react-native-web inject `html, body { height: 100%; overflow: hidden }` and `#root { height: 100% }`. Override them with unlayered rules — `height: auto`, `min-height: 100%` (`100vh` on `#root`) and `overflow: visible` on **both** axes (one clipped axis promotes the other to `auto`).
- `expo-router`'s `Stack` renders each web screen absolutely positioned, which pins the page to one screen: on web, host the routes with `Slot`, or a `Navigator` that renders the focused screen in the flow.
- Every route shares the one window scroll, so a page that is not a chat should open at the top (or where the reader left it): `useScrollRestoration('window')` from [`scroll`](/docs/bloom/main/scroll).

## Turns

- **User** — pushed right with a 6px bleed past the column, as wide as its text up to half the column + 6; radius 16, background-primary, px 12 / py 11, shadow-card.
- **User actions** — `actions` draws the feedback row's buttons under the card, 8 below and right-aligned, 6 apart (copy, edit). On a web pointer (`@media (hover: hover)`) they fade in over 150ms while the turn is hovered or holds focus — opacity only, so they stay in the tab order and the accessibility tree, and tabbing into one reveals the row. Native and touch web always show them.
- **Assistant** — full width, blocks 8 apart, with `AiChatFeedbackRow` last (`feedback={false}` drops it).
- **Blocks** — `AiChatMessageLine` (body-regular; `tone="secondary"` for status lines; `block` for a card), `AiChatBulletList` (a 5px disc in a 21px indent, items 8 apart), `AiChatStrong` (body-medium), `AiChatLinkChip` (inline, radius 8, px 4 / py 3, accent-100 with a 16px link glyph and caption-2-medium accent-500). A bare string child becomes a line; any other element a block line.
- **Motion** — a turn fades in over 400ms while its blocks rise 6px, un-blur 6px (web) and fade in, 500ms `cubic-bezier(0.25, 0.1, 0.25, 1)`, 180ms apart; a bullet list staggers its own items from its slot. `animate={false}` mounts settled (history), as does reduced motion.

## Feedback row

28px squares 6 apart: radius 8, p 6, background-tertiary, background-secondary-hover on hover with the 16px glyph deepening to icon-primary. Each has a `sm` tooltip above after 200ms (keyboard focus raises it too; a press does not). Copy swaps the glyph for a check (blur, 75% scale, fade, 200ms) and holds the tooltip open reading "Copied!" for 1.6s, then dismisses it even if the pointer is still there.

The confirmation follows the copy, not the press. `onCopy` returns `AiChatCopyResult` (`void | boolean | Promise<void | boolean>`): a handler returning nothing or `true` confirms at once, as before; a promise confirms when it resolves (only the latest press's); `false`, a throw or a rejection confirms nothing — a blocked clipboard is not a "Copied!".

`actions` (on the row, or through `AiChatAssistantMessage`'s `feedbackProps`) appends buttons after copy on the same surface:

```ts
interface AiChatTurnAction {
  key: string;                // React key; `${testID}-${key}` names the button
  label: string;              // accessible name and tooltip
  icon: AiChatIconComponent;  // RiVolumeUpLine, not <RiVolumeUpLine />
  onPress: () => void;
  active?: boolean;           // a toggle: hover surface + primary glyph, aria-pressed
  disabled?: boolean;         // 50% opacity, disabled, aria-disabled
}
```

Leave `active` undefined for a plain button: `false` is a toggle that is off, announced "not pressed". `AiChatUserMessage` takes the same `actions`.

```tsx
<AiChatAssistantMessage
  feedbackProps={{
    onCopy: () => Clipboard.setStringAsync(text),
    actions: [
      { key: 'speak', label: 'Read aloud', icon: RiVolumeUpLine, onPress: toggleSpeech, active: speaking },
      { key: 'regenerate', label: 'Regenerate', icon: RiRefreshLine, onPress: regenerate, disabled: busy },
    ],
  }}>
  {reply}
</AiChatAssistantMessage>
```

## Image generation

- The frame unfolds from 0 to 250 tall (550ms `cubic-bezier(0.22, 1, 0.36, 1)`) while it fades in and un-blurs, pushing the thread up instead of popping in.
- A 200×250 card (radius 16, background-primary, shadow-card): on web a canvas of 9px-spaced dots swelling and brightening as rings ripple out from the centre (icon-primary on a ring, icon-quaternary elsewhere, faded at the edges); native draws the still field. Along the bottom, "Generating image" shimmers against a **split-flap countdown** of whole seconds — each digit an 11-wide card whose old top half falls (150ms ease-in to −90°) as the new bottom half rises with a small slap past 0° (230ms, 150ms late).
- It lands after `duration` (4000) — or when a controlled `ready` turns true — firing `onGenerated` once. The status fades out (300ms); on web the artwork is revealed through a radial mask feathered 26% wide sweeping from the centre to 132% while it fades in and un-blurs 10px (1550ms, a registered `@property`); native fades it in.
- The feedback row rises in under it; like and dislike raise a toast over the image's bottom edge (radius 8, neutral-950 @80% with an 8px backdrop blur, body-2-medium white) that rises 8px in and out (420ms) and leaves after 2.2s.

## Panels

Both share a shell: `width` wide, full height, pt 8, gap 10, and a 30-tall header of pill tabs with actions on the right.

- **Code** — Changes (∞) / Browser (globe) with terminal / expand / sidebar glyphs (16px, 8 apart). A summary strip framed on three sides by a 1px background-secondary line (radius 10 on top): "N Uncomitted changes" (body-2-medium secondary), `+156` / `-23` (body-regular success-700 / negative-600) and, only with `onUndo`, an undo glyph; each changed file tucks 7px up under it (radius 10, background-secondary, py 4 / pr 5 / pl 6: a 16px mark, the path with its additions, a `status` chip). Then the code as `CodeLines` at `md`, soft-wrapping, scrolling with a thin scrollbar. The Browser tab shows `browser` or a placeholder; `browser={null}` drops the tab.
- **Gallery** — Gallery (an 18px glyph, optically matching the 20px sparkle) / Styles (the tab shows `stylePresets` or a placeholder; `stylePresets={null}` drops it), with 18px actions on 2px padding (radius 6, primary-hover, tooltips). The wall is explicit balanced columns 8 apart — always filling the shortest — so an insertion only moves its own column; `generated` images are pinned to the head of the first. Tiles (radius 10, background-secondary, the artwork covering them at its `aspectRatio`) cascade in top-left → bottom-right (fade + 8px blur over 400ms, scale from 95% over 550ms, 130ms × order late; a generated tile only fades). Hovering lifts the image 3% and fades in a scrim (neutral-950 40% → clear → 55%) with glass download / more actions (22px, neutral-950 @45%, 65% hovered, 4px blur; each drawn only with its `onDownload` / `onMore`) and the prompt (body-2-regular, two lines). Pressing a tile lifts it into a full-width row above the wall (body-medium prompt, p 10, a minimize action); on web it morphs between the two boxes by FLIP (550ms, 600ms for the enlarged tile) while its neighbours glide, painting above the wall in flight, and the scroller jumps to the top first.

## Known gaps

- **Native:** no dot-wave animation (a still field), no radial mask (a fade), no gallery morph (the tile moves instantly), and the gallery's hover scrim shows only on the enlarged tile. The resize grip works by pan but only appears while dragging.
- **The glass chips** are frost + tint + sheen + rim; the SVG refraction layer of the reference material is not reproduced.
- **Effort at Max** has no flame / starfield flourish (see `composer-panel`).
- The gallery re-baselines rather than animating when the panel's own width changes during a resize drag.

### Custom chat header

`AiChatContainer` can receive a `header` such as Bloom's `PageHeader` with the
application's real actions. Omit `title` and `project` to omit its breadcrumb;
without breadcrumb or action handlers no extra header row is reserved. Share
and more controls render only when `onShare` and `onMore` are supplied. This
keeps applications without public sharing from presenting a dead share action.

### Panels without a backend

A panel control renders only when it can act. The summary's undo glyph needs
`onUndo`, a tile's download and more actions need `onDownload` and `onMore`,
and the header `actions` are the caller's list (pass `[]` for none: the defaults
carry no handlers). A host with no browser preview or no style presets passes
`browser={null}` or `stylePresets={null}` and the tab is gone, so the panel
never presents a preview or a style editor that does not exist.

### Panel keyboard ownership

An open `AiChatShell` panel closes on Escape (web) or Android back. Controlled
hosts keep `panelOpen` in sync through `onPanelOpenChange`; removing their
`panel` closes the desktop rail. At compact widths the drawer moves web focus
inside, cycles Tab/Shift+Tab, and returns focus to its opener when closed.
Portaled menus/dialogs take priority over shell dismissal and focus containment.
Native uses the shared accessibility-focus hook on entry; automatic native
return to an arbitrary caller's opener is not available without a trigger ref.
No device-runtime verification is implied by the Android back-handler tests.

`AiChatContainer.actions` composes real menu triggers or other chat actions in
the breadcrumb action row, replacing the default share/more controls. Use it
with `AiChatMobileHeader` to preserve the template layout without a second toolbar.

## Selection

Content is selectable and the interface is not. Every control takes no selection on web (Bloom's base rule, adopted by the theme provider); the breadcrumb and the web-search trail are navigation and activity, so their text is not selectable either. A reply's lines are content — `AiChatMessageLine` is selectable by default — and a status line passes `selectable={false}`.
