# Surface

`Surface` is a passive container. It owns material, not interaction, navigation or spacing. It is distinct from `surfaces`, Bloom's imperative dialog and sheet API.

```tsx
import { Surface, Button } from '@oxy.so/bloom';

<Surface style={{ padding: 24 }}>
  <Button>Continue</Button>
</Surface>
```

Surface has one material: a subtly translucent body, shared sheen and rim, and one backdrop blur on web. There is no material selector. Opaque semantic fill colours receive 90% opacity; caller-supplied alpha remains explicit. With no fill override, a Surface on the page uses the card role, and a nested Surface derives its fill from the actual parent. `radius` defaults to 20. Geometry precedence is explicit `radius` → resolved `style.borderRadius` → family default, shared with Card and BlurIsland. Host and paint always receive the same resolved radius, including percentage style values. Use `radius` or `style.borderRadius` to set native clipping, rather than a class utility the inner paint cannot inspect. `className` belongs to the root layout node; padding, size and layout remain caller-owned. `children`, `accessibilityLabel` and `testID` pass through.

Surface publishes its resolved base fill to `SurfaceLevelProvider` and `--bloom-surface`, so nested cards, fields and other controls read the same backing that it paints. The gradient and rim decorate this base; they do not create another level. Stepping is based on the actual fill even beyond named level 3. Explicit `fill` takes precedence over `style.backgroundColor`; both are respected and published. Material fills are composited onto the declared parent, an estimate rather than a measurement of the blurred backdrop.

`Surface` has no press, disabled, loading or business state. Controls such as Button own those states and consume the **same paint** directly: `SurfacePaint` for universal components and `surfaceMaterialCss` for web roots. These are internal implementation primitives, not alternate public components. Button keeps its single interactive root without wrapping it in another Surface.

The shared implementation lives in `surface/shared.ts`, `SurfacePaint.tsx` and `web-material.ts`. Web material blurs the backdrop (one `backdrop-filter: blur(8px)`) beneath the 90%-opaque body, which keeps the fill dominant across the whole shape. Native paints a single view: tint as `backgroundColor`, sheen as a CSS gradient, rim as an inset `boxShadow`. There is no SVG, no layout state and no per-surface `BlurView` on native. A surface's own shadow belongs on the outer node; do not clip the native outer node if it needs a shadow.

For existing web hosts, `useSurfaceMaterial` applies the shared decoration through pseudo-elements without adding layout nodes. Painted hosts pass their tint source to `SurfacePaint` and keep the host background transparent; omitting `fill` is reserved for an intentionally tintless optical layer. Native paint is one `View` with the sheen as `experimental_backgroundImage`; omitting `fill` leaves its background transparent. See [Material composition](./material-composition.mdx) for consumers and exceptions.

The web material is verified in Chromium. It remains backdrop-dependent and incurs one blur pass per painted surface; large or densely repeated panes need visual and performance checks. A Surface containing another blurred control can establish a different backdrop for that control, so inspect nested compositions rather than assuming independent panes. Button, Card and the floating Sidebar share this material; unfilled controls and docked backing containers retain their own contracts. `SurfacePaint` selects web optics at runtime, so universal consumers do not need platform forks merely to paint it.

The blur pane stays inset to the host, so rounded corners hold even in nested controls. The specular sheen and rim are decorative lighting, theme-adjusted for both modes.
