# Surface

`Surface` is a passive container. It owns material, not interaction, navigation or spacing. It is distinct from `surfaces`, Bloom's imperative dialog and sheet API.

```tsx
import { Surface, Button } from '@oxy.so/bloom';

<Surface style={{ padding: 24 }}>
  <Button>Continue</Button>
</Surface>
```

Surface has one material, the one Astro's pinned tabs wear: a frosted, translucent body and an edge of light along its top and bottom. There is no material selector. Opaque semantic fill colours receive 72% opacity on web, so the frosted backdrop shows through; caller-supplied alpha remains explicit. With no fill override, a Surface on the page uses the card role, and a nested Surface derives its fill from the actual parent. `radius` defaults to 20. Geometry precedence is explicit `radius` → resolved `style.borderRadius` → family default, shared with Card and BlurIsland. Host and paint always receive the same resolved radius, including percentage style values. Use `radius` or `style.borderRadius` to set native clipping, rather than a class utility the inner paint cannot inspect. `className` belongs to the root layout node; padding, size and layout remain caller-owned. `children`, `accessibilityLabel` and `testID` pass through.

Surface publishes its resolved base fill to `SurfaceLevelProvider` and `--bloom-surface`, so nested cards, fields and other controls read the same backing that it paints. The gradient and rim decorate this base; they do not create another level. Stepping is based on the actual fill even beyond named level 3. Explicit `fill` takes precedence over `style.backgroundColor`; both are respected and published. Material fills are composited onto the declared parent, an estimate rather than a measurement of the blurred backdrop.

`Surface` has no press, disabled, loading or business state. Controls such as Button own those states and consume the **same paint** directly: `SurfacePaint` for universal components and `surfaceMaterialCss` for web roots. These are internal implementation primitives, not alternate public components. Button keeps its single interactive root without wrapping it in another Surface.

The shared implementation lives in `surface/optics.ts` (the measured looks), `surface/shared.ts`, `SurfacePaint.tsx` and `web-material.ts`. On web the shape is always the host's own border radius, so material and host cannot disagree, whatever the radius (capsules, per-corner radii, percentages). Two pseudo-elements paint it:

- `::before` is the body: the backdrop blurred (24px), saturated, flattened and brightened, under the tint.
- `::after` is the edge: the backdrop brightened again through a CSS mask — a 1.25px line along the border (the box minus its padding box), full where it runs flat along the top and bottom, about a third through each corner and gone before the side, plus a glow within 8px of the top and bottom. The falloff is measured by depth from the edge and stops 12px down, so a capsule's ends do not read as an outline.

Hosts set the material's variables through `surfaceOpticsVars(optics, radius)` on every painting element, so none inherits an enclosing surface's values. A host clips with `overflow: clip; overflow-clip-margin: 1px` rather than `hidden`: an exact clip cuts the layers' antialiased edge and Chromium does not antialias it. Its corners are always round on web: Chromium drops every mask inside an element clipped with a non-round `corner-shape`, which would turn the edge into a flat brightening of the whole surface. No blend modes either: a sibling with `mix-blend-mode` switches the body's backdrop filter off.

Native paints a single view: tint as `backgroundColor`, the glow as a gradient and the edge line as an inset `boxShadow`. There is no per-surface `BlurView` on native. A surface's own shadow belongs on the outer node; do not clip the native outer node if it needs a shadow.

`Surface` has no press, disabled, loading or business state. Controls such as Button own those states and consume the **same paint** directly: `SurfacePaint` for universal components, `surfaceMaterialCss` and `useSurfaceMaterial` for web hosts. A `Screen` inside a painted surface leaves its canvas transparent, so the surface's material and edge stay visible.
