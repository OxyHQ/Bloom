# Surface

`Surface` is a passive container. It owns material, not interaction, navigation or spacing. It is distinct from `surfaces`, Bloom's imperative dialog and sheet API.

```tsx
import { Surface, Button } from '@oxy.so/bloom';

<Surface style={{ padding: 24 }}>
  <Button>Continue</Button>
</Surface>
```

Use `material="solid"` (default) for an opaque fill with the shared gradient and rim, or `material="glass"` for the optional refracted web material. Solid composites translucent fills onto the actual parent backing; glass preserves the supplied alpha. With no fill override, a Surface on the page uses the card role, and a nested Surface takes a relative step off its parent. `radius` defaults to 20. A numeric or percentage `style.borderRadius` also updates the native paint's clipping radius. Use `radius` or `style.borderRadius` to set native clipping, rather than a class utility the inner paint cannot inspect. `className` belongs to the root layout node; padding, size and layout remain caller-owned. `children`, `accessibilityLabel` and `testID` pass through.

Surface publishes its resolved base fill to `SurfaceLevelProvider` and `--bloom-surface`, so nested cards, fields and other controls read the same backing that it paints. The gradient and rim decorate this base; they do not create another level. Stepping is based on the actual fill even beyond named level 3. Explicit `fill` takes precedence over `style.backgroundColor`; both are respected and published. For opt-in glass, the published fill is the tint composited onto the declared parent, an estimate rather than a measurement of the refracted backdrop.

`Surface` has no press, disabled, loading or business state. Controls such as Button own those states and consume the **same paint** directly: `SurfacePaint` for universal components and `surfaceMaterialCss` for web roots. These are internal implementation primitives, not alternate public components. Button keeps its single interactive root without wrapping it in another Surface.

The shared implementation lives in `surface/shared.ts`, `SurfacePaint.tsx`, `web-material.ts` and `web-refraction.ts`. Solid uses only an opaque fill, gradient and rim. Optional web glass uses a full-pane blur and SVG displacement beneath the tint, sheen and rim; one filter definition serves all explicit glass instances in a document. Native uses a single SVG tint/sheen layer, with explicit stop opacity and no blur or displacement. A surface's own shadow belongs on the outer node; do not clip the native outer node if it needs a shadow.

For existing web hosts, `useSurfaceMaterial` applies the shared decoration through pseudo-elements without adding layout nodes. Universal hosts can omit `SurfacePaint.fill` to decorate a background they already own. Native paint uses one sheen gradient and an optional flat fill rectangle; SVG IDs are stable across server and client rendering. See [Material composition](./material-composition.mdx) for consumers and exceptions.

The optional web glass material is verified in Chromium. It remains backdrop-dependent and incurs compositor cost per painted surface; large or densely repeated panes need visual and performance checks. A Surface containing another glass control can establish a different backdrop for that control, so inspect nested compositions rather than assuming independent panes. Button, Card and the floating Sidebar share this material; solid and flush variants retain their own contracts. `SurfacePaint` selects web optics at runtime, so universal consumers do not need platform forks merely to paint glass.

Web Surface panes sample an extra 8 px around the pane before clipping, so nearby colours can refract into its interior. Buttons use solid paint and do not capture the backdrop. The displaced image comes from the real backdrop; the specular sheen and rim remain decorative lighting, not a simulated mirror. Light mode preserves the bright rim; dark mode uses a thinner, quieter highlight and a dark lower edge. Both modes share the same sampling and displacement.

Run `node scripts/verify-surface-refraction.mjs` with `CHROME_PATH` pointing to Chromium. It changes only the colours outside the pane while holding the background directly beneath it constant, then checks interior pixels in both modes. Disabling displacement is the negative control: those interior pixels must stop changing. **Capture the full viewport, then crop the captured image:** Chromium screenshots taken with a capture `clip` can trim the backdrop input itself and falsely suggest lateral sampling is absent.

Storybook: **Base / Surface / Nested**, **Base / Surface / Material** and **Base / Surface / Backdrop Reflection**. The latter lets you change only the sides. See [Button](./button.mdx) for the reference comparison and measured stress case.
