# Meter

`Meter` is the determinate bar. Every meter and progress bar in Bloom is this
one — seventeen families used to hand-roll it, and they disagreed about both
colours.

```tsx
import { Meter, MeterRing } from '@oxy.so/bloom/stat-bar';

<Meter value={4} max={5} accessibilityLabel="Cleanliness" valueText="4 of 5" />

<MeterRing value={72} max={100} size={72} thickness={6} accessibilityLabel="Listing quality">
  <Text variant="headline-semibold">72</Text>
</MeterRing>
```

It draws nothing but the rail and the fill: no label, no value, no footer. A bar
with a label is `StatBar`; a bar inside a card is that card's business.

## Props

| prop                  | decides                                                       |
| --------------------- | ------------------------------------------------------------- |
| `value` / `max`       | how far along; clamped into `[0, max]`, `max` defaults to 1    |
| `height`              | 6 by default; `radius` follows it unless you set one           |
| `width`               | a fixed width; without one the bar fills its parent            |
| `fill` / `track`      | the two colours — see below before you pass either             |
| `transitionMs`        | ease the fill on WEB; native snaps, reduced motion snaps       |
| `indeterminate`       | the amount is not known yet: a sweeping segment, no value reported — see below |
| `accessibilityLabel`  | what the bar measures — REQUIRED                               |
| `valueText`           | `aria-valuetext`, the reading ("4 of 5"); without it the share in the reader's locale ("80%", "80 %") |
| `role`                | `meter` (default) for a measurement, `progressbar` for a task's progress — see Accessibility |
| `decorative`          | no role at all, for one segment of a larger meter              |
| `className` / `fillClassName` | actual track and fill hosts; classes override default geometry and paint, while fill width remains data-owned |
| `fillTestID`          | the fill's own `testID`; defaults to `` `${testID}-fill` ``    |

`MeterRing` takes `size` (56) and `thickness` (5) instead of `height`/`width`,
plus `cap` and centred `children`.

### A download ring

`MeterRing` is also the ring an app store shows while it installs: thin
(`thickness` 2 to 3 at 28 to 32 px), `indeterminate` while the amount is not
known, its `value` once it is, and with `onStop` the control that stops it.

```tsx
<MeterRing
  value={fraction ?? 0}
  indeterminate={fraction === null}
  size={30}
  thickness={2.5}
  accessibilityLabel={`Installing ${name}`}
  role="progressbar"
  onStop={cancel}
  stopLabel={`Stop installing ${name}`}
/>
```

| Prop | What it does |
| --- | --- |
| `indeterminate` | a quarter of the ring turns, one turn a second (the native driver natively, CSS on web, still under reduced motion: it is an activity indicator); the progressbar reports no value (`aria-valuenow` absent, `aria-busy`) |
| `onStop` / `stopLabel` | a stop square in the centre (a little over a third of the inside, the arc's colour) and the whole ring a button named `stopLabel`, which `onStop` requires; `children` are not drawn with it |

Without `onStop` the ring is not interactive: draw no stop square for what
cannot be stopped.

## The fill is the accent

Three families used to paint the fill `theme.colors.text` — `RatingBar`,
`WizardProgress` and the lease bar in `tenancy` — while six others used the
accent. A near-black fill reads as **ink**, not as a measurement: on a neutral
rail it is the highest-contrast thing on the row, so a fifth-full bar shouts
louder than the text beside it. The accent is the one colour in the theme that
means "this is the quantity", so that is the default, and `fill` stays
overridable for a status tone.

## The track is `neutral-200`, `neutral-700` in dark

Measured before the fold: seven families at `200/700`, two at `200/800`, one at
`300/700` and one at `100/800`. The majority won on numbers and it is also the
one that holds in both modes — `neutral-100` is invisible on a card, and
`neutral-800` against a `neutral-900` surface is a rail you have to look for.

## A chart is not a meter

If the bars in a group encode **which datum** each one is rather than **how much
of one thing** there is, it is a chart: colour it from `chart-cards/palette.ts`
(`chartHueTone`, `resolveMonoTone`), not from the meter's defaults.
`PricePerAreaComparison` is the case — its rows are a home against its street,
neighbourhood and city, so the highlighted row takes the brand-anchored data hue
and the comparators the single-ink neutral. Painting them with the accent would
have said each row was progress toward something.

## An indeterminate bar

`indeterminate` is the bar for an amount nobody knows yet — a file
transcoding, a step that reports no progress. A segment 40% of the track wide
sweeps across it every 1.4 s, `ease-in-out`, from off its left edge to off its
right one; under reduced motion it parks 30% along, which still reads as
"working". The bar is then a `progressbar` whatever `role` says (a `meter`
always has a value) and reports none: `aria-valuenow` and `aria-valuetext` are
absent and `aria-busy` is set. `value`, `reveal` and `transitionMs` are not
drawn meanwhile.

```tsx
<Meter indeterminate value={0} accessibilityLabel={`Processing ${name}`} />

// A segment of a row whose status text already says it (`TrackUploadRow`):
<Meter decorative indeterminate value={0} height={4} />
```

The sweep needs no measurement: natively the segment's `left` moves as a share
of the track on the JS driver (a layout property cannot take the native
driver), and on the web a keyframe in Meter's adopted stylesheet moves it.
`TrackUploadRow`'s processing bar is this one, and the dialog header's wizard
step is a determinate `Meter`, rather than the hand-drawn bars they had.

## Accessibility

A `meter` named by `accessibilityLabel`, with the FLAT `aria-value*`
attributes, on both platforms. `role` says which of ARIA's two it is, as a Mac
says a level indicator and a progress indicator:

- `meter` (the default): a measurement within a known range — a score, the
  share of the ratings, how full a cart's minimum is. "Level indicator".
- `progressbar`: how far a TASK has got — an upload, a download or an install
  (a download's ring or an indeterminate bar included), an episode listened, a lease's
  elapsed time, an application's steps. "Progress indicator". Bloom's own
  progress families (`creator-studio`, `media-card`, `media-header`,
  `track-list`, `order-status`, `outline-nav`, `listing-actions`, `tenancy`)
  pass it.

react-native-web drops the `accessibilityValue` object entirely, so a bar
setting only that announces its role and no value at all; React Native folds the
flat props back. React Native keeps `aria-valuenow` as a WHOLE number, so a
fraction of 1 would say nothing natively: without `valueText` the bar says its
share of the track in the reader's locale (`meterValueText`, `formatPercent`:
"42%", "42 %"), on both platforms. ARIA never computes a name for a `meter` or a
`progressbar` from its contents and the bar draws no text of its own, which is
why the label is required rather than optional.

A bar that is one segment of a larger meter passes `decorative` and is hidden:
two nested meters announce the same measurement twice.

# StatBar

`Meter` plus the text around it — one bar, two meanings.

```tsx
import { StatBar } from '@oxy.so/bloom/stat-bar';

<StatBar label="Storage" value={62} max={100} minLabel="0 GB" maxLabel="100 GB" />

<StatBar variant="split" label="Votes" percent={64} leftValue="Yes" rightValue="No" />
```

## Which prop decides what

| prop                      | decides                                            |
| ------------------------- | --------------------------------------------------- |
| `variant`                 | `progress` (default) or `split`                     |
| `value` / `max`           | progress: how far along                             |
| `percent`                 | split: where the divide sits                        |
| `leftValue` / `rightValue`| split: what each side is                            |
| `minLabel` / `maxLabel`   | progress: the ends of the range                     |
| `label`                   | what the bar is about — required                    |
| `icon`                    | a glyph beside the label                            |
| `fillColor` / `trackColor`| the colours — default to the meter's                |

The two variants are one component because they are the same object visually,
and one prop rather than two components because a row often switches between
them for the same subject.

## `progress` and `split` are different claims

`progress` says *how much of a maximum has been used* — there is a ceiling, and
approaching it means something. `split` says *how a whole divides between two
named sides* — there is no ceiling and neither side is "full".

Using `progress` for a split reads as the left side filling up toward a limit,
which is a claim you did not intend to make.

## `minLabel` / `maxLabel` on a progress bar

A bar with no scale is a proportion with no units. "62 of 100" is a different
statement from "62%", and only one of them tells the user whether to act.

## `percent` is a number, the values are strings

`leftValue` and `rightValue` are strings because they are labels, not the
maths: "Yes" / "No", "1,204" / "677", "You" / "Everyone else". The bar's
geometry comes from `percent` alone.

## `label` is required

A bar in a stack of stats with no label is a colour. It is also the only thing
a screen reader gets, since the bar itself conveys nothing.

## Visual reveal

`Meter` accepts `reveal={{ visible, once, duration, delay, easing }}`. This is opt-in and independent of `value`: `aria-valuenow`, `aria-valuemax`, `valueText` and the accessible label continue to describe the real measurement during the empty state, delay and animation. `RatingBar` forwards the same prop to its Meter.

Before visibility, the fill is empty. Visibility starts a width animation on both platforms; native uses the Animated JS driver because width is a layout property. `once:true` retains the revealed state when visibility later becomes false. Defaults are `once:false`, duration 300ms, delay 0 and CSS ease (`[.25,.1,.25,1]`). Easing accepts four finite cubic-bezier coordinates with x coordinates in `[0,1]`. Delays and durations are nonnegative milliseconds.

Reduced motion displays the real width immediately, including before the visibility threshold is reached, and cancels any pending delay or active motion when the preference changes. Removing `reveal` restores the ordinary meter. The existing `transitionMs` behavior is unchanged when no reveal is supplied; reveal owns timing when both props are present.

Use [Viewport](./viewport.mdx) to provide real visibility from document scrolling, nested scrolling or native clipping viewports. The observer's `once` disconnects measurement after entry; the reveal's `once` keeps the visual state if a caller supplies a visibility signal that later changes.
