# Fab

`Fab` is a prominent action built on `Button`. It shares color, focus, loading,
press and accessibility behavior. Its parent owns placement.

```tsx
import { Fab } from '@oxy.so/bloom/fab';
import * as Icons from '@oxy.so/bloom/icons';

<Fab icon={Icons.RiAddLine} accessibilityLabel="Create post" onPress={createPost} />
<Fab icon={Icons.RiAddLine} label="Compose" tone="action" appearance="solid" />
```

`size` is `xs | sm | md | lg` (40, 48, 50, 64 points; default `md`). The corresponding glyphs are20,24,26,32points. The default50/26 geometry is shared by standalone, sidebar, Screen and BottomBar actions. `iconSize` optionally sets the glyph dimensions independently; for example, `size={50} iconSize={26}`. The collapsed circle keeps its requested diameter and adjusts its padding around the glyph.
`size` and `tone` inherit from `BloomScope`. `tone` defaults to `accent`: the
theme's primary, with the on-primary glyph, a tinted action as Apple's
`glassProminent` is: on the lens the fill tints the glass at 0.8, so the glass
still shows through it, and on the web the fill is the surface tint (72%) over
the frost;
`appearance` defaults to `solid` and also accepts `subtle`, `outline`, `plain`.
Icon props take a component, which receives its size and foreground color.
Icon-only actions require `accessibilityLabel`; labeled actions use their label.

An explicit tone wins over `BloomScope`, which wins over the `accent` default. A utility such as “Back to top” can use `tone="neutral" appearance="subtle"`. The Color roles prototype demonstrates an action Fab alongside accent navigation and subtle support surfaces.

`shape` is the silhouette: `squircle` (the default, `DEFAULT_FAB_SHAPE`), `rounded` or `circle`.
The two squares take a corner of 28% of the diameter (Material's 16 on 56, and
the owner's reference FAB), `rounded` with circular corners and `squircle` with
Apple's continuous one (iOS `continuous`, CSS `corner-shape: squircle`). The
lens takes the radius as its corner, so the glass, its press and a menu's morph
follow it; the lens draws every corner continuous, so the two squares read alike
on Android and OxyOS. Beside a bottom bar the FAB is the bar's height (62) in
any shape. `FAB_SHAPES`, `fabCornerRadius` and `useFabDiameter` give the same
geometry to a host that draws a FAB's material itself.

```tsx
<Fab icon={Icons.RiAddLine} shape="circle" accessibilityLabel="Create" onPress={create} />
```

Use `AppShell.primaryAction` to coordinate a screen action with navigation, or
`BottomBar.action` for a custom bottom composition. A standalone Fab stays in
normal flow and accepts the usual `style` and `className` layout overrides.

## Controlled collapse

```tsx
<Fab icon={Icons.RiAddLine} label="New post" collapsed={compact} onPress={createPost} />
```

`collapsed` defaults to `false`. It contracts the measured label width and opacity
with Bloom's 300ms motion timing, reverses from the current position, and respects
reduced motion. The same Button stays mounted: focus, accessible name, loading
and disabled behavior remain available when only the icon is visible. Parent
`style` widths remain authoritative, so an extended full-width action can follow
a collapsing sidebar without another animated button or duplicated label.

The existing `minimizeBehavior="collapse"` compatibility prop uses the same label
transition when its minimization context requests it. Explicit `collapsed` also
works independently, without a navigation or Sidebar provider.

## Material

A FAB floats over the content, so on Android 13+ with the native lens installed it is drawn by the lens, tinted with its tone, and morphs when it is the trigger of a menu. Pass `material="surface"` for the shared paint; other platforms always use it.

## Migration

Remove `placement`, `offset`, `zIndex`, and `minimizeBehavior`. Position the action
through `AppShell`/`BottomBar`; the bottom accessory hides on downward scroll
and returns upward by default. Set `actionBehavior="visible"` on `BottomBar`
or `bottomActionBehavior="visible"` on `AppShell` to keep it visible. Replace `variant="primary"` with `tone="action"` for the main task (or `accent` when retaining brand emphasis), `variant="surface"`
with `tone="neutral" appearance="subtle"`. The shared `support` and `action` roles resolve the secondary and tertiary color pairs. Choose them by intent: contextual support or the main task. Replace `small/medium/large` with `xs/md/lg` (40/50/64px respectively), and numeric size
with a preset plus a deliberate style override if needed. Replace icon elements
with icon components and remove the `children` alias.
