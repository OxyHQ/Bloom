# Select

A single-choice picker. A bottom sheet on native, an anchored dropdown on web. Controlled or uncontrolled.

`Select` owns the value, `SelectTrigger` opens it, `SelectContent` renders the choices from an `items` array, and `SelectItem` is one row.

## Basic

```tsx
import {
  Select,
  SelectContent,
  SelectIcon,
  SelectItem,
  SelectItemIndicator,
  SelectItemText,
  SelectTrigger,
  SelectValue,
} from '@oxy.so/bloom/select';

const [country, setCountry] = useState('us');

<Select value={country} onValueChange={setCountry}>
  <SelectTrigger label="Country">
    <SelectValue placeholder="Pick a country" />
    <SelectIcon />
  </SelectTrigger>

  <SelectContent
    label="Country"
    items={countries}
    renderItem={(item) => (
      <SelectItem value={item.code} label={item.name}>
        <SelectItemIndicator />
        <SelectItemText>{item.name}</SelectItemText>
      </SelectItem>
    )}
  />
</Select>
```

`SelectContent` takes the whole `items` array rather than children, so the native fork can hand it to a `FlatList` and the web fork can measure and scroll it. `renderItem` receives `(item, index, selectedValue)`.

`SelectValue` shows the selected ITEM's label on both platforms (`item => item.label` by default; pass a `children` function for other item shapes — it receives the item, not the value). `SelectContent` resolves that item even while its panel is closed, so the trigger reads `Apple`, not `apple`, from the first paint; the web fork used to print the raw value. A value that matches no item clears it, so resetting to `undefined` brings the placeholder back.

Type is the shared ramp, inline in Inter: `text-body-medium` on `md` triggers and options, `text-body-2-medium` on `sm`.

`SelectTrigger` renders a pressable around its children, or hands the open handler to your own control with `asChild` — the same escape hatch every anchored Bloom family offers:

```tsx
<SelectTrigger asChild label="Country">
  <MyField>
    <SelectValue placeholder="Pick a country" />
    <SelectIcon />
  </MyField>
</SelectTrigger>
```

## Look

Colours are taken from the theme through the same ramps `Button` paints from (`floating/menu-palette.ts`):

| part | `md` (default) | `sm` |
| --- | --- | --- |
| trigger | 38px tall (`px-2.5 py-2`, 6px gap), full pill | 28px (`px-[7px] py-1`, 4px gap), full pill |
| value | 14/20 medium | 13/18 medium |
| chevron | 16px round-capped stroke, `text-secondary` | 14px |
| option row | 36px (`p-2`, 10px corner) | `px-2 py-1.5` |

- **Trigger** — a card-coloured field with the `neutral-200` hairline and the xs contact shadow. Hover washes it `neutral-100` and darkens the border to `neutral-300`; keyboard focus draws a 2px accent ring 2px out; disabled is `neutral-100` with `text-tertiary` and no shadow. The value is `text-primary`, the placeholder `text-placeholder` (`neutral-400`). The chevron turns over while the list is open (web). Bloom's button-like controls are full pills rather than a 10px corner here.
- **List** (web) — a 266px-minimum panel (it grows to the trigger's width when that is wider), `p-2`, 16px corner, `shadow-dropdown`, 4px below the trigger, rows 4px apart, scrolling past 240px. It opens and closes on a 150ms fade + `scale-95` + 2px blur.
- **Rows** — hover, keyboard focus and the chosen option share one `neutral-100` wash; the chosen one also carries `SelectItemIndicator`'s `text-secondary` tick. `disabled` options are `text-disabled` and cannot be pressed.
- **Dark** — surfaces go to `neutral-800` with `neutral-700` hairlines and a `neutral-700`-at-60% wash; disabled text uses `neutral-600` (the semantic dark `text-disabled` is the panel colour, which hides the row).

```tsx
<Select size="sm" value={v} onValueChange={setV}>…</Select>
<SelectItem value="x" label="X" disabled>…</SelectItem>
```

### A trigger inside another control

`SelectTrigger`'s `style` sizes the trigger BOX; `fieldStyle` restyles the bordered field itself and is applied after the field's own style, so it is the unambiguous override (a `className` can only compete with the padding classes in Tailwind's emit order). `SelectContent`'s `width` fixes the web list's width instead of the 266px / trigger-width floor. The phone input's country code uses both — a `rounded-lg px-1.5 py-1` trigger and a 220px list:

```tsx
<SelectTrigger label="Country code" fieldStyle={{ borderRadius: 8, paddingLeft: 6, paddingRight: 6, paddingTop: 4, paddingBottom: 4 }}>
  …
</SelectTrigger>
<SelectContent width={220} items={countries} renderItem={…} />
```

### A compact trigger: size it with padding, never a height

A settings row wants a 32px trigger with the `md` value. Get it from padding, so the value's line decides the height:

```tsx
<SelectTrigger label="Color mode" fieldStyle={{ gap: 4, paddingLeft: 8, paddingRight: 8, paddingTop: 5, paddingBottom: 5 }}>
```

Do **not** pin a height (`className="h-8 …"`). The value's line box is 20 × the system font scale, and on native Yoga measures the text no taller than the room left inside the field, so a fixed height cuts the glyphs in half. On Android `h-8` is 28dp (a 14px rem), leaving 15.5dp for that 20dp line: the value is clipped at the default scale, and at a 1.15 font scale only the top half of "System" showed (OxyHQ/Mention#1126). The web hides the defect because an overflowing line is not clipped there.

Spell padding in longhands: react-native-web ranks the `padding-inline` a `paddingHorizontal` becomes above the field's own classes AND above `padding-left`, so a longhand is what lands on both platforms.

The colours are INLINE (or, for the web trigger's hover and ring, custom properties an adopted sheet reads): the ramp stops exist as no CSS variable a class could name. A caller's `style` still overrides them; a `className` on `SelectValue`/`SelectItemText` drops the inline colour so a `text-*` utility can apply.

It used to take a render prop instead, which handed its child a `state` object whose `pressed` was a hardcoded `false` and whose `hovered` the native fork never computed. Press and hover styling on a select trigger was therefore dead while the API read as though it worked. Bring your own control through `asChild` and its own states are real.

## Leading marks

`leading` on `SelectValue` and on `SelectItem` puts a node — a status dot, an icon — before the label, so an option's content can lead with a status dot or a glyph:

```tsx
<Select value={status} onValueChange={setStatus}>
  <SelectTrigger label="Purchase status">
    <SelectValue leading={(item) => item && <Badge dot tone={(item as Status).tone} />} />
    <SelectIcon />
  </SelectTrigger>
  <SelectContent
    items={STATUSES}
    renderItem={(item) => (
      <SelectItem value={item.value} label={item.label} leading={<Badge dot tone={item.tone} />}>
        <SelectItemText>{item.label}</SelectItemText>
      </SelectItem>
    )}
  />
</Select>
```

- In the trigger the mark sits `gap-[5px]` from the value (`gap-1` on `sm`) — the trigger's own gap, not the row's 8.
- A function `leading` receives the selected ITEM (`undefined` until `SelectContent` has resolved one), so the mark follows the value without the caller looking the option up again.
- In a row the mark is the row's first in-flow child, 8px (`gap-2`) from the label; the indicator stays in its absolute right-hand gutter.
- An icon mark can also trim the trigger's left inset to 8: pass `className="pl-2"` to `SelectTrigger`.

[`DataTableSelect`](./data-table.mdx#cell-and-toolbar-parts) packages this for table rows.

## Groups and labels

```tsx
<SelectGroup>
  <SelectLabel>Europe</SelectLabel>
  <SelectItem value="es" label="Spain">…</SelectItem>
  <SelectItem value="fr" label="France">…</SelectItem>
</SelectGroup>
```

`SelectGroup` renders `role="group"` so a screen reader announces the run as one; `SelectLabel` is its heading. Return them from `renderItem` on the first row of each run — `SelectContent`'s list stays flat.

## Long lists

The web dropdown grows to `maxHeight` (default 240, `max-h-[240px]`) and then scrolls with the native scrollbar. Opening it scrolls the selected option into view. There are no scroll buttons by default: they appeared and disappeared as the list moved and made the panel jump in height. `SelectScrollUpButton` and `SelectScrollDownButton` stay exported for a caller composing their own content inside a `SelectScrollProvider`; on native they render nothing, since the sheet's list scrolls under the finger.

## In a `Field`

The trigger IS the select's control, so it takes the field's id, name, described-by
and invalid state, and the field's `disabled` on top of the root's and its own:

```tsx
<Field label="Visibility" error={errors.visibility} disabled={locked}>
  <Select value={visibility} onValueChange={setVisibility}>
    <SelectTrigger>
      <SelectValue placeholder="Choose" />
    </SelectTrigger>
    <SelectContent>…</SelectContent>
  </Select>
</Field>
```

`SelectTrigger`'s `label` is optional for that reason — the chosen value is not a
name ("Medium" says nothing about what is medium), so either the prop or a field
has to supply one. A `Popover` or a `DropdownMenu` inside a field deliberately
does NOT take the field's id: it is not the field's control. See
[Composition](/docs/composition).

## Keyboard (web)

The web select follows the ARIA select-only combobox pattern. Focus goes where a keyboard user expects it, so the list can be operated without a pointer:

| where | key | does |
| --- | --- | --- |
| trigger | <kbd>Enter</kbd> · <kbd>Space</kbd> · <kbd>↓</kbd> · <kbd>↑</kbd> | opens the list with focus on the **chosen** option, or the first enabled one when nothing is chosen |
| trigger, list already open (pointer) | <kbd>↓</kbd> · <kbd>↑</kbd> | moves focus into the list |
| list | <kbd>↓</kbd> · <kbd>↑</kbd> | next / previous enabled option, stopping at the ends (no wrap) |
| list | <kbd>Home</kbd> · <kbd>End</kbd> | first / last enabled option |
| list | <kbd>Enter</kbd> · <kbd>Space</kbd> | chooses the focused option and closes |
| list | <kbd>Esc</kbd> · <kbd>Tab</kbd> | closes without choosing |

Every close — a choice, <kbd>Esc</kbd>, <kbd>Tab</kbd> — returns focus to the trigger, so the next <kbd>Tab</kbd> continues from the select rather than from the top of the page. A pointer open leaves focus where the pointer put it.

<kbd>Esc</kbd> closes the **innermost** open surface only. A select inside a `Dialog` closes its list and leaves the dialog open; a second <kbd>Esc</kbd> closes the dialog. (It used to close both: the list's listener and the dialog's sat side by side on `document`, and the dialog's ran first.) Every anchored surface shares this through `floating/escape-stack.ts`.

Why Bloom supplies this rather than react-native-web: an option is a `role="radio"` `Pressable`, and react-native-web presses one on <kbd>Enter</kbd> only — it synthesises <kbd>Space</kbd> for `role="button"` alone — and it never moves focus into a portaled list. Verified in jest (`SelectKeyboard.web.test.tsx`) and in a real browser (`scripts/verify-web-keyboard.mjs`). Native is unchanged: the list is a bottom sheet there.

## Selection state

Both forks render each option as `role="radio"` with `aria-checked` — the only spelling react-native-web reads, and one React Native folds back into `accessibilityState`. `SelectItemIndicator` draws the mark — a `text-secondary` check in the row's right-hand gutter on both platforms — and the chosen row also takes the highlight wash.

`SelectSeparator` draws a rule between runs.

## Why a row is not `Item`

Every menu row in Bloom is an `Item`. A select row is not, and the reason is its layout.

The web option reserves a 30px indicator gutter and paints the indicator into it ABSOLUTELY, so the label's left edge does not move between a selected row and an unselected one; `Item` has an in-flow leading slot and no absolute one. On top of that, `Item` couples `selected` to its OWN selected background, while the select paints its own row wash — the same one hover and focus use — from the menu palette.

Composing would mean flattening one of those two, and both are visible: the first as a label that jumps sideways on selection, the second as a selected row painted in a colour no other menu row uses. So select keeps its own row, and `radio-indicator` stays the one indicator both it and `Radio` draw.
