# Checkbox

A checkbox. Controlled, with an optional label and description, three sizes and a mixed state.

## Basic

```tsx
import { Checkbox } from '@oxy.so/bloom/checkbox';

const [checked, setChecked] = useState(false);

<Checkbox checked={checked} onCheckedChange={setChecked} label="Remember me" />
```

`label` also becomes the accessible name, so a labelled checkbox needs nothing else. A checkbox with no label needs `accessibilityLabel`.

```tsx
<Checkbox
  checked={notify}
  onCheckedChange={setNotify}
  label="Email notifications"
  description="Get a message when someone replies to you."
/>
```

## The mixed state

```tsx
<Checkbox
  checked={allChecked}
  indeterminate={!allChecked && someChecked}
  onCheckedChange={(next) => setAll(next)}
  label="Select all"
/>
```

`indeterminate` announces as `aria-checked="mixed"` and draws a rounded bar rather than a second glyph — the icon set has no minus, and a rule is what the state means.

## Sizes and colour

`size` is `sm`, `md` (default) or `lg`. `tone` selects the shared semantic fill and its paired mark foreground; it defaults to `accent`.

## What it looks like

Geometry and colours, the latter run through the shared recipe (the `button/shared.ts` ramps).

|         | `sm` | `md` | `lg` |
| ------- | ------- | -------- | ------- |
| box     | 14      | 16       | 20      |
| label   | `body-2-medium` 13/18 | `body-medium` 14/20 | `headline-medium` 16/22 |
| gap     | 6       | 8        | 8       |

`lg` extends the ramp beyond the standard two sizes. The box has a 4px radius. Label and description are set in Inter from the type ramp (`TYPE_SCALE`), not the platform face.

- **Unchecked** — the themed card surface, a 1px semantic border and the `xs` shadow.
- **Checked / mixed** — an accent-500 → accent-600 gradient with an inset white top highlight and an inset 1px accent edge; hover lightens it to 400 → 500. The tick draws itself in over 200ms (skipped under reduced motion); the mixed state is a rounded bar.
- **Disabled** — the BOX drops to 50% opacity. The label stays at full strength.
- No press scale. On native, where there is no hover, a held press shows the hover paint.

## CheckboxCard

A selectable card: the title and an optional description on the left, the box on the right, and a press anywhere on the card toggles it.

```tsx
import { CheckboxCard } from '@oxy.so/bloom/checkbox';

<CheckboxCard
  title="Weekly digest"
  description="A summary of activity every Monday."
  checked={digest}
  onCheckedChange={setDigest}
/>
```

- **Card** radius 10, 1px `border-button-default` edge, padding 12 top/bottom, 16 left, 20 right, a 12px gap; the surface fill, and `background-primary-hover` under a pointer (native: while held).
- **Title** `body-medium`, **description** `body-regular` in `text-secondary`, 2px apart, each truncated to one line.
- **Box** the medium checkbox, taking the card's hover paint; keyboard focus rings the box, not the card.
- **Disabled** the whole card at 50% — the box takes the card's disabled state and applies its own 50% opacity inside it.

`title` is the accessible name and `description` the hint.

## In a `Field`

A checkbox inside a `Field` takes the field's id, its described-by, `aria-invalid`
and `disabled` — and **keeps its own label as its name**, because the words beside
the box are the ones the user reads as the control. The field's label names the
FIELD:

```tsx
<Field label="Terms" error={errors.terms}>
  <Checkbox label="I accept the terms" checked={ok} onCheckedChange={setOk} />
</Field>
```

A checkbox with no label of its own falls back to the field's. Several checkboxes
in one field is the `multiple` case — see [Field](/docs/field).

## Touch target

The box is 16dp at the default size, well under what a finger needs. The pressable is grown to 44dp with `hitSlop` — the target grows, the drawing does not — and the slack is derived per size, so `lg` does not overshoot into a neighbouring row.

For a labelled checkbox the pressable already spans the label, so the whole row is the target.

## Keyboard focus on web

The pressable takes a `:focus-visible` ring, drawn from the same shared recipe every Bloom control's web CSS is built from. The browser focuses the row — the box AND its label — but the ring is drawn around the BOX whenever that row has keyboard focus — `ring-2 ring-offset-2`: a 2px accent ring outside a 2px offset matching the scoped page background; the row's own outline is suppressed so there is exactly one ring, and it is only ever shown for the focused row.

`:focus-visible`, not `:focus`: a mouse click never leaves a ring behind.

## The focus ring's gap

The 2px gap between the box and the ring takes `var(--bloom-ring-offset)`, set
inline from the surface behind the control. It was the literal `#FFFFFF` —
Tailwind's `ring-offset-color` default, never overridden — so in dark mode a
focused checkbox drew a white halo on a near-black page. `FOCUS_RING_OFFSET_COLOR`
survives only as a deprecated alias of the fallback. See
[Styles → The focus ring gap](/docs/bloom/main/styles).
