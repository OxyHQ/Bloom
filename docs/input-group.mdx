# InputGroup

An input with prefixes, suffixes or buttons attached, drawn as **one** bordered
box so the whole thing reads as a single control.

The box paints exactly what [`TextField`](/docs/bloom/main/text-field) paints —
a filled input shell: a 10px radius, the neutral fill, a 2px inset ring
on hover and focus, the red tint when invalid and the dimmed fill when disabled
— so a group sits flush beside a plain field.

```tsx
import { InputGroup, InputGroupAddon } from '@oxy.so/bloom/input-group';

<InputGroup>
  <InputGroupAddon>oxy.so/</InputGroupAddon>
  <TextFieldInput label="Handle" value={handle} onValueChange={setHandle} />
</InputGroup>

<InputGroup>
  <TextFieldInput label="Search" value={query} onValueChange={setQuery} />
  <InputGroupAddon divider>
    <Button size="sm" onPress={run}>Search</Button>
  </InputGroupAddon>
</InputGroup>
```

## Which prop decides what

| prop        | decides                                                       |
| ----------- | -------------------------------------------------------------- |
| `size`      | `sm` 32 · `md` 36 (default) · `lg` 44 — plus a larger rung |
| `invalid` | the error tint on the whole box (and no hover / focus ring)     |
| `disabled`  | paints the disabled fill and marks the group `aria-disabled`    |
| `divider`   | per addon, a rule between it and the input                     |
| `noPadding` | per addon, for an addon that supplies its own (a button)        |

## One shell, not a field inside a field

A `TextFieldInput` (or a `Search`, or any `TextField`) placed in a group renders
**bare**: it draws no fill or ring of its own, takes no side padding, stretches
to fill the middle and inherits the group's `size`, `invalid` and `disabled`.
Before this, the field painted its own shell inside the group's and sized
itself to the group's full width, pushing a trailing addon out of the clipped
box.

Spacing: the shell's side padding (8 at `md`, 6 at `sm`), a leading
addon 2px before the control, a trailing addon 8px after it, and a `noPadding`
addon reaching 4px from the shell's edge. A plain-string addon is `body-regular`
in `text-secondary`.

## Why the state lives on the group

`invalid` and `disabled` are properties of the **control**, not of the input
element inside it. Setting them per part is how a box ends up with a red border
and a normal-coloured button, or an enabled button beside a disabled input.

## A prefix is not a placeholder and not a label

`oxy.so/` as an addon is part of the value's shape: it is always visible, it
does not disappear on typing, and it is not editable. That is different from a
placeholder (an example, which vanishes) and from a label (the name of the
field, which belongs to [`Field`](/docs/bloom/main/field) or
[`Label`](/docs/bloom/main/label)).

`InputGroup` goes *inside* a `Field` — the group is the control, the field is
its label, hint and error.

## `divider`

Use it when the addon is a distinct target — a button, a dropdown. Skip it for
a static prefix or an icon, where a rule makes one control look like two.
