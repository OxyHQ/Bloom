# Locale

A Bloom component that draws fixed text — a Cancel button, a chevron's name, "14 days selected" — speaks it in a **locale**, and so do the dates it formats. The locale is, in order:

1. the component's own `locale` prop,
2. the nearest `LocaleProvider` — `BloomProvider`'s `locale` prop mounts one,
3. the runtime's (the browser's, or the device's).

```tsx
import { BloomProvider } from '@oxy.so/bloom/provider';

<BloomProvider locale={i18n.language}>
  <App />
</BloomProvider>
```

Set it once, from the app's own language, and every Bloom component below follows it — including after a language switch, since the provider re-renders with the new value. `LocaleProvider` (from `@oxy.so/bloom/locale`) scopes a different locale to a subtree.

## Only the app's language is downloaded

Bloom's English strings are inline in each family; every other language is one module per language (`src/locale/translations/<language>.ts`) loaded when a `LocaleProvider` first asks for it. An English app downloads no translation at all; a Spanish one downloads Spanish, once, for every family.

- **First paint.** An explicit `BloomProvider.onFontsLoading` holds a translated first paint until its strings arrive. Without a loading screen, children remain visible in the parent's locale (English at the root), then switch in place. A standalone `LocaleProvider` offers the same choice through `fallback`; Bloom never inserts an implicit blank screen.
- **Automatic versus explicit.** `useBloomLocale()` keeps returning `undefined` when no provider chose a locale explicitly. Integrations can therefore use their account language as a fallback without mistaking the browser language for an app override. Bloom’s internal rendering locale resolves that automatic choice separately, including its server snapshot.
- **Server rendering.** Without an explicit locale, the server and first hydration render use English. After hydration, the browser's locale loads and replaces the published locale without remounting content or returning to a loading screen. Explicit locale props must agree between server and first hydration render; use `loadBloomLocale` before both renders when serving already translated markup.
- **Switching.** A new locale is published to the subtree only once its strings are loaded; until then the subtree keeps the locale it had. Words, dates and numbers change together in one render, with no English frame between.
- **Ahead of time.** `loadBloomLocale(locale)` (from `@oxy.so/bloom/locale`) loads a language before rendering, for a first render that must already be translated without the hold — before hydrating server-rendered markup, for instance.
- **Failure.** A language whose module fails to load renders in English rather than holding the screen; the next request retries.
- **A component's own `locale` prop** renders from the languages already loaded: a language no provider above it has loaded shows English until one does.

## Languages

Bloom ships its strings in `BLOOM_LANGUAGES`: English, Spanish, Catalan, German, French, Italian, Portuguese, Russian, Turkish, Japanese, Chinese, Arabic, Hindi, Bengali and Indonesian. A locale is matched on its primary subtag (`es-MX` → Spanish, `pt_BR` → Portuguese); a language Bloom does not ship falls back to English. `resolveBloomLanguage(locale)` answers which one a tag gets.

## Dates stay Gregorian

Bloom's calendars lay out and return Gregorian `Date`s, so every date they format goes through `formatGregorian` (`src/locale/format-date.ts`): the locale's language, digits and order, on the Gregorian calendar. Without it, a locale whose default calendar is another one — `fa-IR` (Persian), `th-TH` (Buddhist) — would title a Gregorian September with another calendar's month and year, and the day a reader picks would not be the day the app receives.

## Numbers, money and durations

The formatters Bloom's families use are published from `@oxy.so/bloom/locale`
(and the root), so an app's own figures group, sign and place currency exactly
as the components beside them do. Each takes the locale `useBloomLocale()`
resolved, goes through `Intl.NumberFormat` (which Hermes implements) and falls
back to plain English formatting rather than throwing.

| formatter | example (`en`) |
|---|---|
| `formatNumber(value, locale?, options?)` | `12500` → `12,500` (`12.500` in `de`) |
| `formatInteger(value, locale?)` | `1234567.8` → `1,234,568` |
| `formatCompactNumber(value, locale?)` | `12500` → `12.5K` (`12,5 mil` in `es`) |
| `formatPercent(ratio, locale?, digits?)` | `0.25` → `25%` (`%25` in `tr`) |
| `formatSignedPercent(ratio, locale?, digits?)` | `0.052` → `+5.2%` |
| `formatCurrency(amount, currency, locale?, digits?)` | `385000, 'EUR'` → `€385,000` (`385.000 €` in `es`); `digits` `'currency'` → `$9.99`, `¥980` |
| `formatCompactCurrency(amount, currency, locale?)` | `385000, 'EUR'` → `€385K` |
| `formatMultiplier(value, locale?)` | `1.5` → `1.5×` |
| `formatRelativeTime(at, locale?, { now?, style? })` | 3 minutes ago → `3 minutes ago` (`hace 3 minutos` in `es`); within 45 s → `now`; `style: 'short'` → `3 min. ago`; a future time → `in 3 minutes` |
| `formatClock(seconds)` | `83` → `1:23`, the same in every locale |

```tsx
const locale = useBloomLocale();
<Text>{formatCurrency(price, 'EUR', locale)}</Text>
```

Each formatter is built once per locale and set of options and then reused
(`src/locale/formatter-cache.ts`), the dates' `formatGregorian` too, so a
long list of prices or dates constructs one `Intl` formatter, not one per row.

`formatRelativeTime` uses `Intl.RelativeTimeFormat`, which Hermes lacks; there it
falls back to English words (`3 minutes ago`) rather than throwing.

A file size is `formatFileSize` from `@oxy.so/bloom/file-upload`.

## Overriding a string

Each family keeps its `labels` prop. A key passed there wins over Bloom's string for the locale, one key at a time — for wording of your own, not for translation.

## Which families speak it

**All of them.** Every family draws and announces its fixed strings from a catalog in the locale — its own `src/<family>/messages.ts`, or `COMMON_MESSAGES` for the words most families share — and formats its dates on the Gregorian calendar in the locale. A caller's `labels` / `*Label` / `title` / `accessibilityLabel` prop still wins, key by key.

What stays as given is the app's own content: series names, month abbreviations a caller passes in chart data, the country names in `phone-input`'s data table, and any string the app hands a component.

## Adding a family (for Bloom authors)

- The family's English strings live in `src/<family>/messages.ts`: `export const X_MESSAGES: MessageCatalog<M> = defineMessages<M>('X_MESSAGES', { … })`, the id being the export's own name. Each other language lives in `src/locale/translations/<language>.ts` under that id, and `Translations` (`src/locale/translations/types.ts`) lists every catalog — add yours there. Each language module is typed `Translations`, so a new string, family or language fails the type-check until it is translated: a missing translation is never an English word in a translated screen.
- **A language module imports no family module.** Loading Spanish would otherwise link that family's English (and, since fourteen language chunks share it, a bundler would hoist it into the page's eager chunk). A helper several languages' strings call lives in `src/<family>/message-helpers.ts`; a type comes in with `import type`. `locale-catalogs.test.tsx` enforces this and that `src/locale/translations.ts` is each module's only importer.
- Read it with `useMessages(CATALOG, localeProp)`, which also returns the resolved locale to hand to `Intl`. Let `labels?.x ?? messages.x` decide each string.
- Count-dependent strings are functions using `plural(language, n, forms)` (`src/locale/plural.ts`). It carries the CLDR rules itself because **Hermes has no `Intl.PluralRules`**: a catalog calling it would pluralise on web and throw on a phone.
- A word most families say belongs in `COMMON_MESSAGES` (`src/locale/common-messages.ts`, read with `useCommonMessages()`), not in a family catalog: one translation, reviewed once.
- Two gates keep it honest, and neither needs registering: `message-catalogs.test.ts` finds every `messages.ts`, checks it carries English only, and checks each language has English's shape and is not English pasted in (every language is registered for all suites by `__mocks__/setup.ts`; read one with `messagesIn(CATALOG, language)`); `i18n-literal-census.test.ts` scans the source for English still drawn or announced directly. A migrated family leaves the census's `PENDING` list; a literal that is not copy (a brand name, a format pattern) says so with `// i18n-exempt: <reason>`.
- Never join translated words with an English connector: `labelFor(label, subject)` in `COMMON_MESSAGES` does "More actions for Ana" per language.
