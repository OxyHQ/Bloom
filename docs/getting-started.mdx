# Getting started

## Install for your host

```sh
bun add @oxy.so/bloom
```

Select peer versions compatible with your host's React Native and Expo SDK; the
package's `peerDependencies` and `peerDependenciesMeta` distinguish required and
optional packages. A permissive peer range is not proof that every combination
has been tested. Do not install arbitrary latest native peers into an older SDK.

- **Expo / Metro:** use the SDK-compatible dependencies and the app-preset setup below.
- **Vite web:** use the complete [Vite host recipe](./vite.mdx), including dependency
  transforms. Typechecking alone cannot validate worklets or CSS.

## Mount the root provider

```tsx
import { BloomProvider } from '@oxy.so/bloom/provider';
import { Button } from '@oxy.so/bloom/button';

export default function Root() {
  return (
    <BloomProvider mode="system" colorPreset="teal" locale="en">
      <Button onPress={() => console.info('Pressed')}>Continue</Button>
    </BloomProvider>
  );
}
```

`BloomProvider` owns theme, locale, preferences and screen/scroll contexts. Mount
it once above routes; pass the router adapter explicitly when using restoration.
`BloomThemeProvider` is a lower-level theme primitive, not the application root.
The [provider contract](./provider.mdx) describes ownership and initialization
order, including early loading screens.

Visual and platform hosts are separate from that context provider:

- Native apps supply `GestureHandlerRootView`, safe-area and keyboard hosts as
  required by their SDK. Follow [Provider](./provider.mdx) and [Portal](./portal.mdx)
  for native `PortalProvider`/outlet placement and inert app content.
- For imperative `alert`, `confirm`, `prompt` or `surfaces.present`, mount
  `SurfaceProvider` **inside** `BloomProvider`; it provides the default surface
  host. A standalone declarative `Dialog` does not require it.
- For toasts, mount one `ToastOutlet` inside `BloomProvider`. Follow
  [Toast](./toast.mdx) and [Surfaces](./surfaces.mdx) for the complete examples.
- `OxyProvider` from Services already supplies its documented hosts/outlets.
  Do not duplicate them around each route.

## Expo / Metro CSS

Import this stylesheet first in `app/_layout.tsx`, before component imports:

```tsx
import '../global.css';
```

```css
/* global.css */
@import '@oxy.so/app-preset/css/base.css';
@source './app/**/*.{ts,tsx}';
@source './components/**/*.{ts,tsx}';
@source './node_modules/@oxy.so/bloom/lib/module/**/*.js';
/* If the application installs Services: */
@source './node_modules/@oxy.so/services/lib/module/**/*.js';
```

Paths are relative to the stylesheet; adjust for a monorepo's actual installed
package locations. Add the app-root PostCSS configuration (and install `@tailwindcss/postcss`):

```js
// postcss.config.mjs
export default { plugins: { '@tailwindcss/postcss': {} } };
```

Use app-preset's matching Metro configuration. `create-oxy-app` supplies the host wiring. React Native Web resets can
otherwise leave colors working while flex direction, gaps and sizes are wrong.
For a standalone Vite host, use its [own CSS recipe](./vite.mdx), not the Expo
preset's bundler configuration.

Web components adopt their required animation/layout styles automatically. **Do
not inject `BLOOM_DIALOG_CSS` or duplicate inline component style tags.** For SSR,
opt in to `BloomProvider ssrStyles` and follow the host nonce/CSP contract in
[Provider](./provider.mdx); this is distinct from client-side adoption.

## Fonts and the viewport

`BloomProvider` loads the packaged fonts by default; no separate font package or
manual `FontLoader` is needed. Preserve `.woff2` asset URLs in web builds. SSR
hosts can preload them with `BloomFontHead` in the document head; see
[Fonts](./fonts.mdx) for the measured asset and platform-resolution hazards.

Choose a bounded application viewport or a document-scrolling host deliberately.
A bounded web root needs an actual height and `min-height: 0` through its flex
chain. `AppShell`/`Screen` then own the scroll region; adding another route
`ScrollView` changes that ownership. See [Compose layouts](./compose-layouts.mdx)
and the runnable [Vite example](./vite.mdx).

Use the [task catalog](./task-catalog.mdx) to select layouts and controls. For
optional peers loaded off Metro, retain the explicit adapters described in
[Optional peers in web bundlers](./web-optional-peers.mdx).
