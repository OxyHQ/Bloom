# Getting started

## 1. Install

```sh
bun add @oxyhq/bloom
```

Install the peer dependencies. The same set covers native and web — Bloom's
overlays and its toast engine run on react-native-web:

```sh
bun add react-native-gesture-handler react-native-reanimated react-native-safe-area-context react-native-svg
```

## 2. Wrap your app root

```tsx
import { GestureHandlerRootView } from 'react-native-gesture-handler';
import { BloomThemeProvider, SurfaceProvider } from '@oxyhq/bloom';

export default function Root() {
  return (
    <GestureHandlerRootView style={{ flex: 1 }}>
      <BloomThemeProvider mode="system" colorPreset="teal">
        <SurfaceProvider>
          <App />
        </SurfaceProvider>
      </BloomThemeProvider>
    </GestureHandlerRootView>
  );
}
```

- `BloomThemeProvider` is required — every Bloom component reads from it.
- `SurfaceProvider` (or a bare `<SurfaceHost />`) is required only if you use the imperative surfaces — `alert()`, `confirm()`, `prompt()`, `surfaces.present()`. Without it, `<Dialog>` still works on its own.
- `GestureHandlerRootView` is required on native for any sheet-based component.

<Callout variant="warning" title="Web setup">
Inject the CSS animations into your global styles once:

```tsx
import { BLOOM_DIALOG_CSS } from '@oxyhq/bloom/dialog';

// In your HTML head or global CSS file:
<style>{BLOOM_DIALOG_CSS}</style>
```
</Callout>

## 3. Use a component

```tsx
import { Button } from '@oxyhq/bloom/button';
import { toast } from '@oxyhq/bloom';

export function Hello() {
  return <Button onPress={() => toast.success('Hello, Bloom!')}>Greet</Button>;
}
```

## If you build with Vite (or any ESM web bundler)

Bloom reaches its **optional** peers through a `require()` that Metro marks
optional. An ESM web bundle has no `require` at all — measured: `typeof require`
is `undefined` in a Vite bundle — so those loads cannot run and every optional
peer degrades **even when the package is installed**. Metro is unaffected, which
is why this only appears off Metro.

**Check in one line**, in your app's console:

```js
typeof require   // "undefined" -> the optional peers below are inert for you
```

Today one of them can be handed over explicitly:

```ts
import * as ExpoVideo from 'expo-video';
import { provideExpoVideo } from '@oxyhq/bloom/media-flight';

provideExpoVideo(ExpoVideo);   // otherwise video silently shows only its poster
```

The others have no equivalent yet, so on an ESM bundle you currently lose
scoped NativeWind presets (`BloomColorScope`), adaptive colours, haptics and the
connection toasts. Most of them say so in the dev console — the warning ends
`Reason: this bundle has no CommonJS require` — with the exception noted in
`theme/adaptive-colors.ts`, which degrades silently.

## Recommended layout

If your app supports both light and dark themes:

```tsx
<BloomThemeProvider mode="system" colorPreset="teal">
```

`mode="system"` follows the OS preference. `colorPreset` picks one of the 10 named palettes — see [Theme](/docs/bloom/main/theme) for the full list.
