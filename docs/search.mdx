# Search

A search input: magnifier, rounded field, and a clear button that appears once
there is a query.

```tsx
import { Search } from '@oxy.so/bloom/search';

<Search
  value={query}
  onValueChange={setQuery}
  onClearText={() => setQuery('')}
  label="Search people"
/>
```

## Which prop decides what

| prop           | decides                                                    |
| -------------- | ----------------------------------------------------------- |
| `value`        | the query — the field is controlled                          |
| `onChangeText` | typing                                                       |
| `onClearText`  | the clear button's press                                     |
| `label`        | the accessible name **and** the placeholder; defaults to `Search`, localised via `BloomProvider locale` |

`containerClassName` / `containerStyle` style the outer layout box, including
its clear control. `fieldClassName` owns the field's height and padding;
`fieldChromeClassName` owns its inset background, border/ring and corner radius.
These slots work on web and native and retain the existing defaults when omitted.
The field keeps disabled/invalid paint and its focus ring authoritative.
`className` and `style` retain their existing input-only meaning; these surface
slots do not change input typography or selection behavior. Use the input's
`style` for text metrics; the RNW input's own reset still limits layered text
classes, independently of the new surface slots.

```tsx
<Search value={query} onValueChange={setQuery} onClearText={() => setQuery('')}
  containerClassName="w-full"
  fieldClassName="h-11 px-3"
  fieldChromeClassName="rounded-2xl border bg-background" />
```

Other props pass through to the underlying text input.

## `onClearText` reports; it does not clear

The field is controlled, so clearing itself would fight the caller's state and
leave the list filtered by a query the field no longer shows. Handle it:

```tsx
onClearText={() => { setQuery(''); refetch(); }}
```

## The clear button is conditional on purpose

It appears only when `value` is non-empty. A clear button on an empty field is
a dead target that looks live, and a missing one on a full field strands the
user with no way back to the unfiltered list except selecting and deleting.

## Searching as you type, or on submit

`Search` sets `returnKeyType="search"` but does not decide when the search
runs. Both are legitimate:

- **As you type** — cheap, local filtering. Debounce anything that leaves the
  device.
- **On submit** — expensive or paginated search. Say so, by leaving the results
  alone until the key is pressed rather than showing stale ones.

What is not legitimate is issuing a request per keystroke to a server. That is
the same failure as a [`Slider`](/docs/bloom/main/slider) that saves in
`onValueChange`.

## Search or Select

- **Search** — filters something already on the page.
- **[Select](/docs/bloom/main/select)** — picks a value into a form, and the
  picked value stays.

## Icon and clear geometry

`iconSize` changes the leading icon's edge (default20).
`clearButtonProps` accepts `icon`, `size` (the target edge, default28) and
`glyphSize` (default16). Search retains the clear name, callback and disabled
state; a disabled Field or TextFieldGroup disables both the input and clear.
The clear control participates in the field row, separated from the input by
8px. Input typography or padding in `style` cannot overwrite that separation.
Use `fieldClassName` for height and horizontal padding: it positions both icons
against the logical edges. Use `fieldChromeClassName` for background/border/ring.

```tsx
<Search value={query} onValueChange={setQuery} onClearText={() => setQuery('')}
  iconSize={24} clearButtonProps={{ icon: ClearCircleIcon, size: 24, glyphSize: 24 }}
  fieldClassName="h-11 px-4" style={{ fontSize: 16, lineHeight: 20 }} />
```

`TextFieldIcon` also accepts `size` when composing a field directly.
