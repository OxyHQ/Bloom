# ComposerLoader

The loading state that wraps a chat composer while an agent works: an iridescent band of light laps the pill's rim with a soft bloom bleeding inward. `phase` gives the request lifecycle a single controlled API; Bloom fades and animates the presentation while the app owns the request.

```tsx
import { ComposerLoader, type ComposerLoaderPhase } from '@oxy.so/bloom/composer-loader';
import { ComposerPill } from '@oxy.so/bloom/composer-panel';

export function WorkingComposer({ busy, phase }: { busy: boolean; phase: ComposerLoaderPhase }) {
  return (
    <ComposerLoader phase={phase}>
      <ComposerPill busy={busy} defaultValue="" />
    </ComposerLoader>
  );
}
```

## Request lifecycle

The app owns whether a request was sent, is producing output, is being cancelled,
failed, or completed. It passes that state as `phase`; Bloom owns the light's
fade and motion. The loader never submits, cancels, retries, clears an error, or
infers completion from a timeout.

| `phase` | Loader presentation | Composer responsibility |
|---|---|---|
| `idle` | Hidden; an in-progress fade finishes. | Draft is editable and send follows the app's permissions. |
| `submitting` | Fades in over 450 ms and starts the lap. | The app has accepted the send; do not clear or replace the draft unless its submit contract says to. |
| `streaming` | Stays lit on the same lap; a submit-to-stream transition does not restart it. | Keep the stop action available while output is in flight. |
| `stopping` | Stays lit until the app confirms cancellation. | Keep the in-flight state until the cancellation callback resolves. |
| `error` | Fades out over 450 ms. | Pass the actual error to `ComposerPill.error`; Bloom presents its error ring/message. |
| `complete` | Fades out over 450 ms. | Keep the completed response and draft under app control. |

`active` remains as a compatibility prop for existing consumers. Prefer `phase`
for new code and migrate callers while on 17.x; `active` is scheduled for removal
in 18.0.0. This transition keeps current apps working while giving new
compositions one explicit lifecycle API.

**The loader owns the pill surface** (the shared Surface material with `shadow-xs`) and layers the light beneath its children. `ComposerPill` automatically inherits that paint ownership and the nearest loader’s active state for frosted controls. Explicit `surface` and `frosted` values override inheritance. Outside a loader, the pill keeps its own surface and unfrosted controls. Custom children still own their paint contract; an opaque child can cover the decorative light.

The loader takes its width from its container and its height from its children; the default radius is a full pill, or whatever the composer inside reports: a `ComposerPill` squares its corners to 26 when it grows into a stack, and the loader's container and rim follow it. It waits for a positive measured size before mounting the decorative SVG. The composer and its surface are present from the first render; the loader never paints a provisional 640 × 52 outline. Resizing updates the shared perimeter without replacing the composer.

## How the light is drawn

Three dash strokes on the rounded-rect outline, normalised to a path length of 100, each lapping once per `speed` seconds:

| layer | stroke width | blur (σ) | opacity | dash length | head pulled back |
|---|---|---|---|---|---|
| bloom | `bloom × 2` | 14 | `bloomStrength` | band × 0.9 | `bloom + 16` px |
| glow | `line × 3.2` | 6 | 0.8 | band × 0.95 | 10 px |
| line | `line` | 0.5 (taper: `max(0.5, line × 0.8)`) | 1 | band | — |

`band = arc / 360 × 100`. The crisp line leads and every soft layer trails it. The gradient runs left → right across the pill through the four `colors`, with the centre stop a blend of the middle two so the band never washes out to white. `taper` stacks each layer as 14 shorter, centred copies at a fraction of its opacity; the blur melts the steps into a fade.

- **Web** draws a DOM `<svg>`, `pathLength={100}` rects, a self-injected `@keyframes` on `stroke-dashoffset` (0 → -100) with each layer's phase as an `animation-delay`. Blur is an SVG `feGaussianBlur`, not a CSS `filter` — WebKit ignores CSS filters on individual SVG elements, which rendered the light razor-sharp on every iPhone browser.
- **Native** keeps the same shared geometry and `useFrameCallback` phase clock. iOS draws with react-native-svg; its device optics remain unverified. Android 12 / API 31 and newer use Bloom's `BloomComposerLightV1` when the host has registered the native manager and the palette/geometry are supported. The manager measures the rounded path in physical pixels and draws three semantic layers into `RenderNode`s; soft layers rasterize at quarter resolution and use Android `RenderEffect`, while the crisp line stays at full resolution. The native layer receives the same geometry, colors and animated seconds as the SVG path. API 30 and below, older host binaries, and unsupported inputs keep the SVG renderer; Android groups those SVG strokes by layer before applying blur. A persistent software-rendered host draws the current snapshot and hands off to a static SVG cue, stopping the shared clock at its current phase. A temporary software bitmap capture does not trigger that handoff. See the [Pixel 8a Android adapter measurements](/docs/audits/issue-663/composer-loader-multiline-pixel8a-2026-11-10/) and [adapter acceptance record](/docs/benchmarks/composer-loader-android-adapter-2026-11-08.json); these Android results do not verify iOS optics.

Under reduced motion the band rests at its current phase (web: paused CSS animation;
native: stopped frame clock) and visibility changes are immediate. Otherwise the
450 ms fade completes before an inactive loader stops. Hiding/pausing its owner
cancels the opacity transition immediately, including a fade already in progress. A rapid reactivation
cancels the pending stop.

Both renderers suspend when their owning `Screen` becomes inactive or the app
leaves the foreground. Web additionally observes the loader with Bloom's
`useInView` and pauses outside the viewport, including a zero-sized hidden host.
`paused` freezes the decoration without changing `active`, the surface, or the
input. Native consumers placing a loader in a scrolled/virtualized region should
pass `paused={!inView}` from their existing viewport/viewability owner. Native
screen activity is automatic; per-item native visibility is not inferred from
mounting or from a window-size guess. Resuming preserves the lap phase.

```tsx
<ComposerLoader phase={busy ? 'streaming' : 'idle'} paused={!inView}>
  <ComposerPill {...composerProps} />
</ComposerLoader>
```

`paused` does not hide or disable the input and does not represent a request
phase. The app chooses the phase; `ComposerLoader` only presents it.

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `children` | `ReactNode` | — | The composer. |
| `phase?` | `ComposerLoaderPhase` | — | Controlled request lifecycle; takes precedence over `active`. |
| `active?` | `boolean` | `true` | **Deprecated:** show the light; fades in/out over 450ms. Use `phase`. |
| `paused?` | `boolean` | `false` | Freeze the light at its current phase; input and surface remain mounted. |
| `colors?` | `[string, string, string, string]` | Theme primary / support / action foreground roles | Gradient left → right. Any colour string. |
| `speed?` | `number` | `4.5` | Seconds per lap. |
| `intensity?` | `number` | `0.7` | Overall light opacity. |
| `bloom?` | `number` | `16` | How far the bloom bleeds inward, px. `0` drops the layer. |
| `bloomStrength?` | `number` | `0.3` | Bloom layer opacity. |
| `arc?` | `number` | `120` | Band length, degrees of 360. |
| `reverse?` | `boolean` | `false` | Travel counter-clockwise. |
| `radius?` | `number` | the composer's, else full pill | Corner radius, px. Wins over the radius a `ComposerPill` inside reports. |
| `line?` | `number` | `2.5` | Crisp line width, px; the glow scales with it. |
| `bloomOnly?` | `boolean` | `false` | Only the wide bloom — a soft wash for a beam to lead. |
| `surface?` | `boolean` | `true` | Paint the pill surface + `shadow-xs` behind the light. |
| `taper?` | `number` | `0` | 0–1: fraction of the band's length that fades at each end. |
| `blend?` | `ViewStyle['mixBlendMode']` | — | How the light composites, e.g. `'screen'`. |
| `offset?` | `number` | `0` | Moves the band forward, as a fraction of the lap. Lines up two loaders on one pill: a short beam with `offset = (glowArc − beamArc) / 360` leads a wider `bloomOnly` glow tip to tip. |
| `style?` | `StyleProp<ViewStyle>` | — | Outer wrapper. |
| `testID?` | `string` | — | Also derives `-surface` and `-light`. |

The default colours follow the current preset and mode: `primarySubtleForeground`, `secondarySubtleForeground`, `tertiarySubtleForeground`, then primary again to close the moving band. Both platforms use `resolveComposerLoaderColors(theme)`. Pass `colors` for an explicit override.

## Accessibility

The surface and the light are decorative (`aria-hidden`, `pointerEvents="none"`); only the children are exposed. Announce the busy state from the composer itself (for example on its send / stop button).


## Reproducible lifecycle checks

The existing Composer Loader catalogue now includes `Lifecycle`: isolated and
tapered light, `ComposerPill`, and `AgentChatComposer`, with the same mounted
inputs across submitting/streaming/stopping/error/complete/idle, explicit pause,
retained `Screen`, height changes and viewport resize. It is a synthetic Bloom
fixture, not the real Alia route.

Run `scripts/verify-composer-loader-lifecycle.mjs` against this checkout's
Storybook. It resolves the story from `index.json` and uses real mouse clicks,
CSS animation clocks and DOM focus/selection. It verifies submit-to-streaming
continues the same lap, stopping stays lit, and error/completion/idle settle.
Set `STORYBOOK_URL`, `CHROME_PATH` and, when not installed locally,
`PUPPETEER_PATH` to `puppeteer-core`; `CHROME_WS_ENDPOINT` connects to an
already running Chromium.
`RECORD_VIDEO=1` records 9.5 seconds (two default laps); `OUT` chooses the artifact
directory. The JSON report identifies the commit/browser, viewport, geometry,
clock and input observations. Screenshots support visual review; clock results
are not GPU/performance budgets.

On 2026-11-08, Chromium 146 reproduced three running CSS animations with
`active=false` on baseline `e3996b93`; their timelines advanced 500 ms while
invisible. The lifecycle correction passes suspension/resumption (including a real
background-tab transition), AgentChat Stop hit testing, and same-input resize at 320, 390, 768, 1024 and 1440 CSS px. Native tests import the native
renderer explicitly and exercise measurement and the frame callback; they mock
SVG/filter rendering. iOS/Android optical quality, physical-device performance,
background behavior on devices, keyboard/IME, and the real Alia integration

## Android hardware light adapter (integration candidate)

Android 12 / API 31 and newer can use `BloomComposerLightV1`, supplied by Bloom's
existing Android package. Consumers must rebuild their native binary to install
it. Missing managers (including older binaries and Expo Go), API 30 and below,
unsupported colors or dash geometry retain the SVG renderer. A genuinely software host
reports a one-time unsupported event and hands the light back to SVG. A temporary
bitmap capture instead paints the current light synchronously with a CPU Gaussian
blur and leaves the live hardware renderer installed; it never reuses a cached
frame. That one-shot capture cost is separate from the continuous frame budget. The parent
owns one clock throughout that handoff; Surface, draft children, measured bounds,
fade and activity policies remain with ComposerLoader.

The Android SVG fallback groups strokes by semantic layer before applying each
layer blur, avoiding a separate blur operation for every tapered stroke. On one
Pixel 8a phase-origin still comparison with two tapered loaders, this raised the
hardware/software crop PSNR from 38.022437 dB to 40.280698 dB. That single
measurement is not a visual acceptance threshold, a motion comparison, or a
performance result; the fallback still requires product visual and performance
acceptance. A separate physical Pixel 8a recording shows the software fallback
moving for approximately 11 seconds with two tapered loaders (over two default
4.5-second laps); it confirms visible motion only, not frame-rate acceptance.
See `docs/benchmarks/composer-android-2026-11-08/loader-software-two-laps.json`
for APK and capture metadata. Exploratory `top` samples reached 200% and 186% of
one CPU core. The recording cadence was 6.05 fps, but screenrecord cadence is not
an application FPS measurement, and Android `gfxinfo` returned no frame rows for
this software host. These are adverse diagnostic signals requiring a controlled
follow-up, not a formal performance result.

The adapter groups the same strokes by semantic layer and draws their measured
rounded-path segments into three RenderNodes. Soft layers rasterize at quarter
resolution; the crisp layer retains full resolution. For taper, soft sigma uses
0.7 and bloom-only intensity uses 0.8. These are the reviewed moderate optical
calibrations, independent of color or position, rather than pixel equality with
web. iOS and web retain their existing renderers.

The private Pixel 8a harness established the candidate's motion and repeated
performance budget, not acceptance of this packaged integration. A persistently
software-rendered Android host now hands off to the shared SVG geometry and stops
the owner frame clock at the current phase. This avoids leaving the costly SVG
filters animating continuously; the light remains visible as a static busy cue.
Registration guards pass Robolectric API 30/31 and the installed Kotlin compiles
against react-android 0.73.0. Those checks do not establish a running old-RN host.
Physical software-host and temporary bitmap captures pass; the installed package
meets the previously fixed continuous budget in six repeated scene windows. The
JS-only update control retains the earlier native payload byte for byte and paints
SVG successfully when the new manager is absent. Exact artifact hashes and limits
are in `docs/benchmarks/composer-loader-android-adapter-2026-11-08.json`. Android 11 / API 30 on an isolated SwiftShader emulator mounts the SVG fallback
without the manager, suspends its pixels under reduced motion, and resumes after
the original OS setting is restored. Its abrupt lower halo remains visible; this
is compatibility evidence, not optical or performance acceptance. The static
clock handoff was tested on a physical software-window Pixel 8a: with two tapered
loaders and active=true, phase crops about 15 seconds apart were pixel-identical,
and exploratory CPU samples were 4.4–6.8% of one core. The prior animated software
fallback produced 200%/186% exploratory samples during screen recording. These
signals are diagnostic, not a controlled performance threshold. Full visual
acceptance, API 30 physical behavior, and handoff on other host configurations
remain pending. The packaged Pixel lifecycle case preserves pixels/clock while paused
and screen-inactive, excludes background time, survives resize and rapid toggles,
and starts inactive at clock zero. Real packaged ComposerPill and AgentChatComposer
retain input identity, focus, draft and selected content across busy/resize, and
Stop remains operable followed by typing. A negative control found that resize
reverses a backward selection and changes the next Shift+Arrow result; full
selection preservation is therefore not accepted. Direct RN cause isolation,
legacy runtime, Alia, and phase-aligned packaged optics remain pending.
See `scripts/loader-package-lab` for the isolated packaged consumer procedure.
