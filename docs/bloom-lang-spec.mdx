# Bloom (`.bloom`) language specification: draft 0

Status: **draft 0.2, phase 0** (2026-11-26; 0.1 and 0.2 fold in what porting Mention's Settings → Notifications and building the prototype found). Nothing here is released. The
decision record is [ADR 0001](https://github.com/OxyHQ/Bloom/blob/main/docs/adr/0001-bloom-own-language.md). The
TS-embedded language (`@oxy.so/bloom-language` chains in `.tsx`) is called
**the embedded language** below; `.bloom` compiles *to* it, so everything the
embedded language draws, `.bloom` draws the same way.

Notation: `«x»` is a placeholder; "phase 0" marks what the prototype
implements, "phase 1+" what is specified but not built yet.

## 1. A taste

```bloom
import { useTranslation } from "react-i18next"

enum Load<T> {
  loading
  failed(message: String)
  ready(T)
}

struct Draft {
  text: String = ""
  sensitive: Bool = false
}

pub view Composer(maxLength: Int = 500, onSend: async (Draft) -> Result<Unit, String>) {
  let { t } = useTranslation()
  @state draft = Draft()
  @state sending = false

  let left = maxLength - draft.text.count          // derived, recomputed only when draft changes
  let canSend = !sending && left >= 0 && !draft.text.isEmpty

  async fn send() {
    sending = true
    match await onSend(draft) {
      case .ok(_) => draft = Draft()
      case .err(message) => toast(message, type: "error")
    }
    sending = false
  }

  body {
    VStack {
      TextField($draft.text, t("compose.placeholder"))
      HStack {
        Toggle($draft.sensitive).label(t("compose.sensitive"))
        Spacer()
        Text("${left}").foreground(left < 0 ? "error" : "muted")
        Button(Text(t("compose.send"))).disabled(!canSend).onPress { await send() }
      }
      .spacing("sm")
    }
    .spacing("md")
    .padding("lg")
  }
}
```

## 2. Lexical structure

- **Source** is UTF-8. A file is one module.
- **Comments:** `// line`, `/* block */` (nesting), `/// doc` (attached to the next item; shown on hover).
- **Newlines terminate** statements, fields, variants and builder items. A newline does **not**
  terminate when (a) the next non-blank line starts with `.` followed by an identifier
  (a modifier or member continues the expression), or with a binary operator other than `-`
  (`&&`, `||`, `??`, `+`, `*`, `/`, `==`, …), or (b) the line ends inside `(`/`[`, after a binary
  operator, after `,`, `=`, `->`, `=>` or `in`. Comment-only lines count as blank for (a). `;`
  may separate items on one line.
- **Identifiers:** `[a-zA-Z_][a-zA-Z0-9_]*`. Types, views and enum names are `UpperCamel`;
  values, functions, fields and enum cases are `lowerCamel` (a warning otherwise, B0901).
- **Keywords:** `as async await body case default defer else enum false fn for from if import in
  let match none pub return screen layout struct task true type var view while`. Attribute words after `@`:
  `state list record env`.
- **Literals:** `42`, `1_000`, `0xff` (Int); `1.5`, `2e3` (Float); `true`/`false`; `none`;
  strings `"…"` with escapes `\n \t \" \\ \$ \u{1F600}` and interpolation `\(expr)` (2.0; 0.x `${expr}`);
  raw multi-line strings `"""…"""` (interpolation kept, indentation stripped to the closing
  delimiter).
- **Binding projection:** `$name` (a binding to `@state name`, see 7.2).

## 3. Grammar (EBNF)

`NL` is a terminating newline (section 2). `{ x }` is zero or more, `[ x ]` optional.

```ebnf
file          = { import NL } { item NL } ;

import        = "import" "{" import_spec { "," import_spec } [ "," ] "}" "from" STRING
              | "import" "*" "as" IDENT "from" STRING ;
import_spec   = [ "type" ] NAME [ "as" NAME ] ;

item          = { doc } [ "pub" [ "default" ] ]
                ( struct | enum | alias | fn | view | screen | layout | const ) ;
const         = "let" IDENT [ ":" type ] "=" expr ;
struct        = "struct" TYPE_NAME [ generics ] "{" { field NL } "}" ;
field         = IDENT ":" type [ "=" expr ] ;
enum          = "enum" TYPE_NAME [ generics ] "{" { variant ( NL | "," ) } "}" ;
variant       = IDENT [ "(" payload { "," payload } ")" ] ;
payload       = [ IDENT ":" ] type ;
(* 2.0 type declarations (sections 4.8, 4.9, 7.1a): *)
class         = { "@" TYPE_NAME } [ "final" ] "class" TYPE_NAME [ generics ] [ conforms ]
                "{" { member NL } "}" ;
protocol      = "protocol" TYPE_NAME [ conforms ] "{" { requirement NL } "}" ;
requirement   = [ "static" ] "var" IDENT ":" type "{" "get" [ "set" ] "}" | [ "static" ] func_sig ;
extension     = "extension" TYPE_NAME [ generics ] [ conforms ] "{" { member NL } "}" ;
conforms      = ":" type { "," type } ;
member        = { attr } [ visibility ] [ "static" ] ( ( "let" | "var" ) IDENT [ ":" type ] [ "=" expr ]
              | "var" IDENT ":" type block | func | "init" params block ) ;
alias         = "type" TYPE_NAME [ generics ] "=" type ;
generics      = "<" TYPE_NAME { "," TYPE_NAME } ">" ;

fn            = [ "async" ] "fn" IDENT [ generics ] "(" [ params ] ")" [ "->" type ] block ;
params        = param { "," param } [ "," ] ;
param         = [ ".." ] IDENT ":" type [ "=" expr ] ;   (* "..": a rest parameter, last *)

view          = "view"   TYPE_NAME [ "(" [ params ] ")" ] view_block ;   (* a param may be ".." TYPE: props spread *)
screen        = "screen" TYPE_NAME [ "(" [ params ] ")" ] view_block ;   (* a route: default export *)
layout        = "layout" TYPE_NAME [ "(" [ params ] ")" ] view_block ;   (* a route layout *)
view_block    = "{" { member NL } "body" block "}" ;
member        = state | let_stmt | fn | effect | equal ;
equal         = "equal" "(" IDENT "," IDENT ")" block ;   (* contextual, like effect *)
effect        = "effect" [ "(" "id" ":" expr ")" ] block ;   (* contextual: `effect` stays a name *)
state         = "@" ( "state" | "list" | "record" | "env" | "ref" ) IDENT [ ":" type ] "=" expr ;

block         = "{" { stmt ( NL | ";" ) } "}" ;
stmt          = let_stmt | var_stmt | assign | "return" [ expr ] | "defer" block | while | for | expr ;
let_stmt      = "let" pattern [ ":" type ] "=" expr ;
var_stmt      = "var" IDENT [ ":" type ] "=" expr ;
assign        = place ( "=" | "+=" | "-=" | "*=" ) expr ;
place         = IDENT { "." IDENT } ;
while         = "while" expr_no_trailing block ;
for           = "for" pattern "in" expr_no_trailing block ;

type          = base_type [ "?" ] ;
base_type     = TYPE_NAME [ "<" type { "," type } ">" ]
              | "[" type "]"                       (* List<T> *)
              | "[" type ":" type "]"              (* Map<K, V> *)
              | "(" type "," type { "," type } ")" (* tuple *)
              | [ "async" ] "(" [ type { "," type } ] ")" "->" type ;

expr          = if_expr | match_expr | closure | binary ;
if_expr       = "if" cond block [ "else" ( if_expr | block ) ] ;
cond          = expr_no_trailing | "let" pattern "=" expr_no_trailing ;
match_expr    = "match" expr_no_trailing "{" { "case" pattern [ "if" expr ] "=>" ( block | expr ) NL } "}" ;
                (* after "=>", "{" always opens a block; "{}" is the empty block, of type Unit;
                   an arm may also be one statement: case .ok(_) => draft = Draft() *)
task_expr     = "task" block ;                     (* spawns; the expression is Unit *)
closure       = "{" [ closure_params "in" ] { stmt ( NL | ";" ) } "}" ;
closure_params= IDENT [ ":" type ] { "," IDENT [ ":" type ] }
              | "(" IDENT { "," IDENT } ")" ;          (* one tuple parameter, its items named *)

binary        = unary { BINOP unary } ;           (* precedence table in 6.1 *)
unary         = [ "!" | "-" | "await" ] postfix ;   (* "await" binds tighter than a trailing "?":
                                                      await f()? is (await f())? *)
postfix       = primary { call | "." NAME | "?." NAME | "?." "(" [ args ] ")" | "[" expr "]" | "?" } ;
call          = "(" [ args ] ")" [ closure ] | closure ;   (* a trailing closure; never in
                                                          expr_no_trailing heads *)
args          = arg { "," arg } [ "," ] ;
arg           = [ IDENT ":" ] expr | ".." expr ;  (* named argument; a struct spread, or a
                                                   list spread into a rest parameter *)
primary       = literal | "()" | task_expr | STRING | NAME | "." IDENT | "$" IDENT { "." IDENT }
              | "(" expr ")" | "(" expr "," expr { "," expr } ")"
              | "[" [ item { "," item } ] "]" | "[" expr ":" expr { "," expr ":" expr } "]" | "[:]" ;

item          = expr | ".." expr ;                  (* `[..a, b]`: a list's items in place *)
pattern       = "_" | IDENT | literal | "." IDENT [ "(" pattern { "," pattern } ")" ]
              | TYPE_NAME "." IDENT [ "(" … ")" ] | "(" pattern { "," pattern } ")"
              | "{" IDENT [ ":" pattern ] { "," … } "}"     (* record destructuring *)
              | pattern "|" pattern ;
```

Three grammar rules keep it unambiguous, as in Swift:

A keyword that never starts an expression (`type`, `body`, `view`, `screen`, `layout`, `from`)
may name a parameter, a struct field or a value, so a TS API's props and fields keep their
names (`view NoticeRow(type: String, body: String)`, `Text(body)`). Record keys, labels,
members after `.` and the names of a struct's or a protocol's properties may be any keyword
(`public let none: String`, read `copy.none`): a TS record's own field names cross unchanged.
`none` is the literal only where an expression starts.

1. **No trailing closure in a head.** `if x { … }`, `match x {`, `for p in xs {` and `while`
   never read the `{` as a trailing closure of `x`.
2. **Match arms start with `case`**, so a line starting with `.` is always a continuation.
3. **An enum case at the start of a line is qualified** (`Load.ready(x)`), since `.ready(x)` there
   would continue the previous line. `ok(x)`, `err(e)` are prelude constructors.

## 4. Types

### 4.1 The types

| Bloom | Meaning | Runtime representation (zero-cost) | `.d.ts` emitted |
|---|---|---|---|
| `Int` | 64-bit signed integer (Swift's `Int`); exact within ±(2^53 − 1) on the JS backend (4.3) | JS number (Kotlin `Long`, Swift `Int` on the native backends) | `number` |
| `Float` | IEEE double | JS number | `number` |
| `Bool`, `String`, `Unit` | | boolean, string, `undefined` | `boolean`, `string`, `void` |
| `[T]` | immutable list | frozen-in-dev JS array | `readonly T[]` |
| `[String: V]` | immutable dictionary | plain object | `Readonly<Record<string, V>>` |
| `Map<K, V>` | immutable map, any key | `Map` | `ReadonlyMap<K, V>` |
| `Set<T>` | immutable set | `Set` | `ReadonlySet<T>` |
| `(A, B)` | tuple | array | `readonly [A, B]` |
| `T?` | `Option<T>` | the value or `undefined` | `T \| undefined` |
| `Result<T, E>` | success or error | `{ ok: true, value } \| { ok: false, error }` | the same union |
| `struct S { … }` | nominal record | plain object | `interface S { readonly … }` |
| `enum E { a, b }` (no payloads) | | string literal | `"a" \| "b"` |
| `enum E { a, b(T) }` | tagged union | `"a"` or `{ tag: "b", _0: T }` (named payloads keep their names) | the union |
| `(A) -> R`, `async (A) -> R` | a Bloom function (async: one that awaits) | JS function (async → returns a Promise) | `(a: A) => R` / `Promise<R>` |
| `Promise<T>` | a TS promise (it may reject) | the promise | `Promise<T>` |
| `Error` | a JS error: `message: String`, `name: String` | the `Error` object | `Error` |
| `View` | a UI value | an embedded-language node (`Child`) | `Child` |
| `Binding<T>` | read and write of a state | `[value, set]` (the embedded language's binding) | `Binding<T>` |
| token sets (`Space`, `Color`, `Font`, …) | closed string sets from `spec/language.json` | string | the literal union |
| `Foreign` | a TS value Bloom could not type (4.6) | as is | the TS type |

`T??` is rejected (B0203): an optional is never nested, so `undefined` alone can represent it.

### 4.2 Inference

Local bidirectional inference with unification (Hindley–Milner without let-generalisation of
locals). Signatures are required at module level (parameters and results of `fn`, fields,
view parameters), inferred everywhere inside: `let`, closure parameters (from the expected
function type), generic arguments at call sites, empty collections from use. What is expected
reaches in: a closure called at once (`let all: [Item] = { … }()`) gives it, so each `return` is
checked against `[Item]`, and a generic method's result meets it before its arguments are read
(`uris.map { u in ({ id: u }) }` builds `Item`s). Only a declared type (an annotation, a
parameter's, a modifier's) reaches a generic method's result this way, never one inferred from a
sibling (a list literal's earlier item, a ternary's first branch). A record a closure gives (its
last line or a `return`, its result type not written) takes an expected struct or TS type with
any extra fields, as TS checks no excess property on a callback's result; a literal written where
the type is declared (`let x: [T] = [{ … }]`) is checked for them (B0205). Swift's signature writes a closure's result
type by hand: `{ () -> [Item] in … }`, `{ (n: Int) -> Int in n * 2 }`. A list or record literal
is checked against its context as Swift checks one: each element and each ternary branch on its
own against the expected type (an annotation, a TS parameter's, or a spec object parameter's),
never against its sibling's. A spec object parameter is a record of its keys:
`.accessibilityValue(c ? { text } : { min, max, now })`, and a typed one names each key's type
(`Dialog().buttons([…])` takes `[dialogButton]`, `{ label: String, color?, onPress?, … }`: a
button without `label` is B0206, an unknown key B0205). Where a TS type is expected, each list
element and each field of a record literal is TS's to check on its own (tsc does, on the emitted
code): `let s: Style = { transform: [{ scale: 0.5 }, { translateY: y }] }`. A literal
`"md"` checks against an expected token set; `none` against an expected `T?`. A `T` is
promoted to `T?` where a `T?` is expected (never the reverse; unwrap with `if let`, `??`,
`?.`, `match` or `?`). In `if x != none { … }` (also `none != x`, and each side of `&&`) a
local, parameter, prop or `@State` `x` is present in the block, as TS narrows it (a state's value
is the render's, as a `let`'s is; only its reads narrow, so `x = none` and `$x` there are the
state's, `$x` a binding of the narrowed type): `if onEnd != none {
onEnd() }`. So it is on the right of `&&` (`name != none && !name.isEmpty`) and, for `x == none`,
on the right of `||` (`x == none || x.isEmpty`); in the branch of `?:` that knows (`p != none ?
p.x : d`, `p == none ? d : p.x`); and after a guard
that returns (`if x == none { return … }`, also `a == none || b == none`), in the rest of the
block. A test in parentheses narrows as one without (`(p.x != none) ? p.x : d`). Values are immutable, so a member chain of such a name narrows the same way
(`u.name != none && !u.name.isEmpty`, `u?.name`, `u.avatar?.url`); the emitter writes `u.name!`,
since TS does not keep a property's narrowing inside a closure.

Numbers: an `Int` widens to `Float` wherever a `Float` is expected, Bloom to Bloom and at the
TS boundary (a TS `number` reads as `Float`), inside lists, optionals, dictionaries and record
fields too (`[Int]` fits `[Float]`). It costs nothing and loses nothing: both are JS numbers
and an `Int` is exact within 2^53 on the JS backend (4.3), so no conversion is emitted. An integer literal is a `Float`
where one is expected (`let x: Float = 0`). Arithmetic with an `Int` and a `Float` operand
is `Float`; `i / j` of two `Int`s stays integer division (it truncates) even where a `Float`
is expected, while `7 / 2` there is `3.5` (its literals are `Float`s). A conditional with an
`Int` and a `Float` branch is `Float`. A `Float` never narrows implicitly.

Branches that end in `none` join to the optional of the others, nested or not, as TS's
`string | null`: `c ? "x" : d ? "y" : none` is `("x" | "y")?`, `c ? 1 : d ? 2.5 : none` is
`Float?`, `c ? none : d ? n + 1 : n` is `Int?`; the branches besides `none` still share one
type (`c ? "x" : d ? 1 : none` is B0201). A chain of any length does (`a ? "\(x)" : b ?
"\(y)" : none`), and so does a list item (`[c ? f(x) : none, title]` is a `[String?]`). A literal's optional falls back to any string
(`label ?? ""` is a `String`), as TS's `"x" | ""`.

### 4.3 Soundness rules

- No `any`, no implicit null, no implicit narrowing: `Float` → `Int` is `.rounded()`,
  `.floor()`, `.ceil()` or `.truncated()` (B0201). `Int` → `Float` widens implicitly (4.2).
- Exhaustive `match` (B0301 lists the missing cases); unreachable arms warn (B0302).
- Values are immutable. `var` exists only as a local, and as a file's own `private var x: T = v`
  (2.0), a JS module `let` any of its functions and closures may write (a registry callback); it
  is no dependency and no state, so nothing re-renders on it. Any other module `var` is B0106.
  Swift's `f?()` calls an optional function when it is present (`f?.()` in JS). A closure may capture, read and write a
  function's (or a closure's, a handler's) own `var`, as Swift's does: `handlers[tag] = run` in a
  closure is seen by the function once it ran, and each write is a new value (a `var` holding
  another name's list or dictionary never changes it). A `var` of a view's render or of a hook
  function is not capturable (B0402): their closures are cached across renders, and would keep a
  stale binding.
- Equality `==` is defined on `Int`, `Float`, `Bool`, `String`, fieldless enums and `none`
  checks; on structs and payload enums it is structural and compiled to a field comparison
  (phase 1; phase 0 rejects it with B0210). `x == none` / `x != none` tests presence on any
  optional, a function's too. `T == T?` compares as optionals (`a == b` with `b: Int?`), as
  Swift does.
- Integer division `/` on `Int` truncates toward zero; `%` follows the dividend's sign.
- `Int` is a 64-bit signed integer, as Swift's is on every platform Bloom targets: the native
  backends (ADR 0003) compile it to Kotlin's `Long` and Swift's `Int`. The JS backend keeps it a
  JS `number` (zero-cost, and what TS reads), which is exact within ±(2^53 − 1)
  (`Number.MAX_SAFE_INTEGER`). A program whose `Int` leaves that range is in error there: an
  integer literal outside it is B0105, `Int(s)` of text outside it is `none`, and a dev build
  traps an `Int` `+`, `-` or `*` (and `+=`, `-=`, `*=`) whose result leaves it (`$int`, a
  `RangeError`), as Swift traps an overflow; a release build does not check.
- An array's subscript `xs[i]` is a `T` (2.0, Swift's rule): reading past the end is a
  programming error, a trap, not a `none`. A dev build checks the bounds (`$get(xs, i)`, a
  `RangeError` naming the index and the count); a release build emits `xs[i]` and does not.
  `xs.at(i)`, `first` and `last` are the optional reads; a dictionary's `d[k]` stays `V?`.

### 4.4 Structs

```bloom
struct Prefs {
  pushEnabled: Bool = true
  likes: Bool = true
}
let p = Prefs()                      // every field has a default
let q = p.with(likes: false)         // an updated copy
let r = Prefs(..patch, likes: true)  // spread a Prefs or a Partial<Prefs>, then fields
```

A field without a default is required at construction. `Partial<S>` is the struct with every
field optional (a patch), built with `S.patch(field: v, …)`. Construction compiles to an object
literal (no function call). A spread `..p` of a `Partial<S>` fills only the fields `p` has: an
absent or `undefined` field keeps the default (compiled per field, `p?.likes ?? true`), unlike a
JS object spread; an optional patch (`Partial<S>?`) spreads the same way. A field whose
default is `none` that a construction leaves out (or gives as `none`) is left out of the
object, as TS's `x?: T` is: `QueryOptions(queryKey: k, queryFn: f)` is `{ queryKey: k,
queryFn: f }`, never `{ staleTime: undefined, … }`, which overrides a library's default where
it merges `{ ...defaults, ...options }`. The record literal `{ ..p, likes: false }` is the same
copy-and-change: a key written after the spread replaces the spread's field (JS's
`{ ...p, likes: false }`, Rust's struct update), only a key written twice is B0208, and when the
first entry spreads a struct and every key written is one of its fields, the literal is that
struct, each key checked against its field's type, with or without an expected type. Keyed field access (`prefs[key]`, key paths) is phase 1; until then an
exhaustive `match` on a fieldless enum maps a key to a field.

**`@Transparent` structs** (Rust's `#[repr(transparent)]`, a Swift tagged type):

```bloom
@Transparent
public struct UserID: Codable, Equatable, Hashable {
  public let raw: String
  public var isGuest: Bool { raw.hasPrefix("guest-") }
}
let id = UserID(raw: "u1")   // the string "u1" at run time
id.raw                        // the value itself
```

A struct marked `@Transparent` has exactly one stored property, a `let` (B0106 for none, a
second one or a `var`; B0106 on anything that is not a struct). It is a type of its own to the
checker (a `UserID` is not a `String`), and that field at run time: its TS type is the field's
(`export type UserID = string`), `UserID(raw: v)` is `v`, `id.raw` is `id`, `id.with(raw: v)` is
`v`, and `==` (`Equatable`, `Hashable`) compares the field. A derived `Codable` is the field's
codec (`"u1"`, not `{ "raw": "u1" }`). Computed properties and methods are its own, called with
the field's value as `self`. The Kotlin backend writes a `@JvmInline value class`, the Swift
one a struct (`CheckResult.transparent`).

**`UniqueID`** is the standard library's transparent identity, `struct UniqueID { let string:
String }`. `@State private var id = UniqueID()` (a view's state, or a hook function's
`@State var`) is the view's identity for its life, made once when it first appears: React's
`useId()` on the TS backend (`const id = useId()`, no setter, hydration-safe), read as
`id.string` (a label paired with its field, a key into a registry). `UniqueID()` anywhere else
is B0420, and assigning the state is B0403.

### 4.5 Enums, Option and Result

```bloom
enum Shape {
  circle(radius: Float)
  rect(w: Float, h: Float)
}
fn area(s: Shape) -> Float {
  match s {
    case .circle(r) => 3.14159 * r * r
    case .rect(w, h) => w * h
  }
}
```

`Option<T>` is written `T?`: `none`, `x ?? fallback`, `x?.field`, `x?.method(…)`, `f?.(…)`,
`if let v = x { … }`. A `?.` short-circuits the rest of its chain, as in JS: in
`b?.label.uppercased()` the `.uppercased()` reads `b`'s label and the whole is `String?`. A
link whose own type is optional is not read through (`b?.note.trimmed()` with `note: String?`
is B0209; write `b?.note?.trimmed()`). `xs?[i]` is Swift's optional subscript (JS's
`xs?.[i]`), `none` from there through the chain. `?.`, `?[…]` and `??` on a value that is never
`none` are B0201, for a Bloom type: **Bloom's types are guarantees, TS's are claims.** On a
value whose type comes from TS (a `Foreign`, a type read from a `.d.ts`, or what is read from
one, `viewPost.authors`), TS may say it is always there while the data at run time lacks it, so
`viewPost?.authors?.map { … } ?? []` keeps each guard as written, silently, and a guarded link
is optional from there on. `{}` is the empty record where a struct, or its optional, is
expected (`viewPost?.metadata ?? {}`); where a TS type with required fields is expected, `ts.state
?? {}` is TS's `State | {}`, a `Partial<State>` whose fields read as optional. A `let` (a view member too) keeps the
claim of the TS value it holds. A closure's parameter may be wider than the one expected (`{ file:
File? in … }` for `(File) -> Unit`), as Swift's `(T?) -> U` fits `(T) -> U`. A method
JS has compiles to `x?.m(…)`; any other (`s?.toInt()`) reads `x` once and runs only when it
is not `none`. A member Bloom respells keeps its spelling through `?.` and the chain after it,
whatever the generic it came through: `query.data?.count` with `data: T?` and `T = [Post]` is
`query.data?.length`, `xs?.first` is `xs?.[0]`. A member that wraps its object (`isEmpty`, a
dictionary's `keys`, an extension's property, `a?.s.toInt()`) reads it once and is `none` when
it is, so `feed?.items.isEmpty ?? true` is `true` for no feed; a cache depends on the object,
not on the respelled member. An optional call of a Unit function is Unit.
`x!` (2.0, Swift's force unwrap, written against its operand) is the value of an optional;
`none` there is a trap. A dev build checks it (`$unwrap(x)`, a `TypeError`); a release build
emits TS's `x!`, so it costs nothing. `!` on a value that is never `none` is B0201.
`Result<T, E>` has cases `ok(T)` and `err(E)`; `expr?` in a function returning
`Result<_, E>` returns the error early (in one returning `T?`, a `none` early). Inside
`catching { … }` and in a closure TS calls (a TS parameter's function, sync or async, or one of no Bloom type),
`expr?` on a `Result` throws its error instead: `catching` gives it as `.err`, and the promise
TS awaits rejects (`queryFn: { let page = (await api.list())?; page.items }`). Methods:
`.map`, `.mapErr`, `.unwrapOr`, `.ok()` (to an optional), `.isOk`.

### 4.6 Generics

`fn first<T>(xs: [T]) -> T?`, `struct Page<T> { items: [T], cursor: String? }`,
`enum Load<T>`. Type parameters are inferred at call sites. String literals given for a
parameter that names one (`choices(["a", "b"], chosen, onChoose)`) are read after the call's
other arguments, so `T` is what a typed argument says (a TS literal union) and the literals are
checked against it; alone, they make it a `String`.

A type parameter may be constrained (2.0): `func firstIndex<T: Equatable>(_ xs: [T], of x: T)`,
`<T: Titled & Equatable>`, `where T: Titled & Equatable`, or a module's `type TitledValue =
Titled & Equatable` named in one (`<T: TitledValue>`): a composition is one constraint per
protocol, and only a constraint (B0232 as a value's type; `any P & Q` is not yet). Inside the function, a `T: P` value reads `P`'s
requirements (section 4.8) and a `T: Equatable` value compares with `==`. Dispatch is static:
each constraint is one more parameter, a *witness* (`$w_T_P`), which the call site fills for
the type it inferred: the conformance's witness object `Post$$Titled`, or for `Equatable` the
type's `==` (field by field for a struct). A type argument that does not conform is B0232.
`T: Codable` (`Decodable`, `Encodable`) passes `T`'s codec, which the body reads as `T.self`: a
type's `T$$self` (derived for a `Codable` struct, the standard library's for `String`, `Int`, …),
or a generic type's `T.codec(…)` of its arguments' codecs (`Page$$codec(Post$$self)`,
`Array$$codec(…)`), so `let page: Page<Post> = try await api.get("/feeds/home")` decodes with no
codec written. `Sendable` and other built-in protocols with nothing a body reads pass no witness.

A type parameter may instead be bounded by a **shape**: a struct, a record type or a TS
interface (`<T: ProfileGridEntry>`). A shape is structural, as TS's `T extends ProfileGridEntry`
is, which is what it compiles to: a `T` value reads the shape's fields from itself and passes
where the shape is expected, and a call passes nothing for it. A call's type argument that
lacks one of the shape's fields (or has it with another type) is B0232. A data struct's own type
parameters take no constraints (B0106); a function's and a view's do.

### 4.7 The foreign boundary

A TS import is typed from its `.d.ts` (section 10). Declarations bloomc can map (primitives,
arrays, `T | undefined | null`, object types, interfaces, string-literal unions, function
types, `Promise<T>`, generic functions and interfaces without conditional or mapped types)
get Bloom types. A discriminated union of object types (`{ kind: "sources"; sources: … } | {
kind: "lane"; … }`, a field every member has as a distinct string literal) is a type whose one
field is the tag: a `match` on it (`switch rows.kind { case "sources": … }`) is exhaustive over
the tags, and each arm reads its member's fields (`rows.sources`), as an `if rows.kind ==
"sources"` block and the rest after `if rows.kind != "lane" { return … }` do, the way TS narrows
it. Anything else is `Foreign`: a value you may pass back to TS, call, or read
members from (each read is `Foreign` again). **A `Foreign` value is accepted wherever a Bloom
type is expected** (an argument, a modifier, a condition, an annotated `let`, a field, a
return), and there the emitter writes a checked boundary, `(expr satisfies T)`, so the
TypeScript checker verifies it against the real `.d.ts` and its diagnostic maps back to the
`.bloom` span. Where nothing is expected (`let x = foreignCall()`) the value stays `Foreign`,
and using it as a Bloom value with no expected type (an operator, a `match`, a member of a Bloom
type) is B0601 with the fix "annotate it: `let x: T = …`". A list of TS values where a typed
list is expected (`accounts: data ?? []` for an `[Account]`, `Set<String>(ids)`), and a function
whose parameter is typed where the expected one is a TS value (`bans.map(renderBan)` with
`renderBan(_ ban: CommunityBan)`) are accepted too, each checked by `satisfies` (`readonly Account[]`, the
function's TS type when TS's is written out). Nothing crosses unchecked: Bloom code
is checked by bloomc, and every crossing by `tsc`.

**`null` (2.0).** Bloom's `T?` is `T | undefined`, and Bloom code never makes a `null`. A TS
value typed `T | null` (or `T | null | undefined`) crosses in as `T?`, and every test of an
optional is loose: `if let`, `x == none`, `case .some`, `?`, `!`, `??` and optional equality
compile to `!= null` / `== null`, so a TS `null` is `none` at run time. Where such a value goes
on to a Bloom `T?` parameter, prop or field, TS's `null` is not its `undefined`: write
`value ?? none` (`undefined` for a `null`). `title || "Untitled"` of an optional that is not a
`Bool` is JS's value `||`, as for a TS value; when the other side may be absent too
(`user.username || user.handle`), so may the whole, a `String?`, while a chain that ends in a
present value is present (`a || (b || c)` with `c: String`). A TS value in a record's field fits the field's
type (`{ avatar: user.avatar }` where a `PostUser` is expected): TS checks the record where it
lands, and a `T?` field's check takes TS's `null` (`satisfies T | undefined | null`). Anywhere
else a `Foreign` value checked as a `T?` reads TS's `null` as `none`: `((x) ?? undefined)
satisfies T | undefined`, written once (a `??` chain whose last operand is already so checked is
not given a second `?? undefined`, which TS calls always nullish).

`x ?? e` whose two sides both fit what is expected is that type (`authors ?? []` where a
`[Person]` is taken and `authors: [Author]?`, `Author` extending `Person`).

`foreign ?? e` takes `e`'s type (the left side may be `null` in TS as well as `undefined`);
TS checks the whole where it lands; a TS value compared with `none` is compared loosely
(`!= null`), as TS's absence may be `null`. Where `e` says less than TS knows (`data ?? []`), its items
are the TS value's (`NonNullable<…>[number]`), so `.map { m in m.name }` reads TS members. A TS
value beside a number in arithmetic is a number (`insets.top + 4` is a `Float`; for `+` beside
a string, a `String`), and the emitter writes `(insets.top satisfies number)`; so is one beside
an `Int` (`2 * Math.PI` is a `Float`), negated (`-event.translationY`), or compared with a number or
a string (`item.pokeCount > 1`, checked as a `number`; two TS values compare as TS compares them). So does a TS value beside `none` or a Bloom value in a
branch (`on ? none : presets.find { … }`), and `for x in foreign` walks TS items. A TS tuple
of string literals (`['a', 'b'] as const`) is a list of their union, `[("a" | "b")]`. `f || b`
of a TS value `f` is JS's `||` (`list.title || "Untitled"`): `b`'s type, checked by
`satisfies`. A field of a TS value is TS's to write (`player.loop = true`, `p.time += 5`),
emitted as written and checked by tsc. A node's argument TS types (a signature's `value`) takes `none` where TS takes
`undefined` (`SettingsSection(none, …)`), and a TS function's optional parameter (`locale?: string`) takes
an optional as well as its type (`formatRelativeTime(at, locale)` with `locale: String?`), as
TS's `undefined` is `none`; a required one does not. A TS callback typed `() => Promise<void> |
void` (read as `Promise<Unit>?`) takes a closure that returns nothing or one that awaits, as TS
discards its result (`Retry(onRetry: { task { await refetch() } })`). A TS literal union compares
with any `String` (`value == tab` with `value: Tab?` and `tab` from a list), as TS's `===` does; a
string literal compared with it is still held to its values. A TS function whose overloads take
mapped option types Bloom cannot read (TanStack Query's `useQuery`) is `Foreign`, so what it
returns says nothing of its data; a binding module gives it a generic signature
(`public func useQuery<T>(_ options: QueryOptions<T>) -> QueryResult<T>` with `queryFn: () async
-> T`), and `T` is then the `queryFn` closure's result. A TS
class that extends nothing (`ViewModifier`) is a value
and a type, both `Foreign`: `look: ViewModifier? = none` then `.modifier(look ?? card)`.

`x is T` tests a TS value of no Bloom type (`unknown`, a union) at run time, for the types JS
can test: `String`, `Int` (an integer number), `Float`, `Bool` and `[T]` (`Array.isArray`; its
items are taken as `T`). `if x is T { … }` narrows a name to `T` in the block. It sits at the
comparisons' precedence. `is` on a Bloom value, or for another type, is B0213: a Bloom type's
cases are an enum's, matched with `match`. A Bloom file reads no JS global implicitly: numbers
come from the prelude (section 12), timers are `task { await sleep(ms) … }`, and any other global
is imported by name, `import { encodeURIComponent, JSON } from "js"`: nothing is emitted for
the import, and its names are `Foreign`, typed by TypeScript (lib.es, lib.dom) where they cross.
A JS class imported so (`URL`, `AbortController`, `URLSearchParams`, `Error`, …) is
built by a call: `URL(at)` is `new URL(at)`; Bloom has no `new`. `Date` is the standard library's
(Swift's), a JS `Date` at runtime and in TS in both directions, as Swift's `Date` bridges to
`NSDate`: a TS `Date` parameter takes it and a TS `Date` result is one. Its initializers are told
apart by their labels, `Date()`, `Date(timeIntervalSince1970:)`, `Date(millisecondsSince1970:)`,
`try Date(text, strategy: .iso8601)` (JS's `Date.parse`); two are `==` at the same instant, compare
with `<`, and move with `+`/`-` in seconds. A `"js"` import of `Date` does not shadow it. `Foreign<"T">` writes out a
TS type Bloom does not express (`Foreign<"ReturnType<typeof setTimeout>">`,
`Foreign<"AvatarProps['source']">`, `Foreign<"string | number">`): its values are `Foreign`,
and the emitted TS names the type as written, so TS checks every use.

A TS function with no annotated result (a hook in a `.ts` source, `export function useJobForm()
{ … return { title, setTitle, skills, … } }`) returns what its body returns, read as TS infers
it for the shapes hooks are written in: a `useState<T>(x)` pair is a `T` and a `(T) -> Unit`
setter (`T` is `x`'s type without a type argument), a `useCallback(fn, …)` is `fn`, a
`useMemo(() => x, …)` is `x`; literals, comparisons, `Boolean(…)`, `!`, `&&`/`||` of `Bool`s,
arithmetic, ternaries and `??` join as TS's do (`c ? n : undefined` is `Float?`), and an object
literal is a record of them. A name or a call of the module is its declaration's type or result.
Anything else (a generic call, a spread, a method's result) is `Foreign`, named by its TS path
(`ReturnType<typeof useJobForm>["x"]`). A generic function's result is read per use, as TS's.
`ReturnType<typeof f>` (and `typeof x`) in a TS type is that function's result (that value's
type), whether `f` is TS or a `.bloom` hook (through the declarations bloomc writes,
`X.d.bloom.ts`): `type JobForm = ReturnType<typeof useJobForm>` is the record the hook returns,
one type whichever name reaches it. An unannotated `const` of plain data (`export const GAP =
12`, a record or list of literals) is its initializer's type (an integer literal's is an `Int`,
`const MAX = 4`); any other stays `Foreign`. The optional of a TS type Bloom does not map
(`T | undefined`, `x?: T`, a member read through `?.`, `server?.robots`) is `Foreign`, not
`Foreign?`, as its parts are TS's to check; so is `x ?? foreign`.

A record indexed by a union of its keys is the fields they name, joined, as TS's `T[K]`
(`let SIZES = { small: "8", large: "12" }` then `SIZES[size]` with `size: "small" | "large"`
is a `String`; `{ rate: "Rate", notes: "Notes" }[tab]` too); a key it does not have is B0205.

A record literal where a dictionary `[String: V]` is expected is a dictionary literal: each value
is checked as a `V` (a TS value as any other), and `..d` spreads a dictionary into it
(`let ICONS: [String: BloomIcon] = { mixed: RiGitMergeLine }`). A record, or a TS object type,
fits a dictionary when each of its fields fits `V` (`let GAPS: [String: Float] = SPACING`).

A TS indexed access type (`socialContext?: FeedPostSlice['socialContext']`) is the member it
names, through interfaces (and those they extend), object type aliases and chains
(`X['a']['b']`); an optional member is its type's optional, and its parts are named through
`NonNullable<…>` in emitted TS. A member it cannot find is `Foreign`.

A TS type named through re-exports (`export type { SurfaceRenderFn } from './types'` in a
module's index, an `import`/`export` pair, `export *`) is the declaration it names, so a
callback alias types a closure's parameters: with `presentSheet(render: SurfaceRenderFn)` and
`SurfaceRenderFn = (surface: SurfaceControls) => ReactNode`, `presentSheet { surface in …
surface.dismiss() }` reads `surface` as a `SurfaceControls`. TS's object types are structural:
one fits another when its fields do (a `PostUser` where a `ProfileCardData` is expected), a
`Foreign?` passes where TS takes an optional, and the embedded language's `ViewNode` and
`AnyView` are views. A Bloom view where TS takes a React element (`ReactNode`, `ReactElement`,
`JSX.Element`: a prop, an argument, what a TS callback returns, as `presentSheet { surface in
… }` does) crosses as one: the emitter writes `toElement(view)`. An optional one crosses branch
by branch (`footer: bare ? none : Text("foot")` is `bare ? undefined : toElement(…)`). A view given
to a prop of a TS component whose props Bloom cannot read (`ScreenProps extends ViewProps`) crosses
as an element too, as a React component's props take one; `import("./types.js").ScreenProps` in a
declaration names that module's type. A TS `view(function X(props: P) { … })` of the embedded
language is a node factory, a function from `P` to a view: `Badge(label: "a")` is
`Badge({ label: "a" })`, not a mounted component. An UpperCamel arrow in a `.tsx`
(`const List = (props: ListProps) => <… />`) is a component as a function declaration is, and so
is its `memo(List, eq)`.

TS declarations as libraries write them (react-native's): `export * as X from "…"` is a
namespace, `Foreign` (`StyleSheet.create({ … })`); a value and a type of one name (`declare const
Platform: PlatformType; declare type Platform = typeof Platform`) are both read, the value
typed, the type `Foreign`; a const whose type is, through aliases and `&`, a function from props
to a node is a component (`TextInput(value: v)`). As a type, such a component is its instance,
as a ref holds it (`@ref input: TextInput? = none`; read from its `ref` prop, else React's
`ComponentRef`), and `ref: input` passes a TS component the `@ref` itself.

An untyped `Foreign` is TS's `unknown`, and so is what a call, a member read or an index of one
gives (never `ReturnType<>`); TS refuses to use an `unknown`, so a value TS checks is typed
(`Foreign<"(value: string | undefined) => void">`).
An unannotated `.tsx` function is a component, unless what it returns is an embedded-language
`view()`'s node (or `null` beside one): that is a node factory, called as TS calls it.
A TS value given where a TS generic takes its type parameter (`mergeIdentity<T extends
IdentityHolder>(actor: T, …): T` called with a `Foreign` actor) makes `T` that value's type, so
the result is one too and its members are read as TS's.

### 4.8 Protocols

```swift
public protocol Titled {
  var id: String { get }
  var title: String { get }
  func badge(_ count: Int) -> String
}

extension Post: Titled {
  public var title: String { text }                   // `id` is a stored property already
  public func badge(_ count: Int) -> String { "\(title) (\(count))" }
}

func describe(_ item: any Titled) -> String { "\(item.id): \(item.title)" }
```

A protocol lists requirements: properties (`{ get }`, `{ get set }`) and `func` signatures.
A type conforms where it is declared (`struct Post: Titled`) or in an extension
(`extension Post: Titled { … }`); each requirement is met by a stored property, a computed
property or a method, and a missing one is B0231. Structs stay structural at runtime: a
conformance compiles to one witness object (`const Post$$Titled = { id: (self) => self.id,
title: Post$title, badge: Post$badge }`), exported with its type. The built-in protocols are
checked as such: `Identifiable` needs an `id`, `CaseIterable` an enum whose cases carry nothing
(and gives `T.allCases`, in order), `Equatable` and `Hashable` a type `==` compares.

`any P` is an existential, its witness passed with it, written explicitly: a `Post` passed where
`any Titled` is expected becomes `{ self: post, w: Post$$Titled }` (TS type `Titled`), and `item.title` reads
`item.w.title(item.self)`. A protocol written bare as a type (`Titled`) means `any Titled`.

Members and extensions (section 5) are statically dispatched: an instance member `m` of `T`
compiles to the function `T$m(self, …)`, a static one to `T$$m`, and inside a member a name of
one of `T`'s members that the body binds nowhere itself reads `self` (Swift's implicit `self`).
A view's `static let x = v` is the type's constant `T$$x` too: `Card.fallback` reads it anywhere,
and the view's own body reads it unqualified. A value type's `init` in an extension is
`T$$init$<labels>` (`Regex$$init$_`), called by its labels beside the memberwise one, its body
giving the value it makes; a class's `init` makes `self` (`T$$init`).

### 4.9 Classes and observable models

```swift
@Observable
public final class FeedModel {
  public private(set) var posts: [Post] = []
  public private(set) var isLoading = false
  private let api: MentionAPI

  public init(api: MentionAPI) { self.api = api }

  public func like(_ post: Post) async {
    guard let i = posts.firstIndex(where: { $0.id == post.id }) else { return }
    posts[i].isLiked = true      // rebuilds `posts` (value semantics) and writes it once
    posts[i].likes += 1
  }
}
```

A `class` is a reference type: a TS class with its stored properties as fields (a property
written without a type takes its literal's), `init` (lowered to `T$$init`, which makes `self`
and returns it; without one, `T()` is `new T()`), and members lowered as a struct's. A `let`
property is assigned only in `init` (B0403); a `private(set)` or `private` one only in the
class's own members (B0404). A write into a field's element or sub-field (`posts[i].likes += 1`,
also on a `var`'s list) rebuilds the path with fresh objects, so values stay values.

`@Observable` makes the class a store with field-level subscriptions and no proxies: writes go
through `$set(field, value)` (a write of the same value notifies nobody), and bloomc computes at
compile time which fields each view reads of each model it holds (as `@State`, a prop or a
`let`), including what the model's own members it calls read. The view subscribes to those
fields only (`useObserved(model, ["isLoading", "posts"])`) and draws again only when one of them
changes; a cache that reads the model as a whole (a member call) depends on the subscription's
version. A class compares by identity (`==` is `===`).

**A reference held by a view** (2.0, in place of 0.x's `@ref`) is a class in `@State`:
`@State private var ticks = Ticks()` makes the object once (`useState(() => new Ticks())`) and
keeps it across renders. Writing its fields (`ticks.count += 1`) changes the object in place and
draws nothing, so it costs what `useRef` does: one hook, no render. Assigning the state a new
object (`ticks = Ticks()`) draws again, as any `@State`. A host view's instance is
`@State private var field = ViewRef<ViewInstance>()`: `.ref(field)` (or `.inputRef(field)`, a
TS prop `ref: field`) gives the ref itself for the host view to fill, and `field` reads as
`ViewInstance?` outside the body (`none` until it is mounted). It compiles to
`useRef<ViewInstance | null>(null)`, as 0.x's `@ref field: ViewInstance? = none` did.
A class declared in another file of the module is imported with its `init` (`Box(0)` is
`Box$$init`), so a reference's class may live in its own file.

## 5. Values, functions and closures

```bloom
let x = 1                  // immutable
var total = 0              // local, mutable; a closure of its function may write it
fn double(x: Int) -> Int { x * 2 }       // the last expression is the result
async fn load(id: String) -> Result<Post, String> { … }
let inc = { n in n + 1 }                 // closure: (Int) -> Int from use
xs.map { p in p.title }                  // trailing closure
```

A `let` or `var` may shadow a parameter, a view's prop or an outer local, as in Swift (`let
isNested = isNested ?? false`): its initializer reads the outer one, and the new binding takes
a JS name of its own (`isNested$1`), since JS has one scope for a function's parameters and body
and `const x = x` reads the new `x` before it is set.

A list given where a node takes its rest children (`Text(runs)`, `RawText(parts)`) is spread
into them, as TS's `Text(...runs)`.

A rest parameter `..xs: [T]` comes last, has no default, and takes any number of `T`s after
the other positional arguments; in the body it is a `[T]`. A call spreads a list into a rest
parameter (Bloom's or a TS function's `...args`) with `..`: `total(1, ..xs)`,
`joinClasses("row", ..names)` compiles to `joinClasses("row", ...names)`. A spread where no rest
parameter takes it is B0207 (outside a construction, where `..s` spreads a struct). A view takes
props, never a rest parameter.

Named arguments: a Bloom function's parameters can be passed by name (`f(1, label: "x")`)
in any order after the positional ones.

**2.0 (`func`): argument labels.** A `func` parameter is called by its label, which is its name
unless written before it, and `_` drops it: `func move(_ p: Point, to target: Point, by step: Int = 1)`
is called `move(p, to: q)`. A positional argument where a label is due is B0207 ("missing
argument label `to:`", with the fix). A 0.x `fn` keeps positional calls. **Overloading by labels
(Swift's rule):** functions of one name in one file, free functions or one type's methods (static
or instance), may differ by their labels: `func describe(count: Int)` beside
`func describe(name: String)`, `func formatted(digits:)` beside `formatted(currency:)`. A call
takes the overload its labels fit (defaults may be left out; the one leaving out fewest wins); none
fitting, or two fitting equally, is B0207 with the overloads listed. Two with the same labels are
B0217 (overloads differ by labels, not by types), and so is an overloaded name read without a call
(B0202). Each overload is emitted named by its labels (`describe$0$count`,
`Double$formatted$0$digits`); a name declared once keeps its name. A directory module's files share
one namespace, so a function's overloads are declared in one file (B0807 otherwise). That is a
current limit, not the design: Swift takes a name's overloads from anywhere in its module. A closure without
`in` names its arguments `$0`, `$1`…: `points.map { $0.x }`, `reduce(0) { $0 + $1 }` (B0101
outside a closure). A string interpolates with `\(expr)`: `"at \(p.x)"` (0.x `${expr}` still
parses). Visibility is `public` (other modules), `internal` (unwritten: the module) and
`private` (the file), plus `private(set)` for who assigns; a `public` declaration that names an
`internal` or `private` type of its file is B0108. `import Bloom` and `import Mention.Posts` name
modules (resolved by the module graph). A file compiled on its own is its own module, so its
`internal` names are not exported; inside a directory module they are. **In a call to a TS function, named arguments form one
object passed last**: `t("key", defaultValue: "General")` is `t("key", { defaultValue: "General" })`.
react-i18next's `useTranslation()` (declared with a conditional type) is read as what it gives,
`{ t: (String, options?) -> String, i18n, ready: Bool }`: `t(…)` is a `String`.

## 6. Expressions and control flow

### 6.1 Precedence (high to low)

| Level | Operators | Assoc. |
|---|---|---|
| postfix | call, `.x`, `?.x`, `[i]`, `?`, `!` (no space before it) | left |
| prefix | `!` `-` `await` | right |
| multiplicative | `*` `/` `%` | left |
| additive | `+` `-` (`+` also joins `String`s) | left |
| range | `..<` `...` | none |
| comparison | `<` `<=` `>` `>=` | none |
| equality | `==` `!=` `===` `!==` | none |
| and | `&&` | left |
| or | `\|\|` | left |
| default | `??` | right |
| conditional | `c ? a : b` | right |

`if`/`else` and `match` are expressions; every branch has the same type (an `if` without
`else` in a builder yields an optional child).

### 6.2 Control flow and errors (2.0)

```bloom
switch load {
case .loading:
  ProgressView()
case let .failed(message):
  Text(message)
case .ready(let count) where count == 0:
  Text("empty")
case .ready(let count):
  Text("\(count) items")
}

guard let name = names.first else { return "nobody" }   // `name` is in scope after it

func check(code: Int) throws(APIError) -> Int {
  if code >= 500 { throw APIError.status(code: code) }
  code
}

do {
  let ok = try check(code: code)
} catch let error as APIError {
  …
}
let value = try? check(code: 1)                       // Int?: `none` when it throws
```

- `switch` replaces 0.x `match` (which still parses). Each `case` runs to the next one, with no
  fallthrough; `case .a, .b:` matches either, `case let .x(v)` and `.x(let v)` bind (a Bloom
  pattern's lowercase names bind either way), `where` adds a condition, `default:` matches the
  rest, and `break` is an empty case. Exhaustiveness is checked as for `match` (B0301).
- `guard cond else { … }` and `guard let x = optional else { … }`: the block must leave with
  `return`, `throw`, `break`, `continue`, a call that returns `Never` (`fatal(…)`, Swift's
  `fatalError`) or a `do` whose body and every `catch` leave (B0110), and what the condition binds
  is in scope after it. The same ends a path anywhere a value is expected: a function or closure
  whose last statement is one, or a `do`/`catch` whose body and catches each end with one, needs
  no value after it. It compiles to `if (!(cond)) { … }`.
- An `enum` may write Swift's `case` before its cases (`case loading, failed(Error)`).
- Errors are JS exceptions, free on the happy path: `throw e` is a JS `throw`; `try f()` is the
  call; `try? f()` is the value or `none` (an IIFE with `try`/`catch`, `async` under `await`);
  `do { } catch { }` is one JS `try`, where an unnamed catch binds `error` (an `Error`),
  `catch let e as T` types it, and catches with patterns (`catch .offline`) test it in order and
  rethrow what none matches. A `T` that says how to read one from any error (an extension's
  `static func cast(_ error: Error) -> T?`, as the standard library's `HTTPError` has) is tested:
  `catch let e as HTTPError { … e.response.status … }` runs for an `HTTPError` only (one
  `HTTPClient` threw, or a TS client's, as Axios throws it), and `error as? HTTPError` is the
  `HTTPError?` (Swift's conditional cast, at the comparisons' precedence). A cast to a string
  literal union tests membership: `raw as? Tab` (with `type Tab = "videos" | "following"`) is
  `raw` when it is one of `Tab`'s values and `none` otherwise (`raw === "videos" || raw ===
  "following" ? raw : undefined`, `raw` read once); its subject is a `String`, a `String?`,
  another literal union or a TS value. `raw as! Tab` is the `Tab` itself: a dev build traps
  when it is not one (`$cast(raw, [...])` throws a `TypeError`), and a release build is TS's
  plain `raw as Tab`, at no cost, as `x!` is. `as!` to anything else, and a cast of a
  non-string to a literal union, are B0213. `as?` to a type with no `cast` is B0213; an `Error`'s own members are `message` and `httpStatus`/`httpBody`. A function's last statement may be a `do` whose body and catches all return.
  A call of a function that `throws` is written under a `try` (`try f()`, `try await f()`,
  `try?`, `try!`; one `try` or `try!` covers the whole expression to its right: `try g(a) + h(b)`,
  `try ok() ? a() : b()`), or it is B0223. A `try?` covers its operand only, so `try? f() ?? x` is
  `(try? f()) ?? x`. A plain
  `try` is caught: in a function that `throws`, inside `do { … } catch`, or in a closure;
  elsewhere it is B0224 (write `try?`, or handle it). In a `func … throws(E)`, a `throw` outside a
  `do` throws an `E` (`throw .offline`). `Result` and 0.x `?` stay.
  **A function type keeps its effects** (Swift's): `(String) throws -> Int` and
  `() async throws -> T` are types of their own. A call of a value of a throwing type is a
  throwing call (`try f(s)`); a function that does not throw fits a throwing type, and one that
  throws where a non-throwing one is expected is B0201 (a TS callback may throw: JS has no checked
  errors). A closure whose `try` or `throw` nothing in it catches is throwing where a throwing
  type, or none, is expected (`let load = { try parse(s) }` is called `try load()`). The standard
  library's list methods rethrow: `try xs.map(parse)`. `Codec.decode` is
  `(JSONValue, String) throws -> T`, and `JSON.decode(_:from:)` throws.
- A thrown JS `Error` (a `TypeError`, a TS library's own) is the standard library's `JSError`:
  `error as? JSError` and `catch let e as JSError` give its `name`, `message` and `stack`
  (`String?`). Any thrown value is `error.jsValue`, a `JSONValue?` (`none` for `null` or
  `undefined`), read leniently where no type fits it: `value["key"]` is an object's own member and
  `value[i]` an array's element, each `none` when the value is not one or has nothing there (a
  JSON `null` too), and `.string`, `.number`, `.int`, `.bool`, `.array`, `.object` are the value
  as that type or `none`, so `error.jsValue?["response"]?["data"]?["error"]?.string ?? "Could
  not save"` never throws, whatever the server sent. Any other key is B0205.
- `a === b` / `a !== b` (Swift's identity) is whether two references are the same object: a class
  instance, a TS object or an `Error`, an optional of one too (JS's `===`). A struct, an enum, a
  number, a string or a collection is a value with no identity: B0210 (compare it with `==`).

An `if … else` or a `switch` on a line of its own is a statement, its branches' lines statements,
and so is the last one of a closure TS calls whose type is unknown (a handler, `.onPress { … }`): an
`if` is a value only where one is expected. `break` and `continue` are Swift's, emitted as JS's own: `continue` starts the innermost loop's
next turn, `break` leaves the innermost loop, and an unnamed `break` in a `switch` case leaves the
`switch` (a `break` last in a case, or alone, is an empty case). A loop may be named,
`outer: for row in grid { … }`, and `break outer` / `continue outer` leave or continue it from a
loop inside. Outside a loop (or `switch`), and inside a closure whose loop is outside it, either
is B0219, as is a name no loop around it has.

## 7. Views

### 6.3 Ranges

Swift's ranges: `a..<b` holds the `Int`s from `a` up to, not including, `b`; `a...b` includes `b`.
Both bounds are `Int`s (B0201 otherwise), and a range is a collection of them, typed `[Int]`: every
list method reads it (`(0..<n).filter { … }`, `.count`, `.contains(i)`). Ranges bind below `+`
and above the comparisons, so `0..<n + 1` is `0..<(n + 1)`, and they do not chain (B0101).
`bloom fmt` writes them with no spaces.

```bloom
for i in 0..<count { total += i }          // for (let i = 0; i < count; i++)
let squares = (0..<n).map { i in i * i }   // Array.from({ length: n }, ($_, i) => i * i)
let all = Array(1...n)                     // Array.from({ length: n }, ($_, i) => 1 + i)
HStack { for _ in 1...rating { Star() } }  // Array.from({ length: rating }, ($_) => …)
```

No range builds an array it does not return:

- a `for` statement over a range is a counting loop; its bound is read once, as Swift builds the
  range once (a literal or a `let` inline, anything else into a temp);
- `(0..<n).map { … }` and a builder's `for i in 0..<n` (or `for _ in a..<b`) are one
  `Array.from({ length })`, the array they return;
- `Array(r)` is the range's array, and `Array(xs)` / `Array(set)` copy a list's or a set's
  elements;
- a range read as any other value is its array, `Array.from({ length: b - a }, ($_, i) => a + i)`.

A reversed range (`5..<3`) traps when its array is built, as Swift's does (JS's `RangeError` for a
negative length); a `for` over one runs no times.

### 7.1 A view

```bloom
pub view PostRow(post: Post, compact: Bool = false) {
  «members: @state / @list / @record / @env / let / fn»
  body { «one View expression» }
}
```

- A `view` is a component: it compiles to `view(function PostRow(props) { … })` in the
  embedded language, one memoised fiber, the same as a hand-written `view()`. Parameters are its
  props.
- **`..Props` spreads a type's fields as props**: `view PostCard(..PostCardProps, dense: Bool =
  false)`. `..card: PostCardProps` also names their whole value, `card` (emitted `props`, a
  dependency of what reads it), to hand on as is: `summary(card: card)`. The type is a struct, a record type or a TS interface (B0204 otherwise); each field
  is a prop of its name and type, and one with a default (or a TS optional one) may be left
  out. Its props interface `extends` a TS interface and writes a struct's fields out; when the
  view's `XProps` name is the spread type's own, it is `XViewProps`, and with only spreads the
  props are the type itself.
- **`..r` among a call's props** spreads a struct's or record's fields as props, JSX's
  `{...r}`: `W(..p)`, `W(..q, b: 2)` (a later prop of the same name wins). Each field a prop
  takes is checked against it, and the record may have more. On a TS component it is `{ ...r }`,
  which tsc checks.
- **`equal(old, new) { <Bool> }`** is a view member: whether two props are equal for the view,
  compiled to `memo`'s comparator (`view(function X(props) { … }, (old, new_) => …)`); `true`
  skips the render. `old` and `new` are the view's props record as passed, so a prop with a
  default is optional there. It reads only them and module names (it runs outside any render).
  A view has one (B0435), and a screen, a layout or a view without props none.
- A view called with arguments that are all static (literals, module values) is a static
  chain like a node's: built once, at module scope.
- A `fn … -> View`, at module level or as a view member, is **inlined UI**: a plain call, no
  fiber, no state; prefer it for repeated rows inside one view.
- `screen Name { … }` is a view that is the file's default export and an Expo Router route
  (`screen()` from `@oxy.so/bloom-language/router`); `layout Name { … }` the same for `layout()`.
- `pub` exports; `pub default` makes it the default export.

### 7.1a A view, the 2.0 way

```bloom
public struct PostRow: View, Equatable {
  let post: Post                       // a prop
  var dense: Bool = false              // a prop with a default
  let onLike: () -> Void
  @Binding var isOn: Bool              // a prop holding a `Binding<Bool>`
  @State private var draft = ""        // a state: `useState`
  @Environment(\.locale) private var locale
  let title = "Compose"                // a constant, per render

  func send() { draft = "" }           // a member

  var body: some View {
    HStack { Text(post.text) }
      .onAppear { … }                  // once, after the first render
      .onDisappear { … }               // its cleanup
  }

  static func == (a: Self, b: Self) -> Bool { a.post == b.post }   // the memo comparator
}
```

A `struct` that conforms to `View` (or `Screen`, `Layout`) compiles to the same memoised `view()`
fiber as 0.x `view X(…)`: its stored `let`s, and `var`s with a default, are the props; `@State`,
`@Environment(\.key)` and `func` members are 0.x's `@state`, `@env` and `fn` members; `var body`
is the body; `static func ==` is the memo comparator (0.x `equal(old, new)`); and `.onAppear` /
`.onDisappear` at the end of the body are an effect with no dependencies and its cleanup.
`.task`, `.task(id:)` and `.onChange(of:) { old, new in }` stay node modifiers (section 8).
React's `useMemo`/`useCallback` written as a member (`let f = useCallback({ … }, [deps])`), or as
a hook function's top-level `let` (section 7.3), is a plain member, memoised in the view's (or the
hook function's) cache on its exact dependencies, with no hook slot; the written dependencies are
not read.
A prop's default is written on it (`var isNested: Bool = false`, emitted `const { isNested =
false } = props`, TS's own default); a member of a stored property's name (`let isNested =
isNested ?? false`) declares it twice and is B0217.
A menu's actions and content conform to `MenuActions` and `MenuContent`, as a view conforms to
`View`. Their stored `let`s are the props, their members may call hooks, and `body` is the result.
`struct PostMenuActions: MenuActions { let post: Post; let router = useRouter(); var body: [String:
() -> Unit] { ["open": { router.push("/p/\\(post.id)") }] } }` is the embedded language's
`actions(function PostMenuActions(props) { … })`: the tag → action table a chosen row runs, given
as `Menu(…) { Item("Open").tag("open") }.actions(PostMenuActions(post: post))`. A `struct PostMenu:
MenuContent` is `menu(function PostMenu(props) { … })`: its `body` is the rows (builder lines), built
only while the menu is open, given as a `Menu`'s child. Neither has a memo cache or a fiber of its
own, and neither takes a view's modifiers (B0501).
A `struct X: Screen` (or `Layout`) is the file's default export only in a route, a file under the
app's router folder (`app/`), as Expo Router takes it; anywhere else it is its named export, so a
route that renders it imports it by name (`import { WelcomeScreen }`).
A data `struct` takes Swift's members too (`public let id: String`, `public var likes: Int`):
they are its fields (one whose default is `none` is optional in the emitted TS, `readonly
boosts?: number`, so a TS caller may leave it out; any other default stays required, since
Bloom's own construction writes it); its methods, computed properties and `static` members, and an `enum`'s,
are statically dispatched functions (section 4.8). A `@Binding var isOn: Bool` is read as a
`Bool` (`isOn`, compiled `isOn[0]`), assigned as one (`isOn = false`, compiled `isOn[1](false)`),
and passed on as the binding with `$isOn`. `@Environment(\.k)` reads the built-in value `k` (`disabled`, `controlSize`, `buttonStyle`) or the
environment key named `k` that the file declares or imports, typed by the key's default: an app
declares one at module level as `public let session = EnvironmentKey("session", default: Session.signedOut)`. A call takes more trailing closures
after the first, each labelled on the same line (`Button { … } label: { … }`, Swift's form); they
are labelled arguments. `Task { … }` starts async work without awaiting it (0.x `task { … }`). A closure passed where a
`() -> View` is expected and written over several lines is a builder (Swift's `@ViewBuilder`):
each line, `if` and `for` a child, compiled to the list of them, which the stack it lands in
flattens (`let rows: () -> View` called as `rows()` in a `VStack`).
A view's stored `View` or `View?` (`var children: View? = none`, `let content: View`) takes the
trailing builder when no function parameter does, as Swift's `@ViewBuilder let content: Content`
does: `Card(title: "Hi") { Text("inside") }` passes the builder's lines as the prop's value (one
child, or the list of them), built in the caller's render, not a closure. The last such
property not given by label takes it.
A view is generic as a function is (section 4.6): `struct ProfileGridList<T: ProfileGridEntry>:
View { let data: [T]; let renderCell: (T, Double) -> View; … }`, or `where T: P`. It is still
one `view()` fiber with the same hooks: its body is the generic function `function
ProfileGridList<T extends ProfileGridEntry>(props: ProfileGridListProps<T>)`, the factory is cast
back to `<T extends ProfileGridEntry>(props: ProfileGridListProps<T>) => ComposedView` (a type
only), and the `.d.bloom.ts` declares the same, so a TS caller infers `T` too. A shape bound costs
nothing at runtime. A protocol bound (`<T: Titled>`) passes its witness as a prop
(`$w_T_Titled: Post$$Titled`, filled by the call site, a module constant, so it never breaks the
memo); a member function or closure hoisted out of a generic view declares the view's type
parameters itself.
A view holding an `@Observable` model subscribes to
the fields it reads (section 4.9). Phase A does not compile yet: computed properties of a view
other than `body`, and `Button`'s trailing action (its label is the trailing block, as in 0.x).

### 7.2 Builders, modifiers and tokens

- A trailing closure passed to a parameter of type `Children` is a **builder**: each line is a
  child (`View`, `View?` or `[View]`); `if`/`else`, `match` and `for … in` lines build
  conditional and repeated children; `let` lines bind locals. `VStack { a; b }` is
  `VStack(a, b)`. A conditional keeps its slot (structural identity, as SwiftUI does). A
  `[View]` line that is a builder's last fills the rest parameter as its items, as a last `for`
  does (`HStack { title; rows }` is `HStack(title, ...rows)`: siblings, no wrapper); elsewhere
  it is one child, a list. A `[View]` is a child wherever one goes: a conditional's branch
  (`loading ? Text("…") : names.map(row)`), a node's children argument, and `Embed`'s value,
  which takes a React node (`toElement(…)`). So is a list of TS values (`Menu { glyph; rows }`
  with `rows` from a TS function: TS checks its items where they land), an optional list (`c ?
  rows : none`, one child, never spread), and a list literal line (`[row, c ? sheet : none]`,
  its items `View?`).
- **Modifiers are methods on `View`**, typed from `spec/language.json`: each node accepts its
  own modifiers plus the universal ones (B0501 otherwise, with the closest name). Order is
  nesting, as in the embedded language. A modifier that takes a view takes a `View?` too
  (`.trailing(active ? Icon(i) : none)`): an absent one draws nothing. A token modifier whose
  TS value takes `undefined` (`spec/language.json`'s `noneModifiers`, read from `Node`'s
  methods) takes `none` and a token optional too (`.tint(support ? "success" : none)`), which
  leaves it unapplied; any other is B0502 for a `none`.
- **`.id(x)` is on every node** (2.0, 0.x's `key=`), the ones that chain no universal
  modifiers too (`GroupedSectionItem(id).id(id)`), a view and a TS component as well: in a
  `for`, it is the repeated child's identity (`x` a `String` or a number).
- **Icons by name (BloomUI, 2.0):** `Icon(.close)` (and the first argument of `IconCircle`,
  `GroupedSectionIcon` and the action bar's `Action(.close, "Close")`) names a glyph of Bloom's icon set; the
  compiler imports its component (`RiCloseLine` from `@oxy.so/bloom/icons/RiCloseLine`). A file
  that also imports that component itself, from that path, keeps its one import: the two are the
  same glyph, not two declarations.
- **Tokens are string literals checked against the token set** the modifier takes:
  `.padding("md")`, `.background("primary/10")`. A wrong token is B0502 with the valid set.
  A token in a variable has the token set's type (`let gap: Space = compact ? "sm" : "md"`);
  with nothing expected, a conditional of string literals is their literal union (`let side =
  card ? "96" : "48"`, as TS's `const` infers) and a literal beside a literal union joins it
  (`c ? "md" : gutter`), so either fits a token set. A module constant's record literal written
  without a type keeps its string literals' types (`let SIDES = { small: "fit", large: "full" }`
  is `{ small: "fit", large: "full" }`, emitted `as const`), so `SIDES[size]` fits a token set.
  A module constant's list of string literals is a list of their union (`let TABS = ["videos",
  "following"]` is `["videos" | "following"]`, emitted `as const`, frozen inside in a dev
  build), so `for tab in TABS` gives a `"videos" | "following"`, as TS's `as const` tab lists.
  With nothing expected, `c ? s : opt?.x` is the optional of `s`'s type: an optional chain may be
  `none`, as a branch written `none` is. `defineModifier { v in … }` reads `v` as a
  `View` (TS's `V extends ViewModifiers<V>`); the recipe is a value (`.modifier(look ?? card)`).
- **Events take closures**: `.onPress { saving = true }`; an `async` closure
  (`.onPress { await save() }`) runs as a task (section 8).
- **Inputs take bindings**: `TextField($draft)`, `Toggle($prefs.likes)`. `$x` projects
  `@state x`; `$x.field` projects a field (writes `x.with(field: v)`). A closure pair is
  `Binding(get: v, set: { v in … })`.
- **TS React components are nodes**: an imported component `OxyAuthPrompt` is called with its
  props as named arguments, `OxyAuthPrompt(label: t("x"), description: t("y"))`, and a
  trailing builder as `children`. A TS function is a component when it is UpperCamel, takes at
  most its props and returns a React element (`JSX.Element`, `ReactElement`, `ReactNode`, also as
  emitted declarations write them: `import("react").JSX.Element`), and so is a `const` typed
  `typeof` one (react-native's `View`) and a namespace's member (`import * as Skeleton`,
  `Skeleton.Region { … }`) or a component's UpperCamel static (`Button.Group { … }`):
  `EngagementBar(size: "md") {
  Action(…) }` draws the bar with the actions inside, built in the caller's render. A component
  whose props declare no `children` passes the builder to the one node prop (`ReactNode`, a
  `View`) it declares and the call does not give (`Slot(title:) { … }` is its `content`); with
  none, or several, the builder is B0506, and `children:` given beside a builder is B0207. One
  line of text is the component's text children (`TextFieldLabel { label }`, JSX's
  `<TextFieldLabel>{label}</TextFieldLabel>`); a builder line is otherwise a view. A
  builder's nodes are never dropped: a trailing closure past a TS function's parameters is B0207,
  and a node on a line of its own in a closure or function that is not a builder (`func f() {
  Text("x") }`) is B0506 (built and never drawn).

- A token parameter whose TypeScript type also takes a boolean takes a `Bool` (or an optional
  one): `.allowsHitTesting(false)` (`HitTesting`), `.when(on) { … }` (`Condition | boolean`),
  `.accessibilityState(checked: on)` (`boolean | "mixed"`). A modifier's closure whose
  parameter has no Bloom type stays where it is passed, so TS types it from there.
- A modifier's parameter that TypeScript lets be `undefined` takes `none` and any optional
  (`.onEndReached(more ? load : none, 0.5)`, `.footerContent(none)`); a parameter marked `?`
  in its signature may be left out. `c ? a : none` is `A?` wherever it is written, so the
  `none` branch is never held to the other's type.

#### Typed tokens (2.0)

A token is written by its Swift name, an implicit member of the parameter's token set:
`.padding(.md)`, `.spacing(.xxl)`, `.font(.caption1)`, `.foreground(.muted)`, and a colour role at an
opacity `.foreground(.primary.opacity(0.1))`. Each compiles to today's token string (`"md"`, `"2xl"`,
`"caption-1"`, `"muted"`, `"primary/10"`), so the cost is the string literal's. The names come from
a table GENERATED over `spec/language.json`'s token sets
(`packages/bloom-language-compiler/scripts/generate-swift-tokens.mjs`, output
`crates/lang/src/swift_tokens.generated.rs`, checked by the package's `test`): `Nxl`/`Nxs` become
N `x`s (`2xl` → `.xxl`), kebab-case becomes camelCase (`caption-1` → `.caption1`,
`top-leading` → `.topLeading`), and a token with no Swift name (a number, a CSS value) stays a
number or a string. SwiftUI's own names of a set's tokens are aliases in the table (alignment:
`.top`/`.leading` are `start`, `.bottom`/`.trailing` `end`, `.firstTextBaseline` `baseline`), and a
condition may choose between two tokens (`.tint(isLiked ? .danger : .neutral)`). A name not in the
set is B0502 with the closest name; an opacity not on the scale is B0502. The string tokens still compile. SwiftUI's modifier names (`.foregroundStyle`,
`.background(_:)` as a style) are BloomUI's, phase B.

### 7.2b View modifiers

`struct X: ViewModifier` (SwiftUI's) is a reusable wrapper: its stored properties are its
props, it may keep `@State`, read `@Environment` and call hooks in `let` members as a view does,
and `func body(content: Content) -> some View` draws it around `content`, the view it is applied
to. `view.modifier(X(…))` applies it:

```swift
struct SupervisedGate: ViewModifier {
  var allowSupervised = false
  let state = useSupervisionState()
  func body(content: Content) -> some View {
    if !state.ready { DetailSkeleton().header(false) }
    else if state.supervised && !allowSupervised { LockedState().header(false) }
    else { content }
  }
}

FeedsList().title("Feeds").modifier(SupervisedGate())
```

- Its result is the view's place in the tree. On a screen's root it is the root, so the screen's
  chrome is the drawn view's: `content` keeps its `.title`/`.toolbar`/`.header`, and a state
  drawn instead declares its own (`.header(false)` hides the header and its toolbar).
- A modifier with no member but `func`s (and no `.task`/`.onChange` on its body) keeps no
  state: it is called where it is applied (`X({ … })(view)`), rows included.
- One that keeps state is called once per render at the top of the view applying it (`const
  $mod0 = X({ … })`, before the body), so its state and hooks are that view's. It is applied in
  the view's `body` itself (an `if` branch is fine), not in a closure, a `for` row or a member,
  and its arguments read only names declared before the body (props, state, members): B0422.
- `X(…)` anywhere but `.modifier(X(…))` is B0421: a modifier is not a view.
- TS sees `function X(props): (content: ComposedView) => Child`. The native backends emit a
  Swift `ViewModifier` and a Kotlin `@Composable` wrapper.

### 7.3 Reactivity (compile-time)

| Declaration | Meaning | Compiles to |
|---|---|---|
| `@state x = e` | local state | `useState(e)` (lazy `() => e` when `e` is not a constant) |
| `@list feed = src` | a bloom-data list | `useList(src)` |
| `@record post = Post.record(id)` | a bloom-data record, field-level subscribed | `useRecord(Post, id)` |
| `@env scheme = Env.colorScheme` | an environment value | `useEnvironment(key)` |
| `let v = expr` (member) | derived value | inlined if trivial, else memoised on its dependencies |
| `let x = useThing()` | a TS hook (a `use[A-Z]` import) | the call, at the top, unconditionally |
| `fn f() {}` (member) | handler | a closure memoised on what it reads; hoisted to module scope when it reads nothing reactive |

**The dependency graph is known at compile time.** Every member's reads are resolved by the
checker: state, props, hook results and other members. The emitter then writes the memo cache
itself (`react/compiler-runtime`'s `c(n)`, the slot array the React Compiler uses) with exact
dependencies, and marks the body `"use no memo"` so the React Compiler skips it. Because values
are immutable, a dependency is the value itself (no mutation analysis, no proxies, no
subscriptions at runtime). A narrowed name (`sliceKey` inside `if sliceKey != none`, `x` inside
`if x is T`) is the value it narrows, so a child that reads it depends on it. Static subtrees are hoisted to module scope by the existing language
compiler pass, which runs on bloomc's output in the same process.

The cache is kept small. Members written one after another on the same dependencies share one
test (`let label = t("a")`, `let show = t("b")` and `let hide = t("c")` are one `if ($[0] !== t)`
with three value slots, not three tests). A child view is cached on its own when it reads less
than its parent, except a leaf (a node and its modifiers, with no child view, closure or call
among its arguments) that reads its one dependency once (`RawText(hide).font("sm")`): building it
costs about what its test does, so it is built with its parent and takes no slots.

**Writes.** Assigning a state member in a closure is `setX(v)`; when the right side reads the
state (`count += 1`, `count = count + 1`) it is the functional update `setX(count => count + 1)`.
Reading a state member after assigning it in the same closure is B0410 (it would read the
render's value); bind the new value to a `let` first. Hook calls are only allowed as view
members and at the top level of a hook function (B0420), so the rules of hooks hold by
construction. A hook given directly as an argument of such a call is one too
(`let account = useProfileAccount(useRoutedProfileUsername())`): it runs on every render, in the
same order. One in a branch (`c ? useA() : useB()`) or on the right of `&&`, `||` or `??` runs on
only some renders, and is B0420 even as a view member's value. A **hook function** is a `fn` named `use[A-Z]…`: its top-level `let`s and its
result may call hooks (not a branch, a loop or a closure), and calling it is calling a hook. A
`.bloom` module of `pub fn useX(…)` is a module of hooks. A hook function's state is
`@State var x = v` at the top of its body (2.0), as a view's `@State` is: one `useState`, read as
`x`, written as `x = …` (or `x += 1`) in its closures, never in its body itself (B0401), and `$x`
its binding; the setter is never a value of its own. Anywhere else (a branch, a loop, a closure,
a function that is not a hook) it is B0420. A hook function written without
`-> T` has the type of its last line (nothing when that is not a value). Its top-level `let`s are
memoised in one cache on their exact dependencies, as a view's members are (its parameters, and
what it binds, are what changes between calls); a `let` that calls a hook, a cheap read (a name,
a field, a short string), a class instance and a value a later statement writes in place
(`m.set(k, v)`) stay plain. So React's `useMemo`/`useCallback` there are plain `let`s too, with no
hook slot, and the function holds no hook of its own for them.

**Refs.** `@ref x = v` keeps a value across renders without causing one (`useRef`). It is read
and written as `x` (emitted `x.current`; Bloom code never writes `.current`), in handlers,
effects and tasks: reading or writing it while the view draws is B0411, since the body would
not follow it. `.ref(x)` passes the ref itself for a host view to fill; such a ref (`@ref field:
ViewInstance? = none`) holds `null` in JS when empty and reads as `none`. So do `.inputRef(x)`,
a TS parameter typed as a ref (`RefObject<…>`, `Ref<…>`), and, while the view draws, a TS
argument of a type Bloom does not read (`useVisible(target: card)`; tsc checks it). A ref is
never a memo dependency.

### 7.4 Environment

`@env x = key` reads a value set above with `.environment(key, value)`. Keys are made with
`defineEnvironment` (embedded language) and imported. Text traits (`foreground`, `font`, …)
inherit as in the embedded language.

## 8. Effects, tasks and concurrency

**Sync throws.** `catching { … }` runs its block and gives `Result<T, Error>`: the last line's
value is `.ok`, and what TS code in it throws synchronously (`URL(link)`, `JSON.parse(s)`) is
`.err`. It is emitted as an inline `try`/`catch`, with no helper; the block cannot `return`, and
`?` in it ends at it (`let r = (await fetch(url))?` inside: a rejection is `.err`).

**`fail(e: Error) -> Never`** throws `e`. It is allowed where a throw has a catcher: in a
closure TS calls (a TS parameter's function, sync or async, or one of no Bloom type), where a
thrown error is how TS hears of a failure (`mutationFn: { v in if v.isEmpty { fail(Error("Empty")) } … }`,
a rejected promise; a sync TS callback's throw), and in `catching { … }`'s block, which gives
it as `.err`. As a statement or a block's last line it is `throw e;`; where a value is needed
(`c ? x : fail(e)`), an inline throw. Anywhere else a failure is a value: `fail` is B0222,
whose fix is to return `err(e)` from a function that returns a `Result`. `?` on a `Result`
in those closures throws the same way (4.5).

- `async fn` / `await`. Awaiting a Bloom async function yields its result. **A TS function that
  returns a promise has the Bloom type `(A) -> Promise<T>`, and awaiting a `Promise<T>` yields
  `Result<T, Error>`**, because a JS promise can reject; `await f()?` propagates (`await` binds tighter than `?`, as Rust's `.await?`). A synchronous
  TS throw is a panic (a bug), as in Rust. A Bloom `async` function (or closure) never rejects,
  so it is TS's `(A) => Promise<T>` where TS takes one (`onRefresh: reload`); a closure that
  awaits, given for one, has `T` as its result.
- **An async call is awaited or spawned, never dropped**: calling an async function or a
  promise-returning TS function without `await` is B0430, except as `task { await save(v) }`,
  which spawns it (fire and forget, completing like a handler) and is `Unit`. A binding setter
  that saves is `Binding(get: prefs.likes, set: { v in task { await save(.likes, v) } })`.
- `defer { … }` runs when the enclosing block exits, after an early `return` too (compiled to
  `try`/`finally`); the place for "`saving = false` whatever happened". At the top of a
  `.task { … }` it also runs when the task is cancelled (the view unmounts or its `id:`
  changes), at once rather than at the next `await`, and then not again.
- **`effect { … }`** is a view member: synchronous work that runs after a render. Its
  dependencies are inferred from its reads, exactly as the memo scopes' are (no deps array);
  `effect(id: x) { … }` re-runs for `x` instead; a tuple `id: (a, b)` is its values, each a
  dependency (`[a, b]`, never a fresh array per render), for `.task(id:)` too. It writes states as a handler does. A `defer`
  at the top of its body is its cleanup, run before the next run and on unmount (several run
  last first); a `defer` in a nested block keeps its block meaning. Once a cleanup is set the
  effect does not `return` (B0434): return before the `defer`. It does not `await` (B0215):
  start async work with `task { … }`, or use `.task`. It compiles to exactly one `useEffect`.
- **`.task { … }` on a view's body** starts when the view appears and is cancelled when it
  disappears. `.task(id: value) { … }` restarts when `value` changes. Inside, `Task.signal` is the
  `AbortSignal` to hand to `fetch`/bloom-data, and after every `await` a cancelled task stops. A
  Bloom call in it that takes `cancellation: TaskSignal?` and is given none takes `Task.signal`
  (`sleep(for:)`, `HTTPClient`'s calls), as Swift's child work is cancelled with its task.
  `await Task.cancellation` returns once the task is cancelled: a top-level `defer` before it
  runs exactly then (the id changes, the view leaves), as a React effect's cleanup does
  (`let s = start(); defer { stop(s) }; await Task.cancellation`). Without it, the `defer` runs
  when the body returns, as any `defer` does.
  Compiles to one `useEffect` with an `AbortController` (what a careful hand-written effect does).
- **`.onChange(of: value) { old, new in … }`** runs after a change (one `useEffect`, comparing in a
  ref only when `old` is used).
- **Handlers' async closures complete**: a user action (a save, a like) is not cancelled by
  navigating away; the state writes after unmount are no-ops.
- **Structured concurrency:** `let (a, b) = await all(loadA(), loadB())` (both or the first error);
  `await race(…)`; `sleep(ms)`. A task's children are cancelled with it.
- **`async let x = f()`** (2.0) starts the async call `f()` where it is declared, and `await x`
  reads its result; `try await (a, b)` reads several together (`Promise.all`). A throwing call
  is written without `try` in the declaration, and its error surfaces at `try await x`. Only in
  an async function (B0215); `x` is read only with `await` (B0227), and it is awaited before its
  block ends (B0227: an unread result would drop its error). Compiled to `const x = f();`, the
  promise marked handled until it is awaited.
- **`actor Name { … }`** (2.0) is a class whose instance methods run one at a time, in call
  order: each method `m` is `async` from outside (a call is `await counter.increment()`) and
  runs through the actor's queue (`actorIsolated`, the standard library's Concurrency), an
  `async` one holding it until its end. The actor's own members call each other directly
  (`m$isolated`), so a call from inside never waits on itself. Unlike Swift's, an actor is not
  re-entrant at its `await`s.

## 10. Modules and interop

- **A file is a module**; items are private unless `pub`. Module-level `let` must be a constant
  expression (no calls with effects), so there is no global mutable state; shared state lives in
  bloom-data entities, lists and models, which are explicit stores.
- **Prelude** (always in scope): the core types, `ok`/`err`/`none`, `all`/`race`/`sleep`, every
  node of `spec/language.json` (`VStack`, `Text`, `Button`, …) with its modifiers, `Embed`,
  `toast`, `navigate`.
- **BloomUI's own types and recipes (2.0):** a package file names `ViewModifier`,
  `IconComponent`, `defineModifier` and `defineTokens` without importing
  `@oxy.so/bloom-language` (the types are imported `type`). A file that still imports one of
  them (the migration mode) keeps its import, and a name a file imports itself is never
  imported a second time. A class's `init` (`Box(0)`, `Box$$init`) is imported with the class.
- **Bloom modules:** `import { PostRow } from "./PostRow.bloom"`.
- **Platform files (2.0):** in a directory module, `X.native.bloom`, `X.ios.bloom`,
  `X.android.bloom` and `X.web.bloom` (and `X.bloom` beside them) are alternatives, one compiled
  per platform as Metro picks them, not siblings: they declare the same names without B0807. The
  module's other files import them by the base name (`./X`), which the checker reads from the
  first of `native`, `ios`, `android`, `web` that exists.
- **File scope (2.0):** a directory module's files share one namespace, so two `internal` or
  `public` declarations of one name are B0807. A `private` declaration is its file's only, as
  TS's file scope is: it may share a sibling's name, which it shadows inside its own file (the
  sibling's is not imported there), and every other file of the module reads the sibling's.
  `bloom migrate` writes a TS file's non-exported declarations `private`.
- **Bloom standard modules:** `import { … } from "bloom/data"` (bloom-data),
  `"bloom/router"`, `"bloom/motion"`; they compile to the matching `@oxy.so/*` import.
- **TS/npm modules:** `import { useAuth } from "@oxy.so/services/ui/client"`; typed from its
  `.d.ts` (4.7); a module that writes `export = N` (`@types/react`) exports namespace `N`'s
  members (`import { type ComponentType, lazy, memo } from "react"`).
  `let Panel = lazy { import("./Panel") }` (React's `lazy`, imported) is a component whose props
  TS checks; `import("…")` is a dynamic import, emitted as written. A `use[A-Z]` function is a hook (7.3). An import is a **component** (a node,
  7.2) when its type is a React component type (`ComponentType`, `FC`, `ComponentClass`, the
  exotic ones: `MemoExoticComponent`, `ForwardRefExoticComponent`, `LazyExoticComponent`,
  `NamedExoticComponent`; a wrapped component gives its props), a function of one props object
  returning an element, `memo(Inner)` or `memo(function Inner(props: P) { … })` (`Inner`'s
  props), or an `UpperCamel` class (`extends Component<P>` gives `P`; any other's
  props are TS's to check), or, when it is `Foreign`, when its name is `UpperCamel` and it is
  used as a node. A TS object type with call signatures beside members (zustand's store hook,
  `{ (): S; <U>(selector: (state: S) => U): U; getState(): S }`) is callable by each signature,
  as a Swift value with `callAsFunction` overloads is: a call takes the first signature its
  arguments fit by count, a generic one instantiated (`useStore { s in s.items }` is the
  selector's `[Item]`), and the members stay members (`useStore.getState()`). One with only a
  call signature (`ToastFn`), a construct signature or an index signature
  (`[key: string]: unknown`) is `Foreign`: callable, and taking any keys, checked by TS.
- **Resolution:** relative paths; the project's `tsconfig.json` `compilerOptions.paths` (`@/*`);
  packages through `node_modules` and their `exports` (`types`, then `react-native`, `import`).
  An explicit import shadows a prelude name. A module is never both `X.tsx` and `X.bloom`
  (B0610): an extensionless import must mean one file.
- **TS importing Bloom:** bloomc writes `Name.d.bloom.ts` beside `Name.bloom` (TS's
  `allowArbitraryExtensions`), so `import { Composer } from "./Composer.bloom"` type-checks in TS;
  `bloom-lang-dts --root . <dirs>` writes them beside the sources (`bloomc build --out` writes
  them into its out directory). A `view` is a node factory, as in the embedded language: TSX draws it with
  `toElement(Composer({ maxLength: 280 }))`, not `<Composer />`; inside the embedded language it
  is a node like any other. A module constant that names a view (`public let PostItem =
  PostItemContent`, TS's `memo(PostItemContent, eq)`) is declared as that view, `typeof
  PostItemContent`, and a private view it names is declared beside it, unexported. A view's
  `T?` prop and a function's `T?` parameter are declared `T | undefined | null`: TS's `null`
  is `none` to Bloom, so a TS caller may pass either.
- **Gradual:** a `.bloom` file and a `.tsx` file import each other freely, one file at a time.

## 11. What bloomc emits

For each `.bloom` file bloomc emits typed TypeScript, then runs the embedded-language pass
(hoisting static chains) on it in the same process, then hands it to the host transformer
(Metro/Babel/Noxcturnal, babel-jest, Vite). A source map composes all three back to `.bloom`.
A file's output can depend on the declarations of what it imports (named arguments, whether a
callee is a view); `bloomc build`'s cache follows imports, while Metro's and Jest's per-file
caches do not yet (phase 1: the adapters' cache keys include the imports' declarations).

```ts
// view Counter { @state n = 0; body { Button(Text("${n}")).onPress { n += 1 } } }
import { c as _c } from "react/compiler-runtime";
import { useState } from "react";
import { Button, Text, view } from "@oxy.so/bloom-language";
export const Counter = view(function Counter() {
  "use no memo";
  const $ = _c(3);
  const [n, setN] = useState(0);
  let t0;
  if ($[0] !== n) {
    t0 = Button(Text(`${n}`)).onPress(() => setN((n) => n + 1));
    $[0] = n;
    $[1] = t0;
  } else t0 = $[1];
  return t0;
});
```

Zero-cost rules the emitter keeps (each is gated, see the ADR):

1. Struct construction and `with` are object literals; fieldless enums are strings; `T?` is
   `undefined`; `?`/`??`/`?.` are inline conditionals. No wrapper objects, no runtime library
   calls for language features.
2. One fiber per `view`, none per `fn -> View`. Hooks only for `@state`/`@list`/`@record`/`@env`,
   imported hooks, `.task`/`.onChange`, and one memo cache when anything is memoised.
3. Closures that read nothing reactive are module-scope constants.
4. `"use no memo"` on every emitted view body; bloomc owns the memoisation.

statement and closing-brace boundaries, so one typo reports one error.

## 14. Formatting

`bloomc fmt` is the only style (no options): 2-space indent, 100 columns, one modifier per line
once a chain does not fit on one line, trailing commas in multi-line argument lists,
members ordered as written, blank lines kept (at most one), imports sorted by path, struct fields
and enum variants one per line. A block with one statement stays on one line when it fits (a
view's `body` never does); an `if`/`else` chain is on one line together or breaks together; a
builder line's chain breaks one modifier per line once its builder spans lines; a chain inside an
expression breaks only with two or more calls. A binary expression breaks after its operator, but
before `<` and `>` (a line ending in `>` may close a type's arguments; one ending in `<` goes on).
Formatting is idempotent and preserves comments.

### 14.1 `bloomc migrate --from 0.x` (2.0)

`bloomc migrate --from 0.x [--check] <paths…>` rewrites 0.x files in 2.0's forms, mechanically:
`fn` → `func` (a parameter a call in the file labels keeps its label, the others become `_ name`,
and a positional argument to a labelled one gets the label), `pub` → `public` (and the file's
types a `public` declaration names become `public`), `${x}` → `\(x)`, `match … =>` → `switch …:`,
enum cases → `case`, struct fields → `let` / `var` (a field with a default), and
`view X(p: T) { @state s = v; body { … } }` → `struct X: View { let p: T; @State private var s = v;
var body: some View { … } }` (`@env` → `@Environment(…)`, `equal(a, b)` → `static func ==`). What
2.0 cannot say mechanically stays 0.x, with a note: a view with `..Props`, an `effect`, an `@ref`,
`@list` or `@record`. The output is formatted and re-parsed (never written when it does not parse).
Its test (`crates/fmt/tests/migrate.rs`) migrates every 0.x emit fixture, Mention's Notifications
screen among them, and requires the same TypeScript (exports aside); the migrated Notifications is
itself a golden (`emit/surface_mention_notifications.bloom`). The `bloom` CLI exposes it as
`bloom migrate`. The 0.x forms keep parsing for it, each with one warning per file (B0950, at its
first use, with how often the file uses it): `fn`, `pub`, `${…}`, `match`, `view`/`screen`/`layout`,
the `effect` member, `@ref`, `equal(old, new)` and `..Props`.

## 15. Cheat sheet for agents

1. A file is a module. `pub view Name(params) { members; body { … } }`; a route is `screen`.
2. UI is a builder: one child per line; `if`, `for`, `match` build children; modifiers chain with
   `.name(…)` on the next line; order is nesting.
3. Every style value is a token string: `.padding("md")`, `.foreground("muted")`.
4. State is `@state x = v`; write it with `x = …` in a closure; inputs take `$x`.
5. Derived values are `let` members; handlers are `fn` members or closures. Never memoise by hand.
6. No null: `T?`, `none`, `??`, `?.`, `if let`. No exceptions: `Result`, `?`, `match`.
7. `match` arms start with `case`; an enum case at the start of a line is `Type.case`.
8. Awaiting a TS promise gives `Result<T, Error>`.
9. TS: `import { x } from "pkg"`; hooks (`useX`) only as view members; TS components are nodes
   with named-argument props; named arguments to a TS function become one options object; a TS
   value goes straight into any typed position (tsc checks it there).
10. An async call is `await`ed or spawned with `task { … }`; `defer { … }` for cleanup.
11. Navigation: `navigate("/path")` in screens; inside a surface with its own router (a settings
   modal), use that surface's router hook.
12. Run `bloomc check` and `bloomc fmt`; every error says what to write instead.
