# Drop zone

A view that takes drops: a file manager's files dropped on a folder or the
Trash, a link or an image dragged out of a browser, text from an editor.

```tsx
import { DropZone } from '@oxy.so/bloom/drop-zone';

<DropZone
  accept={['files']}
  actions={['move', 'copy']}
  onDragEnter={() => setOver(true)}
  onDragLeave={() => setOver(false)}
  onDrop={({ action, data }) => {
    setOver(false);
    for (const file of data.files) {
      if (file.uri) move(file.uri, folder, action);
    }
  }}
>
  <Folder highlighted={over} />
</DropZone>
```

## Props

- `accept`: the kinds of content it takes: `files`, `text`, `url`, `html`, or
  media types named exactly (`image/png`, or a platform's own, such as
  `application/x-oxyos-application`, whose content `other` holds).
- `acceptFileTypes`: the media types of the files it takes (`image/png`,
  `image/*`; case and parameters ignored). A drag of files is taken only when
  every file dragged is of one of them, as a Mac's Dock lights an
  application's icon only for documents it opens; a drag whose files' types are
  unknown is not taken. Absent, files of any type.
- `actions` (default `['copy']`): the actions it supports, its preferred one
  first, or named by `preferredAction`. The action a drop takes is chosen as a
  Mac chooses it: Option (Alt) held forces a copy, Command (Meta) a move, both
  a link, if both sides allow it; otherwise the preferred action the source
  allows, else the next it allows; none if none (nothing is dropped).
- `folder`: the folder files dropped on it go into, as a `file://` URI. Where
  the platform knows the volume each dragged file is on (OxyOS), a drag of
  files prefers a move when every one is on this folder's volume and a copy
  when any is not, as Finder does; Option still forces a copy and Command a
  move. It matters only when `actions` allows both (`['move', 'copy']`).
  Ignored on the web, whose drags name no folders.
- `disabled`: it takes nothing while true.
- `onDragEnter`, `onDragOver` (`DropTargetDragEvent`: the point in the view,
  the action a drop would take, the kinds offered that it accepts, and
  `fileTypes`, the media type of each file dragged, each once, empty for a drag
  of no files) and `onDragLeave`, for a drag it would take.
- `onDrop` (`DropTargetDropEvent`): the action and the content (`DropData`):
  - `files`: each with its `name`, and its `file://` `uri` on a native
    platform (what `expo-file-system` takes) or the browser's `File` as `raw`
    on the web;
  - `urls`: the URIs dropped that are not files;
  - `text`, `html`, and `other` (each media type accepted by name, as text).

## Where it works

- **The web:** HTML5's drag and drop on its element. During a drag a page sees
  the kinds offered and the type of each file (its `DataTransferItem`s) and
  never the content, which it reads at the drop (the
  browser's protected mode); `dropEffect` follows the chosen action, and the
  zone is left only when the pointer leaves it, not when it crosses a child,
  or at a drop anywhere in it, also one a child keeps from it (a sidebar row's
  own drag dropped on that row).
- **A platform whose adapter reports `drag-and-drop`** (OxyOS): the platform's
  drop target (`docs/platform-surface.mdx`). Drops come from any application,
  the content only to the target dropped on.
- **Elsewhere** (a phone today): a view that takes nothing.

Starting a drag of the application's own content to another application is
the platform's `usePlatformDrag()` (`docs/platform-surface.mdx`), for an
application that runs its own pointer gestures. Its image is the dragged view
itself (`previewRef`), stacked with a count for several items (`count`); its
`data.other` offers media types of the application's own, and `vanish` makes a
drop on nothing a puff of smoke instead of the image sliding back. On the web
those are the platform's alone: an HTML5 drag sets its own types in
`dragstart` (`dataTransfer.setData`).

## A drag over the window

`useWindowDrag({ onEnter, onExit })` follows drags over the whole window, from
any application: `onEnter()` when a drag first comes over it, `onExit(dropped)`
when it has left or ended, `dropped` true when it was dropped on this window,
told after that drop's `onDrop`. A window that opened a folder under a drag
(a spring-loaded folder) puts itself back when the drag exits without a drop,
as Finder does. The handlers are read when called, so they need not be
memoised.

```tsx
useWindowDrag({
  onExit: (dropped) => {
    if (!dropped && sprungFrom) navigate(sprungFrom);
    setSprungFrom(null);
  },
});
```

- **The web:** the document's HTML5 drag events. A drag comes over the page
  with its first `dragenter`; it has left the page when it leaves the element
  it last entered for nothing of the page (within the page the next element is
  entered before the last is left, which also holds when the element under the
  drag is replaced); a `drop` that reaches the document is dropped, a release
  over nothing that takes it or Escape is not; a drag of the page's own ends at
  its `dragend`, dropped when its `dropEffect` is not `none`.
- **A platform whose adapter reports `drag-and-drop`** and has `drag.watchWindow`
  (OxyOS): the platform says when a drag comes over the window's surfaces and
  leaves them all (`docs/platform-surface.mdx`).
- **Elsewhere**, or an adapter without `watchWindow`: nothing is told.

## The image of an HTML5 drag

On the web a drag starts in an element's `dragstart`, which the browser owns.
`setDragImage(event.dataTransfer, element, { x, y, count })` gives it the same
image the platform's drag shows: the dragged element as it looks, the point
pressed in it (`x`, `y`, its own pixels) under the pointer, and for `count`
above one the element over stacked copies of it with the count on a red badge
at its top right, as a Mac's drag of several files. Call it in `dragstart`; the
stack is built off screen, pictured by the browser at once and removed. On
native it does nothing: there the platform's drag draws its image from
`previewRef`.

```tsx
node.addEventListener('dragstart', (event) => {
  event.dataTransfer?.setData('text/uri-list', uris.join('\n'));
  setDragImage(event.dataTransfer, node, {
    x: event.offsetX,
    y: event.offsetY,
    count: uris.length,
  });
});
```
