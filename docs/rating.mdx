# Rating

```tsx
import { Rating, RatingBar, RatingInput } from '@oxy.so/bloom/rating';

<Rating value={4.92} count={128} />                        // ★ 4.92 (128)
<Rating value={4.81} count={214} countStyle="reviews" />   // ★ 4.81 · 214 reviews
<Rating value={null} />                                     // ★ New

<RatingBar label="Cleanliness" value={4.9} display="4.9" />
<RatingBar label="5" labelWidth={12} value={0.86} max={1} display="86%" />

const [stars, setStars] = useState<number | null>(null);
<RatingInput value={stars} onChange={setStars} accessibilityLabel="Overall rating" />
```

`Rating` shows a rating that exists; `RatingInput` is how one comes to exist.

## `Rating`

| prop                 | decides                                                                                 |
| -------------------- | --------------------------------------------------------------------------------------- |
| `value`              | a number (drawn 5.0, 4.9, 4.92) or a pre-formatted string; `null`/`undefined`/`''` = no rating yet |
| `count`              | the review count, number or string (`"1.2k"`); hidden when there is no rating           |
| `countStyle`         | `'parenthesis'` → "(128)" (default) or `'reviews'` → "· 128 reviews"                    |
| `reviewsLabel`       | the word after the count, default `"reviews"` — translate it                            |
| `newLabel`           | drawn instead of the value when there is no rating yet, default `"New"`                 |
| `size`               | `'small'` (14px star, body-2 text) or `'medium'` (default, 16px star, body text)        |
| `variant`            | `'compact'` (default, one star) or `'stars'` (five stars, filled fractionally, before the value) |
| `color`              | paints the star(s), the value and the count — e.g. white over a brand-coloured hero      |
| `starColor`          | the filled star(s) only (a gold star beside neutral text); default `color`               |
| `countColor`         | the count only; default `color` when given, else text-secondary                          |
| `emptyStarColor`     | `stars` only: the unfilled part of each star; default the border colour                   |
| `fillValue`          | `stars` only: the number the stars fill to, clamped to `0..5`, independent of the drawn `value` |
| `accessibilityLabel` | replaces the composed name — pass a translated sentence                                 |
| `style`, `testID`    |                                                                                          |

The star and value are text-primary (`body-semibold`), the count text-secondary
(`body-regular`). The whole row is one accessible element — `role="img"` on web —
named "Rated 4.92 out of 5, 128 reviews", so a screen reader does not read the
star, the number and the brackets as separate items. That sentence is English;
apps in other languages pass `accessibilityLabel`.

### Five stars, and colour

`variant="stars"` draws a row of five stars 2px apart instead of the single
star. Each is the unfilled star (`emptyStarColor`) with the filled star clipped
over it to its share of the value — 4.3 fills four stars and 30% of the fifth.

A string `value` is drawn exactly as given. The fill comes from `fillValue` when
you pass it — clamped to `0..5` — so a localised figure never has to be parsed:

```tsx
// "4,5" in a French or Spanish UI, isolated with FSI…PDI inside RTL text.
<Rating variant="stars" value={localisedFigure} fillValue={4.5} count={128} />
```

Without `fillValue` the string is parsed for the fill: bidi isolates and marks
(U+2066–U+2069, U+200E/U+200F, U+061C) are dropped, a comma or the Arabic
decimal separator counts as the decimal point, and Arabic-Indic digits are read,
so `"4,5"` wrapped in FSI…PDI still fills four and a half stars. A string that
cannot be read fills nothing. Prefer `fillValue` — it is the number you already
formatted from. The accessible name is built from the DRAWN text ("Rated 4,5 out
of 5"), never from `fillValue`; its sentence is English, so pass
`accessibilityLabel` in other languages. The clip is anchored
with a logical inset, so in a right-to-left layout the row fills from the right
(the root carries `dir` on web for react-native-web to resolve it). The row
stays ONE named image, like the compact rating.

```tsx
<Rating variant="stars" value={4.3} count={128} color="#fff" emptyStarColor="rgba(255,255,255,0.35)" />
```

Over a surface the theme's text pair cannot sit on — a brand-coloured hero — pass
`color`; the default text-primary/text-secondary are measured against the PAGE.

## `RatingBar`

| prop         | decides                                                                     |
| ------------ | --------------------------------------------------------------------------- |
| `label`      | the row's text and the bar's accessible name                                |
| `value`      | position on the scale, clamped to `0..max`                                  |
| `max`        | the scale, default `5`; pass `1` for a fraction                             |
| `display`    | the text on the right ("4.9", "86%"), also the bar's `aria-valuetext`      |
| `labelWidth` | without it the label flexes and the bar is 96 wide (a category list); with it the bar flexes (a distribution) |

The bar is a [`Meter`](/docs/stat-bar): 4 tall with a 2px radius, the shared
neutral-200 (dark neutral-700) track, filled with the ACCENT. It used to be
filled with text-primary — a near-black bar reading as ink rather than as a
measurement — and a rating breakdown is not a chart: the rows do not encode
different categories by colour, they all say "how good is this, out of 5". It is
a `progressbar` carrying `aria-valuemin`, `aria-valuemax`, `aria-valuenow` and
`aria-valuetext` (from `display`).

## `RatingInput`

The picker for a review form. Fully controlled: `value` is `1..max` or `null`
while nothing is chosen, and `onChange` fires with the star that was chosen.

| prop                 | decides                                                                                      |
| -------------------- | -------------------------------------------------------------------------------------------- |
| `value`              | the chosen rating, or `null` for nothing chosen yet                                          |
| `onChange`           | called with the chosen rating; never called with the value already chosen                    |
| `max`                | how many stars, default `5`                                                                  |
| `size`               | `'small'` (24px star), `'medium'` (default, 32) or `'large'` (40)                            |
| `disabled`           | no press, no keyboard, the group at `DISABLED_OPACITY`                                       |
| `accessibilityLabel` | **required** — the name of what is being rated ("Overall rating")                            |
| `formatStarLabel`    | each star's own name, default `"1 star"` / `"4 stars"` — translate it                        |
| `style`, `testID`    | `testID` derives `-star-<n>`                                                                  |

Chosen stars fill with the ACCENT, the rest are `RiStarLine` outlines in the
neutral ramp — the same reasoning as [`RatingBar`](#ratingbar)'s fill: a chosen
star is an answer somebody gave, and text-primary reads as ink rather than as
one. Under a pointer the stars up to the hovered one fill as a preview, which
never touches `value`.

### Operating it without a mouse

The group is a `radiogroup` named by `accessibilityLabel`, holding one `radio`
per star named by `formatStarLabel`. Exactly one of N is what a rating IS, so
`radio` is the role rather than a `slider` — and it is the only one that gives
each star its own touch target and its own name to announce.

The tab stop roves: the chosen star is the one in the tab order, or the first
star while nothing is chosen, so one Tab reaches the group either way. Inside
it, ArrowRight/ArrowUp, ArrowLeft/ArrowDown, Home and End move **and** choose,
which is how an ARIA radio group behaves. The focus ring is drawn on the star.

### No half stars, and no clearing

Half a star doubles the keyboard stops and halves the target — 16px of a 32px
star, under any touch floor — and the icon set has no half-star glyph, so the
state could not be drawn honestly either. `Rating` still DISPLAYS fractional
values (`4.92`): a display has no target and no keyboard.

Clearing is left out for the reason re-choosing a [`Radio`](/docs/radio) is a
no-op — a radio has no "off". A form that has no rating yet holds `null`; it
does not need the group to express a state it cannot draw.

## `RatingInput` in a `Field`

The stars are a `radiogroup` that draws no words, so `accessibilityLabel` is the
name — or, inside a [`Field`](/docs/field), the field's label, which is why the
prop is optional:

```tsx
<Field label="Cleanliness" error={errors.cleanliness}>
  <RatingInput value={stars} onChange={setStars} />
</Field>
```

The field's `disabled` freezes the whole row, including the hover preview.
