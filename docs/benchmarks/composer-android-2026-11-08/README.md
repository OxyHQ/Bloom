# Physical Android composer evidence (2026-11-08)

Device: Google Pixel 8a, Android 16/API 36, 1080×2400, density 420, font scale 1.15.

The current Alia fixture APK was pulled from the installed package and matched SHA-256 `52fa66aed6617ec303af6a1ce5b44ef300bb73a3190579250f05ff92feb8ed56`. Its installed Bloom package mirror is `d96928aa3d8396f29fd0fdc3009625328445515adafb41e3ee6eae893e34b803`; this is a local integration candidate, not a published package. The fixture uses local synthetic streaming, not production inference.

- `selection-direction.json`: no-transition, resize and busy comparisons. The backward selection stayed `[5,4]`; the next Shift+Left extended it to `[5,3]`.
- `composers.json`: packaged ComposerPill and AgentChatComposer resize/busy, Stop, draft, focus, identity and subsequent typing results.
- `alia-issue-663-workflow.mp4` is a 12.7-second screen recording from the exact current installed APK: idle composer/draft, synthetic stream, visible loader and Stop with keyboard open, Stop activation, and return to idle. `alia-two-laps.mp4` records a later 10.87-second active stream (more than two default 4.5-second laps), then Stop; `alia-two-laps-mid.png` shows Stop and the moving light. Hashes and start/stop markers are in `alia-workflow.json` and `alia-workflow-current-candidate.log`. Stop activation and resumed typing were physically verified in separate interactions.
- `alia-stop-accessible.png` and `alia-stop-accessible.xml` preserve the visible and native accessibility state from an earlier fixture APK. The embedded AliaComposer and Android adapter source hashes match the current candidate, but the hierarchy was not recaptured from the current APK. The earlier callback capture is in `alia-stop-interaction.log`.
- `loader-lifecycle.json`: physical pause/resume, inactive screen, background, width resize, rapid toggle, and initial-inactive timing/pixel checks.

Phase-aligned optical comparison, full product lifecycle/visual/performance acceptance and iPhone validation remain pending.
- `loader-phase-comparison.json` records same-origin captures of the same packaged loader and state on the Pixel 8a, once with hardware Canvas and once with the manifest-forced software host/SVG fallback. Bloom, native adapter and fixture source hashes match. The cropped PSNR is recorded as a measurement without claiming parity; no acceptance threshold exists yet.
- `loader-grouped-fallback-comparison.json` records a tapered, two-loader same-origin comparison before and after grouping fallback SVG strokes by blur layer. Grouping raised hardware/software crop PSNR from 38.022437 dB to 40.280698 dB on the same Pixel 8a capture region. This is a single still-image measurement; no visual acceptance threshold or performance claim is established.
- `loader-software-two-laps.mp4` records the pre-fix animated software-window fallback on the physically installed package: two tapered loaders move for approximately 11 seconds (>2 default laps). Its exploratory samples reached 200%/186% of one core; screenrecord cadence was 6.05 fps but is not an app FPS metric. The updated static-handoff candidate and its pixel/CPU evidence are in `loader-software-static-fallback.json` and related artifacts. Neither run establishes the final cross-platform performance budget.
- `loader-software-static-fallback.json` records the updated physical software-window candidate with active=true and speed=4.5. Two cropped captures ~15 seconds apart were pixel-identical; four exploratory CPU samples ranged from 4.4% to 6.8% of one core. This verifies the current phase is held after handoff for this scene, not visual acceptance or a controlled threshold.
- `loader-software-top.txt`, `loader-software-gfx.txt`, and `loader-software-memory.txt` preserve pre-fix software-fallback diagnostics. `loader-software-static-top.txt` and `loader-software-static-gfxinfo.txt` preserve diagnostics for the updated candidate.
