# Theme

Wrap your app with `BloomThemeProvider`. It accepts controlled `mode` and `colorPreset` props — persist them however you like (AsyncStorage, Zustand, etc.).

```tsx
import { BloomThemeProvider } from '@oxy.so/bloom/theme';

<BloomThemeProvider mode="system" colorPreset="teal">
  <App />
</BloomThemeProvider>
```

## Modes

| Mode | Behavior |
|------|----------|
| `light` | Force light theme. |
| `dark` | Force dark theme. |
| `system` | Follow OS preference (`useColorScheme`). |
| `adaptive` | iOS/Android native dynamic colors when available, falls back to `system`. |

## Color presets

10 named palettes:

`teal` · `blue` · `green` · `amber` · `red` · `purple` · `pink` · `sky` · `orange` · `mint`

Each preset has a tuned light + dark variant and a contrast-checked primary color.

## Reading theme values

```tsx
import { useTheme } from '@oxy.so/bloom/theme';

function MyComponent() {
  const theme = useTheme();
  return (
    <View style={{ backgroundColor: theme.colors.surface }}>
      <Text style={{ color: theme.colors.text }}>{theme.isDark ? 'Dark' : 'Light'}</Text>
    </View>
  );
}
```

### Tokens

Every preset exposes:

- `colors.primary` — brand color.
- `colors.background` — page background.
- `colors.surface` — elevated surface (cards, sheets).
- `colors.text` — body text.
- `colors.muted` — secondary text.
- `colors.border` — divider lines.
- `colors.success` / `colors.warning` / `colors.danger` — semantic colors.
- `isDark` — boolean.
- `mode` — resolved mode (`'light' | 'dark'`).

<Callout variant="info" title="Web CSS variables">
On web, Bloom also writes the active palette to CSS variables on `:root`, so non-React surfaces (e.g. raw HTML pages) can theme themselves with `var(--bloom-primary)`.
</Callout>

## Mobile web document appearance

The app-wide provider is the sole runtime owner of document appearance. It
paints `html` and `body` from the canonical `--background` token, applies the
resolved `color-scheme`, and owns one `theme-color` meta so browser chrome
follows manual modes, system changes, presets and dynamic seeds. On first
mount it adopts one startup meta and removes the remaining fallback entries;
app-specific runtime writers must therefore be removed. Color and seed scopes
do not change these document-wide settings.

These settings take effect when the provider mounts. Prerendered apps may
supply media-qualified light/dark metadata and background CSS as a startup-only
fallback; Bloom transfers that ownership during hydration. Server rendering
cannot know a local persisted preference, so the OS preference is the honest
pre-hydration fallback. Loading and auth gates should paint with
`theme.colors.background`, never a hardcoded light or dark colour.
Browser and operating-system navigation areas may ignore `theme-color`; their
final appearance must be checked on a real mobile device.
