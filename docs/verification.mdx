# Verification

Read these failure modes before treating a passing command as evidence about a
component or a consumer. Follow the normal package gates and release workflow.

## Jest does not resolve `.native.*`

**No Jest haste/platform setup:** bare `./X` selects `X.tsx`, never `X.native.tsx`. Native files need explicit imports; most have none. The bare target is usually web-safe.

Two consequences, both silent:

- A `.native.*` file can stop compiling and the suite stays green. Precedent in the fleet: **1545 tests passed over a file that did not parse.**
- Vendored `preset: react-native` suites cannot run unchanged. Teleport tests stay outside the tree, not `.skip`ped into false coverage (`docs/teleport.mdx`).

**Recorded debt:** a platform config needs native peers installed/mocked; asserting native behavior via a web-resolved file measures the wrong file.

## Canvas readbacks can change the backend being verified

Use a **fresh destination canvas for each pose** in avatar pixel gates, and never
read pixels from canvases used for timing. Repeated `getImageData` calls can make
Chromium move a Canvas2D destination from GPU to CPU rendering. The resulting
filtering path differs from an untouched GPU reference even though the renderer
and presentation code did not change.

Measured on Pixel 8a / WebView 148: a reused 112 CSS / 224 backing destination's
third capture reported 110,277 changed RGBA pixels and 110,190 changed PNG pixels
for eight working avatars. Repeating the same pose with fresh destinations gave
zero differences. All nine fresh size/action combinations compared 2,482,176
pixels exactly, including decoded PNGs. Smaller 64 CSS / 128 backing canvases
were already CPU-backed and did not show that migration. Earlier 96/112 CSS
captures also reported one-unit raw RGBA differences while decoded PNGs matched.
See [physical presenter evidence](./benchmarks/avatar-web-presenters-2026-10-31.json).

Capture all reference pixels and destination PNGs synchronously for the same
submitted frame, before awaiting image decoding. Decode each PNG into a fresh
scratch canvas for comparison. A WebGPU destination cannot also supply a 2D
context; copying it with `drawImage` was observed to produce transparent pixels
in a browser where its immediate PNG was correct. Check nonblank alpha and
actual backend counters, so neither that copy hazard nor a silent fallback can
produce a passing fidelity gate. These checks do not waive the separate scaled
WebGPU differences observed in WebView 148.

## Verifying a LOCAL Bloom build in a consumer (four silent wrong passes)

These silently verify the PUBLISHED package instead:

- **`bun add file:<tgz|dir>` silently no-ops** when the installed version matches. Bump the local version, or symlink.
- **Metro `resolver.extraNodeModules` is a FALLBACK:** a real `node_modules/@oxy.so/bloom` wins. **`expo export`/`expo start` disagree:** the dev server indexes only `projectRoot` + `watchFolders`; put the local copy inside the consumer repo, gitignored.
- **Metro port is baked at BUILD time** (`-PreactNativeDevServerPort`, not `RCT_METRO_PORT`); emulators resolve it via host loopback, which `adb reverse` misses. Confirm it in `gradleResValues.xml`.

**Live-edit: `node scripts/mirror-into-consumer.mjs <consumer-root> --watch`** mirrors `src/` into `bloom-local` (`--into=<dir>`: inside what Metro WATCHES, else edits are never seen) and links `node_modules/@oxy.so/bloom` to it; restart Metro for NEW files, `--restore` before trusting a typecheck.

**Assert what you test first:** resolved version plus a marker only the local build produces. **Never write over `node_modules/<pkg>`:** bun hardlinks its global cache, mutating it for every worktree/session.



### A source mirror changes React Compiler coverage

React Compiler's default `sources` predicate excludes filenames containing
`node_modules`. The mirror lives in `bloom-local`, so a consumer with React
Compiler enabled can compile mirrored Bloom as application code while leaving
the published package uncompiled. Matching versions and source hashes do not
prove matching compiled output.

Measured on 2026-10-28 in Mention's native feed row-cost harness: the 15.59.3
source mirror reported 270 hooks for a link-preview row; the published package
reported 292, with the same 62 context reads. Transforming identical Card source
under the two paths emitted `react/compiler-runtime` only for the mirror. The
valid release comparison was published 15.59.2 → 15.59.3: 302 → 292 hooks and
64 → 62 context reads, with all existing budgets unchanged.

For performance comparisons, use the same compiler scope on both sides, or
restore the mirror and run the final gate against the published package. Record
which artifact was measured; never present a source-mirror improvement as a
published-package result or adjust timing/budget gates to hide the difference.
