# Booking

Five pieces for booking a stay, all under one subpath:

| component        | what it is                                                                          |
| ---------------- | ----------------------------------------------------------------------------------- |
| `BookingCard`    | the reservation card beside a listing: price, dates, guests, Reserve, breakdown     |
| `PriceBreakdown` | itemised charges and a bold total — inside the card, or alone on a checkout page    |
| `BookingBar`     | the phone-width bar pinned under a listing: price, dates, Reserve — the stay preset of [`ActionBar`](/docs/bloom/main/listing-actions) |
| `TripCard`       | an upcoming or past reservation: photo, place, host, dates, status, actions         |

```tsx
import {
  BookingBar,
  BookingCard,
  PriceBreakdown,
  TripCard,
} from '@oxy.so/bloom/booking';
import { GuestPicker } from '@oxy.so/bloom/stay-search';
```

The guests panel is [`GuestPicker`](/docs/bloom/main/stay-search) — the same
picker the search bar's "Who" panel uses, so guests behave identically in both.

Prices, dates and guest summaries arrive **pre-formatted strings** — the app owns
currency, locale and plurals. Nothing here adds amounts up or formats a date.

## BookingCard

```tsx
const [guests, setGuests] = useState({ adults: 2, children: 0, infants: 0, pets: 0 });

<BookingCard
  price="$180"
  priceUnit="night"
  rating={4.92}
  reviewCount={128}
  checkIn={checkIn}            // "10/12/2026", or undefined while unselected
  checkOut={checkOut}
  guests="2 guests"
  onPressDates={(field) => openDatePicker(field)}
  activeField={datePickerField} // 'checkIn' | 'checkOut' | null — outlines the open field
  guestPicker={
    <GuestPicker size="small" value={guests} onChange={setGuests} maxGuests={4} note="Pets aren't allowed." />
  }
  onReserve={reserve}
  loading={reserving}
  breakdown={{
    rows: [
      { label: '$180 x 5 nights', amount: '$900' },
      { label: 'Weekly stay discount', amount: '$90', tone: 'discount' },
      { label: 'Service fee', amount: '$127', details: <Text>What this covers…</Text> },
    ],
    total: '$937',
  }}
  footer={<Button variant="link" linkTone="secondary" size="small">Report this listing</Button>}
/>
```

| prop                                          | decides                                                                                  |
| --------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `price`, `originalPrice`, `priceUnit`         | the header; `originalPrice` is struck through before the price                            |
| `priceUnitPrefix`                             | drawn before the unit, not spoken: `"/"` draws "$180 / night"                             |
| `priceAccessibilityLabel`                     | the spoken price, default `"$162 per night, originally $180"`                            |
| `rating`, `reviewCount`                       | a small `Rating` on the right; `null` draws "New", omitted draws nothing                 |
| `checkIn`, `checkOut`, `guests`               | the values in the box; an empty date shows `datePlaceholder` ("Add date")                |
| `onPressDates(field)`, `onPressGuests`        | the cells' presses — open your pickers here                                              |
| `activeField`                                 | the field whose picker is open: 2px text-primary outline, and `aria-expanded` on all three cells. Leave it `undefined` if the card cannot know, and no cell claims a state |
| `guestPicker`, `guestsOpen`, `onGuestsOpenChange` | makes the guests cell open a `Popover` (a bottom sheet on native) holding `guestPicker`, as wide as the box; controlled or not. A `GuestSelect` inside it closes it with "Close" without extra wiring |
| `checkInLabel`, `checkOutLabel`, `guestsLabel` | translate the cell labels (drawn uppercase)                                             |
| `reserveLabel`, `checkAvailabilityLabel`      | the button reads `"Reserve"` once both dates are set and `"Check availability"` before, unless `reserveLabel` is given |
| `onReserve`, `reserveDisabled`, `loading`     | the primary large `Button`; `loading` shows its spinner and ignores presses              |
| `note`                                        | the centred line under the button — default "You won't be charged yet" once both dates are set; `null` hides it |
| `breakdown`                                   | `PriceBreakdown` props, drawn 24 below                                                    |
| `footer`                                      | anything centred at the bottom                                                            |

**What it looks like.** The chrome every listing action card shares (the rental,
sale and swap cards in [Listing actions](/docs/bloom/main/listing-actions) draw
the same shell). Up to 372 wide (`width: 100%`), radius 16, a 1px hairline
(neutral-200, dark neutral-700), `shadow-m`, padding 24 on the card surface. The
box is radius 12 with a 1px neutral-300 (dark neutral-600) border and dividers;
each cell is a `caption-2-bold` uppercase label over a `body-regular` value. A
cell washes neutral-100 under a pointer or a press — colour only, nothing scales.

### Sticky beside the listing (web)

The card is a plain block; pinning it is the page's job. With `AppShell` (which
scrolls the **document** on web), put the card in its own column and make that
column's child sticky:

```tsx
const sticky = { position: 'sticky', top: 96 } as unknown as ViewStyle; // RN has no 'sticky' type

<View style={{ flexDirection: 'row', gap: 64, alignItems: 'flex-start' }}>
  <View style={{ flex: 1 }}>{/* listing */}</View>
  <View style={{ width: 372, alignSelf: 'stretch' }}>
    <BookingCard {...props} style={sticky} />
  </View>
</View>
```

`top` is the height of anything pinned above (a header). Sticky stops working if
any ancestor between the card and the document sets `overflow: hidden` or
`scroll` — that ancestor becomes the scroll container. The column must be as tall
as the listing (`alignSelf: 'stretch'`), or there is nothing to stick within. On
native, and below the breakpoint where the card sits beside the listing, use
`BookingBar` instead.

## PriceBreakdown

```tsx
<PriceBreakdown
  rows={[
    { label: '$240 x 3 nights', amount: '$720' },
    { label: 'Early booking discount', amount: '$72', tone: 'discount' },
    { label: 'Cleaning fee', amount: '$60', onPressLabel: explainCleaning },
    { label: 'Service fee', amount: '$64', details: <ServiceFeeNote /> },
  ]}
  totalLabel="Total (USD)"
  total="$772"
/>
```

- A row is a `body-regular` label and a right-aligned tabular amount, 12 apart.
- `tone: 'discount'` paints the amount in the success colour (the success
  pair's legible-on-page member) and puts a typographic minus before it, unless
  the string already starts with one.
- `onPressLabel` makes the label an underlined button; `details` makes it open
  a `Popover` above it (a bottom sheet on native) with that content. Both can be
  set.
- `total` adds a hairline and a `headline-semibold` total row; omit it for no
  total.

## The guests popover

`guestPicker` turns the guests cell into a `Popover` trigger (a bottom sheet on
native) as wide as the date/guest box. A `GuestPicker` inside it gets a "Close"
that closes the popover without wiring `onClose`; `maxGuests` caps adults +
children and `note` adds the line under the rows. The picker's rules and props
are documented with it, in [StaySearch](/docs/bloom/main/stay-search).

## BookingBar

```tsx
<BookingBar
  price="$180"
  priceUnit="night"
  dates="Oct 12 – 17"
  onPressDates={openDatePicker}
  onReserve={reserve}
/>
```

`BookingBar` is [`ActionBar`](/docs/bloom/main/listing-actions) with the stay
wording (`dates` as its subtitle, "Reserve" as its button); use `ActionBar` for a
rental, a sale or a swap. A 1px top hairline, the page background, padding 12 above and 24 at the sides,
and **12 plus the bottom safe-area inset** below — read from
`react-native-safe-area-context`'s context when a provider is mounted, 0 when
not; `bottomInset` overrides it. The dates are underlined `body-2-medium`, a
button with `onPressDates`. `reserveLabel`, `reserveDisabled` and `loading` work
as on the card.

Keeping it at the bottom of the screen is the screen's job:

- **Native** — render it after the `ScrollView`, not inside it, in a
  `flex: 1` column; give the scroll content no extra bottom padding.
- **Web with document scroll** — `position: 'fixed'` with `left: 0`, `right: 0`,
  `bottom: 0` (cast as for `sticky` above), and add the bar's height as bottom
  padding to the page so the last content is not hidden under it. Mount it only
  below the breakpoint where the `BookingCard` column is shown.

## TripCard

```tsx
<TripCard
  image={trip.coverId}            // a URL, or an id for ImageResolverProvider
  imageVariant="medium"
  title="Cliffside cabin in Val Serena"
  subtitle="Hosted by Marisol"
  dates="Oct 12 – 17, 2026"
  status="confirmed"              // 'confirmed' | 'pending' | 'cancelled' | 'completed'
  onPress={() => openTrip(trip.id)}
  actions={<Button variant="secondary" size="small" onPress={message}>Message host</Button>}
/>
```

- Radius 16, 1px hairline, padding 12; the photo is radius 12 (neutral tile
  while absent), 176 × 132 beside the text or full width at 3:2 above it.
- `orientation="auto"` (default) measures the card and lays out horizontally
  from 480 wide; it renders vertical until measured. Force it with
  `'horizontal'` or `'vertical'`.
- The status is a subtle `Badge`: confirmed success, pending warning, cancelled
  error, completed neutral (`TRIP_STATUS`); `statusLabel` translates it.
- `onPress` lays one button UNDER the content, so `actions` are not nested inside
  another button — they stay separately pressable and separately announced.

## Accessibility

- **Cells** are buttons named `"Check-in: 10/12/2026"` (or the placeholder). With
  `activeField` set they carry `aria-expanded`; with `guestPicker` the guests
  cell also gets `aria-haspopup` from the popover trigger.
- **Price** reads as one element, `"$162 per night, originally $180"` —
  `role="img"` on web, one `accessible` node on native — because a
  strikethrough is not announced and the parts read separately would invert the
  offer. `Rating` does the same.
- **TripCard** with `onPress` is a button named by title, dates and status
  (`accessibilityLabel` overrides); the drawn photo and text are hidden from
  assistive tech so they are not read twice, and the actions stay reachable.
- Every pressable shows a 2px accent focus ring under keyboard focus on web
  (`:focus-visible`, from an adopted stylesheet); the cells draw it inset.
- `GuestPicker` steppers are named by their kind (Adults, Children…); see
  [Stepper](/docs/bloom/main/stepper).
