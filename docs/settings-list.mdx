# SettingsList

iOS-style grouped settings list. Items, groups (with optional headers and footers), and dividers. Built for the dense, list-heavy screens common in account / preferences UIs.

## Basic

```tsx
import {
  SettingsListGroup,
  SettingsListItem,
  SettingsListDivider,
} from '@oxy.so/bloom/settings-list';

<SettingsListGroup title="General">
  <SettingsListItem
    icon={<PersonIcon />}
    title="Account"
    value="ada@oxy.so"
    onPress={() => navigate('Account')}
  />
  <SettingsListDivider />
  <SettingsListItem
    icon={<GlobeIcon />}
    title="Language"
    value="English"
    onPress={() => navigate('Language')}
  />
</SettingsListGroup>
```

The group renders a rounded card on iOS-style platforms and on web. The first item rounds top corners, the last item rounds bottom corners.

## With description

```tsx
<SettingsListItem
  icon={<ShieldIcon />}
  title="Two-factor authentication"
  description="Add a second sign-in step with an authenticator app."
  value="On"
  onPress={() => navigate('TwoFactor')}
/>
```

`description` is multi-line and styled in muted text under the title.

## Toggle row

```tsx
<SettingsListItem
  icon={<MoonIcon />}
  title="Dark mode"
  rightElement={<Switch checked={darkMode} onCheckedChange={setDarkMode} />}
/>
```

When `rightElement` is set, the chevron is hidden automatically (you can override with `showChevron`).

## Destructive

```tsx
<SettingsListGroup title="Danger zone">
  <SettingsListItem
    icon={<TrashIcon />}
    title="Delete account"
    destructive
    onPress={confirmDelete}
  />
</SettingsListGroup>
```

`destructive` switches the title to the negative color and uses the destructive icon tint.

## Disabled

```tsx
<SettingsListItem
  icon={<KeyIcon />}
  title="Reset password"
  description="Coming soon"
  disabled
/>
```

## The group knows what it is sitting on

A group paints the `card` colour, which reads as a raised card on a page painted
in `background`. Inside something *already* painted `card` — a `ContentPanel` —
that same group has no edge left: the rows float, and the group is there,
correct, and invisible.

**You do not tell it which.** A container that paints a surface publishes the
colour it painted (the surface ladder in [Styles](/docs/bloom/main/styles)), and
the group resolves off that colour:

- on the **page**, `theme.colors.card` — what these groups have always painted;
- on **anything else**, one ladder step off the fill the container published.

So this is the whole of it, on a page and in a panel alike:

```tsx
<ContentPanel>
  <SettingsListGroup title="Account">
    <SettingsListItem title="Privacy" onPress={openPrivacy} />
  </SettingsListGroup>
</ContentPanel>
```

This used to be a `variant="filled"` at every call site — ~75 of them in one app
with a settings tree, each one a chance to forget, and forgetting produced no
error and no visible control. A question about the PARENT is not something a call
site should have to answer.

| `variant` | Surface |
| --- | --- |
| *(unset — the normal case)* | `card` on the page; one step off the container's own fill anywhere else |
| `plain` | `card` |
| `filled` | `backgroundSecondary` |

**A step, rather than `backgroundSecondary`, because `backgroundSecondary` is
calibrated against `card` and nothing else.** On a `ContentPanel` it works (dark
1.378–1.404 across all 64 presets); on the menu surface `FloatingPanel` and
`QueuePanel` publish it measures **1.086–1.106 in dark, failing the ladder's 1.1
just-noticeable floor on 52 of the 64 presets** — the disappearance this default
exists to prevent, one container over. The step measures 1.296–1.312 there, on
all 64. In light both clear it, which is why this is only visible if you look in
dark.

### Every container this changes

Anything that publishes a surface now decides what a group inside it paints, not
just `ContentPanel`:

| Container | What a group inside it paints now |
| --- | --- |
| a bare screen | `card` — unchanged |
| `ContentPanel` | a step off the panel's fill (was `card` unless you passed `variant="filled"`) |
| `FloatingPanel` — `Popover`, `DropdownMenu`, `ContextMenu`, `HoverCard`, `Select`, menu flyouts | a step off the menu surface (was `card`) |
| `QueuePanel` (as a panel) | a step off the panel surface (was `card`) |
| `Dialog`, `BottomSheet` and the sheet-backed surfaces | `card` — unchanged; they publish `colors.background` |

The first row and the last are the ones to notice: nothing on a plain screen and
nothing in a dialog moves. A group that was ALREADY passing `variant="filled"`
inside a panel keeps painting `backgroundSecondary` until the prop comes off.

### When to pass `variant` anyway

For a surface Bloom does not paint and so cannot publish a fill for — your own
coloured section, a third-party container. An explicit `variant` always wins over
the ambient one.

```tsx
<View style={{ backgroundColor: colors.card }}>
  <SettingsListGroup variant="filled" title="Account">…</SettingsListGroup>
</View>
```

The alternative, if that container is yours and holds more than a settings list,
is to publish the surface once instead of annotating everything inside it.
`SurfaceLevelProvider` ships on the **`styles` subpath**, not the root barrel:

```tsx
import { SurfaceLevelProvider } from '@oxy.so/bloom/styles';

<View style={{ backgroundColor: mySectionColour }}>
  <SurfaceLevelProvider level={1} fill={mySectionColour}>
    <SettingsListGroup title="Account">…</SettingsListGroup>
  </SurfaceLevelProvider>
</View>
```

Pass `fill` as well as `level`: the level says how deep you are, the fill says
what you actually painted, and it is the fill the group steps off.

### Overlays do not inherit the panel

A dialog, a bottom sheet or a menu opened from inside a `ContentPanel` starts its
own painting context, so a group inside a dialog is a `card` again whether the
trigger lived on a bare screen or inside a panel. That takes a deliberate reset:
React context reaches through a portal and through an RN `<Modal>` even though
neither paints anything. `Dialog` and the bottom-sheet shell publish
`colors.background`, `FloatingPanel` publishes the menu surface, and
`overlay/OverlayRoot` resets the ambient surface for anything portaled that does
neither.

Two portaled surfaces paint something they do not publish — `SettingsModal`
(`resolveSettingsPalette(theme).full`) and `Tooltip` (the menu palette) — so a
group inside either reads the page rung and paints `card`. That is inherited from
before the ladder existed, and the fix is for each of them to publish its own
fill.

## Footer / header text

```tsx
<SettingsListGroup
  title="Notifications"
  footer="Push notifications require an enabled device permission."
>
  <SettingsListItem title="Marketing emails" rightElement={<Switch checked={mktg} onCheckedChange={setMktg} />} />
  <SettingsListDivider />
  <SettingsListItem title="Product updates" rightElement={<Switch checked={prod} onCheckedChange={setProd} />} />
</SettingsListGroup>
```

`title` is the group header (uppercase muted label on iOS-style platforms); `footer` is a soft explanatory line under the card.

## Components

### `SettingsListGroup`

| Prop | Type | Description |
|------|------|-------------|
| `title?` | `string` | Section header. |
| `footer?` | `string` | Section footer. |
| `children` | `React.ReactNode` | `Item`, `Divider`. |
| `style?` | `StyleProp<ViewStyle>` | Override group container style. |
| `variant?` | `'plain' \| 'filled'` | Overrides the surface the group would resolve from the container's published fill — `card` or `backgroundSecondary`. Normally left unset; see [above](#the-group-knows-what-it-is-sitting-on). |

### `SettingsListItem`

| Prop | Type | Description |
|------|------|-------------|
| `icon?` | `React.ReactNode` | Leading icon. |
| `title` | `string` | Primary label. |
| `description?` | `string` | Multi-line secondary text. |
| `value?` | `string` | Right-side value string. |
| `rightElement?` | `React.ReactNode` | Replaces value / chevron with a custom node. |
| `showChevron?` | `boolean` | Defaults to `true` when `onPress` is set. |
| `destructive?` | `boolean` | Negative palette for title + icon. |
| `onPress?` | `() => void` | Tap handler. |
| `disabled?` | `boolean` | |
| `accessibilityLabel?` | `string` | Override the derived label. |
| `accessibilityHint?` | `string` | |
| `accessibilityRole?` | `'button' \| 'link' \| 'none'` | Defaults to `'button'` when pressable. |
| `leftInset?` | `number` | Left inset to align text when no icon is set. |

### `SettingsListDivider`

| Prop | Type | Description |
|------|------|-------------|
| `inset?` | `number` | Left inset to align with text (default `52`). |

## Recipes

### Mixed read / link rows

```tsx
<SettingsListGroup title="About">
  <SettingsListItem title="Version" value="1.4.2" />
  <SettingsListDivider />
  <SettingsListItem title="Build" value="231" />
  <SettingsListDivider />
  <SettingsListItem title="Terms" onPress={() => navigate('Terms')} />
  <SettingsListDivider />
  <SettingsListItem title="Privacy" onPress={() => navigate('Privacy')} />
</SettingsListGroup>
```

### Sign-out section

```tsx
<SettingsListGroup>
  <SettingsListItem
    title="Sign out"
    onPress={signOut}
    accessibilityRole="button"
  />
</SettingsListGroup>
```

### Account switcher

```tsx
<SettingsListGroup title="Accounts">
  {accounts.map((a, i) => (
    <Fragment key={a.id}>
      {i > 0 ? <SettingsListDivider /> : null}
      <SettingsListItem
        icon={<Avatar uri={a.avatarUrl} size={28} />}
        title={a.name}
        description={a.handle}
        rightElement={a.id === activeId ? <CheckIcon /> : null}
        onPress={() => switchTo(a.id)}
      />
    </Fragment>
  ))}
</SettingsListGroup>
```
