# AgentChat

The chat workspace: transcript, composer and history rail in one. It has no sidebar shell, side panel or image generation; for those use [`AiChat`](./ai-chat.mdx) (see [Building AI interfaces](./ai-overview.mdx) for which to pick). Five public pieces, usable together or alone:

| Export | What it is |
| --- | --- |
| `AgentChat` | The workspace: chat card (header, transcript, composer) beside the history rail |
| `AgentChatMessage` | One turn — the user bubble, or an assistant reply with copy / read-aloud / timestamp |
| `AgentChatComposer` | The 52px pill composer and its status row, wrapped in `ComposerLoader` |
| `AgentChatActions` | The header's share button and "more" menu |
| `AgentChatHistory` | The 260px history rail: new chat, recent threads, account strip |

```tsx
import { AgentChat } from '@oxy.so/bloom/agent-chat';

const { messages, status, sendMessage, stop } = useChat({ transport });

<AgentChat
  messages={messages.map((m) => ({ id: m.id, role: m.role, text: textOf(m), at: arrivedAt[m.id] }))}
  status={status}
  onSubmit={(text) => sendMessage({ text })}
  onStop={stop}
  model="openai/gpt-5-nano"
  provider="OpenAI"
  threads={threads}
  activeThreadId={activeId}
  onSelectThread={openThread}
  onNewChat={startNewChat}
  onRenameThread={renameThread}
  onToggleUnread={toggleUnread}
  onDeleteThread={deleteThread}
  onExport={exportThreads}
  historyProps={{ account: { name: 'Maya Collins' }, onLogOut: signOut }}
/>
```

Give it a sized parent — it fills it (`flex: 1`); a 12px page frame on `background-full` is a good default.

The workspace uses `AppShell panelLayout` with stable `conversation` and `history`
panels. Its conversation declares `Screen scroll="auto"`, with `PageHeader` in
`header`, the shared composer in `bottomBar` through `PageFooter`, and
`ScreenScrollView` for the transcript. The shell supplies panel framing and the
local viewport; header/footer clearances and scroll state belong to Screen.
History visibility resolves against the shell container, retaining its mounted
state when it becomes hidden. Standalone `AgentChatHistory` retains its own frame.

## Data, not transport

Bloom wires none of the AI SDK (`useChat`), `localStorage`, or a `/api/chat` route into this component. Everything it needs from them is a prop:

- **`messages`** — `{ id, role, text, at?, agent?, reasoning?, toolCalls?, markdown? }`. An assistant turn renders its parts in this order: the delegated `agent` (avatar + name), the `reasoning` block (`{ text, durationMs?, streaming? }`, an `AgentThinking` disclosure: "Thought for N s"), the `toolCalls` (`{ id, name, label?, status: 'running' | 'done' | 'error', detail?, error?, durationMs?, onPress? }`, `AgentLogToolCalls` lines on the log's guide), then the text. `markdown: true` sets the text with `Markdown` (streaming-aware) instead of plain paragraphs; `onLinkPress` receives its links.
- **`status`** — `'ready' | 'submitted' | 'streaming' | 'error'`, the AI SDK's own values. `submitted` and `streaming` are *busy*: the composer shows stop and lights its `ComposerLoader` band, the rail is disabled (switching mid-stream would strand the reply), and suggestions and Enter are refused.
- **`threads`** — `{ id, title, updatedAt, unread? }`, in the order you want them listed. Ordering, persistence, title derivation and "reading a chat marks it read" are the consumer's.
- **Every action** — `onSubmit` (trimmed, non-empty), `onStop`, `onAttach`, `onShare`, `onExport`, `onCopyMessage`, `onReadAloud`, and the thread callbacks.

What the component still owns is interaction state: the composer text (uncontrolled unless you pass `value`), the menus, inline rename, the "Copied" confirmations, following the newest message.

## Anatomy

### Header

`PageHeader` renders the title and floating action islands above the transcript.
`headerLeading` accepts navigation controls. The title defaults to the active
thread's title; `title` overrides it. `headerIdentity` accepts an avatar/name
composition such as `AgentProfile` and defaults to centered alignment;
`headerTitleAlign` can override that alignment. The composed identity determines
header height. `AgentChatActions` uses the shared `ButtonGroup` and menu trigger.

### Transcript

A column max 768 wide, `px 16 / pt 16 / pb 24`, 20px between turns. While empty it centres the empty state: `title-2-medium` heading, a `body-regular` line and wrapping suggestion pills (`suggestions`, three by default; `[]` hides them). `emptyState` replaces the **whole card body** — transcript and composer — which is where an "Add an API key" notice would go.

While busy and the last reply has no text yet, `AgentThinking` (wave, "Thinking") sits under the transcript: reasoning models stream nothing visible first, so the indicator stays up until a word exists. `error` (default `status === 'error'`) adds the `role="alert"` line.

### AgentChatMessage

- **User** — right-aligned bubble, max 75%, radius 16, `px 12 / py 11`, `background-primary`, `shadow-card`.
- **Assistant** — the optional agent notice, reasoning and tool calls, then the reply split into its non-empty lines, 12px apart. Each line softens in **once** as it first appears (opacity, 5px blur on web, 4px lift, 420ms `cubic-bezier(0.22, 0.61, 0.36, 1)`) and then only grows, so a streamed reply never re-animates what is already on screen. Line-level, not word-level: a token arrives as a fragment and a per-word blur stutters as the fragment mutates. Reduced motion mounts lines settled.
- **Action row** — copy and read aloud (28px circles, 16px glyphs) and the timestamp (`"3 minutes ago"`, `formatTime`). Mounted at all times so it is reachable by keyboard and never shifts layout; hidden and inert while `streaming`.

### AgentChatComposer

Uses `ComposerPill` inside `ComposerLoader`: a multiline, growing prompt with
Bloom's shared send, stop, keyboard and model controls. The provider and message
count remain in the status row. Uncontrolled drafts clear through ComposerPill after sending; AgentChat owns and clears its controlled workspace draft.
`composerProps` exposes the shared pill API for model selection, attachments,
voice, permissions, labels and keyboard integration; the chat owns draft and
turn state. Add attachment and voice controls appear when host handlers exist.
The workspace `disabled` prop and `composerProps.disabled` combine as restrictions: either blocks editing, Enter, send and suggestion submission. Stop stays reachable while busy and disabled. Enter sends; Shift+Enter inserts
a line break, and IME composition does not submit.

### AgentChatHistory

260 wide, `p 12`, 24px between "New chat", the list and the footer. The workspace shell owns its surface and corners; the standalone history supplies its own frame.

- **Threads** — radius 10; the active row, a row whose menu is open, and a hovered row share the `background-secondary-hover` fill, so hovering previews selecting. Unread rows carry a 6px dot and primary text. A 28px trailing slot holds the compact age (`now`, `34m`, `5h`, `3d`; `formatAge`) and, stacked on it, the `⋮` trigger — the age steps aside on hover or keyboard focus, never both at once. The menu offers Rename (inline field; Enter or blur commits the trimmed title, Escape cancels), Mark as unread and Delete, each shown only when its callback is set.
- **Footer** — a 1px `separator-border` rule, the account trigger (`account`: avatar + name) and the 24px export disc (`onExport`; disabled with no threads). The account menu opens upward: "Usage left" (`usage`) expands in place to measured rows and "Upgrade" (`onUpgrade`), then `accountItems`, a divider and "Log out" (`onLogOut`).

## Platforms

`app-shell`, `composer-loader`, `composer-panel` and `dropdown-menu` are web-forked, so `agent-chat` is too: `AgentChat.web.tsx` binds the web `AppShell`, `ComposerLoader` (DOM `<svg>` on CSS keyframes) , `ComposerPill` and `DropdownMenu` (anchored `FloatingPanel`); `AgentChat.tsx` binds the native ones (react-native-svg loader, menus as sheets). The implementation is shared and receives them through context — so a web bundler that resolves `package.json#exports` rather than platform extensions still reaches the web pieces.

On **native**:

- There is no hover, so the assistant action row simply shows (except while streaming), and a thread row's `⋮` trigger is transparent over the age — pressing the slot still opens the menu, as expected on touch.
- Copy and read aloud render only when `onCopyMessage` / `onReadAloud` are given (web defaults to `navigator.clipboard` and `speechSynthesis`). Share defaults to the Web Share sheet or the clipboard on web and does nothing on native without `onShare`.
- Header materials follow PageHeader; message lines animate without the blur.

## Language

Every default string — names, placeholders, the empty state and its suggestions, the error line, the status row, "3 minutes ago" and the rail's compact ages, the transcript's speaker names — is localised via `BloomProvider locale`. Each `labels` key, `suggestions`, `formatTime` and `formatAge` still win.

## Design notes

- **Pill rule** — the header, message and row-menu icon buttons are circles, per Bloom's full-radius rule for button-like controls. Rows, cards and the model chip keep a smaller corner radius.
- **No press scale** anywhere; hover is colour only.
- **No native `title` tooltips** on icon buttons — the accessible names are kept, the browser tooltip is not.
- **App navigation left out** — a sidebar navigation with its phone drawer, plan/upgrade prompts and a setup notice aren't included. Use `headerLeading`, your own layout, and `emptyState`.
- **No markdown or code rendering** — replies render as plain paragraphs.
- **The rail's visibility** — it shows when `threads` is given and the shell container is at least 1280px wide, or as `showHistory` says. The modular layout keeps only the conversation when the panels’ minimum widths cannot fit.
