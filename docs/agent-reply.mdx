# AgentReply

The pieces a conversation with several agents is made of. Each agent answers in its own bubble, its 3D avatar and name under it, and the row of actions at the other end. The header names the team.

```tsx
import {
  AgentProfile,
  AgentReply,
  AgentReplyActions,
  AgentReplyBubble,
  AgentReplyIdentity,
} from '@oxy.so/bloom/agent-reply';

<AgentProfile agents={team} onPress={openTeam} />

<AgentReply
  identity={<AgentReplyIdentity character={lumi.avatar} name={lumi.name} thinking={streaming} />}
  actions={!streaming && <AgentReplyActions onCopy={() => copy(text)} />}
>
  <AgentReplyBubble>
    <Markdown>{text}</Markdown>
  </AgentReplyBubble>
</AgentReply>
```

`MultiAgentChat` is built from exactly these, so a thread built here looks like it.

## Pieces

| Piece | What it is |
| --- | --- |
| `AgentReply` | The reply on top; under it, `identity` at the start and `actions` at the end. On web the actions appear on hover or focus; touch platforms keep them shown. It carries 12px of margin at each side and above; `style` is applied after, so a thread that already pads its content passes `marginHorizontal: 0`. |
| `AgentReplyBubble` | The tinted surface (`background-tertiary`, radius `2.5xl`, 12px padding) the reply sits on. Takes `style` and `className`. |
| `AgentReplyIdentity` | The agent's 3D avatar and name. While `thinking`, the avatar grows to 32px, plays its working animation and the name gives way to "Thinking…". Pass `onPress` to make it a button (`pressLabel` names it). |
| `AgentReplyActions` | Helpful, unhelpful and — with `onCopy` — copy, as bare icons in a row (a plain [`Button`](./button.mdx) each): nothing around them until one is hovered. Add your own after them with `AgentReplyAction` children (read aloud, retry…). |
| `AgentReplyAction` | One bare icon button. It draws no text, so `label` is its name. `selected` lights it and is announced as a toggle. |
| `AgentProfile` | The conversation's header target: one agent large, two or three overlapped, a longer team as its first three and "+N". The capsule names them ("Lumi + Atlas + Sol"). Pressing it makes every avatar in it wave, then calls `onPress`. |
| `AgentStack` | Up to three avatars overlapped in one square, for a list row. |

An agent is `{ id, name, label?, avatar }`, where `avatar` is an [`AvatarCharacter`](./agent-avatar.mdx).

## Votes

`AgentReplyActions` keeps the vote itself. Pass `vote` (`'up' | 'down' | null`) to keep it yourself — a controlled row ignores what it was tapped to — and `onVoteChange` to be told.

## Accessibility

A tile draws no text: its name is `label`, and `selected` is set as both `aria-pressed` and `accessibilityState` because react-native-web reads only the first. `AgentProfile` is a button named by `accessibilityLabel` (the label when absent) and reports `expanded` as `aria-expanded`. While `thinking`, `AgentReplyIdentity` is named "{name} is thinking" and the "Thinking…" status is announced as `role="status"`.

## Language

The row's labels and the thinking status follow `BloomProvider locale`. Names and the profile's text come from you.

## Hazards

- **Give the avatar's box to a caller that animates it** with `avatarRef` (identity or profile), and hide it with `avatarHidden` while an avatar is on its way to it. [`AvatarFlight`](./avatar-flight.mdx) does the flying: `avatarRef={flights.anchor(key)}`, `avatarHidden={flights.isLanding(key)}`.
- **`workingKey` is read once**, on the first render: a reply that is already thinking when it mounts starts its working animation once, a finished one never does.
