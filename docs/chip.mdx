# Chip

A labelled pill. A filter you can toggle, a tag you can remove, or a static token.

`Chip` is what shadcn calls `Badge`. Bloom's own [`Badge`](/docs/bloom/main/design-tokens) is a different component — a counter or a dot that rides on another control — so if you are porting a `<Badge>Draft</Badge>` from shadcn, this is the one you want.

## Basic

```tsx
import { Chip } from '@oxy.so/bloom/chip';

<Chip>Draft</Chip>
<Chip variant="solid" color="success">Published</Chip>
<Chip variant="subtle" color="warning">Needs review</Chip>
```

## Tone and fill

`color` picks the tone (`default`, `primary`, `success`, `warning`, `error`, `info`) and `variant` picks how loudly it is painted (`solid`, `subtle`, `outlined` — default `subtle`, a tinted chip). shadcn's four badge variants map onto that pair: `default` is `solid` + `primary`, `secondary` is `subtle` + `default`, `destructive` is `solid` + `error`, and `outline` is `outlined` + `default`.

Both come from `theme/accent-colors.ts`, the one resolver `Chip` and `Badge` share. Never derive a tint yourself by appending alpha to a token — an accent resolves to `rgb(...)`, so the appended-hex form parses back fully opaque and paints the label on its own colour at contrast 1.00.

## Data hues

Chip has a second colour system beside the status tones: DATA hues, for a category, a department, an objective. `hue` paints one of them instead of `color` + `variant`:

```tsx
import { Chip, resolveChipHueColors, type ChipHue } from '@oxy.so/bloom/chip';

<Chip size="medium" hue="lime">Shipped</Chip>
<Chip size="large" hue="gray">$1.290</Chip>
<Chip size="small" hue="purple">Design</Chip>
```

| hue | light | dark | theme source |
|---|---|---|---|
| `lime` | 200 / 800 | 950 at 60% / 500 | `success` ramp |
| `rose` | 200 / 800 | 950 at 60% / 500 | `negative` ramp (danger table) |
| `yellow` | 200 / 800 | 950 at 60% / 500 | `warning` ramp |
| `cyan` | 200 / 800 | 950 at 60% / 400 | `info` ramp |
| `blue` | 200 / 800 | 950 at 60% / 300 | accent ramp |
| `purple` | 100 / 600 | 900 at 50% / 300 | Tailwind purple re-anchored on `primary` — the same stops `AiProfileCard`'s delta chips use |
| `neutral` | neutral-200 / neutral-500 | neutral-800 / neutral-500 | `background-tertiary` / `text-secondary` |
| `gray` | neutral-100 / text | neutral-900 / text | `background-secondary` / `text-primary` |
| `soft` | neutral-100 / neutral-500 | neutral-900 / neutral-500 | `background-secondary` / `text-secondary` |

The hues sit BESIDE the accent recipe, not inside it: `resolveAccentColors` is untouched, and a chip without `hue` paints exactly as before. While `hue` is set, `color` and `variant` are ignored (no border); `selected` still promotes a pressable chip to the brand tone.

**The dark fills are translucent** (`color-mix(… 60%, transparent)`), so what paints depends on what the chip sits on. They are pre-mixed over `surface` — by default the page background (`background-full`: the card colour, dark neutral-925), where a dashboard table's chips typically sit. A chip on a card in dark mode should pass that card's colour as `surface`, or its fill reads a shade off. `resolveChipHueColors(theme, hue, surface?)` returns the same pair for a caller painting its own element.

## Filter pills

```tsx
<Chip variant="subtle" selected={active} onPress={toggle}>
  Music
</Chip>
```

`selected` promotes the chip to the brand tone rather than to a colour system of its own, and announces as `aria-pressed`. On web a keyboard user gets a `:focus-visible` ring — keyboard-only, so a mouse click does not leave one behind.

### Role

A pressable chip's ROLE decides which state attribute it carries, and the four are not interchangeable:

| `role` | web | native |
|---|---|---|
| `button` (default) | `aria-pressed` | `accessibilityState.selected` |
| `checkbox` | `aria-checked` | `accessibilityState.checked` |
| `radio` | `aria-checked` | `accessibilityState.checked` |
| `tab` | `aria-selected` | `accessibilityState.selected` |

`aria-pressed` is invalid on a radio and on a tab, which is what this component used to emit for every one of them. Put a `radio` inside a `role="radiogroup"` and a `tab` inside a `role="tablist"` — `ChipRow` takes that role for you.

A multi-select filter row (brands, sizes, amenities — any number on at once) is a `group` of `checkbox` chips: a screen reader then says "checked"/"not checked" rather than "pressed", which is what a filter is. `onCheckedChange` receives the next state.

```tsx
<ChipRow accessibilityLabel="Brand">
  {brands.map((brand) => (
    <Chip key={brand} role="checkbox" checked={picked.has(brand)} onCheckedChange={(on) => toggle(brand, on)}>
      {brand}
    </Chip>
  ))}
</ChipRow>
```

On web, `tabIndex` and `onKeyDown` are passed through for a roving-tabindex row (one tab stop, arrows move focus). Both are inert on native. A chip also forwards a ref to its pressable, so a row can focus one.

### `inverted`

`variant="inverted"` is a fourth fill and a different idea rather than a fourth loudness. At rest it is a hairline on the page (transparent fill, neutral-200 border, dark neutral-700); selected, it turns the page's own reading pair OVER — fill `text`, label `background`.

That pair is legible by construction in both modes and under every preset, which is what a filters sheet needs and what promoting to the brand tone cannot promise. It answers hover with its BORDER rather than the shared opacity step, because a pill with no fill has nothing to fade.

```tsx
<Chip size="2xl" variant="inverted" role="radio" selected={value === n} onPress={() => onChange(n)}>
  {String(n)}
</Chip>
```

## `ChipRow`

The pill row that scrolls sideways, with a fade at whichever edge has more behind it. Without the fade a clipped pill stops mid-glyph and reads as a rendering fault rather than as "there is more".

```tsx
import { Chip, ChipRow } from '@oxy.so/bloom/chip';

<ChipRow role="tablist" accessibilityLabel="Result types" fadeColor={card}>
  {tabs.map((tab) => (
    <Chip key={tab.value} size="xl" role="tab" selected={tab.value === value} onPress={() => onChange(tab.value)}>
      {tab.label}
    </Chip>
  ))}
</ChipRow>
```

| prop | |
|---|---|
| `gap` | between pills, default 8 |
| `contentInset` | side padding inside the scroller |
| `fadeColor` | the surface BEHIND the row — the row cannot know it. Default the page background; pass the card colour when the row sits on a card, or the fade blends into the wrong thing |
| `ringInset` | room kept for a pill's focus ring inside the scroller, taken back out with negative margins so the row still lines up. Default 4 |
| `role` / `accessibilityLabel` | the row's semantics, which belong to the caller |

The fade is web only (it is a CSS gradient); the row scrolls on both platforms.

## Removable

```tsx
<Chip onClose={() => removeTag(tag)}>{tag}</Chip>
```

The close affordance is its own control inside the pill, with its own label and its own hit slop.

## Sizes and icons

| `size` | height | padding-x | gap | icon | text |
|---|---|---|---|---|---|
| `small` | 24 | 6 | 4 | 14 | `caption-1-medium` |
| `medium` (default) | 24 | 6 | 4 | 16 | `body-medium` |
| `large` | 28 | 6 | 4 | 16 | `body-medium` |
| `xl` | 32 | 12 | 8 | 16 | `body-medium` |
| `2xl` | 40 | 16 | 8 | 18 | `body-medium` |

The scale used to stop at `large`, which is why five families grew a pill of their own rather than use this one: 28 tall with 6px sides is a TAG, and a filter you tap needs a target. `xl` is the filter/segment pill; `2xl` is the filters-sheet pill, and it pins a `minWidth` of 48 so a one-character label ("1", "8+") stays a pill rather than collapsing to a dot — a rung with a `minWidth` also centres its contents.

**Override the side padding with `paddingHorizontal`, never `paddingLeft`/`paddingRight`.** react-native-web maps the shorthand this component uses to `padding-inline`, which its atomic sheet ranks above `padding-left` whatever the array order — so a longhand override drops on WEB and lands on native. Two families were overriding it that way and had been drawing 6px on the web since they shipped. Better still: pick the rung that already carries the padding you want.

The close glyph is Remix `close-line` at 16. `startIcon` and `endIcon` take any node, and both are sized to the RUNG rather than to whatever was passed — an icon in a `small` chip and the same icon in a `2xl` one come out proportional.

## The focus ring

The `:focus-visible` ring is the accent ramp's 500, the colour every other ring in the library uses. It used to be the chip's own LABEL colour, which is the one colour guaranteed to be invisible: on a solid chip the label is white and so was the ring — measured 1.09:1 in light mode, black on black in dark. The ring is drawn with `outline-offset: 2px`, i.e. on the PAGE, so what it has to contrast with is the page; `accent[500]` clears 4.2:1 against it on all 64 presets in both modes.

## A pill does not shrink

In a flex row of chips — a filter bar, a tag list — each pill keeps its size and the row overflows, rather than every label squeezing into an ellipsis to make room. Inside one pill, the label yields first: a chip narrower than its own text ellipsises rather than spilling past its radius.

## Compatibility

The shared `size`, `tone` and `appearance` vocabulary coexists with the previously published family props. Explicit shared props take precedence over legacy spellings; existing size and state callbacks remain supported. New code should prefer the shared vocabulary.
