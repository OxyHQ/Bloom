# Android predictive Back

Bloom's optional Android host draws an existing retained tab page behind the
current pager. It does not duplicate, reparent, capture a bitmap of, or focus the
destination. Screen activity and media permissions remain owned by the committed
route. The native callback tracks progress; JavaScript receives one completion
with the navigation session and a process-unique gesture ID. Cancelling never
changes navigation history.

The host is compiled only with `bloom.predictiveBackEnabled=true`. This requires
React Native's public `ReactActivity.getBackNavigationCoordinator()` API and a
ReactAndroid build that actually contains that API. Until an upstream release
contains it, use the reviewed, version-pinned React Native source backport and
Expo's `buildReactNativeFromSource` integration. A Java source patch beside an
unmodified Maven AAR does not change the runtime. Default Bloom builds exclude
the feature and keep existing JavaScript navigation unchanged.

`TabPagerProvider` enables the public RN runtime mode for its mounted lifetime,
including cold-start pushed routes. It first verifies the native host exists and
both Expo guarded-navigation capabilities are present. New JavaScript delivered
to an older binary never enables the mode. Nested providers share ownership and
the final unmount disables it; applications should not add a second global toggle.
Expo's focused-owner registry retains its ordinary JavaScript fallback whenever a
focused navigator or pending navigation cannot delegate safely.

Native ownership is permitted only while the current screen is resumed, visible,
window-focused, and the coordinator reports native navigation enabled with no
JavaScript interceptors. Unknown JavaScript BackHandler subscriptions remain
interceptors. A pushed native screen, overlay, app backgrounding, changed
navigation session, changed destination, or resized viewport invalidates the
preview. No reflection into React Native internals is used.

The pager must admit and lay out the true historical destination before a gesture;
it may be nonadjacent. Until that view is ready, the callback still completes the
correct back action but displays the current page without a preview. This safe
fallback is not evidence of successful predictive rendering. Physical acceptance
must inspect the real destination, including a nonadjacent tab, and cancellation
must preserve the source route, selection, focus, scroll and media state.

A completed gesture holds the destination until JavaScript acknowledges its
`gestureId` using `settledGestureId`. Rejected or prevented actions must acknowledge
immediately; accepted tab changes acknowledge after the native pager has selected
the destination. A navigation-session change also invalidates the drawing. The
caller must retain the completed owner props during the accepted native handoff
so an early React render cannot flash the old source. Cancellation animation
respects Android's disabled animator setting.

Run the Android unit tests and default compilation against the published React
Native AAR, then compile and test the opted-in source set against the actual
patched ReactAndroid source. Both variants are required; passing only the default
variant does not compile the predictive host. Gesture-state unit tests alone do
not verify Android dispatcher arbitration, retained-page drawing, or native
lifecycle behavior; those require native integration and device acceptance.

## Expo integration

Enable the config plugin together with the source-build requirement, then run
prebuild and rebuild the Android binary. An OTA update cannot add a native host
or change ReactAndroid's dispatcher implementation. The Android config flag
sets the manifest's `enableOnBackInvokedCallback`; the Bloom plugin configures
the native library source sets. Both are required.

```js
export default {
  android: { predictiveBackGestureEnabled: true },
  plugins: [
    ['expo-build-properties', { android: { buildReactNativeFromSource: true } }],
    ['@oxy.so/bloom', { predictiveBack: true }],
  ],
};
```

Applications using Expo's experimental native stack also need the
[React Native Screens ownership adapter](https://github.com/software-mansion/react-native-screens/pull/5118)
or its reviewed, version-pinned 4.30 backport. The plugin's
`rnscreens.nativeBackOwnershipEnabled` property selects that adapter; setting the
property does not add its code to an unpatched Screens package. Install the
compatible RN, Expo and Screens source integrations together before enabling
native ownership. This preserves JavaScript overlay priority above pushed routes.

The Expo router must expose `registerNativeBackNavigation` and
`dispatchWithResult` on navigator helpers. Bloom registers the tabs navigator
only when both that public router contract and the native host exist. Older
routers/binaries retain their existing JavaScript Back handling. Overlays and
compact drawers temporarily release the registration and suppress the tab
preview. Overlay consumers still follow the existing `onRequestClose` contract:
a dismissible overlay closes itself on Back, while an intentionally blocking
overlay consumes Back. Merely registering overlay paint order does not supply a
close handler or prevent the ordinary JavaScript fallback from navigating.

Pass the current authority scope to the shared provider when account switching
does not unmount the navigation tree:

```tsx
<TabPagerProvider destinations={destinations} navigationScopeKey={sessionScope}>
  {children}
</TabPagerProvider>
```

The value is an opaque identity, not a credential. Change it whenever the viewer
or session authority changes. A scope change cancels pending previews even when
the route keys, selected tab and history remain identical.

Completion dispatches the router's ordinary `GO_BACK`, guarded against the exact
state previewed at reducer execution. It does not select a tab or rewrite history
independently. Prevented, stale, unhandled and no-op results settle immediately;
successful completion waits for the native pager's destination-selection event.
Repeated completion events are ignored by gesture ID, and a prevented gesture
does not disable a later retry against the same history.
