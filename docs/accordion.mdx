# Accordion

Sections that expand and collapse. Use it when a page holds more than a reader
needs at once and the sections are *independent* — an FAQ, a set of advanced
options, a long form split into stages.

```tsx
import { Accordion, AccordionItem, AccordionTrigger, AccordionContent } from '@oxy.so/bloom/accordion';

const [open, setOpen] = useState<string | string[] | undefined>('shipping');

<Accordion type="single" value={open} onValueChange={setOpen}>
  <AccordionItem value="shipping">
    <AccordionTrigger>When will it arrive?</AccordionTrigger>
    <AccordionContent>Two to four working days.</AccordionContent>
  </AccordionItem>
  <AccordionItem value="returns">
    <AccordionTrigger>Can I return it?</AccordionTrigger>
    <AccordionContent>Within 30 days, unopened.</AccordionContent>
  </AccordionItem>
</Accordion>
```

## Which prop decides what

| prop            | decides                                                              |
| --------------- | -------------------------------------------------------------------- |
| `type`          | `single` — one open section — or `multiple`                           |
| `value`         | which section(s) are open: a string for `single`, an array for `multiple` |
| `onValueChange` | receives the next value, or `undefined` when everything closes         |
| `disabled`      | per `AccordionItem`, a section that cannot be opened                   |
| `icon`          | per `AccordionTrigger`, appears before the label                   |
| `className` | on Root, Item, Trigger and Content: styles that component’s actual host |
| `contentClassName` | on Content: styles its measured inner body, including padding |
| `transition` | default `"spring"`, or `{ duration, easing? }` for a timed reveal and chevron |

**It is fully controlled — `value` and `onValueChange` are required.** There is
no uncontrolled mode and no `collapsible` flag: closing the last open section
means `onValueChange` hands you `undefined`, and whether you accept that or
re-open something is your decision, not the component's. That is what a wizard
(always something open) and an FAQ (nothing open is fine) actually differ by.

```tsx
// FAQ: allow everything closed.
onValueChange={setOpen}

// Wizard: never let the current step close.
onValueChange={(next) => setOpen(next ?? open)}
```

## When an accordion is the wrong shape

- **The user needs to compare sections.** Collapsing hides exactly what they are
  comparing.
- **The content is two lines.** More interaction than reading it would have been.
- **Something inside must be findable.** Browser find-in-page and screen-reader
  search do not see collapsed content, so an accordion is a bad home for
  anything a user might arrive looking for.

## Animation

The height transition is driven imperatively from a measured content height
rather than by a layout animation. On web that distinction is load-bearing:
an animation started from a Reanimated mapper never ticks, so the obvious
"animate the content in" silently does nothing. If you nest something that
animates its own height, let one of the two own the measurement.


### Authored surfaces and motion

Defaults remain in the base CSS layer on web; component and utility classes
can override geometry, typography and paint. On native the same class props
resolve after default styles. `contentClassName` belongs to the measured inner
body, so changing its padding also changes the reveal's measured height.
`style` remains available; a string trigger label inherits trigger typography,
and `textStyle` overrides the label explicitly.

```tsx
<Accordion value={open} onValueChange={setOpen}
  transition={{ duration: 250, easing: [0.23, 1, 0.32, 1] }}>
  <AccordionItem value="details" className="border-border">
    <AccordionTrigger className="px-0 py-4">Details</AccordionTrigger>
    <AccordionContent contentClassName="px-0 pb-4">
      <Text>Details stay mounted while the section is closed.</Text>
    </AccordionContent>
  </AccordionItem>
</Accordion>
```

`duration` is milliseconds; zero settles immediately. `easing` is a cubic Bézier
with x control points in `0..1`, defaulting to CSS ease. Omitting `transition`
keeps the existing spring recipes. The operating system's reduced-motion
preference takes priority, including changes while an animation is running.

Each trigger controls a uniquely identified, labelled region on web. A closed
region is inert and hidden from accessibility, while remaining mounted and
measurable. If a controlled collapse hides the focused field, focus returns to
its trigger. Native uses the corresponding hidden-descendant accessibility
properties. Input values therefore survive a close/open cycle without leaving
closed fields in keyboard navigation.

For a body controlled by an existing option rather than a disclosure button, use
[Collapsible](./collapsible.mdx). It shares the measured frame while avoiding a
fabricated trigger or missing `aria-labelledby` target. Accordion keeps its
spring defaults, linked region, trigger semantics and content padding.
