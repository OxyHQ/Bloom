# AgentCreator

A controlled editor for an agent's name, label, description, appearance and response preferences. The host owns the agent, saving, and the surrounding panel. The implementation is shared across web, iOS and Android; the platform entry points bind Bloom's existing select and popover surfaces.

```tsx
import { useState } from 'react';
import { AgentCreator, type AgentCreatorAgent } from '@oxy.so/bloom/agent-creator';

const [agent, setAgent] = useState<AgentCreatorAgent>({
  id: 'designer', name: 'Designer', label: 'Design', description: '',
  avatar: { preset: 'blue_beret' },
});

<AgentCreator agent={agent} onChange={setAgent} onClose={closePanel} />;
```

Mount under `BloomProvider` and give the editor a bounded height. Layout classes resolve through Bloom's styled primitives; web consumers must scan Bloom's built `lib/` in their NativeWind/Tailwind pipeline.

## Appearance

`agent.avatar` is an `AvatarCharacter` ([Agent Avatar](/docs/agent-avatar)): `{ preset }` or complete
parts and a paint. Every control writes one edit through `updateAvatarCharacter`, so the
saved character is always written out in full: choosing a body keeps the face, the hat and
the paint, and a `color` and a `bodyColor` are never held together.

The preview is 162px. The editor, eye chips and shape silhouettes use the shared production SVG
renderer. No hosted character engine is required. The controlled `AvatarCharacter`
contract and the profile/preferences layout are unchanged.

- **Shape arc:** 28 distinct silhouettes, including the 13 flat forms, in one 210px circular track (an unbounded index, spring, drag and wheel). Press a silhouette; arrows, Home and End select on web. Crossing between bodies retains the mounted avatar. RTL reverses horizontal movement.
- **Eye orbit:** the 12 current eye styles, including Todd and Clippo. Each body defines its own eye positions and size, so every style follows the layout of the shape it sits on.
- **Colors:** the named palette (`AVATAR_COLORS`) and a custom `#rrggbb` picker. The saved color remains the character paint; editing it retains the selected shape and parts.
- **Template, eyewear and accessory:** Bloom Select rows. Templates (`CHARACTER_TEMPLATES`) are creation choices, complete characters that start Felipe orange with sleepy eyes where the saved `blue_beret` preset is blue with oval ones; a character that is exactly one shows its name, and any edit shows Custom.

Upright eye chips orbit at a 116px radius; dragging or a mouse wheel rotates the orbit. Hover, focus, backgrounding and reduced motion pause automatic movement. The shape selector uses a 210px circular track, an unbounded index, spring, drag and wheel geometry. Choose a silhouette by pressing it; keyboard arrows, Home and End select shapes on web. BloomProvider’s direction reverses horizontal movement in RTL.

Appearance selection updates immediately. While the selected geometry is being prepared, a localized live status announces the work; an older asynchronous response cannot replace the latest selection. Only the two neighboring silhouette recipes are prepared during idle time, rather than loading the entire catalog.

Undo and redo retain up to 50 immutable character snapshots without changing the name, description, or speech preferences. A continuous color drag is one edit. Restore original returns to the character at the start of this editing session and can itself be undone. Switching agent IDs or receiving a genuinely external character replacement starts a new baseline; controlled echoes and profile-only changes retain history. On web, Ctrl/Cmd+Z and redo shortcuts work inside the editor without intercepting text input undo.

Nine glossy color presets and the shared custom picker edit both original and migrated bodies. The picker contains a saturation/brightness field, hue rail and hex entry. The visible field and every committed hex use the shared minimum skin lightness (L* 45); typing a darker hex shows its permitted normalized value. HSV state preserves the selected hue while dragging through gray; invalid hex input resets to the last emitted color. The sampled SVG field is memoized separately, so saturation/brightness dragging moves the thumb without rebuilding the color field. Choosing a named engine swatch clears its custom RGB override. Speech and appearance edits preserve the agent’s identity and unrelated fields.

Equivalent legacy shape IDs share one editor choice. Opening a saved avatar only aliases its selected chip; it never rewrites its shape or template. Selecting a different silhouette writes the chosen canonical ID. Catalog comparison stories retain all saved IDs for compatibility inspection.

The preview accepts pointer and touch reactions. **React** and **Work** buttons also support keyboard activation and play the SVG character's motion, including the hands and screen during work. Working returns to the interactive preview after its episode. Eye chips and body-only shape chips are static SVG portraits with the current paint; they do not use PNGs or 3D canvases.

The `clippo` preset is a grey open wire body with large ring eyes and asymmetric eyebrows. Its body and eyes are independent catalog choices: the Clippo eyes stay selected when another body is chosen (`{ shape: 'heart', eyes: 'clippo', … }`).

Eyewear and accessories use Bloom Select; `'none'` removes either. The retired bulb is absent from current choices and templates; saved `orb` values resolve to `none`. Headwear, bow and Tuft attach to each body's anchors, eyewear fits the final eye geometry and headphones use body anchors. The SVG renderer fits the chosen parts to the character and preserves its motion. Felipe uses the same reaction as Peri, keeping his orange paint and sleepy eyes; the beret follows its own motion instead of spinning with the body. Work keeps the chosen body and fitted parts. Catalog titles keep their English names by default; hosts translate them through `labels.characterOption(category, id, title)`, and control labels follow the editor locale.

## Preferences and speech

`AgentPreferences` carries `voice`, `speed`, `language` and `notifications`. Defaults are voice `alice`, speed `1`, language `auto`, notifications `true`. Supported speeds are `0.75`, `1`, `1.25`, `1.5`; languages are auto-detect, English, Turkish, Spanish, French, German, Japanese and Portuguese. `normalizeAgentPreferences()` restores supported values and limits voice identifiers to 200 characters.

`agent.handle` (optional) adds a **Username** row after the name; omitted, there is no row. A host whose agents have a unique username (Alia's) passes it and saves it with the rest.

`showPreferences={false}` draws the profile and the look alone: no voice, speed, language or notifications, and `agent.preferences` is left as it was. A host whose agents have no voice (Alia's) uses it.

Web previews use the browser's local device voice catalog and cancel playback when the editor unmounts. iOS and Android hosts provide `voices` (`{ id, name, language }[]`) and `onPreviewVoice(text, preferences)` to integrate their own speech provider; no speech dependency is added to Bloom. Without a provider, native speech selection and preview are disabled while saved preferences remain intact. Changing notification preferences updates data; delivering a notification belongs to the consumer.

`className` and `style` apply to the editor's outer node. Profile limits are 48 characters for name, 60 for label and 500 for description. `onClose` closes the host panel and does not save.

## Locale and shared primitives

Fixed labels, hints and accessible control names use the `AGENT_CREATOR_MESSAGES` catalog and Bloom’s 15 supported locales. `locale` overrides the root locale for this editor; `labels` overrides individual catalog entries. Agent names, descriptions and host voice names remain consumer data.

Profile inputs, textarea, select, switch, segmented control, close control and popover reuse Bloom’s current primitives. Original layout and interaction class chains are retained. Bloom’s active palette and materials supply their colors. The custom HSV picker reads `Field` membership: disabling the enclosing field disables its gestures, keyboard updates and hex input; field errors and descriptions associate with its inputs.

The original rainbow artwork and glossy color artwork are retained. Web applies the original shape mask and scroll blur; native uses SVG clipping and edge gradients for CSS effects its renderer cannot express. Native gesture hit areas remain rectangular, and native scroll fades do not apply a backdrop blur. These adaptations need device verification.

## Validation boundary

Tests verify profile and avatar edits preserve unrelated data, preference updates, host speech preview, color round trips, canonical shape choices, SVG rendering selection for every preview, and availability without a hosted engine. Jest does not execute gesture arbitration or the Reanimated frame loop; motion, wheel hit testing, custom picker dragging, and native speech providers require browser/device verification.

Track listeners retain their DOM attachment and read current callbacks; changing profile text does not rebuild shape/eye choices. A controlled eight-move browser drag recorded 144 listener additions/removals before cleanup and 54 afterward on the field and hue rail combined. Those totals include gesture/RNW listeners; the editor track hook itself reattached zero listeners. The color-field DOM remained unchanged during the drag. These small timing samples do not establish a frame-rate improvement. Tests also cover callback replacement, wheel removal, disabled pending gestures, unmount cancellation and translated choice updates.
