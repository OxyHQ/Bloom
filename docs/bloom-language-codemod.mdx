# Bloom language codemod

`packages/bloom-language-codemod` (`@oxy.so/bloom-language-codemod`, private)
rewrites an app's JSX as [Bloom language](./bloom-language.mdx) chains, only
where the result renders the same. Everything else stays JSX, embedded in the
chain with `Embed`, and the report says why.

## What it converts

A **region** is a JSX element the codemod converts whole, with everything
inside it. It is placed back in its JSX with `toElement(chain)` (a root `key`
is `toElement`'s second argument, a child's `.id()`).

| JSX | Language |
| --- | --- |
| React Native `View` | `VStack(…)`, or `HStack(…)` with `flex-row` |
| React Native `Pressable` with `onPress` or `onLongPress` | a stack with `.onPress()` / `.onLongPress()` |
| Bloom `Text` (`@oxy.so/bloom/typography`), its `variant` and `numberOfLines` | `Text(…runs)`, `.font()` / `.weight()`, `.lines()` |
| Bloom's typography components (`Muted`, `H2`, `Small`…), without a `className` | `Text(…runs).textStyle('muted')` |
| a Bloom component with a rule (`src/components.ts`, below) | its node, prop by prop |
| React Native `Text` | `RawText(…runs)`: React Native's own Text in the app preset's base face, then only what its chain names |
| Bloom `Button` (`@oxy.so/bloom/button`) | `Button(Icon(lead), Text(label), Icon(trail))` with `.style()`, `.tint()`, `.size()`, `.shape()`… as the language's Button parity cases draw it |
| a Bloom icon (`<RiHeart3Line size="sm" />`, or `size={16}`, a rung's points) | `Icon(RiHeart3Line).size('sm').foreground('primary')` (a bare Bloom icon paints primary) |
| `className` | modifiers through the className table, in the language's layer order |
| `md:`, `dark:`, `web:`… and, on a `Pressable`, `hover:`, `active:`, `focus-visible:` | `.when(condition, (v) => …)` |
| `testID`, `accessibilityLabel`, `accessibilityHint` | `.testID()`, `.label()`, `.hint()` |
| `{cond ? <A/> : <B/>}`, `{isX && <A/>}` (a boolean by its form) | the branches as nodes |
| any other child (`{items.map(…)}`, a component) | `Embed(…)`, its own regions converted inside it |

A className converts only when **every** class lands exactly. One class that
does not keeps the element JSX. Each class goes through the className table
(`packages/bloom-language/codemod/classnames.generated.json`):

- A width class and a colour class (`border-b border-border`) are one
  `.border(role, width, edge)`; `absolute` and its insets are one
  `.position({…})`; frames join one object.
- A margin is `.margin()`, `flex-1` is `.flex('1')` (Tailwind's grow 1,
  shrink 1, basis 0%), `overflow-hidden` is `.clipped()` (a corner alone
  does not clip), and `pl-4`/`left-0`/`border-l` are the physical `left`
  side.
- The table's words (`mx-auto` is "centred in a column"), its tokens, app
  classes, motion and missing modifiers are reasons, never guesses.
- Two classes setting one thing (`p-4 px-2`, two colours) are a conflict: in
  CSS the later rule wins, in the language two paddings add.
- A text style on a `View` is a reason: NativeWind does not hand it to the
  `Text` inside, and the language's environment would.
- Two corner classes of one corner (`rounded-t-3xl rounded-tl-lg`) are a
  reason (`corner-overlap`): which wins is Tailwind's rule order on the web
  and React Native's own precedence on native.
- A class the app's own stylesheet draws differently from Bloom's (an app
  `@theme` or `:root` that redefines `--radius-lg`) is a reason (`app-theme`).
  The codemod compiles the app's CSS entry and Bloom's with Tailwind and
  compares every class's declarations, variables resolved.

Measured on the corpus and kept as reasons (`measuredDifference` and
`rounding` in `src/resolve.ts`):

- A colour at an opacity (`bg-primary/10`, `text-white/60`): the language
  writes it inline on the web as a `color-mix()`, and react-native-web's
  `normalizeColor` drops any colour that is not a `var()`, so nothing is
  drawn. The Chrome check below renders the mix directly, past
  react-native-web, so it does not see this; the jsdom web suite does.
- `text-white/70` and the like: NativeWind writes a fixed colour at an opacity
  as an 8-bit hex alpha, rounded down (`#ffffffb2`), where `0.7` is 178.5/255.
- A line height as a ratio or a letter spacing in em whose product has more
  than two decimals: NativeWind rounds it (`20.625` to `20.63`).

## Bloom components

Each rule in `src/components.ts` names the node a Bloom component is, as the
language's parity cases pair them (`packages/bloom-language/parity/*.cases.tsx`):
its constructor's arguments (a prop, a `Binding` of a value prop and its
setter, the text children, an options object, a chip's label and glyphs), its
modifiers by Bloom prop, and its children. Each value has a form: a static
token (checked against the spec's enum or the node's densities, or a scale
turned round, `radius="radius-16"` to `'lg'`, `spacing={12}` to `'md'`), a
string or number (any expression without JSX, carried as it is), a flag, a
handler, a Bloom icon, a view (an element converted where it can be, else
`Embed`), or an array of data (`items`, carried as it is, the elements inside it
too, each a region of its own where it converts). A prop the rule does not name, or a value in another form, keeps
the element JSX with the reason `Node:prop`.

| Bloom | Language |
| --- | --- |
| `Switch` | `Toggle([checked, onCheckedChange])` |
| `GroupedSection`, `GroupedSectionItem` | `GroupedSection(...rows).title().caption()`, `GroupedSectionItem(title).leadingView().trailing().value()` |
| `ScreenScrollView` | `ScrollView(...children).keyboardTaps().onEndReached(action, threshold).refreshable([refreshing, () => onRefresh()], tint).scrollIndicators(value, axis)` |
| `SettingsSection`, `SettingsValueField` | `SettingsSection(label, ...children).trailing()`, `SettingsValue(text)` |
| `TextFieldInput` (bare, or in a `TextField` shell with its `TextFieldIcon`s), `Textarea`, `Search`, `Checkbox`, `Field` | `TextField([value, set], label)`, `TextEditor([value, set], label)`, `Search([value, set])`, `Checkbox([checked, set], label)`, `Field(label, ...children)` |
| `Card`, `Item`, `Chip`, `ResponsiveGrid` | `Card(...children)`, `Row(title)`, `Chip(Icon, Text, Icon)`, `Grid(...cells)` |
| `Divider`, `Loading`, `Badge`, `IconCircle`, `Avatar`, `EngagementAction` | `Divider()`, `Loading()`, `Badge(content)`, `IconCircle(icon)`, `Avatar(source, { variant, name })`, `Action(icon, label, { activeIcon, pop })` |
| `ChatEmptyState` | `ChatEmptyState({ title, description, illustration, action })` |
| `PageHeader`, `SpinnerIcon`, `Slider`, `Admonition` | `Header(title).inPage()`, `SpinnerIcon()`, `Slider([value, set], label).bounds(min, max)`, `Admonition(Text(…)).style(type)` |
| `Tabs` with its `TabsTrigger`s | `Tabs([value, set], TabItem(value, label).count(n)…).style(variant)` |
| `SegmentedControl` with its `SegmentedControlItem`s (each its `SegmentedControlItemText`) | `Segmented([value, set], Option(value, text)…)`, `type="tabs"` its `.tabs()` |
| `SettingsSelect`, `AvatarGroup`, `List` | `SettingsSelect(label, [value, onChange], items)`, `AvatarGroup(items)`, `List(items).headerContent().emptyState()` |
| `VirtualList` | `VirtualList(data, (item, index) => row).itemKey().onEndReached(action, threshold)` |

A binding takes the setter Bloom reads (`onValueChange`, else `onChangeText`);
both given is a reason. Some rules hold only where the Bloom component reads
nothing around it:

- A bare `TextFieldInput` draws its own shell with the enclosing `Field`'s
  state, and the `TextField` node draws its shell as it is; an input inside a
  `TextField` or a `Field` in the file stays JSX (a `Textarea` or `Search`
  inside a `Field` too). A shell around it from another file is not seen. A
  `TextField` holding one input and its glyphs converts with it, as one node
  (`.icon()`, `.trailingIcon()`, the shell's `size` and `invalid`).
- A node drawn only inside a Bloom component (a `ScrollView` in a `Screen`, an
  `Action` in an `EngagementBar`) has both sides of its parity drawn in one.

A scroll view's `refreshControl` of React Native's `RefreshControl` is
`.refreshable(binding, tint)`: the binding is its `refreshing` and a setter a
pull calls with `true`, which calls `onRefresh` with no arguments, as React
Native does (`() => onRefresh()`; a function of no parameters is carried as
it is). Its tint paints the control's `tintColor` and `colors` from one role,
so a `tintColor` and `colors` of the same theme colour are its tint, and a
`tintColor` alone (iOS only, Android's spinner left the platform's) stays
JSX. `showsVerticalScrollIndicator={false}` is
`.scrollIndicators('hidden', 'vertical')` (`true` is `'visible'`; horizontal
alike).
A static `contentContainerStyle` of paddings and a gap, each a space token
(`{ padding: 16, gap: 12 }`), is `.contentMargins(edge, token)` and
`.spacing(token)`: the language's content container style holds the same keys.
A `contentContainerClassName` stays JSX: Bloom lays a class out in a view of
its own inside a content container that grows to the viewport (and reports no
intrinsic height to a content-sized screen), where the margins pad the content
container itself. A prop a rule names in `differs` is kept with that reason.

A compound element converts whole, with its parts (`parts` and `partOf` in a
rule), as the language's parity cases draw it: each child is one of its parts
by the part's own rule, a block comment, or a `.map()` whose arrow function
returns a part (`tabs.map((tab) => <TabsTrigger … />)` is
`tabs.map((tab) => TabItem(…))`, its array carried as it is). Anything else
among the children, or a part that does not map, keeps the whole element JSX;
a part is never converted alone (`TabItem:part`). The language keys a part by
its value, so a part's `key` is not carried. The parity draws an array a
region carries as the corpus's sample items (`ITEMS`), the same on both sides.

A `VirtualList`'s `renderItem` is its row only as an arrow that reads its item
and index (`({ item }) => <Post post={item} />` is `(item) => Embed(<Post post={item} />)`,
its element converted where it can be); a named function may read the rest of
FlashList's argument, so it is a reason. Its header, footer and empty state are
JSX elements only: a name there may be a component, which the node does not draw.

`PageHeader` is `Header(title).inPage()`: Bloom's PageHeader on every platform,
iOS in a native stack included (a `Header` alone is the system bar there).

A route's `Screen` is its `screen()` body (`SCREEN`): a default-exported
function component (named, not async, with no return type, its name read
nowhere else) whose every return is a Bloom `Screen` becomes
`export default screen(function Name(props) { … })`, each `Screen` the body's
root: its one child, with the Screen's props as the root's screen modifiers
(`scroll` is `.screenScroll()`, `kind` `.screenKind()`, `documentScroll`,
`headerPlacement`, `contentClearance`, `navigationScope`, `colorPreset`,
`testID`). No `header` is `.header(false)`; a header element is
`.header(Embed(…))` (an element, or a `const` holding one), drawn as it is,
since a `Header` node would be the system bar on iOS in a native stack where
Bloom's PageHeader stays in the page. The route converts whole: one Screen that stays JSX keeps the others JSX
(`screen:route`). Its parity draws the root with the language's `ScreenHost`,
as `screen()` does.

Kept as JSX with their reason (`KEPT`): a `Screen` anywhere else, `Dialog`
(presented from the view that owns it, `.dialog(isPresented, Dialog(...))`) and
`DropdownMenu` with its parts (the language's `Menu` is the platform's own menu
on Android and iOS, Bloom's DropdownMenu only on the web and as a fallback).
Components removed in Bloom 22 (`SettingsRow`, `SettingsCard`, `GlyphButton`, `CloseButton`,
`ButtonGroup`, `ButtonGroupItem`) are reported as `removed:` with their Bloom 22
replacement (`REMOVED`, from `docs/migrating-to-22.mdx`): the app moves to it in
its Bloom 22 upgrade.

Beside the rules: an icon's `fill` read from Bloom's `useTheme()` is
`.foreground(role)` and a `width` and `height` of one number its `.size()`;
`accessibilityRole` is `.role()`; a static `style` (an object literal, a
module `StyleSheet`'s style, or a list of them) is read as the Tailwind
utilities that write the same declarations (`gap: 12` is `gap-3`), so it lands
through the className table. React Native's `flex: 1` is no utility (Tailwind's
`flex-1` is grow, shrink and a 0% basis). A style built at runtime stays JSX.

A className chosen at runtime between two static strings by one plain
condition (`active ? 'bg-primary px-3' : 'bg-muted px-3'`, or a template
literal holding one such choice, `` `text-sm ${unread ? 'font-semibold' :
'font-medium'}` ``) converts when both branches resolve and write the same
modifiers in the same order, only values differing: each differing value is
chosen in place, `.background(active ? 'primary' : 'mutedFill')`. The
condition is a read without a call (names, properties, literals, comparisons,
`!`, `&&`, `||`), since the chain reads it once per value. Branches that write
different modifiers, more than one choice, and `cn()` (its merge is the app's
own) stay JSX as `dynamic-className`.

## Running it on an app

The app is read, never changed, unless `--write` is given. In the Bloom
worktree (`bun install` there first):

```bash
cd packages/bloom-language-codemod
bun src/cli.ts ~/Oxy/Mention/packages/frontend --out /tmp/mention-codemod --fixtures
# a CSS package the app installs and Bloom does not:
#   --package @oxy.so/app-preset=~/Oxy/oxy/packages/app-preset
# the app's CSS entry when it is not global.css or styles/global.css:
#   --css path/to/global.css
```

It writes to `--out`:

- `report.md` and `report.generated.json`: elements considered and converted,
  the reasons by frequency, and each element that stayed JSX with its reasons;
- `files/`: the converted files (with `--write`, the app's files in place);
- with `--fixtures`, the parity corpus: `corpus.generated.tsx` (each region's
  before and after, every carried value a hole), `fixtures.generated.json`
  and `app.generated.css` (the app's stylesheet for the corpus's classes).

Then prove it:

```bash
CODEMOD_CORPUS=/tmp/mention-codemod npx jest -c jest.config.js --selectProjects 'parity native'
CODEMOD_CORPUS=/tmp/mention-codemod npx jest -c jest.config.js --selectProjects 'parity web'
```

Each run writes `parity-native.json` / `parity-web.json` beside the corpus.
Without `CODEMOD_CORPUS` the suites render the package's own sample
(`parity/sample-app`, regenerated with `bun run corpus`).

## The proof

Each region is rendered twice in Jest through the language's parity harness
(`packages/bloom-language/parity/support`), under Bloom's provider, in light
and dark:

- **Before:** the JSX as written, drawn by NativeWind's own runtime
  (`react-native-css`'s components, as the app's Babel preset rewrites React
  Native's imports; React Native's `Text` as `@oxy.so/app-preset` 6.8.0 bundles
  it, in Bloom's base face, `parity/support/app-text.ts`) over the app's
  Tailwind stylesheet, compiled for native
  with the preset's `inlineRem: 16`, and in the jsdom document on the web.
- **After:** the chain the codemod wrote.
- **Holes:** every value carried over (a handler, a text run, an embedded
  element, a condition, an array of data) is the same stand-in on both
  sides, so a region is rendered without the app around it. An element's type
  arguments (`<SegmentedControl<Cadence>`) draw nothing and are left out.
  A region with a condition is rendered twice more, every condition `false`
  (`name (false)`), so both branches of what it chooses are proven.

Native compares committed host trees; the web compares each element's tag,
attributes and the CSS that reaches it. The spellings both sides may use for
one value are folded first, each a rule React Native or the browser applies
(`parity/support/normalize.ts`, `parity/support/web-css.ts`): shorthands as
longhands, a border side with no width as no side, React Native's defaults
where nothing inherits them, rem at 16px, `calc()` evaluated, lengths at
Chrome's 1/64 px, a third as `33.3333%`.

A colour at an opacity (`.background('mutedFill/30')`) is written inline as a
`color-mix()` of a variable, which jsdom's style probe drops, so the web suite
cannot compare it. Chrome does:

```bash
node scripts/verify-colors-chrome.mjs /tmp/mention-codemod
```

It renders each such class the corpus converted, Tailwind's rule beside the
language's inline mix, under the theme's variables in both schemes (written
by the web suite as `theme-variables.json`), and compares the computed
colours (`parity-chrome-colors.json`).

## Reviewing a run

1. Read `report.md`: the conversion rate, then the reasons. A reason that is a
   table row (`annotated`, `token`, `measured-difference`) is a decision for
   the table or the language, not for the app.
2. Run both parity suites on the corpus. A failure is a codemod bug: the
   region must stay JSX until the codemod or the language is fixed. Never
   ship a region whose parity fails.
3. Typecheck the app with the converted files (`--write` in a branch of the
   app): the language's types check every token and every text run.
4. Format with the app's Biome; the codemod prints with recast and does not
   format.
5. Review the diff for readability: regions full of `Embed` are correct but
   gain little; convert the embedded components first.
