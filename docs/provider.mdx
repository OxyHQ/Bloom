# BloomProvider

Mount one `BloomProvider` above every render branch, including loading UI. It
composes theme, image resolution, haptics and scroll storage without importing a
router. It is exported from both `@oxy.so/bloom` and `@oxy.so/bloom/provider`.
Without `scrollAdapter`, automatic route restoration is inactive.

```tsx
import { BloomProvider } from '@oxy.so/bloom/provider';
import { expoRouterScrollAdapter } from '@oxy.so/bloom/scroll/expo-router';

<BloomProvider scrollAdapter={expoRouterScrollAdapter}>
  <App />
</BloomProvider>
```

Keep the adapter reference stable. Vite and other router integrations supply their
own `ScrollRouterAdapter`; Expo consumers now pass the adapter explicitly instead
of receiving an implicit router dependency.

Visual hosts (`ToastOutlet`, `SurfaceHost`, portal/dialog outlets) stay outside the
provider: their position determines stacking, and mounting duplicate outlets draws
duplicate surfaces. `Screen` scopes coordinated geometry and motion locally.

The original depth hazards remain: `useScrollRestoration()` throws outside its
provider, and legacy `useMinimizeState()` creates a private fallback without its
provider. Mounting providers beneath a sibling scroll region recreates those
failures. New screen chrome uses the local `Screen` shared values, rather than
sharing one global motion state across retained routes. `useTheme()` also throws
outside its provider, including an early-return splash branch on cold start.

`PortalProvider`/`PortalOutlet` are native infrastructure; the web portal uses its
own DOM implementation. Choose outlet placement deliberately and mount each once.
