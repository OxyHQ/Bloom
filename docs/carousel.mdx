# Carousel

A gallery you slide through: prev/next buttons above, a track that snaps to each slide, and dots below.

```tsx
import { Carousel, CarouselItem } from '@oxy.so/bloom/carousel';

<Carousel accessibilityLabel="Product photos">
  {photos.map((photo) => (
    <CarouselItem key={photo.id}>
      <Image source={photo} style={{ height: 240, borderRadius: 12 }} />
    </CarouselItem>
  ))}
</Carousel>
```

`accessibilityLabel` is required: the region announces itself as a "carousel" (web `aria-roledescription`) and each slide as "N of M", so callers never number their own slides.

## Props

| Prop | Default | |
| --- | --- | --- |
| `header` | | Leading content of the arrows row, e.g. a section title. Header at the start, arrows at the end — one row, not two. |
| `showArrows` | `true` | Prev/next buttons. They disable at each end; use your app's breakpoint to hide them on small screens. |
| `arrowsPlacement` | `'header'` | `'header'` shares the title row; `'overlay'` centers controls vertically on the track's start/end edges without reserving a controls row. |
| `showDots` | `true` | Position indicator, one dot per stop (see below); never shown for a single stop. Each dot is a button. |
| `align` | `'start'` | Where a slide rests when it snaps: `'start'` or `'center'`. |
| `gap` | `16` | Space between slides, px. |
| `inset` | `0` | Horizontal padding of the header row, the dots and the track's two ends. Slides scroll under it to the edges, and a start-aligned slide snaps to the inset rather than flush. |
| `index` | Uncontrolled | Optional zero-based child index. Requests that child’s measured stop; clamps to the available list. |
| `onIndexChange` | | Uncontrolled: the slide in view changed. Controlled: a user navigation request; pair with `index`. |
| `previousLabel` / `nextLabel` / `dotLabel` | Localised via `BloomProvider locale` | Override the button names. |

`CarouselItem` fills the track by default, so exactly one slide is in view. Pass a smaller `width` to peek the next slide (pair it with `align="center"` for a centred gallery).

## What it looks like

Column gap 16; arrows are small secondary icon buttons 8 apart; dots are 6px-tall pills 6 apart — the active one 16 wide in the text colour, the rest 6 wide in the tertiary surface (neutral-200, dark neutral-800), hovering to neutral-400 (dark neutral-600); width and colour ease over 200ms, skipped under reduced motion.

The arrows are Bloom's `Button` (full pill, 18px glyph), per Bloom's radius rule for button-like controls.

## How it works

The track is a real horizontal `ScrollView` — a native scroller rather than a transformed strip — so swipe, momentum, trackpad and (on web, once the track has focus) arrow-key scrolling come for free.

- **Snapping** is CSS `scroll-snap` on web and `snapToOffsets` on native (computed from the measured slides, centre-adjusted for `align="center"`).
- **Positions are measured** with each slide's `onLayout`, never derived from a width, so mixed-width slides keep working.
- **One list of stops drives everything.** A stop is a distinct place the track can rest. Slides narrower than the track share one: every slide that cannot reach the start edge clamps to the same end offset, so the end is ONE stop however many slides it holds. Arrows, dots, snap offsets, the active dot and `onIndexChange` all read that list, so no dot or arrow can scroll nowhere. A shared stop reports its first slide, except the end, which reports the last.
- **The arrows step from where the track is**, to the nearest stop before or after the scroll offset — never by slide index, which near the end names a slide whose stop the track already rests at.
- **The active stop is the one nearest the scroll offset**, compared against where each stop RESTS (inset and centring included), not where its slide sits in the content.
- **The ends are pinned, not measured.** Within 1px of either end the first/last stop is active, so the last dot always lights at the far end.
- Programmatic scrolls animate unless the user prefers reduced motion.

Web CSS (snap, hidden scrollbar, the track's `:focus-visible` ring, dot transitions) is self-injected through `adoptStyleSheet` on `dataSet` hooks — nothing to copy into a consumer stylesheet.

## Overlay controls

```tsx
const { width } = useWindowDimensions();
<Carousel accessibilityLabel="Featured categories" arrowsPlacement="overlay"
  showArrows={width >= 640} showDots={false}>
  {categories.map(category => <CarouselItem key={category.id} width={172}>
    <CategoryTile category={category} />
  </CarouselItem>)}
</Carousel>
```

Overlay buttons are 44px, inset 8px from each track edge. A supplied `header`
remains above the track; an omitted header reserves no row. The space between
controls permits pointer interaction with slides. Their logical placement and
chevrons mirror in RTL; scroll events, imperative navigation and native snap
positions normalize each platform's offset convention. Reduced motion disables
programmatic scroll animation in either placement.

## Controlled galleries and thumbnails

```tsx
const [index, setIndex] = useState(0);
<>
  <Carousel accessibilityLabel="Product photos" index={index} onIndexChange={setIndex}>
    {photos.map(photo => <CarouselItem key={photo.id}>
      <Image source={photo.source} style={{ height: 360 }} />
    </CarouselItem>)}
  </Carousel>
  {photos.map((photo, i) => <Button key={photo.id} onPress={() => setIndex(i)}>
    {photo.label}
  </Button>)}
</>
```

`index` counts children, not the deduplicated stops used by dots. Several narrow
children can share a stop at the end; selecting one does not rewrite the owner's
index to that stop's last child. Negative indices clamp to zero, indices beyond
the list clamp to its last child, fractional indices truncate, and nonfinite
values use zero. An empty list does not scroll or notify.

Controlled arrows and dots request a new index through `onIndexChange`; the
owner accepts by updating `index`. A swipe or keyboard/trackpad scroll reports
once it settles (150ms without scrolling, after the pointer/drag is released).
Declining that request restores the controlled selection. Prop-driven movement,
initial positioning, resize and list changes do not echo through the callback,
and intermediate smooth-scroll positions never overwrite a requested thumbnail.

Keep stable child keys. Measurements follow those keys through reordering and
replacement, while the selected position remains a child index. Initial layout,
resize and list changes reposition immediately; a changed selection animates
unless reduced motion is enabled. Omit `index` to retain the existing carousel
behavior and its live `onIndexChange` notifications.
