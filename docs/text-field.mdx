# TextField

A composable text input. `TextField` is the field itself; put a `TextFieldInput` inside it, plus any of `TextFieldIcon`, `TextFieldSuffix` and `TextFieldGhost`. The field tracks focus, hover, invalid and disabled state and hands it to those parts, so the whole chrome reacts as one.

## Look

Coloured by Bloom's theme through the same ramps as `Button`:

|                 | `md` (default) | `sm` |
|-----------------|--------------------|---------|
| height          | 36                 | 32      |
| shell padding-x | 8                  | 6       |
| text inset      | 4                  | 4       |
| text            | 14/20 regular      | 14/20 regular |
| icon            | 20                 | 20      |
| radius          | 10                 | 10      |

The shell uses the shared secondary surface with a 2px **inset** ring: transparent at rest, the semantic border under the pointer, and primary while focused. A focused field darkens its placeholder to the text colour.

- **Invalid** tints the fill red (`red-100`; red-950 at 60% over the page in dark), reddens the placeholder and the icons, and drops the ring.
- **Disabled** dims the fill, the value, the placeholder and the icons, drops the ring, and (web) shows the `not-allowed` cursor over the control.

All of it is resolved by `text-field/shared.ts`, which `Textarea` and `InputGroup` read too, so the three always agree.

| part | typography | colour |
|------|-----------|--------|
| `TextFieldLabel` | `body-medium` 14/20, 4px above the shell, 2px between text, asterisk and glyph | text; asterisk in the error colour; info glyph is Remix `RiInformationFill` at 16px in `foreground-icon-quaternary` |
| `TextFieldHint` | `caption-1-medium` 12/16, tracking .15, 1px top inset, 4px below | secondary; error colour when invalid |

Every size above is a `TYPE_SCALE` step (`typography/scale.ts`), set in Inter. Adornments use Remix icons (`RiMailLine`, `RiQuestionLine`… from `icons/remix`).

## Basic

```tsx
import { TextField, TextFieldInput } from '@oxy.so/bloom/text-field';

<TextField>
  <TextFieldInput
    label="Email"
    value={value}
    onValueChange={setValue}
    keyboardType="email-address"
  />
</TextField>
```

`label` is required and is the input's accessible name. Without an explicit `placeholder` it doubles as the placeholder; pass `placeholder={null}` for none.

## One input needs no wrapper

```tsx
<TextFieldInput label="Email" value={value} onValueChange={setValue} />
```

`TextFieldInput` on its own wraps itself in a `TextField`, so the common case is one element. Reach for the explicit `TextField` when you have more than one part to put in it, or when you need `invalid` or `radius` on the field.

## With an icon

```tsx
<TextField>
  <TextFieldIcon icon={RiMailLine} />
  <TextFieldInput label="Email" value={email} onValueChange={setEmail} />
</TextField>
```

The field lays its children out in a row and focuses the input when you click anywhere in it (web).

## Which parts need the field

`TextFieldIcon` and `TextFieldSuffix` read the field's focus, hover and invalid state, and **throw** when rendered outside a `TextField` — they have nothing to colour themselves against, and a part that renders anyway would look finished while never reacting to anything. The message names what is missing:

```
TextField parts must be rendered inside a <TextField>.
```

`TextFieldInput` does not throw: a missing field is how it knows to wrap itself. `TextFieldLabel` sits above the field by design, and `TextFieldGhost` reads no state — both render anywhere.

## Sizes, label and hint

```tsx
<TextFieldLabel required tooltip>Email</TextFieldLabel>
<TextField size="sm" invalid={invalid}>
  <TextFieldIcon icon={RiMailLine} />
  <TextFieldInput label="Email" value={email} onValueChange={setEmail} />
  <TextFieldIcon icon={RiQuestionLine} position="trailing" />
</TextField>
<TextFieldHint invalid={invalid}>We never share it.</TextFieldHint>
```

## Leading addon (phone input)

```tsx
<TextField leadingAddon={<CountryCodeSelect />}>
  <TextFieldInput label="Phone Number" placeholder="(123) 000-0000" value={number} onValueChange={setNumber} />
  <TextFieldIcon icon={RiQuestionLine} position="trailing" />
</TextField>
```

`leadingAddon` puts a CONTROL in the leading slot — e.g. [`PhoneInput`](./phone-input.mdx), whose country-code select sits inside the field. With an addon the shell tightens its left padding to 4px (`pl-1`) and keeps its right one (`pr-2`, `pr-1.5` on `sm`), in longhands; the addon is `shrink-0`, 2px before the input. It replaces a leading `TextFieldIcon` — don't render both.

- **Focus within.** While the addon holds focus (web) the shell draws its focus ring — but not while the focused control reports `aria-expanded="true"`: while the list is open the ring falls back to the hover ring, and comes back when it closes. The input's `focus:` placeholder colour stays the input's alone.
- **Clicks.** A click on the addon stops there: the shell's own click focuses the input, which would take focus from the control that was pressed.

The finished component, with the vendored country list and flags, is [`PhoneInput`](./phone-input.mdx) (`@oxy.so/bloom/phone-input`).

## Disabled

```tsx
<TextField disabled>
  <TextFieldIcon icon={RiMailLine} />
  <TextFieldInput label="Email" value={email} onValueChange={setEmail} />
</TextField>
```

`disabled` on the field makes the input non-editable (and, on web, a real `disabled` input that leaves the tab order), sets `aria-disabled` and paints every part disabled. An input with `disabled` or `editable={false}` reports the same state up to the field on its own, so the icon beside it dims too.

## Validation

```tsx
const [value, setValue] = useState('');
const [touched, setTouched] = useState(false);
const invalid = touched && !value.includes('@');

<TextField invalid={invalid}>
  <TextFieldInput
    label="Email"
    value={value}
    onValueChange={setValue}
    onBlur={() => setTouched(true)}
  />
</TextField>
<TextFieldHint invalid={invalid}>Enter a valid email</TextFieldHint>
```

`invalid` paints the field in the negative palette, sets `aria-invalid` on the input and reaches every part through context. `TextFieldInput` takes its own `invalid` too, for the wrapper-less spelling.

## Floating label

```tsx
<TextField>
  <TextFieldInput floatingLabel label="Email" value={email} onValueChange={setEmail} />
</TextField>
```

The label starts inside the field and animates to a caption at the top on focus or once there is a value. State drives it, not CSS, so web and native behave identically; reduced motion snaps instead of animating. Its taller geometry is Bloom's own; its colours are the input palette above.

## Multiline

```tsx
<TextField style={{ minHeight: 96, alignItems: 'flex-start' }}>
  <TextFieldInput label="Bio" value={bio} onValueChange={setBio} multiline />
</TextField>
```

For a real multiline field — rows, auto-grow, a character counter — use [`Textarea`](/docs/bloom/main/textarea), which shares this shell.

## Suffix

```tsx
<TextField>
  <TextFieldInput label="Workspace" value={url} onValueChange={setUrl} />
  <TextFieldSuffix label="domain">.oxy.so</TextFieldSuffix>
</TextField>
```

## Components

### `TextField`

| Prop | Type | Description |
|------|------|-------------|
| `invalid?` | `boolean` | Paints the field in the negative palette and exposes it via context. |
| `disabled?` | `boolean` | Disables the input and paints every part disabled. |
| `size?` | `'md' \| 'sm'` | 36 or 32 tall. Default `md`. |
| `radius?` | `number` | Corner radius of the chrome, default `10`. A large value (999) reads as a pill. |
| `leadingAddon?` | `React.ReactNode` | A control before the input (the phone input's country code); the shell's left padding becomes 4px. |
| `style?` | `StyleProp<ViewStyle>` | Override the container style. |
| `children?` | `React.ReactNode` | The input, plus any icon / suffix / ghost. |

### `TextFieldInput`

Accepts React Native's `TextInputProps`, plus:

| Prop | Type | Description |
|------|------|-------------|
| `label` | `string` | Required. The accessible name, and the default placeholder. |
| `value?` / `onValueChange?` | `string` / `(v: string) => void` | The controlled value. |
| `placeholder?` | `string \| null` | Overrides the label as placeholder; `null` for none. |
| `invalid?` | `boolean` | For the wrapper-less spelling. |
| `disabled?` | `boolean` | Disables the input; the field around it paints disabled. |
| `size?` | `'md' \| 'sm'` | For the wrapper-less spelling. |
| `floatingLabel?` | `boolean` | Material-style animated label. Default `false`. |
| `inputRef?` | `RefObject<TextInput \| null>` | Merged with the field's own ref. |

### `TextFieldIcon`

| Prop | Type | Description |
|------|------|-------------|
| `icon` | `React.ComponentType<SVGIconProps>` | A Bloom icon component, drawn at 20px in the tertiary colour; dimmed when disabled, red when invalid. |
| `position?` | `'leading' \| 'trailing'` | `leading` (default) sits 2px before the input; `trailing` 8px after it. Place it in that order. |

### `TextFieldLabel`

A visible label rendered ABOVE the field, outside it. `required` appends the asterisk, `tooltip` the info glyph.

```tsx
<TextFieldLabel>Workspace</TextFieldLabel>
<TextField>
  <TextFieldInput label="Workspace" value={name} onValueChange={setName} />
</TextField>
```

### `TextFieldHint`

The caption under the field. `invalid` paints it in the error colour; `nativeID` and `style` are optional.

### `TextFieldSuffix`

Inline trailing text — domain suffixes, units. `label` is its accessible name; `accessibilityHint` and `style` are optional.

### `TextFieldGhost`

Greyed completion text drawn behind the input, for "type `acme`, see `acme.oxy.so`". Takes the typed prefix as `children` and the suggested remainder as `value`; it is `aria-hidden`.

## Accessibility

- Clicking anywhere in the field focuses the input (web).
- `label` is the input's `accessibilityLabel`; the floating label itself is hidden from assistive tech so it is not announced twice.
- On web the browser's own focus ring is stripped, because it follows the input's box rather than the field's and pokes out of a pill's corners. The inset ring IS the focus signal.
- `invalid` and `disabled` reach the input as `aria-invalid` / `aria-disabled` — react-native-web reads only the `aria-*` spellings.
- Invalid state paints the chrome. Surface the reason as text under the field — colour alone is not an announcement.

## Recipes

### Password with visibility toggle

```tsx
const [show, setShow] = useState(false);

<TextField>
  <TextFieldInput
    label="Password"
    value={password}
    onValueChange={setPassword}
    secureTextEntry={!show}
  />
  <Button icon={show ? <RiEyeOffLine /> : <RiEyeLine />} accessibilityLabel={show ? 'Hide password' : 'Show password'} onPress={() => setShow(!show)} appearance="outline" tone="neutral" />
</TextField>
```

### Search

Reach for `Search` rather than rebuilding it: it is a `TextField` at the pill radius with the magnifier, the clear button and the keyboard settings a query field wants.
