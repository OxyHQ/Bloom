# Project Board

## Controlled records

`ProjectBoard<Item>` composes arbitrary records into caller-controlled columns. Use it
when a product owns its properties, grouping, permissions and persistence:

```tsx
import { ProjectBoard, BoardDragHandle } from '@oxy.so/bloom/project-board';

<ProjectBoard
  variant="embedded"
  columns={groups.map((group) => ({
    id: group.id,
    title: group.name,
    items: group.records,
  }))}
  getItemId={(record) => record.id}
  getItemLabel={(record) => record.title}
  dragMode="handle"
  allowReorder={false}
  renderCard={(record, column, { isDragging }) => (
    <RecordCard record={record} groupId={column.id} dragging={isDragging}>
      <BoardDragHandle accessibilityLabel={moveLabel(record)} onPress={() => openRecord(record.id)}>
        <RecordTitle record={record} />
      </BoardDragHandle>
      <RecordProperties record={record} />
      <MoveRecordAction record={record} />
    </RecordCard>
  )}
  renderColumnHeader={(column) => <GroupHeader name={column.title} />}
  renderColumnFooter={(column) => <AddRecord groupId={column.id} />}
  onMove={({ itemId, fromColumnId, toColumnId }) =>
    updateRecordGroup(itemId, fromColumnId, toColumnId)
  }
  readOnly={!canEdit}
/>
```

The board never copies or mutates records. A drop requests `onMove`; the caller
updates `columns` after accepting the move. Data changes from collaboration,
optimistic updates and rollback render immediately. `renderEmptyColumn` supplies
optional empty content, `columnWidth` defaults to 273, and `columnStyle` customizes
the column frame. The board uses the existing `AppShellPanels` deck and its viewport. Provide a
parent with bounded height: both modes fill it and each column uses the existing
`ScreenScrollView`. Use `variant="grouped"` for subgroups: Bloom owns the outer
Screen viewport, ordinary vertical scrolling, collapsible lane headers and each
bounded board. Consumers pass data and callbacks; they do not measure heights or
wrap the board in another scroller.

```tsx
<ProjectBoard
  variant="grouped"
  lanes={subgroups.map((group) => ({
    id: group.id,
    title: group.name,
    columns: group.columns,
    collapsed: group.collapsed,
  }))}
  getItemId={(record) => record.id}
  renderCard={renderRecord}
  renderLaneHeader={(lane) => <GroupLabel name={lane.title} />}
  renderLaneActions={(lane) => <GroupMenu groupId={lane.id} />}
  renderColumnFooter={(column, lane) => <AddRecord groupId={column.id} subgroupId={lane.id} />}
  onLaneCollapsedChange={setGroupCollapsed}
  onMove={(move, laneId) => updateRecordGroup(move, laneId)}
/>
```

`renderLaneHeader` supplies content inside Bloom's collapse trigger; independent
menus belong in `renderLaneActions`. Moves and column-order callbacks identify the
lane, and the footer receives its full lane descriptor. Repeated record or column
IDs in different lanes remain independent. Lane expansion is controlled, and
scrolling does not snap between groups.

`ProjectBoard` uses one canvas in its ticket and controlled modes: the original
columns and card material, interaction controller, Gesture Handler recognizer,
measured presence animation and Reanimated landing overlay. `variant="embedded"`
hides the template header while preserving the existing panel deck, PageHeader,
column scrolling, card material and layout behavior from the ticket board. Render slots supply product-owned content without
converting records into tickets. There is no separate board component or HTML
drag engine.
Mouse movement activates after five pixels; native touch activates after 180 ms.
The template keeps whole-card dragging. Use `dragMode="handle"` for cards with
editable properties and put `BoardDragHandle` around the title or a separate grip.
Keep independent inputs, selectors and move buttons outside that handle. Its
`style` and `className` apply to the outer layout container, and optional `onPress`
activates the record on a normal click while suppressing the click after a drag.

On web, focus a handle and press space to pick up, arrows to move, space to commit,
or Escape to cancel. Left/right follow the locale direction. Native accessibility
actions move between adjacent columns and, when enabled, up/down. An explicit move
menu can provide direct access to distant columns on every platform. Handle labels
come from the consumer; `getItemLabel` supplies the pickup announcement. Shared
instructions and action labels use Bloom's Project Board locale catalog.

Each mounted board scopes its own gesture. Measurement keys include both column
and item ID, so a record can appear in several groups. A move changes only the
source occurrence and destination; unrelated groups remain intact. Permissions,
source membership and destination existence are checked again at drop time.
Canceling discards the transient preview while retaining incoming collaborative
changes. `readOnly` disables drag, keyboard and accessibility moves; the caller
must also disable mutation actions supplied in slots and enforce authorization
when persisting.

`allowReorder` defaults to true. Completed moves include `toIndex` in the full
destination column and an optional `beforeItemId` insertion anchor. Set
`allowReorder={false}` when rows use a product-defined sort; same-column moves then
produce neither a reordered preview nor a callback. `onMove` remains a request:
only updates to the controlled `columns` persist it. The existing panel-deck viewport owns horizontal scrolling. Both modes register
their `ScreenScrollView` column scrollers for edge auto-scroll. The
viewport also reveals newly created tickets without consumer width arithmetic.
`fillColumns` shares spare room through the deck. Optional `onColumnOrderChange`
enables controlled column reordering; omit it when the product does not persist
column order. `renderColumnHeader` supplies the PageHeader title content and
`renderColumnActions` supplies its actions.

## Ticket template

A shared project board for web, iOS and Android. It keeps the original five-column ticket layout, compact member avatars, priority/project chips, sort/filter/display menus, empty-column illustration, create-more flow and ticket detail panel.

```tsx
import { ProjectBoard } from '@oxy.so/bloom/project-board';

<ProjectBoard
  initialColumns={columns}
  members={members}
  projects={['Bloom', 'Product']}
  currentUserId="maya"
  onColumnsChange={saveColumns}
/>
```

`initialColumns` is copied on mount. Updates are local until `onColumnsChange` persists them. Limits are display metadata, as in the original board; reaching a limit does not reject a ticket. The package has no demo people or fake activity. The Project Board template outside `src/` supplies the original columns, people, descriptions, discussion, resources and token series.

Tickets carry description, assignees, priority, project, favorite state and comments. `resources` supplies external resource chips; `tokenUsage` supplies the existing `TokensChartCard`. Opening a card calls `onTicketOpen`. `initialTicketId` opens a detail panel on mount; web also recognizes `#ticket=<id>` and hash changes. Provide `onCopyTicketLink` and `onCopyTicketId` for the product's native clipboard and routing integration; web defaults to the current URL and browser clipboard. Copy failures are announced.

Creation and detail panels use `useDialogControl()` through Bloom's platform-bound Dialog. Creation trims fields, rejects a blank title and supports creating several tickets without closing. Detail edits persist immediately; description editing has Save/Cancel. Comments reject whitespace and append without replacing history.

Drag uses Gesture Handler and Reanimated on both platforms: mouse movement activates after five pixels; touch activates after 180 ms. Hit testing chooses the column underneath the pointer before its ticket positions, so a short neighboring column cannot steal a drop. Empty columns accept drops; dropping outside or cancelling leaves the original order intact. Filtered moves preserve hidden tickets. Drag sets sorting back to manual. Pointer proximity scrolls columns and the board during movement.

On web, Enter opens a ticket; space picks it up, arrows move it, space commits and Escape restores the previous order. Left/right follow the locale direction. Native screen-reader actions move up/down or to an adjacent column. Fixed strings use the Project Board catalog in all fifteen Bloom languages. Direction follows the existing locale/I18nManager hook; content supplied in props remains product data.

## Motion and verification

The original Tailwind class recipes, custom SVG glyphs, empty-state geometry and reveal timing remain in the shared NativeWind content. Ticket presence expands/collapses the measured slot and its 6px gap over 320ms while fading, scaling between 0.7 and 1, and changing blur between 6px and 0. Initial tickets stay at rest. Removed tickets become inaccessible immediately; the gesture owner remains mounted through a long cross-column drag. Drops keep the visual overlay for the 320ms trip to the measured destination, hiding the resting card until arrival. Cancelling a cross-column preview discards that projection without replacing newer controlled data. The template preserves the original 272px drawer, 325ms reveal, 273px columns and shell insets while reusing Bloom’s current Sidebar. Buttons, chips, fields, selectors, menus, tooltips and charts compose the current Bloom primitives. Palette and material follow the current Bloom theme.

Web runs the original create Genie displacement field and the detail Genie’s cached perspective bands: live content remains interactive at rest; visual copies are inert and have rebased SVG IDs. The dialogs retain Bloom’s imperative lifecycle, focus handling and overlay stack through `presentation="custom"`. Entry/exit reverse from the current shape when interrupted and respect reduced motion. Detail snapshots target Bloom’s shared chart SVG and rebase its paint references. Its plot reveal waits for the Genie handoff; `TokensChartCard animate={false}` paints the full plot without a reveal frame loop and changing back to `true` restarts from zero. Raw injected CSS uses normal selectors, including the dark shadow, rather than CSS-module syntax.

React Native can animate the original stretch, scale, translation and timing through Reanimated, but it does not expose a View’s live pixels as `feDisplacementMap` input or DOM clipping bands. Those two pixel deformations remain specific to web. Native touch/paint behavior has not been verified on a physical device; platform CSS exports do not establish pixel equivalence.

Chrome at 1440×900 compared the original and Bloom side by side: create measured 560×230px and detail 609×876px in both, with the original descriptions, people, resources, activity and token data. Real browser checks cover wide/compact, dark and RTL rendering, keyboard moves, creation, favorites, comments and Escape. Focused Jest cases cover data transitions, shared gesture configuration, controlled previews and cancellation, duplicate occurrences, filtered insertion anchors, permission changes, keyboard focus, interactions and default/custom Dialog completion semantics. Browser keyboard capture is intentional because react-native-web consumes space before bubbling. The polish browser checks now establish pointer drops within a column, across columns after holding for 1200ms, and outside-column cancellation; all finish without a residual overlay. These pointer checks cover LTR; RTL pointer dragging and edge auto-scroll remain unverified. At 390×844 the detail measures 374×828 with 8px outer insets. Native long creation forms have a bounded ScrollView that preserves submit taps. A local headless Chrome frame sample over 1.6 seconds measured 90 frames in the reference and 61 in Bloom, with maximum gaps of 103ms and 130ms respectively; equivalent geometry and timelines do not establish equal rendering performance.
