# Hooks

`@oxy.so/bloom/hooks` is the set of behaviours Bloom's components share. They
are exported because apps hit the same problems, and because a second copy of
any of them drifts.

```tsx
import { useInteractionState, useDelayedLoading, useGutters } from '@oxy.so/bloom/hooks';
```

## `useInteractionState`

Press and hover state as plain booleans, with the handlers to wire up.

```tsx
const { state: pressed, onIn, onOut } = useInteractionState();

<Pressable onPressIn={onIn} onPressOut={onOut} style={[base, pressed && dim]}>
```

Bloom uses this rather than `Pressable`'s function-form `style`, which
NativeWind's css-interop swallows — taking the base container style (background,
radius, border, shadow) with it. That failure is silent and total: the component
renders unstyled and nothing errors.

## `useDelayedLoading`

Holds a flag true for a fixed delay, then flips it false.

```tsx
const settling = useDelayedLoading(300);        // true for 300ms, then false
const showContent = !settling && !isFetching;
```

It takes the DELAY, not the loading flag: `useDelayedLoading(delay, initialState?)`.
Use it to guarantee a minimum on-screen time. A spinner that appears for 80ms
and vanishes is worse than no spinner — the flash reads as a glitch, and the
user cannot tell what happened.

## `useThrottledValue`

A value that updates at most every N ms. For anything that re-renders a
expensive tree on a continuous input — a drag, a scroll position, a typed
query.

## `useDebouncedValue`

The value once it has stopped changing for N ms. Key a search request on it,
so typing a place name asks once when the typing pauses rather than once per
keystroke (`docs/place-picker.mdx`).

```tsx
const term = useDebouncedValue(query.trim(), 250);
const places = useQuery({ queryKey: ['places', term], queryFn: …, enabled: term.length >= 3 });
```

## `usePressAnimation`

The shared press transform, so a press dip is the same everywhere.

## `useGutters`

The screen's horizontal insets, from one place, so a header and the content
below it agree about where the margin is.

## `useContainerWidth`

The width the component was laid out at, or `null` before the first layout.

```tsx
const { width, onLayout } = useContainerWidth();

<View onLayout={onLayout}>
  {width !== null && width >= 600 ? <Wide /> : <Narrow />}
</View>
```

A component measures ITSELF rather than the window, so a page split into a
content column and a side column picks its layout from the space it has rather
than from the size of the screen. The width is rounded and only stored when it
changes, so a resize that lands on the same pixel does not re-render.

Nine families across housing and music reached into `listing-details` for this
before it lived here.

## `moveItem` / `dragTarget` / `dragShift`

The list maths behind every drag-to-reorder surface — a track list, a queue, a
photo grid. Pure, so the drag, the keyboard path and the move buttons share one
definition of "move".

```tsx
const target = dragTarget(drag.from, drag.dy, ROW_HEIGHT, rows.length);
const shift  = dragShift(index, drag.from, target, ROW_HEIGHT);   // px, per row
onReorder(moveItem(rows, drag.from, target));
```

Degenerate input, where the three copies of this used to disagree:

- `moveItem` clamps and rounds the TARGET into range, but refuses an
  out-of-range SOURCE — clamping that would silently move the wrong item.
- `dragTarget` answers `from` when there are no rows or the row has not been
  measured (`rowHeight <= 0`). Answering `0` sends the row to the top of a list
  nobody has measured yet.

`@oxy.so/bloom/queue-panel` publishes the same three as `moveQueueItem`,
`queueDragTarget` and `queueDragShift`; they are re-exports.

## `useHapticFeedback` / `useHaptics`

Haptic feedback through Bloom's optional-peer boundary — a no-op when
`expo-haptics` is not installed, rather than a build failure.

Mount `BloomHapticsProvider` if the app needs to turn haptics off globally
(a user setting, or a platform where they are inappropriate).

Use `useHapticFeedback()` for actions: `tap()`, `confirm()`, `selection()`,
`toggle(on)`, `success()`, and `error()`. Android uses view feedback and falls
back to older Android constants where necessary. It is silent if an older peer
lacks Android view feedback. On iOS, selection and notification feedback fall
back to a light impact when the installed peer lacks those methods. The
existing `useHaptics()` strength callback remains available for consumers that
need it. Both APIs are inert on web and when haptics are disabled.

`TabPagerBottomBar` uses `tap()` on selection. On Android with an older
`expo-haptics` that lacks `performAndroidHapticsAsync`, this makes its feedback
silent; navigation is unchanged. Install a compatible peer to restore feedback.

```tsx
const haptics = useHapticFeedback();
// After a user commits a change:
haptics.confirm();
```

## `useImagePreload` / `preloadImage`

Fetch an image before it is rendered — the transition into a full-screen viewer,
the next page of a carousel.

## `useIsRtl`

Whether the layout is mirrored, read from where each platform's layout engine
reads it: `<html dir>` on web (observed live, so a language switch re-renders),
`I18nManager.isRTL` on native (fixed for the process — `forceRTL` applies on the
next launch). The server snapshot is `false`.

Use it only for what a logical style key cannot express — a `translateX` or
`scaleX` sign, a `transformOrigin`, a floating `side`. Insets should be the
CSS logical keys (`paddingInlineStart`, `insetInlineEnd`), which mirror with no
hook; in a reanimated mapper, React Native's `paddingStart` spelling is dropped
on web. Capture it into a worklet as a multiplier and list it in the deps:

On web, react-native-web resolves logical insets against a `dir` prop on an
ancestor `View`, not against `<html dir>` — so a root that uses them also
needs `<View dir={useIsRtl() ? 'rtl' : undefined}>` (Bloom's page-frame
families do this themselves).

```tsx
const dir = useIsRtl() ? -1 : 1;
const style = useAnimatedStyle(() => ({ transform: [{ translateX: dir * 24 * p.value }] }), [p, dir]);
```

## `useAppForeground`

`true` while the app is in the foreground: the native app reports `active`, or
the web tab is visible. React Native Web reports `document.visibilityState`
through the same `AppState`, so one subscription serves both platforms. It counts
as foreground until the platform positively reports otherwise (an unavailable or
unanswered `AppState` is not evidence the app went away); iOS's transient
`inactive` counts as away. On a screen, prefer
[`useScreenVisible`](/docs/screen#visible-to-the-reader), which adds the Screen's
activity.

## `useItemAccessibilityFocus`

Screen-reader focus that follows the current item of a collection that keeps the keyboard itself — a file list whose arrows move its selection while the list stays the one focused control, as Finder's list keeps the key view and VoiceOver says each row the selection reaches. Each item hands its mounted view under its key; when the current key changes, focus moves to that item's view (after the same settle as `useAccessibilityFocus`), or as the view mounts, for a virtualized list that draws the row it scrolled to. Only a change moves it: the collection appearing with an item current, or a row scrolled away and drawn again, takes nothing from where the cursor is. Native only. A platform that follows the screen reader's focus with the keyboard's only for controls of the keyboard (OxyOS, Android) leaves the keyboard on the collection.

```tsx
const focusItem = useItemAccessibilityFocus(selection.focus);

{items.map((item) => (
  <Row key={item.key} ref={(view) => focusItem(item.key, view)} item={item} />
))}
```

## `mergeRefs`

Combines several refs into one callback.

Note the return type: `(instance: T | null) => void`, **not**
`React.RefCallback<T>`. That is deliberate — the plain function type stays
assignable across duplicate copies of `@types/react` in a consumer's tree,
which the branded type does not.
