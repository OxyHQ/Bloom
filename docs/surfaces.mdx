# Surfaces

The surface stack is Bloom's **one** imperative overlay API. `alert()`,
`confirm()` and `prompt()` present from anywhere — no ref, no local `open`
state, no second provider — and a single `<SurfaceHost>` renders whatever is on
the stack.

```tsx
import { alert, confirm, prompt } from '@oxy.so/bloom/surfaces';

alert('Saved', 'Your changes are live.');

if (await confirm({ title: 'Leave this page?', confirmLabel: 'Leave' })) {
  router.back();
}

const name = await prompt({ title: 'Name this list', placeholder: 'Reading list' });
```

## Why these are not components

They are answers to a **question**, so the call site wants a value back, and a
component you have to mount cannot be awaited. `confirm()` resolves to a
boolean and `prompt()` to a string or `null`. That difference is the whole
reason this API exists beside [`Dialog`](/docs/bloom/main/dialog):

- **Surfaces** — a one-shot question from inside an event handler, in code
  that has no render tree of its own (a mutation callback, a service).
- **Dialog** — a surface with real content that belongs to a screen.

## Mounting

`<SurfaceProvider>` wraps the app; `<SurfaceHost>` renders the stack. **Both
stay out of `BloomProvider`** — where an outlet sits is an app decision, and a
second mount would duplicate every surface.

A surface renders inside whatever wraps its host, and on web a portal keeps the
context of where it was rendered. When the provider sits above the app's own
providers (the Oxy SDK's `OxyProvider` mounts it) and surfaces need those
contexts (i18n, data, the app shell), mount a `<SurfaceHost />` beneath them:
inside a `<SurfaceProvider>` it takes the stack over, and the provider stops
rendering its own until that host unmounts. Only one host draws at a time.

```tsx
<OxyProvider>          {/* mounts <SurfaceProvider> */}
  <AppProviders>
    <App />
    <SurfaceHost />     {/* surfaces see AppProviders' contexts */}
  </AppProviders>
</OxyProvider>
```

## Two calls in a row STACK, they do not queue

```tsx
alert('First');
alert('Second');   // paints over the first; dismissing reveals it
```

If you want them one after the other, `await` the first. This is deliberate: a
queue would delay an urgent surface behind a trivial one, and there is no
general rule for which of two surfaces matters more.

### Cancel a confirmation owned by a session

Pass an `AbortSignal` to `confirm` or `confirmWithSuppression` to dismiss
that confirmation when its owner becomes invalid. Other surfaces stay open.
An already-aborted signal presents nothing. Aborting resolves `confirm` as
`false`, including for `dismissible: false`; the suppressible variant returns
`confirmed: false` and the current checkbox value. The first answer or abort
wins. The answer may arrive before its exit animation completes: the signal
remains attached until the confirmation is removed and its host layers unmount.
An abort during that exit removes the confirmation without changing the answer.

```tsx
const controller = new AbortController();
const answer = confirm({
  title: 'Continue?',
  signal: controller.signal,
  onClosed: stopObservingOwner,
});
// On session invalidation or owner teardown:
controller.abort();
```

Callers must still verify that their session remains valid before acting on a
confirmed answer: the session can change after the confirmation settles.
Keep the owner and its observer alive until `onClosed`, which runs once
asynchronously after stack removal and host unmount, including abort or reset
before mounting or failure to install the signal listener. The callback and
result are independent; for a surface that never mounts, the callback can run
before the caller observes the result. It does not guarantee a painted frame or
close other surfaces.

## "Don't ask again": `confirmWithSuppression()`

A desktop alert's suppression checkbox. `confirm()` keeps resolving a plain
boolean; this resolves both answers:

```tsx
import { confirmWithSuppression } from '@oxy.so/bloom/surfaces';

const { confirmed, suppressed } = await confirmWithSuppression({
  title: 'Close 12 tabs?',
  confirmLabel: 'Close tabs',
  suppressionLabel: "Don't ask again", // required: the checkbox's words
  suppressed: false, // optional initial state
});
```

It takes every `confirm()` option plus `suppressionLabel` and `suppressed`. The
checkbox (Bloom's `Checkbox`) sits under the description. `suppressed` is
reported however the surface closed, so a cancelled answer can be remembered
too. Also on the `surfaces` object as `surfaces.confirmWithSuppression`.

## The keyboard (web)

- **`confirm()`** opens with focus on the confirm button: <kbd>Enter</kbd>
  confirms, <kbd>Esc</kbd> cancels (when `dismissible`), <kbd>Tab</kbd> reaches
  Cancel.
- **`confirmWithSuppression()`** opens with focus on the checkbox:
  <kbd>Space</kbd> toggles it, <kbd>Enter</kbd> confirms from anywhere but a
  focused button (a focused Cancel still cancels), <kbd>Esc</kbd> cancels.
- **`prompt()`** focuses its field with the text selected, so typing replaces
  a `defaultValue` (rename flows): <kbd>Enter</kbd> submits, <kbd>Esc</kbd>
  cancels from inside the field.

Closing any of them returns focus to the control that opened it.

## `present()` is the general form

```tsx
const size = await present<string>(
  (surface) => <SizeList onPick={(s) => surface.dismiss(s)} />,
  { placement: 'bottom', title: 'Pick a size', label: 'Pick a size' },
);
```

The content resolves the promise by calling `surface.dismiss(value)`. Note what
it does **not** call: `Dialog`'s own `close()`. The value has to reach the
`present()` promise, and it resolves on the press — a surface closed any other
way resolves with nothing, which reads as the user having cancelled.

### Cancel a surface when its owner ends

Use `presentCancelable` when the surface belongs to a session or another
cancelable operation. Its required `signal` closes only this surface and
resolves the promise with `undefined`; an already-aborted signal presents
nothing. The first dismissal or abort wins. Other stacked surfaces remain open.
If a child belongs to the same session, present it with the same signal too.

```tsx
import { presentCancelable } from '@oxy.so/bloom/surfaces';

const choice = await presentCancelable<string>(
  (surface) => <SizeList onPick={(size) => surface.dismiss(size)} />,
  { title: 'Pick a size', signal: controller.signal, onClosed: stopObservingOwner },
);
// choice is string | undefined; verify the session again before acting.
```

The same function is available as `surfaces.presentCancelable`, including from
inside another surface. Existing `present` and `SurfaceControls` remain
unchanged. Abort removes the entry from the stack immediately, without its exit
animation; React removes the rendered content when it commits the update. If
the content is private, the consumer must also guard its own data against a
session change. Dismissal without abort keeps the normal exit animation.

The result can resolve while that animation is still running. Keep the owner
and its session observer alive until `onClosed`, which runs once asynchronously
after the entry leaves the stack and every mounted host layer unmounts. It also
runs if the signal was already aborted, the stack resets, or the surface closes
without ever mounting. It also runs if signal setup fails or the required signal
is missing; in those cases the result rejects. The signal remains attached until
then, so an abort during exit removes the entry while preserving an earlier
result. The callback can run before the caller observes a result when the
surface never mounts.
`onClosed` does not guarantee a painted frame or close independently stacked
children.

### Content beside the sheet that moves with it

A sheet that the screen behind it reacts to (a video that shrinks above its
replies) passes a shared value as `progress`; Bloom writes the sheet's
presented fraction into it on the UI thread, `0` closed to `1` up, through
every frame of a drag. `backdrop` sets the paint behind the sheet, so the
screen can stay fully visible while a tap on it still dismisses. A fixed
height for content that loads in comes from the frame's `size`:

```tsx
const progress = useSharedValue(0);

present((surface) => <Replies onClose={() => surface.dismiss()} />, {
  placement: 'bottom',
  scrollable: false,
  progress,
  backdrop: { blurIntensity: 0, dimOpacity: 0 },
  frame: { key: 'replies', size: { height: windowHeight * 0.62 } },
});
```

## Buttons

A built-in surface's buttons carry `shouldCloseOnPress: false` and dismiss
through `surface.dismiss(result)` for that reason. A `'cancel'` colour on a
`DialogAction` is purely visual; it does not make the button dismiss.

The default words — Confirm, Cancel, and `alert()`/`prompt()`'s OK — are localised via `BloomProvider locale`, resolved where the surface renders; `confirmLabel`, `cancelLabel` and a button's `text` still win.
