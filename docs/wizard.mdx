# Wizard

Two parts for any flow that walks the user through steps: `WizardProgress` on
top, `WizardFooter` at the bottom. The steps themselves are the app's — these
parts only show where the user is and move them along.

```tsx
import { WizardFooter, WizardProgress } from '@oxy.so/bloom/wizard';
import { Screen, ScreenScrollView } from '@oxy.so/bloom/screen';

const steps = [
  { title: 'Property type' },
  { title: 'Address', description: 'Only people you confirm see the exact address.' },
  { title: 'Photos' },
  { title: 'Publish' },
];

function Flow() {
  const [step, setStep] = useState(0);
  const last = step === steps.length - 1;
  return (
    <Screen
      scroll="auto"
      bottomBar={
        <WizardFooter
          onBack={step > 0 ? () => setStep(step - 1) : undefined}
          onNext={last ? publish : () => setStep(step + 1)}
          nextLabel={last ? 'Publish' : 'Next'}
          nextDisabled={!canContinue}
          loading={publishing}
        />
      }
    >
      <ScreenScrollView contentContainerStyle={{ paddingLeft: 24, paddingRight: 24 }}>
        <WizardProgress steps={steps} current={step} />
        {renderStep(step)}
      </ScreenScrollView>
    </Screen>
  );
}
```

## `WizardProgress`

One segment per step, sharing the width. Each segment is a decorative
[`Meter`](/docs/stat-bar) — the shared neutral-200 (dark neutral-700) track and
the ACCENT fill; it used to fill with text-primary, a near-black bar reading as
ink rather than as a measurement. Done steps are filled, later steps are empty,
and the current step fills to `currentProgress` (default `0.5`, so it always
reads as under way). Under the bar: the count ("Step 3 of 8") with an
optional `action` on its right — a "Save and exit" button, say — then the
current step's title as a heading and its description.

| prop | default | |
| --- | --- | --- |
| `steps` | — | `{ key?, title, description? }[]` |
| `current` | — | 0-based index, clamped |
| `currentProgress` | `0.5` | 0..1 fill of the current segment |
| `formatStepCount` | `Step n of total` | localise the count line |
| `hideTitle` | `false` | keep only the bar and the count |
| `action` | — | node right of the count |
| `headingLevel` | `1` | the title's heading level on web |
| `accessibilityLabel` | count + title | the bar's name |

The bar is ONE `progressbar` over the whole flow: `aria-valuemax` is the number
of steps and `aria-valuenow` the done steps plus the current step's progress, so
a screen reader hears "Step 3 of 8, Photos" with a value, not eight unnamed
bars. The segments themselves carry no role, which is what `Meter`'s
`decorative` is for. The fill eases on web (300ms) and snaps under reduced
motion.

## `WizardFooter`

Back is the underlined text action on the left (omit `onBack` on the first
step and it disappears; Next stays right). Next is a primary `Button` at
`large`; `loading` is the Button's own loading state and keeps its width.
An optional `status` line ("Draft saved") sits between them from 480 wide.

**Shared footer composition.** `WizardFooter` delegates placement, safe-area handling and occupied bottom edges to `PageFooter`. In `Screen.bottomBar`, Screen positions and measures it and reserves the exact footprint for the step's scroller; it creates no second sticky layer or clearance claim.

Outside that slot, `sticky` defaults to true: PageFooter keeps it in normal flow and pins it to the bottom of its scroll container on web, above occupied app navigation. Native keeps it in flow, so place it after the scroller. `sticky={false}` uses normal flow on both platforms, including inside a card or dialog. Flow placement already reserves the footer's height; do not add `usePageFooterInset()` padding for it.

The shared footer adds native bottom safe area when no navigation edge already occupies it. The wizard retains its opaque background, top hairline, 16px vertical padding, the page gutter for its sides (PageFooter's 16px, 24px from `sm`, the same inset the content uses, so the bar lines up with it), underlined Back, status and Next controls. Web container queries hide the status line below 480px without React updates on each resize pixel.
