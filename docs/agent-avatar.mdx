# Agent Avatar

`AgentAvatar`, AgentCreator, MultiAgentChat, avatar selectors and chat previews use the same
TypeScript/WebGL engine in `runtime/`, and they all describe an avatar the same way: a
**character**. There is no second model, no second renderer and no fallback.

```tsx
import { AgentAvatar, AgentAvatarProvider } from '@oxy.so/bloom/agent-avatar';

<AgentAvatarProvider runtimeUrl="https://example.com/bloom-character/runtime.mjs">
  <AgentAvatar character={{ preset: 'blue_beret' }} size={128} interactive label="Peri" />
  <AgentAvatar character={{ preset: 'blue_beret', accessory: 'crown', color: 'orchid' }} />
  <AgentAvatar
    character={{ shape: 'heart', eyes: 'oval', eyewear: 'none', accessory: 'bow', bodyColor: '#ffd838' }}
  />
</AgentAvatarProvider>
```

## The character

One flat shape, the same in `AgentAvatar`, `AgentCreator` (`agent.avatar`), `MultiAgentChat`
and your saved JSON:

| Field | Values |
| --- | --- |
| `preset` | `AVATAR_PRESETS`: a named template. Any part or paint you leave out comes from it. |
| `shape` | `AVATAR_SHAPES`: the 21 catalog bodies. |
| `eyes` | `AVATAR_EYES`, or `'none'` to hide the face. |
| `eyewear`, `accessory` | `AVATAR_EYEWEAR`, `AVATAR_ACCESSORIES`; `'none'` removes it. |
| `color` | `AVATAR_COLORS`: named paint. |
| `bodyColor` | An exact `#rrggbb`. It wins over `color`. |
| `eyeSpacing` | 0.5 to 1.5, a multiplier on the shape's eye separation. |

Without a `preset`, all four parts and a paint are required. Every field is optional with
one; nothing else is read. The catalogs are exported so a UI can offer exactly what the
renderer can draw, and `catalog-ids.test.ts` pins them to the runtime's catalog index in both
directions.

- `resolveAvatarCharacter(character)` fills in every part and the paint, validates each id and
  throws on anything the renderer cannot draw. `AgentAvatar` calls it, so an invalid character
  fails at the component that was handed it.
- `parseAvatarCharacter(json)` is the JSON boundary for saved values: flat characters only,
  unknown fields refused.
- `updateAvatarCharacter(character, patch)` is an edit: the result is written out in full, so
  choosing a body keeps the face, the hat and the paint the preset supplied. A `color` replaces a
  `bodyColor` and the other way round; the two are never held together.
- `characterFromLegacy(saved)` migrates an avatar saved before 10 (see
  [Migrating to 10.0](/docs/migrating-to-10.0)).

### Which animation plays

A character that is **exactly its preset** (paint aside) plays the preset's own authored
animation. Change a part, set `eyeSpacing` or hide the face and the animation is **retargeted**
onto the new parts. That is the whole rule, and it is decided in one place,
`resolveAvatarCharacter(...).authored`, from the data: writing a part out that equals the
preset's own does not change it, and naming the preset's own paint again does not repaint it.

## Hosting and packaging

The runtime URL defaults to `BLOOM_CHARACTER_RUNTIME_URL`, the SDK's hosted copy
(`https://alia.onl/bloom-character/runtime.mjs`, CORS open), on web and native alike, so an app
that does not self-host the runtime needs no setup. To self-host, serve the package's complete
`assets/character-runtime/` directory and pass its absolute URL to `BloomProvider
characterRuntimeUrl` or `AgentAvatarProvider runtimeUrl`. Native needs the optional
`react-native-webview` peer. Missing assets or an unavailable bridge produce an explicit translated
unavailable state. Geometry and motion load lazily; keep the generated chunks
and assets beside the entry point with their original relative paths.

`bun run build` builds the runtime before the library, then verifies all runtime
files and their hashes against the actual package file list. For runtime-only
work use `bun run build:avatar-runtime`. `manifest.json` records the generated
files. Build output replaces the entire runtime directory; old files and selector
PNGs cannot silently survive an incremental build.
Production avatars load the selected geometry and idle/reaction motion first. Computer
geometry, its episode and its repeating loop are optional resources: an idle-only scene or
portrait does not fetch them. The first `workingKey` prepares that character's work assets
before starting its first presented action frame. Preparation is shared by matching assets;
existing idle/reaction samplers and other avatars' clocks remain independent. Once prepared,
work assets stay available to that live scene for subsequent requests.

`avatar-motion-transport.mjs` produces separate base/work files for development and builds,
relocating the original Float64 channel bytes without rounding or resampling. The authored
source bundles remain frozen fidelity evidence. The public character and action API is
unchanged; runtime diagnostic tooling can still request a complete eager rig.

The source lives outside `src/` so Three and browser-only code never enter
Metro's native import graph. Vite application output preserves `createAvatar`
and external binary assets; library mode would inline these assets and defeat
lazy loading.

## Stills

`Avatar account={bot}` (see [Avatar](/docs/avatar)) draws a character as a cached still below
profile size. The still pipeline renders a paused `portrait` through this same runtime, one at a
time, into an invisible fixed-size box (web) or one hidden WebView (native), reads the canvas back
once and caches the PNG by content. Native retains the same WebView document throughout a
burst of requests: the runtime module, decoded donors and compatible GL pool survive between
characters. The preceding paused scene remains attached until the next picture is ready, then
is disposed; the hidden host is released 1.5 seconds after the queue empties. Each request has
its own capture identity, so an old completion cannot supply a later character's picture.
Web uses the same brief scene retention. Both paths wait for the first painted frame and the
created controller before capture; web runtime loading or creation that outlives the 15-second deadline
cannot block the queue, and its late controller is disposed. Failed module requests can be
retried; a failed native document is replaced for subsequent work.

Unmounting the provider or replacing its runtime disposes that cache's queued work. Cancelled
queued requests settle with `null`; late results cannot repopulate a disposed cache. These are
resource-lifetime guarantees, not native frame-rate measurements. `AgentAvatar` takes `onReady`,
called when the renderer has painted its first picture.

## Editing and proportions

A preset is a default, not the identity of an edited avatar: the first edit with
`updateAvatarCharacter` writes every effective part and paint, so changing a template later
cannot change a saved custom avatar. AgentCreator's templates (`CHARACTER_TEMPLATES`) are
complete characters of their own: Felipe (orange, sleepy eyes), Todd (Clippo eyes, bow, coral),
Alfred (Cyclops, monocle, bow, cyan) and Iris (Clippo eyes, round sunglasses, no accessory).
Edited characters compose the selected actual geometry, smooth materials and animation
channels; color is instance state and does not rebuild meshes. Bodies use the smooth solid
surface for every device. The runtime neither builds hair strands nor loads their pile/card
textures; body silhouettes, eyes, attachments and authored motion remain live 3D.

The catalog has 21 bodies, Todd's among them. Clippo's open wire and asymmetric face remain
independently selectable. Todd's eyes, Clippo's face, Cyclops and the other catalog eye styles
can be fitted across bodies. Hidden faces (`eyes: 'none'`) contribute no eye meshes.

`catalog-layout.ts` assigns each silhouette its own Tuft position, scale and
rotation, and eye size, separation and height. Attachment depth follows actual
triangles, not the bounding box. Tuft's root joins a smooth shoulder in the body;
its exposed tips retain their height. The surface uses the body's pigment, including animated material updates. Normals and
morphs follow the join and rotation. This work happens once per composed geometry, not per frame.
Todd keeps paired eyes on its stalks and places Cyclops on its forehead.
Eyewear follows the composed face and accessories remain attached during motion.
An explicit `eyeSpacing` is included in geometry identity.

The shape selector draws only the body in the selected color. The eye selector
draws only the eye meshes, framed independently, with no body or accessories.
Both use paused portraits from the same engine; no selector PNGs or second
renderer remain. Preview-only choices never change the saved avatar. The color
palette precedes accessory controls and stays available when changing shapes.
The editor accepts and saves any RGB color unchanged. The engine bounds body
pigment in linear sRGB to relative luminance 0.21–0.68, keeping shadows and
highlights readable. This also applies to presets and saved configurations;
body-colored hands and Tuft share the adjustment. In-range colors are unchanged. Chat handoff captures the visible avatar once,
on demand, and moves that image; it does not regenerate the removed SVG artwork.

## Motion and resource ownership

`reactionKey` plays the body's authored reaction; `workingKey` starts Computer.
`workingCycles` repeats complete Computer episodes before returning to idle at
the verified endpoint. `entranceKey` replays a scale/position/rotation entrance
inside the same scene. New actions start at their first presented frame, so a
slow preceding frame cannot consume an entire reaction before it is visible.
Other instances retain their elapsed clocks. `interactive` enables pointer and drag input.
Every avatar wanders its gaze on its own; pointer input owns gaze while interacting. Retargeted
characters still lack the per-eye gaze profiles available for authored scenes; body gaze and
eye animation remain active.

A browser document shares live instanced scenes grouped by resolution. Each
avatar has independent pose, phase, paint and action state. Paused, portrait,
reduced-motion and offscreen instances stop advancing independently. Fully
quiescent scenes stop requesting animation frames. Geometry donors are immutable
and cached within a byte budget; fitted geometry and GPU ownership are released
with the last live scene. There is no cached animation sprite playback.

Live native avatars still use separate WebView documents: they cannot share the web
document's GPU context or decoded geometry across avatars. The shared still host does not
change that live-renderer boundary. Sharing live native rendering would require a shared
surface that owns native positioning, clipping and input, or a native renderer port; merely
sharing a JavaScript scheduler cannot share these documents' GPU resources. Web correctness
checks do not establish native crowd performance. Physical Android and iOS integration
remains necessary for that claim. Software GL browser tests likewise do not establish laptop
FPS, and browser CPU throttling is not a substitute for measuring a low-end mobile GPU.

A separate reliability gap remains under native memory pressure: the live avatar bridge
currently handles its JavaScript protocol but does not subscribe to Android
`onRenderProcessGone` or WKWebView `onContentProcessDidTerminate`. These are real OS process
termination events, including memory reclamation; they are different from a runtime-reported
rendering error. A live avatar may therefore need remounting after its WebView process dies.
The still queue's deadline can release and replace a stalled document, but it does not prove
live-avatar recovery. See the [WebView event reference](https://github.com/react-native-webview/react-native-webview/blob/master/docs/Reference.md#onrenderprocessgone).

`className` and `style` apply to the outer layout node. `label` defaults to the
translated “Agent avatar”; `locale` overrides the scope and `accessibilityLabel`
overrides the accessible name. Use an agent's name when it identifies them.

## Catalog retarget

A character that is not exactly its preset takes the catalog path: the donor's observed clips
are retargeted onto the composed parts (`runtime/avatar/catalog-retarget.ts`). A preset plays its
authored clip instead, so a Storybook default never shows what follows.

- **An eye's pivot offset is carried by the eye's own world turn, never by its parent's.** The
  six-lobed body rolls 180° in plane during the reaction (its outline hides it) while the eyes
  stay put. Writing the offset in the parent's frame dragged them together: the painted gap fell
  to 0.26 of rest and stayed there to the end of the clip. Carrying it by the identity fixed the
  flower and broke the heart (0.20), whose eyes ride the body. Scale and any turn the eye makes
  about itself still pivot on the offset.
- **The body turns about its own centre** (`centerDelta`: destination centre minus donor centre),
  not the ground. About the ground, that same roll left the flower 0.17 high, held.
- **Measure the painted result:** the gap between the two eye centres across the clip, and the
  body's end translation, for every shape (a sweep of 19 shapes moved only the flower).
  `src/agent-avatar/__tests__/catalog-retarget.test.ts` pins both cases on synthetic clips.
- `assets/character-runtime/` is tracked: after editing `runtime/`, run
  `node scripts/build-avatar-runtime.mjs` and commit the output.

## Verification

Storybook's **Shape Proportions** gallery displays all distinct silhouettes with
four eye styles, glasses, reaction and Computer controls. **Editor** exercises
the production editor through the shared engine; **Many Avatars** covers a crowd.

```bash
node --test scripts/test-avatar-*.mjs
node scripts/verify-avatar-cutover.mjs
node scripts/verify-avatar-runtime-bundle.mjs
node scripts/verify-avatar-action-presentation.mjs
node scripts/verify-avatar-shape-proportions.mjs
node scripts/verify-avatar-editor-engine.mjs
node scripts/verify-avatar-editor-pool.mjs
node scripts/verify-avatar-accessory-attachments.mjs
node scripts/verify-avatar-catalog-pigment.mjs
```

Browser checks require `CHROME_PATH` and an installed `puppeteer-core` (or
`BLOOM_PUPPETEER_MODULE`). Tests under `scripts/fixtures/avatar/` store frozen
independent geometry expectations. They contain data only: deleting the old
engine does not replace fidelity oracles with the implementation being tested.
The chronological measurements, shader hazards and known residuals remain in
`docs/benchmarks/avatar-engine-research.md`; historical commands in that record
are not the current build process.
