# Agent Avatar

`AgentAvatar` uses the recovered original beta engine for its 3D characters. With an `AgentAvatarProvider`, existing recipes for the paper and blob silhouettes also render through that engine, retaining its fur, lighting, volume and animation. Circle, triangle, flower, diamond and heart reuse the engine’s corresponding shapes. Eight distinct bodies extend that catalog: pebble, squircle, slender, pocket, petal, star, cloud and shield. Their contours come from Bloom’s existing artwork; saved recipes do not need rewriting. All supported bodies use the original 3D eye catalog and animation.

```tsx
import { AgentAvatar, AgentAvatarProvider, FOLD_CONFIG } from '@oxy.so/bloom/agent-avatar';

<AgentAvatarProvider runtimeUrl="https://example.com/bloom-character/runtime.mjs">
  <AgentAvatar
    config={{ ...FOLD_CONFIG, character: {
      preset: 'blue_beret', selections: { accessory: 'crown' },
    } }}
    size={128}
    interactive
    label="Peri"
  />
</AgentAvatarProvider>
```

Host the package's complete `assets/character-runtime/` directory. The provider takes the URL of `runtime.mjs` and loads it only when an avatar is visible. The original generated engine files are preserved byte for byte with an integrity manifest. See the asset directory's README for provenance and source limitations.

## Editing

The `character` recipe holds a `preset` and optional `selections` for shape, color, eyes, eyewear and accessory. Explicit selections override preset defaults. `none` removes eyewear or an accessory. The editor reads the engine's actual selection and availability, including shape-dependent eye styles. Changing shape clears an explicit eye override so an unsupported pair is not restored.

The editor presents one shape catalog and one eye catalog through `ShapeArc` and `EmotionPicker`. The eye orbit offers the engine’s nine native styles for both original and migrated bodies, with unsupported combinations disabled. Migrated bodies default to the original oval eyes. Saved expression, eye-size, spacing and tilt fields no longer modify a migrated face; the engine owns its eye geometry and animation. The shared `GlossArt` palette and custom color picker edit either body source. Original presets keep their authored appearance until explicitly edited.

Alien avatars have been removed from the available catalog. Saved aliens, mascots and hidden-face recipes retain compatibility rendering. The shape selector shows static silhouettes without eyes or accessories: original catalog PNGs and cached SVG contours for migrated bodies. Paper grain and material effects become the engine’s 3D surface. Migrated bodies accept the original eyewear and accessory catalog. Headwear, Bulb, bow and Tuft use rigid contour anchors; eyewear and headphones retain their original placement. Original meshes, materials and fur remain intact.

## Interaction and lifecycle

`interactive` enables the original engine's pointer tracking and touch/drag interaction. Change `reactionKey` from an accessible button to replay its authored signature reaction for an intact preset, or the original 3D wave for customized and migrated bodies. Shape changes retain the last painted frame while the new geometry prepares. Changing `workingKey` starts a working episode and then returns to the interactive mode; `workingCycles` controls its duration. The creator’s **React** and **Work** buttons preview these original animations for both original and migrated bodies.

`paused`, reduced motion and `motion: 0` stop animation after a complete appearance frame. `portrait` prepares a static thumbnail. The beta can report readiness while drawing transparency if initialized with its reduced-motion flag; the adapter waits for painted pixels and then freezes its clock instead.

Web uses one physical WebGL2 context and a packed canvas shared by every visible, animated character. Each original or migrated avatar keeps its own animation, input, work state and render targets. `shared-surface.mjs` maps default-framebuffer operations into its region, resolves MSAA locally before the atlas copy, and clips presentation to prevent neighbouring avatars leaking into a fitted image. Deleting one character cannot destroy the shared context; the last lease releases it. The shared clock targets 30 fps with a round-robin submission allowance; this is a target, not a guarantee of 30 fps per avatar on every device.

Shaders and linked programs are shared by exact source and attribute bindings. Logical program handles retain independent uniforms and Emscripten metadata; switching skips values already present on the physical program. Small avatars (up to 128 CSS pixels) use the original compact mesh. The drawing resolution uses DPR at most 1 up to 64 CSS pixels, 1.5 up to 128, and 2 above that, with a 64-pixel floor and 512-pixel ceiling. The original engine derives its fur draw count from that drawing size, so reducing prepared fur arrays would not reduce its draw calls. Original fur and materials remain in use. The two 512-pixel mipmapped RGBA8 images and the 576×960 RGBA8 atlas share storage only when bytes and parameters match exactly; mutation or framebuffer attachment creates an independent copy. Private render targets, mutable geometry buffers and other textures remain per-character.

Driver errors are checked once at the end of a synchronous shared submission batch. Native setup/probing and Emscripten’s own `GL.lastError` checks retain their behavior. A graphics error discards every pending image in that batch and reports failure to its touched characters; it is never converted into a successful frame. The scheduler estimates the full completed cost, including driver synchronization and image presentation, to limit later batches. An 8 ms CPU-only submission timer was insufficient: software WebGL could queue hundreds of milliseconds of GPU work before that timer expired. A single native render remains non-interruptible.

Original and migrated bodies share one rendering WASM module and one preparation worker (the worker owns its own WASM instance). Prepared geometry identities include the contour and attachment transform. Cold preparation is admitted serially, while already painted moving avatars remain resident. Offscreen/background characters release their lease and retain their last complete 2D image. Static portraits use a bounded 64-image cache and release rendering resources after painting. Storybook’s **Many Avatars** story exercises 48 original/migrated avatars with React/Work controls and scrolling.

### Physical-device measurements

The [recorded benchmark](./benchmarks/avatar-shared-renderer.json) uses a Pixel 8a (Mali-G715, Android 16, Android WebView 148), with all avatars visible at 48 CSS pixels and 64 backing pixels. Original presets and migrated contours alternate. After every avatar is ready, a three-second warmup precedes a roughly five-second sample. Output pixel hashes confirm that every avatar moves; page RAF cadence is measured separately from each avatar's paint rate.

| Visible avatars | Mean paints per avatar per second | Page RAF interval, p95 | Time until all are ready | WebGL contexts |
| --- | --- | --- | --- | --- |
| 24 | 3.76 | 25.2 ms | 24.6 s | 1 |
| 48 | 2.59 | 25.2 ms | 74.1 s | 1 |

These results remove context loss, but **do not deliver fluid 30 fps animation**. Preparation latency and per-character drawing cost still need improvement. Readiness starts with a new document and engine but warm HTTP caches; it is not a cold-download measurement. Pixel-hash readback adds about 7.5–8.4 ms per batch every 500 ms. This short run does not establish sustained thermal performance.

Exact texture sharing avoids a calculated 109.85 MiB of duplicate requested mip storage at 24 avatars and 224.47 MiB at 48. These are payload calculations, not measurements of total GPU memory. Both runs have nine physical programs and zero graphics errors; deleting one preserves its neighbours, and deleting all releases the context, characters and preparation worker. Touch reactions are accepted in both runs. The working state is settled at 24; at 48 it is accepted and active but still pending at the single 1.8-second observation. The recorded asset snapshot predates the later failed-allocation rollback guard, which is covered separately by the browser surface test.

`className` and `style` apply to the outer layout node through Bloom's NativeWind wrapper. `label` defaults to the translated “Agent avatar”; `locale` overrides the scope and `accessibilityLabel` overrides the name. Prefer a meaningful name when the avatar identifies an agent.

## Native and fallback

The optional native bridge uses `react-native-webview` and requires an absolute runtime URL reachable by the device. The web adapter is also exercised in a physical Android WebView; that does not validate a React Native multi-WebView screen. Each native WebView owns a separate document, so context sharing is **per document, not application-wide on native**. Separate WebViews cannot share engine memory, graphics contexts or the web document’s viewport reclamation.

An unavailable runtime or missing native peer displays the translated unavailable state. Consumers without a runtime provider retain the universal SVG renderer for procedural recipes. That renderer preserves the original contours, folds, expression springs and deterministic grain; it does not support the beta's new 3D parts.
