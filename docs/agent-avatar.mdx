# Agent Avatar

`AgentAvatar`, AgentCreator, MultiAgentChat, ConversationSidebar, account avatars and
chat previews use the same flat **character** and SVG renderer. Local vector assets
and pure frame projection provide spatial motion without starting a WebGL engine.
AgentCreator uses the same renderer for its preview and static vector paths for
its shape and eye controls.

```tsx
import { AgentAvatar } from '@oxy.so/bloom/agent-avatar';

<AgentAvatar character={{ preset: 'blue_beret' }} size={128} interactive label="Peri" />
<AgentAvatar character={{ preset: 'blue_beret', accessory: 'crown', color: 'orchid' }} />
<AgentAvatar
  character={{ shape: 'heart', eyes: 'oval', eyewear: 'none', accessory: 'bow', bodyColor: '#ffd838' }}
/>
```

## SVG rendering

```tsx
<AgentAvatar character={{ preset: 'lime_frog' }} size={128} interactive />
```

SVG rendering does not need a hosted character runtime. The current catalog supports 34
shapes, 12 current eye styles, five eyewear styles and eight accessories (plus `none`). All edits use
`AvatarCharacter` and the existing validation and serialization boundary. Exact templates
retain their extracted geometry and clips. Edited characters fit vector parts to the target
body; painting preserves the chosen parts. Idle, reaction and work share the same frame
projection on web and native, including the working hands and screen. The 13 procedural flat forms
keep their silhouettes stable while the eyes follow pointer direction. Depth is approximated
with projected vector contours and visibility masks; this is flat artwork with spatial
motion, not the legacy renderer’s lighting or a promise of identical depth at every angle.

The flat forms are independently constructed from circles, polygons and parametric curves
in the offline geometry generator. Their centered, front-facing capsule eyes use declared
size and separation parameters; gaze is a head pose, not a permanent face offset.
Earlier development explored external outline data. Those snapshots and derived silhouettes
were replaced before publication; the generator does not read or transform them. Each capsule sits in one tangent plane on a virtual
sphere, so absolute left/right and up/down gaze moves the pair and foreshortens the outer
eye without distorting the capsule outline. Shape-specific visual centers keep asymmetric
bodies centered too. The body outline remains flat and stable.

Composition preserves these native eye parts and animation tracks when changing paint or
accessories. Generated-asset-only checks previously passed while the compositor replaced
the face with a normalized donor; the gate now checks all 13 forms through the real loader
and compositor, with and without headwear. It also checks clean symmetric capsules,
neutral centering, mirrored directional gaze and rendered interruption continuity
(`vector-frame.test.ts`). Fit parts when the character changes, not during each animation
frame, to avoid abrupt shifts between competing contact positions. If no translation can
fit a complete custom expression across the supported gaze range on a concave body,
composition reduces the whole expression uniformly, including its blink vectors. It never
warps an individual eye or silently disables the style. State changes capture
the currently displayed pose and blend all channels, including hands and screen; an
interrupted transition starts from that captured pose. Idle breathing, blinking and gaze
sampling are deterministic, while pointer input controls an absolute look direction.

AgentCreator loads the selected animated asset on demand. Shape and eye thumbnails are
static SVG paths, so opening the editor does not load every animation. Web verification
covered the existing Basic story: template, eyes, paint and accessory edits, work returning
to idle, reaction playback, unchanged profile fields and no canvas. Native uses
`react-native-svg`; this migration has not been verified on a device.

## The character

One flat shape, the same in `AgentAvatar`, `AgentCreator` (`agent.avatar`), `MultiAgentChat`
and your saved JSON:

| Field | Values |
| --- | --- |
| `preset` | `AVATAR_PRESETS`: a named template. Any part or paint you leave out comes from it. |
| `shape` | `AVATAR_SHAPES`: 21 original bodies and 13 flat forms. |
| `eyes` | `AVATAR_EYES`, or `'none'` to hide the face. |
| `eyewear`, `accessory` | `AVATAR_EYEWEAR`, `AVATAR_ACCESSORIES`; `'none'` removes it. |
| `color` | `AVATAR_COLORS`: named paint. |
| `bodyColor` | Skin `#rrggbb`, normalized to minimum perceptual lightness. It wins over `color`. |
| `eyeSpacing` | 0.5 to 1.5, a multiplier on the shape's eye separation. |

Without a `preset`, all four parts and a paint are required. Every field is optional with
one; nothing else is read. The catalogs are exported so a UI can offer exactly what the
renderer can draw, and `catalog-ids.test.ts` checks their compatibility with the offline source catalog. The editor offers 12 paired-eye
styles; the historical `cyclops` ID remains readable in saved characters but is not offered
in current choices or templates.

- `resolveAvatarCharacter(character)` fills in every part and the paint, validates each id and
  throws on anything the renderer cannot draw. `AgentAvatar` calls it, so an invalid character
  fails at the component that was handed it.
- `parseAvatarCharacter(json)` is the JSON boundary for saved values: flat characters only,
  unknown fields refused.
- `updateAvatarCharacter(character, patch)` is an edit: the result is written out in full, so
  choosing a body keeps the face, the hat and the paint the preset supplied. A `color` replaces a
  `bodyColor` and the other way round; the two are never held together.
- `characterFromLegacy(saved)` migrates an avatar saved before 10 (see
  [Migrating to 10.0](/docs/migrating-to-10.0)).
- `avatarCharacterInColor(character, color)` paints a character in its ACCOUNT's colour:
  `color` is what Oxy stores as `User.color`: a Bloom colour preset key or a hex (`#rrggbb`,
  `#rgb`), both ordinary account colours. The body takes the preset's identity seed, or the hex,
  lifted to the skin floor, as `bodyColor` (so a hex an editor wrote back paints exactly itself); every part is kept and `color` is dropped. A colour that does not resolve
  (`null`, `undefined`, an unknown key) returns the character unchanged. This is the one place a
  account colour becomes an avatar paint: a bot is drawn in the colour its profile is themed with.

### A bot is drawn in its account's colour

An agent's colour belongs to its account, not to its character. Store the character's parts
(no `color`, no `bodyColor`) and paint it at the edge:

```tsx
<AgentAvatar character={avatarCharacterInColor(agent.character, agent.account.color)} />
```

`Avatar` does it for you: a `kind: 'bot'` account (`<Avatar account={user} />`) is drawn as its
`character` painted in the account's `color` (`AvatarAccount.color`). Without a colour the
character's own paint (or its preset's) applies, and a character with no paint at all falls back to
the account's image and initials as any undrawable character does.

### Which animation plays

A character that is **exactly its preset** (paint aside) plays the preset's own authored
animation. Change a part, set `eyeSpacing` or hide the face and the animation is **retargeted**
onto the new parts. That is the whole rule, and it is decided in one place,
`resolveAvatarCharacter(...).authored`, from the data: writing a part out that equals the
preset's own does not change it, and naming the preset's own paint again does not repaint it.

## Assets and packaging

Production avatars load packaged vector data through the shared asset loader. They do not
fetch a hosted character module or require a WebView. Web and native use the same numeric
composition and projection; native drawing uses `react-native-svg`.

The old geometry engine under `runtime/` is an **offline extraction tool**, not an app
renderer. `bun run build:avatar-vectors` (`scripts/build-avatar-vector-assets.mjs`) samples its shapes, parts and authored
motion into vector data. Keep generated assets, import mappings and static portraits in
sync when rebuilding that source data. The static portraits (`vector-static`, ~310 KB of paths)
are drawn only by the agent creator's shape arc and eye picker, never by an avatar; they load on
first use through `use-static-portraits` (`import()`), and `static-portraits-lazy.test.ts` keeps
every other module from importing them. Normal library builds and package verification
must ship all vector assets; no consumer can depend on the extractor's filesystem. The generator
ends by packing the assets (shared payloads in `vector-assets/blobs/`, one `catalog/<kind>-<id>.ts`
module per asset); do not edit those files by hand.

`renderer`, including its historical `'webgl'` value, is a deprecated compatibility
prop and no longer selects another renderer. `AgentAvatarProvider.runtimeUrl`,
`AgentAvatarProvider.stillStorage` and `BloomProvider.characterRuntimeUrl` are also
deprecated and inert. `BLOOM_CHARACTER_RUNTIME_URL` remains exported as an empty
string for source compatibility; it is not a fetch location. The provider maintains
only a bounded capability map, not an offscreen rendering queue.

## Choosing which assets an app ships

Bloom ships 70 vector assets (shapes, eyes, eyewear, accessories and authored templates), about
30 MB of JSON before compression. Each is a lazy module, so none is in an app's first paint, but
a bundler that sees an `import()` emits the file, and Metro and `expo export` link every one of
them. The default build therefore ships all of them, whether the app draws one character or all.

Three things keep that bounded:

- **One copy of every payload.** Assets share most of their geometry and many animation tracks.
  Each distinct payload is stored once under `vector-assets/blobs/<hash>.json`; an asset file keeps
  only its small metadata and the hashes (`scripts/avatar-vector/pack-assets.mjs`, lossless:
  `scripts/test-avatar-vector-pack.mjs` and the manifest gate check it). 58 MB became 30 MB with no
  app change.
- **Only the clips that are drawn are fetched.** An asset (pack format 2) keeps each part's tracks
  per clip, `tracks[i] = { idle, reaction, work }`, each its own payload. An avatar first loads its
  character at rest (`VECTOR_REST_CLIPS`, `['idle']`): the idle tracks and the geometry they draw.
  A mood (`mood="sad"`, the empty state's gemie shaking its head "no") is drawn on the idle clip
  and needs nothing more, and a portrait is the idle clip's first frame. `reaction` and `work`
  (with the computer, hands and screens only `work` draws, the `workOnly` parts) are fetched the
  first time one plays: the idle animation carries on meanwhile, the gesture starts when its
  tracks arrive, and an interactive avatar asks ahead when the pointer reaches it. Every
  `VectorAssetLoader` method and `VectorAssetImport` takes the clips it should read; a loader or
  importer that ignores them hands back the whole asset, as before. For the empty state's
  character in Gemies this is 135 KB brotli instead of 281 KB, and 21 fewer requests
  (`vector-clips-on-demand.test.tsx`).
- **The renderer is not in the first chunk.** `Avatar` loads the character renderer on first use
  (`React.lazy`), so a screen that draws no bot character carries none of the geometry code.
- **An app can ship only what it draws.** List the assets you use, hand the loader to the
  provider, and build with the full catalog switched off:

```tsx
import { BloomProvider } from '@oxy.so/bloom/provider';
import { createVectorAssetLoader } from '@oxy.so/bloom/agent-avatar/catalog';
import circle from '@oxy.so/bloom/agent-avatar/catalog/shape-circle';
import oval from '@oxy.so/bloom/agent-avatar/catalog/eyes-oval';
import blueBeret from '@oxy.so/bloom/agent-avatar/catalog/template-blue_beret';

const avatarCatalog = createVectorAssetLoader({
  shape: { circle },
  eyes: { oval },
  template: { blue_beret: blueBeret },
});

<BloomProvider avatarCatalog={avatarCatalog}>{/* ... */}</BloomProvider>;
```

Then keep Bloom's own copy of the full catalog out of the bundle. It is linked from one place,
`agent-avatar/default-catalog`, through a single lazy `import('./vector-assets')`.

**Metro (Expo native and web).** Metro inlines no environment variable inside `node_modules`, so
resolve that one import to an empty module in `metro.config.js`:

```js
const upstream = config.resolver.resolveRequest;
config.resolver.resolveRequest = (context, moduleName, platform) =>
  moduleName === './vector-assets' &&
  /agent-avatar[\\/]default-catalog\.(ts|js)$/.test(context.originModulePath)
    ? { type: 'empty' }
    : (upstream ?? context.resolveRequest)(context, moduleName, platform);
```

**Vite, webpack, esbuild.** Define `process.env.EXPO_PUBLIC_BLOOM_AVATAR_CATALOG` as `"none"`
(`define: { 'process.env.EXPO_PUBLIC_BLOOM_AVATAR_CATALOG': '"none"' }`); the condition is
folded and the import disappears.

`AgentAvatarProvider catalog={...}` and the `catalog` prop of `AgentAvatar` do the same at a
narrower scope. Module names are `<kind>-<id>` with kind `shape`, `eyes`, `eyewear`, `accessory` or
`template` (the `bot` face is `shape-bot_blob`); the ids are in `catalog-ids.ts` and
`vector-assets/manifest.json`. An id that is not listed fails to load exactly like an unknown id (the
avatar keeps its placeholder), so list every shape, eyes, eyewear and accessory your characters use,
and a `template` entry for each preset you draw as authored (a preset that is not listed as a
template still renders, retargeted from its parts, without its authored animation).

Without any of this nothing changes: the default is the full catalog, loaded lazily on first use,
and apps that do nothing keep working. `scripts/verify-avatar-bundle-size.mjs` bundles the built
package both ways and fails CI past its budgets.

## Portraits

Visible account and agent avatars animate at every size. Only explicit `motion="never"` or
reduced motion uses a paused SVG portrait of the same character.
Static account frames share a cache keyed by the resolved character, independent of
display size, and request no animation frames. They do not persist PNGs or create a hidden
WebView. `onReady` fires
when the first picture has been painted. Shape and eye pickers use their smaller static
path catalogs rather than loading every character's animation.

## Editing and proportions

A preset is a default, not the identity of an edited avatar: the first edit with
`updateAvatarCharacter` writes every effective part and paint, so changing a template later
cannot change a saved custom avatar. AgentCreator's templates (`CHARACTER_TEMPLATES`) are
complete characters of their own: Felipe (orange, sleepy eyes), Todd (Clippo eyes, bow, coral),
Alfred (paired oval eyes, monocle, bow, cyan) and Iris (Clippo eyes, round sunglasses, no accessory).
Edited characters compose the selected vector geometry and animation channels. Paint updates
preserve the selected parts; changing a choice fits its geometry once, not on every frame.

The catalog retains 34 saved body IDs; the editor groups visually equivalent silhouettes
without rewriting saved IDs. Clippo's open wire and asymmetric face remain selectable.
Hidden faces (`eyes: 'none'`) contribute no eye paths.

Headwear seats against the body's actual support surface. Eyewear fits the final eye
contours, and headphones use body anchors. Reference-form head accessories follow the
shared head direction as rigid parts; eye deformation does not distort hats or glasses.
An explicit `eyeSpacing` changes the pair's spacing without rotating its expression.
Single-ink eyes switch to a readable light ink on dark bodies when needed;
multicolor iris and highlight styles retain their colors.

The shape selector draws the body in the selected paint; the eye selector draws only the
paired eye style. Both use static SVG paths. Preview-only choices never change saved data.
The editor preserves permitted RGB colors exactly and visibly normalizes colors below
the shared perceptual skin-tone floor of 45. Chat handoff may capture the visible
avatar once for its flight presentation; that snapshot is not the avatar renderer.

## Motion and resource ownership

`reactionKey` plays the body's authored reaction; `workingKey` starts Computer.
`workingCycles` repeats complete Computer episodes before returning to idle at
the verified endpoint. `entranceKey` replays a scale/position/rotation entrance
inside the same scene. New actions start at their first presented frame, so a
slow preceding frame cannot consume an entire reaction before it is visible.
Changing `idleKey` returns to idle without remounting.
Manual action changes blend from the currently displayed pose, including an
interrupted transition. The final Computer episode includes its screen and hands
exit in its last 280 ms, so work props do not linger after completion. Earlier
repeats remain working; pausing freezes the transition clock.

`mood` is a state rather than a key: it holds for as long as it is set. `mood="sad"` is for
an empty or not-found state, a refusal, something that could not be done. As the mood starts
(or the avatar mounts sad) the character shakes its head "no": three turns in 1.4 s, the first
the widest, starting and ending at rest. Then it stays downcast on top of its idle: looking
down and a little aside, sunk, slightly deflated, head tilted, lids heavy, still breathing and
blinking. Back to `neutral` the droop eases out over about a second, and a neutral avatar draws
exactly as it did before moods existed.

```tsx
<AgentAvatar character={{ preset: 'blue_beret' }} size={112} mood="sad" />
```

The mood is procedural (`vector-mood.ts`), like gaze and blinking, so every body has it: the
presets, edited characters and the 13 flat forms. A reference face shakes and lowers its head
through its look direction (its hats follow); any other body turns and tilts whole. Reactions,
work and pointer gaze still play underneath; a transition between them never captures the mood,
which runs on its own clock. Reduced motion and `paused` show the settled sad pose with no shake;
a `portrait` still is always neutral. In an `EmptyState`, pass it as the `illustration` at
`EMPTY_STATE_GEOMETRY[variant].illustration` (see [Empty State](/docs/empty-state)).
`vector-mood.test.ts` checks the shake and the sad pose on every template through the real
compositor, and `AgentAvatar-mood.test.tsx` the reduced-motion still.

The panel, screen glyphs and hands share the panel's visibility envelope, including
fractional camera visibility. Independent glyph coverage previously left text floating
after the panel vanished. The regression checks intermediate rendered paths and opacity
across all 23 templates, plus interrupted exits; endpoint-only counts missed this failure.

Other instances retain independent clocks. `interactive` enables pointer and drag input;
otherwise deterministic gaze wandering, breathing and blinking provide idle motion.
Paused, portrait, reduced-motion, background and offscreen instances stop advancing.
Composition donors remain immutable and loaded assets are cached. There are no WebGL
contexts or shared instanced GPU scenes in the production avatar path.

Browser checks do not establish native crowd performance. Native device verification is
still required; the shared numeric renderer alone does not prove native SVG drawing speed.

`className` and `style` apply to the outer layout node. `label` defaults to the
translated “Agent avatar”; `locale` overrides the scope and `accessibilityLabel`
overrides the accessible name. Use an agent's name when it identifies them.

## Historical extraction hazards

These measured failures belong to the offline geometry and animation source. Retain
these constraints when regenerating vector assets; they are not production WebGL setup
instructions. The source retargeter is `runtime/avatar/catalog-retarget.ts`.

- **An eye's pivot offset is carried by the eye's own world turn, never by its parent's.** The
  six-lobed body rolls 180° in plane during the reaction (its outline hides it) while the eyes
  stay put. Writing the offset in the parent's frame dragged them together: the painted gap fell
  to 0.26 of rest and stayed there to the end of the clip. Carrying it by the identity fixed the
  flower and broke the heart (0.20), whose eyes ride the body. Scale and any turn the eye makes
  about itself still pivot on the offset.
- **The body turns about its own centre** (`centerDelta`: destination centre minus donor centre),
  not the ground. About the ground, that same roll left the flower 0.17 high, held.
- **Measure the painted result:** the gap between the two eye centres across the clip, and the
  body's end translation, for every shape (a sweep of 19 shapes moved only the flower).
  `src/agent-avatar/__tests__/catalog-retarget.test.ts` pins both cases on synthetic clips.
- If changing the offline extractor, regenerate its vector output and run the geometry
  fidelity checks; production consumers do not execute the extractor.

The timing, heap, vertex-count and before/after parity measurements below record
the development catalog before the 13 procedural silhouettes were replaced for
publication. They are historical optimization evidence, not new measurements of
the replacement artwork. Current geometry and attachment invariants are rerun
against the generated release assets.

The chronological measurements, shader hazards and known residuals remain in
`docs/benchmarks/avatar-engine-research.md`; historical commands in that record
are not the current production renderer. The old cold raster path measured 31 requests
and 16.1 MiB for one character, and the hosted source runtime occupied 214 MB. These
figures describe the removed path, not current vector asset transfer sizes. The old
shaded engine also bounded body pigment to linear-sRGB luminance 0.21–0.68; that
lighting policy is historical, not a transformation of current saved SVG paint.


Paint-only edits reuse the same fitted geometry and clips through a bounded,
24-entry cache per asset loader. Failed loads are evicted for retry. The current
pose, gaze and action clocks survive recoloring; painting never mutates source
assets, so returning to a light body restores the original dark ink. Eye chips
and the character use the same normalized skin RGB color (allowed saved RGB stays exact). Applying the retired lighting
clamp only to chips once made the main character appear more saturated.

Single-ink eyes adapt contrast on every shape. The three dark-base glint styles
retain their original fill and highlight colors, with a two-unit light outline
only when needed on a dark body. Other artwork and laptop borders are unchanged.
Static chip frames share the same policy and cache.

Measured editor drag processing dropped from 10.48 s to 1.17 s for the same
25-event sequence after geometry reuse, frame-coalesced input, and stable preview
props. The latter run measured 42.9 ms median event-to-paint and 77.3 ms p95, with
no blank avatar. These are development-browser observations under external host
load, not device frame-rate guarantees. A same-process 207-pose paired benchmark
measured renderer medians of 13.27 ms before and 11.83 ms after; 621 full-frame
outputs remained exactly equal. Projection preparation and bounded visibility
scans retain the original visibility resolution and animation cadence.


### Coordinated animation and measured limits

Visible characters share one frame scheduler. Their clocks, pointer state, actions and
interrupted poses remain independent. Only exactly matching geometry, paint and pose inputs
share projection within one tick; the result cache is cleared at the end of that tick.
A failed subscriber stops itself and reports its error without freezing the other characters.
The editor prepares at most two adjacent recipes after a 250 ms quiet interval, sequentially
in browser idle callbacks (a deferred timer on native). Selection changes cancel queued work;
already-started module imports cannot be aborted. The existing 24-entry geometry and 12-entry
asset caches remain bounded, but JavaScript module strings themselves are runtime-cached.
`onLoadingChange` reports selected animated geometry preparation until its actual frame is
painted; paint-only edits do not reload it.

Removing unused generated edge arrays reduced the raw asset catalog from 89.44 to 58.72 MB
and its summed gzip size from 22.74 to 12.41 MB. This is lossless: faces still derive contour
topology, and 630 before/after rendered frames were identical. The complete catalog is not
fetched at startup. Example selected asset sets of 1/6/10 distinct benchmark characters total
1.37/8.52/13.12 MB raw or 0.284/1.71/2.58 MB gzip; these are file encodings, not measured network
transfer promises (server compression and caches matter).

Run `CHROME_PATH=... node scripts/verify-avatar-crowd.mjs report.json` for 10/30/50 visible
identical characters. `MIXED=1 COUNTS=1,6,10 THROTTLE=4` selects diverse recipes and a fourfold
Chromium CPU slowdown. The fixture is an internal module, not another Storybook destination.
It records frame counts, elapsed time, main-thread task/script durations, pointer response
and forced-GC JavaScript heap. Heap includes the loaded development Storybook page; it is
not total process RAM, GPU memory, or a native-device measurement.

On the measured development machine, shared exact-state calculation gave roughly 30 fps
for 10/30/50 identical characters with 7–30 ms pointer response and 34–37 MB retained JS heap.
Distinct recipes are materially more expensive. After asset compaction, the desktop mixed
fixture measured about 27–30 fps for six characters and 17.5 fps for ten, with 41/66 ms pointer
response and 80.7/104.0 MB retained heap (31.2 MB empty fixture). Transient pre-GC samples in
the broader profiling run reached 174 MB; retained heap alone is not a peak-memory budget.

The final **fourfold CPU slowdown** measured:

| Visible distinct characters | Approx. observed fps | Retained JS heap | Pointer-to-reaction observation |
| --- | --- | --- | --- |
| 1 | 30 | 31.5 MB | 39 ms |
| 6 | 7.2 | 80.5 MB | 177 ms |
| 10 | 4.8 | 104.9 MB | Not observed within the test's two-second response window |

The empty fixture used 30.8 MB. Six and ten distinct characters occupied about 99% of the
measured main-thread window; the one-character case occupied about 78%. The response window
includes browser input dispatch, so its timeout is not a precise latency value. CPU throttling
is an approximation, not evidence from an ARM laptop or phone. SVG removes the old WebGL
renderer but still performs software projection/visibility and browser compositing. These
results do **not** establish readiness for many complex characters on low-memory or low-end
devices; actual target-device testing remains necessary. No visible character is silently
frozen or rendered at reduced quality to meet a benchmark.

A proposed painter-order shortcut was rejected: although conservative geometry bounds
preserved scene ordering, removing regional masks changed edge antialiasing in 234 simple
frames (worst mean channel difference 0.108/255 on white). Its approximately 0.31 ms average
saving did not address complex-character costs. The existing exact visibility renderer remains.


Bow fitting must seat depth as well as height. A center-only neck anchor retained the
circular donor's depth on other silhouettes: the front of the star and cloud intersected
the upper wings, visibly clipping the bow. The compositor now moves the complete bow
assembly to the actual front contact surface before ordinary depth visibility and animation.
It does not force accessories into a foreground layer. Star/cloud face anchors are centered
and placed 7% of body height above the midpoint; other silhouettes keep their existing anchors.
The regression uses all four saved/current star and cloud IDs, native and custom eyes, and
checks immutable source geometry, complete neutral bow contours and directional/work states.
Browser checks must wait for the requested `data-geometry` identity; an old frame with a
cleared busy flag does not prove that the newly selected shape has rendered.


Expression fitting uses each selected body's paired eye anchors, rather than carrying the
donor expression's spacing onto a different silhouette. This previously placed oval and
sleepy eyes between the upper lobes when choosing Todd's shape from another preset.
The dominant iris/lid layer defines each anchor; brows and glints keep their local offsets.
Complete assemblies translate together, with uniform scale only where required to keep
the two eyes from merging. Eye spacing multiplies the canonical separation once, and
expression transforms retain their fitted per-eye pivot. Presets and their explicit recipes
use the same resolution contract; authored clips remain intact. The regression covers all
12 current expressions, preset/explicit equality, and idle/reaction/work.

### Minimum skin lightness

Skin uses a shared HCT/L* floor of 45. Below-floor colors retain hue and chroma where the sRGB gamut permits; allowed RGB values remain exact. The picker displays the permitted colors and normalizes typed input, while resolve, parse and edit boundaries apply the same policy to saved characters and presets. A 0.2-tone rounding margin prevents repeated serialization from changing the normalized color. Named palette colors already clear the floor. This is skin-only: it does not recolor eyewear or accessories. Color conversion is bounded-cache work on edits, never animation-frame work.

### Surface contact and relief

A one-way outward seat left already-floating accessories untouched: measured neutral gaps included about 0.197 world units beneath a monocle. Other apparent gaps were actual authored thickness (some eye layers protruded about 0.23), so translating every assembly inward would cut its base into the body. Composition now seats complete assemblies and modestly compresses excess front relief while preserving their internal depth order, XY geometry and animation tracks. Every overlapping vertex retains at least its previous surface clearance; shallow assemblies remain unchanged. The flat-body facial carrier is reduced by at most 18%, bounded against the supported look envelope, preserving neutral capsule geometry. Reference headwear rotates around a real brim vertex nearest the body contour, rather than around the face center, which previously lifted it during downward work gaze. These fits run once per composition, not per animation frame.

The wire body uses 20% larger eye assemblies around its existing paired anchors. The same shape rule applies to presets and manually selected styles before eyewear fitting, so glasses follow the larger eyes; depth, separation and authored animation tracks are retained.

### Eyewear contour preservation

Fitting each lens independently, blending those transforms across the bridge, and narrowing inner rims distorted the original frames. Eyewear now uses one proportional transform for the whole authored frame; lens contours, bridge and temples remain continuous. Open oval frames and monocles retain the underlying eyes. Opaque sunglasses suppress the underlying eye paint and outlines while worn, rather than stretching shallow lenses to cover arbitrary tall eyes; removing the glasses restores the unchanged eye geometry and paint. The integrity gate (`bun scripts/test-avatar-eyewear-integrity.ts`) checks all 34 shapes × five eyewear styles: 465,494 vertices, exact topology and maximum XY similarity residual below 4.5e-15. Depth seating remains the separate shared surface-contact operation.

A diagnostic SVG serializer once omitted `fillOpacity`, falsely showing eye remnants that the production component correctly hid. Visual checks must forward every painter attribute, and final evidence uses the actual component with both wearing and removal states.

### Measured cleanup: composition, frame work and cache ownership

The scheduler's recipe identity must refer to the immutable fitted geometry, not each instance's recolored wrapper. Using the latter silently defeated sharing even for identical visible characters. The key now includes the raw geometry identity, complete requested geometry recipe and normalized paint; clocks, gaze and interrupted poses remain independent and exact, without phase quantization.

The frame owner no longer projects or rasterizes fully unpainted, non-stroked parts. Explicit strokes, the panel's implicit outline and eyes-only bounds keep their previous behavior. Camera channels are sampled once per part, ignored TRS channels are not sampled for matrix-driven tracks, default channel objects are reused, and per-vertex morph coordinates avoid callback allocation. The asset loader also guards rejected requests by promise identity: an older request evicted from its 12-entry cache must not delete a newer in-flight load of the same importer.

Composition prepares reference projectors once per look, caches immutable part/rest-track bounds weakly, hoists invariant inverses, avoids donor motion calculations for parts that never use them, and shares identical baked carrier channels. An alternating local benchmark of ten fresh recipe compositions with already-loaded donor data measured 1573 → 1204 ms median (23.46% less); this is fitting work, not network cold start. Warm cache hits were already below a millisecond and are not claimed as a meaningful improvement.

A separate unprofiled alternating frame benchmark across the actual crowd presets plus one opaque-eyewear recipe measured a median paired ratio of 0.878 (about 12% less frame work). The opaque recipe skipped 8114 hidden vertices. These are local microbenchmarks with external machine load, not ARM/native or end-to-end FPS guarantees. All 170 shape/eyewear geometries and authored tracks remained exact. The frame comparison checked 1530 painted frames plus 170 eyes-only frames: visible paths, clipping and painter attributes were identical; only fully invisible paths were omitted. The 322-square depth grid and vector contours are unchanged.

Distinct workloads remain CPU/allocation-heavy: the ten-distinct result did not improve reliably over the earlier approximately 11 frames/s sample. No low-memory/mobile readiness is inferred from the duplicate-recipe gain. Transient peaks are sampled during animation and interaction; they differ from retained heap after explicit garbage collection. The editor cleanup reduced repeated field listener registration/removal from 144 to 52–54 across its comparison and final check, retained zero color-field DOM mutations during saturation/value dragging, and preserved history and final color values; no absolute picker latency gain is claimed.

### Projection allocation follow-up

Authored mesh projection now reuses one call-local scratch vector for morph, world,
view and motion transforms. Final projected vertices remain independently owned;
source points, morph deltas, sampled channels and previously returned frames never
share the scratch storage. Analytic-face geometry retains its allocating projection
path: extending scratch reuse there regressed its warmed benchmark by roughly 9–12%.
This capability-based distinction does not change any recipe, contour or animation.

In the final alternating fixed-pose comparison, the spectacles recipe measured
17.13→9.55 ms per frame, while the analytic cloud measured 1.99→2.02 ms. These
local pure-render timings are not browser FPS guarantees. Two visibility-loop
experiments were rejected: warmed contour-scratch and nearest-distance-ring variants
measured 82.08 and 105.55 ms versus the unchanged 58.23 ms across ten mixed scenes.
Fewer allocations alone did not make those loops faster.

The final development-browser sample still showed significant limits: six distinct
avatars rendered about 12.4 frames/s, retained 79.9 MB of JavaScript heap after GC,
and reached a sampled 276.3 MB peak; ten rendered about 5.8 frames/s, retained
105.6 MB, and reached 382.5 MB. The ten-avatar interaction exceeded the two-second
observer timeout under that load. A fresh earlier sample measured 14.4/4.7 frames/s
and 284.1/374.8 MB peaks respectively, so there is no reliable browser-wide speed
or memory reduction claim. These are Storybook observations under variable machine
load, not total process RAM, GPU usage, or ARM/native validation. Dense mixed scenes
remain unsuitable as evidence of low-end readiness. No visible avatar was paused,
no frame-rate target was reduced, and no depth-grid or contour fidelity was changed.

### Retired native renderer observations

The previous native companion and WebView routes are no longer selected or shipped by
Bloom. Their historical evidence remains in the [research appendix](benchmarks/avatar-engine-research.md)
and [phase-two report](benchmarks/avatar-efficiency-phase2.md): nine visible WebViews on
a physical Pixel 8a lost one WebGL context, leaving eight ready. The former native pool
used at most sixteen instances, 64/128/320 size buckets, 4× MSAA and two outstanding
presentation batches; taps were cancelled after six logical pixels of movement. Those
are retired backend limits, not SVG guarantees. Its recovery budget reset after thirty
seconds, still requests had a fifteen-second deadline, the retained hidden host was
released after 1.5 seconds, and persistent still cache version 3 corrected first-frame
capture. Native context loss and physical process-kill recovery were not fully validated.
The SVG cutover does not convert those historical checks into native-device validation.

`useAvatarRendererCapabilities({ enabled })` remains exported: shared live scheduling is
available on every SVG platform when enabled, without an adapter or manifest request.
Installing the former native companion no longer selects another rendering backend.
