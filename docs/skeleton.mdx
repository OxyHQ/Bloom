# Skeleton

Placeholders for content that has not arrived. `Skeleton` is a namespace of
primitives you compose into the shape of the real thing.

```tsx
import * as Skeleton from '@oxy.so/bloom/skeleton';

<Skeleton.Region label="Loading profile" style={{ gap: 12 }}>
<Skeleton.Row style={{ gap: 12 }}>
  <Skeleton.Circle size={40} />
  <Skeleton.Col style={{ gap: 6 }}>
    <Skeleton.Text style={{ width: 140 }} />
    <Skeleton.Text style={{ width: 90 }} />
  </Skeleton.Col>
</Skeleton.Row>
</Skeleton.Region>
```

## The parts

| part               | takes                | for                                |
| ------------------ | -------------------- | ---------------------------------- |
| `Skeleton.Region`  | `children`, `label`, `style`, `className`, `testID` | loading semantics and shared shimmer |
| `Skeleton.Text`    | `style` (`width`, `lineHeight`) | a line of text          |
| `Skeleton.Circle`  | `size`               | an avatar                          |
| `Skeleton.Pill`    | `size`               | a chip, a badge, a button          |
| `Skeleton.Box`     | `width` / `height`   | anything rectangular               |
| `Skeleton.Row` / `Skeleton.Col` | `style`  | layout, so a placeholder needs no extra views |

`Skeleton.Text` reads its width and line height out of `style` rather than
taking props for them, so the same style object you would give the real `Text`
produces a placeholder the right size — which is the point.

It is a namespace rather than flat exports because the names are generic
(`Text`, `Box`, `Row`) and would collide with everything. Each ships as a
subpath, so `import * as` costs no tree-shaking.

## Shape it like the content, not like a grey box

The point of a skeleton is that nothing moves when the data arrives. A
placeholder wider than the real text, or one line where there will be two,
produces a jump that is more distracting than a spinner would have been. Match
the line count and the rough widths; do not match them exactly, because
identical widths on every row read as a pattern rather than as text.

## Skeleton or Loading

- **Skeleton** — you know the shape of what is coming and it fills the region.
  A feed, a profile header, a table.
- **[Loading](/docs/bloom/main/loading)** — you do not know the shape, or the
  wait is short, or it is a small inline region. Also the right choice for an
  action in progress, where a skeleton would imply content is arriving.

Do not show a skeleton for longer than a couple of seconds. Past that it stops
reading as "almost there" and starts reading as broken; show progress or an
explanation instead.

## Accessibility

Wrap a composed placeholder in `Skeleton.Region`. It announces a busy group with
`label` (localized “Loading” by default); shapes are decorative and hidden from
assistive technology. The region adds no sizing, padding or layout decisions.
Use `style` or NativeWind `className` to match the incoming content.

Shapes in a region share a shimmer phase. Nested regions inherit it and do not
repeat the loading announcement. Without a region, shapes still work independently.
Reduced motion keeps placeholders static, including changes to the OS preference.
`blend` reduces a shape's opacity; an explicit `style.opacity` on Box, Circle or
Pill replaces its animated opacity.

The public components and composition are shared across native and web. Native
uses one non-interactive native animation driver per region, so virtualized lists
can continue rendering rows. Web installs its CSS keyframes through Bloom's
stylesheet owner and uses ordinary views. New shapes align with the region phase
once on mount; CSS owns subsequent frames without React state updates.

Loading placeholders must leave the scheduler free to reveal loaded content. The
previous React Native Animated web driver scheduled React updates per shape per
frame; a composed feed with 40 shapes in each of four suspended panels could
schedule 160 updates per frame. In the compiled consumer, pending route retries
sometimes remained behind those updates after every import had resolved. The
regression checks that animated fallbacks do not keep committing React renders
and that a resolved suspended child replaces them. Browser release checks also
exercise cold route loading with ordinary motion enabled.
