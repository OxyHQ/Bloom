# Slider

For a value where the *approximate* position matters more than the exact number:
volume, brightness, a zoom level, a price ceiling.

```tsx
import { Slider } from '@oxy.so/bloom/slider';

<Slider
  value={volume}
  onValueChange={setVolume}
  onSlidingComplete={persistVolume}
  min={0}
  max={100}
  step={1}
  accessibilityLabel="Volume"
/>
```

## Which prop decides what

| prop                | decides                                                  |
| ------------------- | --------------------------------------------------------- |
| `value`             | the position — the slider is fully controlled              |
| `onValueChange`     | fires **continuously** while dragging                      |
| `onSlidingComplete` | fires **once**, when the finger lifts                      |
| `min` / `max`       | the range                                                  |
| `step`              | the granularity; omit for continuous                       |
| `disabled`          | dims and ignores gestures                                  |
| `label`             | a visible label above the track; also the fallback name    |
| `showTooltip`       | the value bubble above the thumb (default `true`)          |
| `formatValue`       | the text in the bubble                                     |

`RangeSlider` takes the same props with `value: [number, number]` (and `onValueChange` / `onSlidingComplete` receiving the pair), `formatValue(value, index)`, and `thumbLabels` — the accessible name of each thumb, default `['Minimum', 'Maximum']`. The thumbs cannot pass each other; the fill runs between them; each carries its own bubble, and each is its own `adjustable` control with its own value.

## What it looks like

The slider, in Bloom's colours.

- **Track region** 32 tall, with 32 more reserved above it while `showTooltip` is on (the default — pass `showTooltip={false}` where the bubble would crowd a row).
- **Rail** 6 tall, full pill, the shared secondary surface with an inset shade; hovering uses the tertiary surface.
- **Fill** an accent-500 → accent-600 left-to-right gradient with a white top highlight.
- **Thumb** 20, themed card fill, 1px semantic hairline, a soft drop plus inset highlight, holding an 8px accent dot. Hover darkens the border; dragging turns it accent with an accent-tinted shadow and brightens the dot. The thumb does not scale on press — no Bloom control scales on press.
- **Bubble** 28 tall, min 32 wide, radius 8, `caption-1-medium` text, with an 8px arrow whose tip sits 4.5px below the bubble; it lifts 2px with a deeper shadow while dragging or focused. A press focuses the thumb, so the bubble stays lifted after the drag until focus moves on.
- **Label** `body-medium`, 8px above the track.
- **Cursor** (web) `grab` over a thumb, `grabbing` while dragging, `not-allowed` when disabled.
- **Disabled** 50% opacity. Keyboard focus rings the thumb: a 2px accent ring outside a 2px page-coloured offset (`ring-offset-2`, scoped in both modes).

## The two callbacks are the whole API

`onValueChange` fires on every frame of a drag. Put the *preview* there — the
number under the thumb, the live volume — and nothing else.

`onSlidingComplete` fires once. Put anything expensive or persistent there: a
network request, a write to storage, a re-render of a large list. A `PATCH` in
`onValueChange` sends one request per frame, which is the classic way a slider
takes a settings screen offline.

```tsx
onValueChange={setLocalValue}          // cheap, immediate
onSlidingComplete={(v) => save(v)}     // once, at the end
```

## Give it a label and a unit

A slider announces a number with no meaning attached. `accessibilityLabel`
names it; if the number is not self-evident (a price, a duration), show the
formatted value beside the track so it is readable without dragging.

The label is not optional in practice, only in the type. ARIA computes no name
from a `slider`'s contents — a track and a knob render no text — so a caption
beside it names nothing, and the `aria-value*` props say how far along it is
and never what it is. Omitting it warns once in development, dev-only and never
throwing; an empty or whitespace-only string counts as missing, because
`aria-label=""` is not a name.

## In a `Field`

`Slider` draws a track and a knob and hides its own `label` from assistive
technology, so the name is a prop — or the enclosing field's label:

```tsx
<Field label="Maximum price" description="Per night" disabled={!hasDates}>
  <Slider value={price} onValueChange={setPrice} min={0} max={500} />
</Field>
```

The field also supplies the id, `aria-describedby` and `aria-invalid`, and its
`disabled` stops the pan responder as well as dimming the track.

## When a slider is the wrong control

- **The exact value matters.** Use a number input; a slider cannot be typed
  into and is hard to land on a specific value.
- **There are fewer than about five positions.** Use a
  [`SegmentedControl`](/docs/bloom/main/segmented-control) or a
  [`Radio`](/docs/bloom/main/radio) group — they name the options.
- **The range is huge and non-linear.** A slider over 1–1,000,000 gives most of
  its travel to values nobody wants.

## The thumb's focus ring

The ring around a focused thumb is the `box-shadow` form (an outline on the
focusable ancestor would draw round the wrong box), and its gap takes
`var(--bloom-ring-offset)` from the surface behind the control. It was a
hardcoded `#FFFFFF`, which in dark mode was a white halo. See
[Styles → The focus ring gap](/docs/bloom/main/styles).
