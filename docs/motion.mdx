# Motion

Shared enter/exit presets and a screen transition, so a sheet and a menu on the
same screen do not open at subtly different speeds.

```tsx
import {
  ScaleAndFadeIn,
  ScaleAndFadeOut,
  ShrinkAndPop,
  ScreenTransition,
} from '@oxy.so/bloom/motion';

<Animated.View entering={ScaleAndFadeIn} exiting={ScaleAndFadeOut}>
  <Panel />
</Animated.View>
```

The value of shared presets is not the numbers — it is that a change to "how
fast things feel" happens in one place rather than being renegotiated per
component. It is also where the web rules below are already applied, which is
the stronger reason to use them rather than hand-writing an enter.

## Panel layout motion

Declare `transition: 'exit-before-enter'` on the shared panel layout to fade and
recede outgoing panels, move the surviving tracks, then reveal incoming content
at a usable width. The default `simultaneous` policy coordinates those changes
together. Both policies respect reduced motion and keep stable panel identities.
Web uses compositor-owned CSS; native uses Reanimated. Applications do not add
route-level enter animations, measurements or timers to implement a layout toggle.

Reordering is a move, not a new entrance. The shared gesture and ordering model
keeps retained content and its scroll position, commits the controlled permutation
after the landing completes, and preserves logical accessibility order. Native
per-frame drag paint stays in shared-value worklets; web updates the existing DOM
transforms. Measurement, callbacks and domain edge scrolling still require work:
this is not a promise of zero JavaScript or identical platform paint.

A transient document-Deck `revealPanel` waits for the owning compositor transitions
to settle before scrolling to a newly inserted panel. It cancels obsolete requests
and excludes unrelated content animations; reduced-motion and nonanimated layouts
do not incur an artificial delay. See [AppShell](/docs/bloom/main/app-shell).

## Continuous loading motion must not schedule React renders

React Native Animated's JavaScript driver on web schedules a React update for
each animated view on each frame. A dense looping Suspense fallback can keep
higher-priority updates arriving while the resolved content waits in retry lanes.
`isInteraction: false` prevents a native interaction handle; it does not change
React's web scheduling priority.

[Skeleton](/docs/bloom/main/skeleton) keeps one shared component implementation:
CSS opacity keyframes on web, a non-interactive native driver on native. Web
phase alignment happens at mount, not on every frame, and reduced-motion CSS
stops the loop. Avoid per-frame React state for decorative animation or consumer
workarounds that disable motion to make asynchronous routes load.

## Never fade or filter a material host or its ancestors

On the web an `opacity` below 1, any `filter` (`blur(0px)` too), a mask, a
`clip-path` or a `mix-blend-mode` makes an element the backdrop root of the
surface material inside it: the material blurs nothing and loses its edge light
until the motion ends, then pops back. A motion that ends on `blur(0px)` (a
keyframe or transition to `none` interpolates to it, and so does a mapper that
returns `blur(${x}px)` at rest) leaves the material flat for good.

- A surface that paints the material moves and scales with `transform` only and
  fades through its presence (`surface/use-surface-presence.ts`,
  [Surface](/docs/bloom/main/surface)): its layers through
  `--bloom-surface-presence`, its content through `useSurfacePresenceContent`.
- A wrapper that fades or blurs content holding a material control (a tile with
  a dismiss button, a crossfading layer of buttons) is a presence root too.
- A blur in a motion lands on `'none'`, never `blur(0px)`, and is never on a
  material host or its ancestors.
- Native has no backdrop filter and keeps its opacity motion.

`backdrop-root.web.test.tsx` and `scripts/verify-backdrop-root.mjs` gate it.

## Three ways animation silently does nothing on web

These are not Bloom quirks; they are how Reanimated behaves in the
configuration every Oxy web app ships. Each fails with **no console output**.

### An animation started from a mapper never ticks

Returning `withTiming` / `withRepeat` from `useDerivedValue` or
`useAnimatedStyle` does nothing on web. Drive a shared value **imperatively**;
`useAnimatedStyle` only ever READS.

```tsx
// ✅ someone calls this
progress.value = withTiming(1, { duration: 200 });

const style = useAnimatedStyle(() => ({ opacity: progress.value }), [progress]);
```

### Without the worklets Babel plugin, mappers re-run on their DEPS ARRAY

Not on auto-tracked reads. Omit an animating shared value from the deps and the
mapper runs once and freezes at frame 1. **List every shared value the mapper
reads** — note the `[progress]` above, which is doing real work.

`useAnimatedReaction` also needs explicit dependencies in builds without the
worklets plugin, including every captured shared value. Reactions can observe
shared values; they do not make missing dependencies or animations started from
style mappers safe.

### A custom `Keyframe` as `entering` freezes the element

An animation name absent from Reanimated's built-in map also schedules a
cleanup that pins the element — `position: absolute` plus a frozen box — at
`duration × 5`. It is a layout bug with no error, and `exiting` is unaffected,
so it looks intermittent.

## Bloom's rule: pick the mechanism per DIRECTION

- **`entering`** runs on the real element. It is EITHER a predefined builder
  (`FadeIn`, `SlideInUp`) OR driven imperatively from a shared value. Never a
  `Keyframe`, never a custom builder.
- **`exiting`** runs on a throwaway clone, so a custom `Keyframe` is safe there —
  and is the only way to express a multi-property, multi-stop shape.

Consequences to accept rather than work around: a predefined builder cannot
combine fade with scale, so a web enter drops one; and `Keyframe` has no
`.easing()`, so web keyframes run linear unless a per-stop easing happens to
resolve to one of Reanimated's built-in names. Add intermediate stops if the
curve matters.

## Verifying

Jest and `tsc` catch none of these. Verify in a real **foregrounded** tab — a
hidden tab freezes plain CSS transitions too, which mimics "the class didn't
apply". Read the class attribute, or set `transitionProperty: 'none'` before
reading computed styles.

### Static Storybook and Reanimated's CommonJS bridge

A live Vite preview can animate correctly while its static build crashes in
Reanimated's DOM updater at `Object.keys(node.props)`. Measured here: the static
bundle left the optional `require('react-native-web/dist/exports/StyleSheet/compiler/createReactDOMStyle')`
in Reanimated's ESM `webUtils.web` module. The browser's missing `require` was
swallowed by its `try/catch`, leaving the DOM compiler undefined; a DOM element
then reached the legacy component-props branch. Dev `optimizeDeps` had converted
the same call successfully. Storybook's `build.commonjsOptions` now enables
`transformMixedEsModules` and converts `try/catch` requires only for installed
`react-native-web/dist/*` modules. Other optional-peer boundaries remain intact.
The source gate guards that wiring; emitted bundle inspection and a real static
open-overlay check are required to verify it. Reanimated remains the real package.

The same static audit exposed a separate Expo bootstrap omission: `expo-image`
read `globalThis.expo.NativeModule` after tree shaking discarded the empty web
`ensureNativeModulesAreInstalled` bridge and its polyfill import. Expo marks the
polyfill as side-effectful but not that bridge. Storybook narrowly marks the real
`expo-modules-core/src/ensureNativeModulesAreInstalled.ts` module as side-effectful;
it neither mocks Expo nor creates a replacement global. A minimal production
bundle confirmed the installer precedes the first NativeModule read.

### Intent recipes

`MOTION_RECIPES` and `animateMotion(value, target, intent, reducedMotion?)` share
press, select, expand, present and dismiss behavior. The helper retargets the
existing shared value without resetting its position; selection and expansion
use springs so rapid reversals remain interruptible. All recipes respect the
system reduced-motion setting, and a true override settles immediately.
Components retain geometry, gesture velocity and completion callbacks. Overlay
presentation can retain its existing duration while sharing the accessibility
policy; callbacks still run when Reanimated settles immediately.

Screen collapse and TabBar minimization share the expansion recipe. Selected
capsules share selection motion. Retained tab entries and ScreenTransition omit
spatial transitions under reduced motion. Native Screen initializes keyboard
visibility before reserving bottom chrome, including inherited shell clearance.
Portaled overlays isolate screen navigation state while preserving theme and
locale; scrolling their content cannot collapse the navigation behind them.


Animating live layout geometry (a pane's width) uses a cubic ease-out timing
animation, never a **duration** spring: Reanimated 3's duration spring
integrates at most 64ms per frame but compares its forced completion against
the full elapsed wall time, so expensive layout frames leave it far behind and
it then jumps hundreds of pixels at the deadline. Timing evaluates elapsed time
directly. Verify the last moving frame as well as intermediate frames in a
browser; counting intermediate frames alone does not catch a large final snap.
(The list/detail slide that measured this, `AppShellSplitPanes transition`,
was removed in 11.0 with no consumer; the hazard stands for the next one.)
