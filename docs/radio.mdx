# Radio

A radio is a **control**: the label is part of the target, the group announces
itself as a group, and exactly one option is selected. `RadioGroup` is the form
you almost always want; `Radio` is the single row, for when the options are not
a flat list.

```tsx
import { RadioGroup } from '@oxy.so/bloom/radio';

<RadioGroup
  label="Delivery speed"
  value={speed}
  onValueChange={setSpeed}
  options={[
    { value: 'standard', label: 'Standard', description: 'Two to four days' },
    { value: 'express', label: 'Express', description: 'Next working day' },
    { value: 'pickup', label: 'Collect in store', disabled: !storeNearby },
  ]}
/>
```

## Which prop decides what

| prop                      | decides                                            |
| ------------------------- | --------------------------------------------------- |
| `label` (group)           | the accessible name of the whole group — required    |
| `value` / `onValueChange` | the selection; the group is fully controlled         |
| `options`                 | the choices, each with its own `label`/`description` |
| `size`                    | `sm` · `md` · `lg`                         |
| `disabled`                | the whole group, or one option via its `disabled`    |

## What it looks like

The dot is [`RadioIndicator`](/docs/bloom/main/radio-indicator); the row puts an 8px gap between it and the label.

|       | `sm` | `md` | `lg` |
| ----- | ------- | -------- | ------- |
| dot   | 14      | 16       | 20      |
| label | `body-2-medium` 13/18 | `body-medium` 14/20 | `headline-medium` 16/22 |

`sm` is the `sm` size and `md` the `md` size; `lg` extends the ramp — the same rungs as `Checkbox`, so a form mixing the two lines up. A disabled option dims the whole row to 50%. On web, keyboard focus draws a `ring-2 ring-offset-2` around the dot: a 2px accent ring outside a 2px offset matching the scoped page background. Text is Inter from Bloom's type ramp. There is no hover or press paint and no press scale — selection is the only thing that animates.

## Cards

`RadioCard`: title and an optional description on the left, the 16px dot on the right, the whole card selects. The easy spelling is the group:

```tsx
<RadioGroup
  label="Plan"
  variant="card"
  value={plan}
  onValueChange={setPlan}
  options={[
    { value: 'starter', label: 'Starter', description: 'Up to 3 projects.' },
    { value: 'pro', label: 'Pro', description: 'Unlimited projects and history.' },
  ]}
/>
```

`RadioCard` is also exported for a custom layout — put it inside your own `radiogroup`. The card is radius 10 with a 1px `border-button-default` edge, padding 12 / 16 left / 20 right, the surface fill turning `background-primary-hover` under a pointer; the title is `body-medium`, the description `body-regular` in `text-secondary`, each one line. Disabled dims the whole card to 50%. Keyboard focus rings the dot.

## The label belongs to the radio, not next to it

`Radio` renders its own `label` and `description` and makes the whole row the
press target. A dot with a separate `<Text>` beside it is a smaller target, and
tapping the words does nothing — which reads as an unresponsive control.

If you need the dot alone — inside a custom row, a card selector, a table cell —
that is [`RadioIndicator`](/docs/bloom/main/radio-indicator), which is
presentational and takes `checked`. Using the indicator where you meant the
control is how a "radio group" ends up announcing as decoration.

## In a `Field`

A radio set is the several-controls case, so the field is a `multiple` one: it
becomes a labelled `group`, names the `RadioGroup` (whose own `label` is optional
for that reason), and disables every option without any of them being able to opt
out.

```tsx
<Field label="Billing period" multiple error={errors.period} disabled={locked}>
  <RadioGroup value={period} onValueChange={setPeriod} options={PERIODS} />
</Field>
```

Each radio keeps its OWN name — the option's text, which is what the user reads
beside the dot. See [Field](/docs/field).

## Radio, Switch or Checkbox

- **Radio** — one of several named options, all visible, mutually exclusive.
- **[Switch](/docs/bloom/main/switch)** — a single thing that is on or off,
  taking effect immediately.
- **Checkbox** — several independent options, or an intent confirmed later.

Two radios is usually a sign the choice is really a switch — unless both
options need naming ("Metric" / "Imperial"), which is exactly when radios are
right.

## A group with nothing selected

`value` may be `undefined`. Prefer that over pre-selecting an option the user
did not choose: a default that happens to be first is indistinguishable from an
answer, and it silently becomes the submitted value.

## The focus ring's gap

Both the row's dot ring and `RadioCard`'s ring take their 2px gap from
`var(--bloom-ring-offset)`, set inline from the surface behind the control. It
was a hardcoded `#FFFFFF` — a white halo in dark mode. See
[Styles → The focus ring gap](/docs/bloom/main/styles).


`Radio` and `RadioCard` use `checked` and `onValueChange`: choosing an option reports its value, never a false toggle. `RadioGroup` accepts controlled `value` or uncontrolled `defaultValue`. The duplicate `selected` and `onSelect` props have been removed.

An explicitly supplied `value={undefined}` is a controlled empty selection. Omit `value` to opt into uncontrolled state with `defaultValue`; callbacks do not commit a controlled selection until its parent updates the prop.

## Composed row labels

A standalone `Radio` accepts `labelContent?: ReactNode` for a decorative layout
inside a View. It replaces the visible `label`; pass `label` or
`accessibilityLabel` as the explicit accessible name. Do not put controls inside
this slot. The existing radio row owns the press target and selected state.
`labelStyle` still styles the built-in string label; custom content owns its own
styles. `RadioGroup`'s data-driven options and `RadioCard` keep their string label
and title contracts.

```tsx
<Radio value="helpful" checked={order === 'helpful'} onValueChange={setOrder}
  accessibilityLabel="Most helpful"
  labelContent={<View><Text>Helpful</Text><Text>By votes</Text></View>} />
```

A collection of composed rows belongs inside a named `radiogroup`. Space selects
a focused row on web; choosing an already-selected row remains a no-op. This
slot does not add arrow-key or roving-focus behavior to a custom collection.

## Group row geometry and keyboard navigation

`RadioGroup optionStyle` styles each option's whole interactive row (including
card options); `style` continues to style only the group. For example,
`optionStyle={{ minHeight: 44, paddingVertical: 12 }}` gives full-width choice
rows without wrapping controls or duplicating their hit targets.

On web the group has one tab stop: the selected enabled option, or the first
enabled option when there is no enabled selection. Arrow keys focus and select
the next enabled option, wrapping at each edge. Horizontal arrows respect RTL;
Home/End reach the first/last enabled option. Disabled options are skipped, and
a disabled group has no tab stop. Controlled values remain caller-owned.
Space and Enter activate the focused option once. On a native host that gives
Bloom the window's keys (`PlatformKeyboard`, OxyOS's Full Keyboard Access) the
group is the same one stop through the platform's keyboard focus: only that
option is `focusable`, and while an option has the keyboard focus the four
arrows choose the next enabled one round the ends, the focus following the
choice once the value lands (`hooks/use-native-roving-group.ts`, as
[`SegmentedControl`](/docs/bloom/main/segmented-control) does). Without such a
host every option stays focusable, as before.

## Composing option bodies

Options accept `labelContent` for decorative layout, with `label` or
`accessibilityLabel` supplying the control's name. `renderOption(option, control,
state)` can wrap the owned radio with sibling content. Render `control` exactly
once, unchanged; `state.checked` and `state.disabled` report group-owned state,
and `state.controlRef` references the actual focusable host on web and native.
The group retains selection, disabled behavior and its one keyboard tab stop.
Interactive siblings keep their own keyboard behavior and do not select a radio.

Use [Collapsible](./collapsible.mdx) with `open={state.checked}` and
`returnFocusRef={state.controlRef}` for a revealed form. Never place inputs,
selects or buttons inside `labelContent`. `optionStyle` still styles each owned
radio, including logical row composition such as `flexDirection: 'row-reverse'`.

## Radio chips

`RadioGroup variant="chip"` renders `RadioChip` controls: pills without a dot,
with the same controlled/uncontrolled selection, roving focus, RTL arrows,
Home/End and Space behavior as other radio groups. The default layout is a row
with wrapping and an 8px gap. The default tone is neutral for chips; row and card
defaults are unchanged. `size` xs/sm/md/lg gives minimum heights 32/36/40/44px;
native touch hit slop brings smaller targets to 44px.

```tsx
<RadioGroup label="Size" variant="chip" value={size} onValueChange={setSize}
  size="md" tone="neutral" appearance="outline"
  options={[{ value: 'small', label: 'Small' }, { value: 'large', label: 'Large' }]} />
```

`appearance` controls selected chip paint (outline by default, also solid,
subtle or plain). Unselected options retain a quiet neutral outline; plain chips
have no border and underline the selected label. Neutral outlined selection uses
the theme's text-colored edge. Selection never promotes a neutral choice to the
brand tone. Description is an accessibility hint; use a row/card for visible
secondary descriptions. `labelContent` stays decorative and requires `label` or
`accessibilityLabel` for its name.

`optionClassName` and `optionLabelClassName` accept a string or a function of
`{ checked, disabled, controlRef }`, on all three group variants. The option
class replaces its standard layout and paint; the label class replaces the
built-in string label typography/color. The group `className` replaces its
default layout. Explicit `optionStyle`, `labelStyle` and `style` remain last.
The semantic disabled state and group keyboard handling stay owned by Bloom.
Standalone `RadioChip` accepts the corresponding `className` and
`labelClassName` props and the same `checked`/`onValueChange` contract as `Radio`.

## Colour swatches

`RadioGroup variant="swatch"` renders `RadioSwatch` controls: round discs, each
its option's `color`, as a desktop's accent colour picker draws its choices.
Nothing is drawn beside a swatch, so its option's `label` (or
`accessibilityLabel`) is the colour's NAME, which a screen reader says ("Blue,
selected, radio button"); `description` is its hint. The chosen swatch shows a
dot at its centre in the option's `foreground` (white unless given: pass the
colour's readable foreground for a light one).

```tsx
<RadioGroup label="Accent colour" variant="swatch" value={accent} onValueChange={setAccent}
  options={ACCENTS.map((name) => ({ value: name, label: names[name], color: hex[name] }))} />
```

|      | `xs` | `sm` | `md` | `lg` |
| ---- | ---- | ---- | ---- | ---- |
| disc | 16   | 18   | 22   | 26   |
| dot  | 6    | 6    | 8    | 10   |

The swatches sit in a wrapping row 8px apart, each target reaching 4px into
the gap so neighbours meet without overlapping. The group is the same ONE
keyboard stop as every radio group: on web the chosen swatch takes the tab stop
and the arrows choose the next; on a native host that gives Bloom the window's
keys the chosen swatch is the only `focusable` one and the four arrows choose
the next round the ends, the focus following once the value lands (a session
preference the platform keeps lands later, and the reader then says the swatch
once, already chosen). Disabled dims a disc to 50%. On web keyboard focus draws
a 2px accent outline 2px off the disc. `RadioSwatch` is also exported for a
layout of its own inside your own `radiogroup`.
