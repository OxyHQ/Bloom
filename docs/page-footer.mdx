# PageFooter

Page-local actions float over a bounded scroller, above the app's bottom
navigation. The background uses the same surface color and gradient as
`PageHeader`, mirrored upward. Content continues behind the footer; the measured
clearance lets the last item scroll fully above its controls.

```tsx
import { ScrollView, View } from 'react-native';
import { Button, PageFooter, PageFooterProvider, usePageFooterInset } from '@oxy.so/bloom';

function Message() {
  const bottom = usePageFooterInset();
  return (
    <View style={{ flex: 1, minHeight: 0 }}>
      <ScrollView contentContainerStyle={{ paddingBottom: bottom }}>
        <MessageBody />
      </ScrollView>
      <PageFooter
        actions={<><Button onPress={reply}>Reply</Button><Button onPress={forward}>Forward</Button></>}
      />
    </View>
  );
}

export function MessagePane() {
  return <PageFooterProvider><Message /></PageFooterProvider>;
}
```

The provider adds no layout and belongs around one pane. `usePageFooterInset()`
returns the footer's measured row height, its safe-area padding, and its bottom
offset. Use it **instead of** adding the bottom navigation inset again. It
starts with a 56px row estimate and updates when controls wrap or text scales;
the decorative gradient tail does not reserve layout. Removing the footer
(for example while replying) releases its clearance. If navigation still
overlaps the scroller then, retain its `useBottomEdgeInset()` as a fallback.

`bottomInset` defaults to Bloom's occupied bottom edge. `AppShell bottomBar`
publishes that measurement, including the safe area. Pass `bottomInset={0}`
when the containing frame already ends above navigation, or in a desktop pane
whose bottom edge differs from the app's. When the shell owns safe-area
handling, pass `safeArea={false}`. Otherwise the footer adds the native bottom
safe area only when its bottom offset is zero; web requires `safeArea` opt-in.

The footer reads the global bottom-edge registry but publishes its footprint
only in its local provider. It never increases the inset it uses to position
itself. Two panes have independent providers and measurements.

`actions` inherits the surrounding `BloomScope` size and supports wrapping.
`children` is an optional flexible slot before the actions. Group related
controls with `ButtonGroup` when desired. The scrim and the space between
controls let pointer events pass through. The gradient has no motion, including
when reduced motion is enabled. `scrim="none"` removes it; `scrimColor` overrides
the inherited opaque surface color. `style` and `testID` address the outer host.

The default `position="absolute"` anchors this page chrome inside a bounded parent.
Place it beside the scroller, never inside its scrolling content.

For web pages that scroll the document, use `position="document"`. Bloom pins
its controls to the viewport bottom while an invisible, zero-height anchor
tracks the actual content column. Sidebar widths, responsive layout and RTL
remain owned by the page layout; consumers need no fixed styles or measured
coordinates. Mount it in the column, outside transformed/animated containers
(which establish a different fixed-position containing block). Resize observers
follow its ancestor frames, and horizontal scrolling updates the viewport
coordinate without rendering again for unchanged bounds. Native keeps the
existing absolute positioning within its bounded screen.

Both positions publish the same measured `usePageFooterInset()` clearance.
Wrap the page and footer in `PageFooterProvider` and use that value as bottom
padding, instead of a guessed spacer. A purchase
summary with price and booking controls belongs to `ActionBar`, which has a
different opaque, in-flow layout contract.

### Follow the bottom edge of the content

Set `scrim="auto"` inside `ScrollMetricsProvider`, with a sibling `ScrollArea`
(or a list bound with `useScrollMetricsBinding`). The gradient is absent at the
bottom, for non-scrollable content, and before measurements arrive. It fades
in over `scrollThreshold` (default 20px) of remaining content. The actions stay
visible and their measured clearance does not change. Without a metrics owner,
`auto` remains hidden; the existing default `always` is unchanged.

Use `PageHeader scrim="auto"` in the same provider for matching behavior at the
top. Both keep their existing `scrimColor` override independently of scroll
visibility; neither paints a backing behind the gradient.
