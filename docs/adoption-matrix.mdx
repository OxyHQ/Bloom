# Adoption matrix

The contracts in [Composition](/docs/composition) are worth something only where they are read. This page is that measurement, and it is derived from the source on every change rather than written down once — a matrix maintained by hand is wrong the first time a family changes without its row being updated, and a stale row reads exactly like a fresh one.

## What is measured

- **Field membership** — `field/context.ts, field/membership.ts`. The id, accessible name, description, error, invalid, required and disabled state of an enclosing `Field`, applied to the control. Applies to a family that renders a raw `TextInput` or writes a form role of its own.
- **Control presentation** — `control-surface/context.ts`. The material and density a container asks the controls inside it for. Applies to a family that PAINTS a container material, or whose size prop is the density pair `medium | small`.
- **Trigger composition** — `floating/TriggerSlot.tsx`. `asChild`, the composed press handler, the cancellable open, the refused fragment and the two-sided disabled guard. Applies to a family that declares an `asChild` prop of its own.
- **Controlled / uncontrolled state** — `hooks/use-controllable-state.ts`. One reconciliation of "controlled the moment the prop is passed", with the callback firing either way. Applies to a family that declares both halves of a pair (`value` and `defaultValue`, `open` and `defaultOpen`, …).

A contract that a family does not read is not automatically a failure, and this is where a matrix usually starts lying in one direction or the other. `Search` renders no control of its own — it composes `TextFieldInput` — so the field contract is not its to read. A menu row carrying `role="checkbox"` is a menu item, not a form field. Every family a contract applies to and that does not read it is therefore classified, with a reason, in `src/__tests__/support/adoption-matrix.ts`:

| verdict | means |
| --- | --- |
| `reads` | the family imports the contract and applies it itself |
| `delegated` | it hands the decision to a child that reads it |
| `n/a¹` | the derivation matched something that is not the contract’s subject — the reason is below |
| `**adaptation**` | a real remaining gap, named rather than hidden |
| blank | the contract does not apply: the family renders nothing it governs |

The classification is an EQUALITY in `src/__tests__/adoption-matrix.test.ts`, not a floor: a family that starts matching a contract and is not classified renders as `**UNCLASSIFIED**` and fails the gate, and a classification whose family no longer matches fails it too.

## What remains — the named adaptations

### Field membership

- `listing-actions` — the mortgage calculator’s term picker is a hand-written `radiogroup`; it sits beside `TextFieldInput`s that DO read the contract, so one form has two association models.
- `listing-editor` — the property-type, offering and address-precision pickers are hand-written `radiogroup`s over cards, for the same reason and with the same cost as `questionnaire`.
- `questionnaire` — a FORM whose multi-select answers are hand-written `role="checkbox"` rows instead of `Checkbox`, so a `Field` can neither name nor disable them. Not closed here: the rows carry their own card chrome and selection model, so it is a redesign of the answer control rather than an import.
- `shipment-request` — the load KIND is the same hand-written `radiogroup` over `listing-editor`’s cards. The rest of the form is worse than that, not better: its `TextField`, `Textarea`, `Switch` and `SegmentedControl` all read the contract, so one form has two association models.
- `vehicle-picker` — a hand-written `radiogroup` over `listing-editor`’s selectable cards — it REUSES that family’s card rather than writing a third one, so it inherits the same gap for the same reason: a `Field` can neither name nor disable the group.

### Controlled / uncontrolled state

- `chart-cards` — a card’s range selector reconciles `range`/`defaultRange` by hand, in three cards, each with its own copy.
- `chat-list` — the folder tabs reconcile `value`/`defaultValue` with their own `useState` seeded from the default, so a controlled caller’s later change to `value` is honoured but the callback and the internal state can disagree.
- `creator-studio` — the streams chart’s metric picker keeps its own state seeded from `defaultMetric` instead of the shared hook.
- `input-otp` — reconciles `value`/`defaultValue` by hand (`const controlled = value !== undefined`) because it also CLEANS and pads the string to `length`, which the shared hook does not do.
- `questionnaire` — the step and the answers are each reconciled by hand, which is two copies of the rule in one family.
- `queue-panel` — the panel’s tab keeps its own state seeded from `defaultTab` instead of the shared hook.
- `track-list` — the selection set keeps its own state seeded from `defaultSelectedIds` instead of the shared hook, which matters more here because the value is an ARRAY and identity decides whether a caller’s update lands.

### Control presentation

- `chat-composer` (does-not-apply) — the `small | medium` prop sizes a composer PART (an attachment row), not a control a container would set the density of.
- `chat-people` (does-not-apply) — sizes an avatar row of its own, not a control: there is nothing for a container’s density to mean here, and honouring it would resize a presentation block.
- `chat-screen` (does-not-apply) — sizes the chat HEADER, which is chrome around the screen rather than a control a container sets the density of.
- `creator-studio` (does-not-apply) — sizes a studio stat block — a presentation part, whose two sizes happen to be spelled with the same two words as the density pair.
- `media-header` (does-not-apply) — sizes the media header’s meta row, which is layout of a header rather than a control inside a container.
- `note-editor` (delegated) — the toolbar passes `size` straight to `ButtonGroup`, which reads the contract — so a `ControlSurface` reaches the formatting row without this family reading anything.
- `phone-input` (delegated) — passes `size` straight through to `TextField`, which inherits density — so a `ControlSurface` reaches the phone field without this family reading anything.
- `place-card` (does-not-apply) — its `density` is the CARD’s — a result row against a detail header — not a control’s size, and the only controls it draws are `Button`s, which read nothing by design (`docs/composition.mdx`).
- `tenancy` (does-not-apply) — sizes a tenancy summary row: a presentation part, for the same reason as `creator-studio` and `chat-people`.

### Trigger composition

- `button` (does-not-apply) — `Button`’s own `asChild` renders the button AS an anchor or a router `Link` — it opens nothing and merges no open handler, so it is a different feature with the same name. It FORWARDS the trigger contract’s props when an anchored family clones it, which is the half that matters here.
- `theme` (does-not-apply) — `BloomColorScope`/`SeedScope` clone their child to merge a style instead of adding a layout node. No surface, no press, no open.

### Controlled / uncontrolled state

- `map-controls` (delegated) — the layer picker declares `open`/`defaultOpen` and hands both straight to `DropdownMenu`, which reconciles them with the shared hook — so a controlled caller is honoured without this family reconciling anything itself.
- `textarea` (does-not-apply) — the VALUE belongs to React Native’s `TextInput`, which reconciles `value`/`defaultValue` itself; the only local state is the character count, which is why it is kept for the uncontrolled case alone.
