# Avatar

Display a user's avatar. Accepts a URL, a `Shapes.ImageSource`, or no image at all — falls back to a tinted initials shape with the first letter of `name` (tint deterministic per name). Optional verified badge. Clips to a circle, a squircle, one of the named shapes, or an outline you supply.

## Basic

```tsx
import { Avatar } from '@oxy.so/bloom';

<Avatar uri="https://cloud.oxy.so/avatars/abc.png" size={48} />
```

`onImageError={() => ...}` reports a failure of the current primary photo once
per image request. Use it to disable an action that needs the photo, such as
opening its full-size version. Avatar still owns the fallback image and initials;
their failures and character rendering do not emit this callback. Replacing the
photo starts a new request and ignores late errors from the previous one.

Only a primary photo with `onImageError` mounts an observer: one component with
one ref and one layout effect. Photos without the callback, fallback images and
initials allocate none of that observation lifecycle. Adding or removing the
callback can remount the image node, but preserves the current fallback stage;
it does not retry a failed primary or resurrect a failed fallback. Replacing one
callback function with another keeps the observer mounted.

## Initials fallback

```tsx
<Avatar name="Ada Lovelace" size={48} />
<Avatar initials="M" color="blue" size="md" />
```

The fallback uses the selected silhouette behind its initials. `initials`
sets the text explicitly; otherwise it is the first letter of `name`. `color`
picks the tint; without it a `name` lands deterministically on one of the four,
so the same user always gets the same tint, and explicit `initials` default to
`neutral`.

| `color`   | disc                               | initials                  |
| --------- | ---------------------------------- | ------------------------- |
| `neutral` | `neutral-300` (dark `neutral-800`) | `neutral-500`             |
| `blue`    | `primary` ramp 300                 | `primary` ramp 900        |
| `lime`    | `success` ramp 200 (lime shape)    | `success` ramp 700        |
| `pink`    | `negative` ramp 200 (pink shape)   | `negative` (500)          |

The hue tints are not repainted in dark mode. `lime` and `pink` read Tailwind's lime/pink lightness ABSOLUTELY
(`absoluteRamp` in `avatar/initials.ts`): `colorRamp`'s gradient offsets would
sink `lime-700` to near-black against a theme `success`. `pink` reads
`negative` rather than `tertiary`, whose value can be a pale yellow that leaves
no legible letter.

`placeholderColor` still overrides the disc; with it and no `color` the letter
is white, since Bloom cannot know the contrast of an arbitrary colour.

## Sizes

`size` takes pixels or one of four rungs; the initials follow the rung:

| `size` | px | initials                          |
| ------ | -- | --------------------------------- |
| `xs`   | 20 | 10/15 semibold                    |
| `sm`   | 24 | `caption-1-semibold`, tracking 0  |
| `md`   | 32 | `headline-semibold` (16/22)       |
| `lg`   | 36 | 18/24 semibold                    |

A numeric size between rungs takes the next rung up's type (40 keeps `lg`'s);
above 40 the letter scales with the
disc (45% / 60% line height), since there is no larger rung to follow. On web a
size change animates width, height and font size over 200ms.

## Verified badge

```tsx
<Avatar uri={user.avatarUrl} verified size={64} />
```

Custom badge:

```tsx
<Avatar uri={user.avatarUrl} verified verifiedIcon={<StarIcon />} size={64} />
```

## Shapes

```tsx
<Avatar uri={user.avatarUrl} shape="squircle" size={56} />
```

`'squircle'` is Bloom's sampled superellipse (exponent 4.5). It is shared with `Shapes.Image`, `Shapes.Fill` and `Shapes.Border`; it does not claim an exact match to Apple's continuous corners.

Beyond it there is a registry of named outlines, for apps that let people pick
how their avatar is cut:

```tsx
<Avatar uri={user.avatarUrl} shape="heart" size={56} />
<Avatar uri={user.avatarUrl} shape="pentagon" size={56} />
<Avatar uri={user.avatarUrl} shape="6-sided-cookie" size={56} />
```

`Shapes.LABELS` gives every name with a display label, in a sensible
order, so a picker does not have to hardcode the list:

```tsx
import * as Shapes from '@oxy.so/bloom/shapes';

Shapes.LABELS.map(({ name, label }) => (
  <Pressable key={name} onPress={() => setShape(name)}>
    <Avatar uri={user.avatarUrl} shape={name} size={44} />
    <Text>{label}</Text>
  </Pressable>
));
```

`Shapes.LABELS` is English; `Shapes.labels(locale)` gives the same
rows in the app's language (pass the `BloomProvider locale`). The live badge's
word is localised via `BloomProvider locale` too; `liveLabel` overrides it.

For anything not in the registry, pass your own outline. `viewBox` is the side
length of the square space the path is drawn in, so a path written over a
0–100 grid needs no rescaling:

```tsx
<Avatar
  uri={user.avatarUrl}
  shape={{ d: 'M50 2L96 50L50 98L4 50Z', viewBox: 100 }}
  size={56}
/>
```

Local assets, `{ uri }` objects and URLs all use the selected outline. Arrays and request options such as `headers`, `method`, `body` or `cache` are unsupported on every shape; use a directly accessible URL, signed URL, data URI or local asset. Optional descriptor metadata is `width`, `height` and `scale`; Metro web assets may also carry a `toString` function, which is ignored without invocation and does not change the image request key. If the image and optional `fallbackSource` fail, the background behind the initials keeps that outline. An arbitrary `placeholderIcon` is centered above the fill; it is not masked, so size custom content to fit inside the silhouette.

Every shape except `'circle'` clips through `react-native-svg`; a circle is
drawn with `borderRadius`; a gradient ring still uses SVG. A `ring` follows
whichever outline the avatar uses. A shape name that does not resolve falls
back to a circle rather than rendering an empty clip — which matters when a
persisted user preference outlives the build that offered it.

## Inner border

```tsx
<Avatar shape="squircle" source={{ uri: user.avatarUrl }} ring={{ colors: ['#E1306C', '#FCAF45'], width: 3 }} />
```

`ring` draws inside the silhouette with uniform requested thickness and leaves the layout size unchanged. Its fields are `colors`, optional `width`, and optional `gradientDirection` (`diagonal`, `horizontal`, `vertical`). There is no outside gap option. `live` uses the same border and adds its badge.

## Pressable

```tsx
<Avatar uri={user.avatarUrl} size={40} onPress={() => navigate('Profile', { id: user.id })} />
```

Wraps the avatar in `Pressable` when `onPress` is set.

## Custom placeholder

```tsx
<Avatar
  placeholderColor={theme.colors.primary}
  placeholderIcon={<PersonIcon />}
  size={64}
/>
```

When no `source`, `uri`, or `name` resolves, you can fully control the placeholder.

## Bot accounts: the character, a still, or live

AI agents are Oxy accounts (`kind: 'bot'`) that carry a stored 3D `character`
(`AvatarCharacter`, see [Agent Avatar](/docs/agent-avatar)). `Avatar` draws it itself, so no app
wraps it:

```tsx
<Avatar account={user} size="lg" />            // a person: their image. A bot: its character.
<Avatar account={bot} size={128} />            // profile-sized: the character moves
<Avatar account={bot} size={36} activity="working" /> // moves while the agent works
<Avatar character={{ preset: 'blue_beret' }} name="Peri" /> // no account: an explicit character
```

`account` is the part of the account object an avatar reads: `{ kind, avatar, character,
username, name }` (`name` is a string or Oxy's `{ displayName, first, last, full }`). **Resolution order:
character, then image, then initials.**

Stored account characters accept the service's string-key DTO and are validated by
Bloom before drawing. Unknown or incomplete recipes fall back to the image/initials;
the explicit `character` prop remains typed as `AvatarCharacter`. A nonblank service
`name.displayName` takes precedence over the structured full name and handle.

`useAvatarRendererCapabilities().sharedLiveRendering` reports whether the current
provider can share live rendering across many independent avatars. It is true on
web, and on Android only after the integrated native adapter confirms the provider's
runtime manifest. It remains false while that check is pending, on iOS and without
the native adapter. A consumer may use it to select `motion="always"` for small bot
accounts and retain `auto` on the fallback topology, without inspecting private
renderers or mounting many WebViews during compatibility checks. It does not
override reduced motion or promise a particular frame rate.
Pass `{ enabled: false }` when no valid bot character needs that decision: the
hook then loads no native adapter and sends no manifest request. Human-only
lists should not initialize an avatar renderer merely to choose their motion policy.

1. **Character**: an explicit `character` prop, else a bot account's `character`. `character={null}`
   opts out and draws the image path. A remote or federated bot has no character and keeps its
   remote `avatar`. An invalid stored character is not an error: that avatar falls to its image,
   so one bad row does not take a list down.
2. **Image**: `source`/`uri` as before, else `account.avatar` (a URL or a resolver-handled id).
3. **Initials**: from `name`, else the account's name or handle.

The character is drawn unclipped (its silhouette is its own); `shape` applies to the image and
initials. `ring`, `verified` and the live-stream badge work the same.

### Still or live

| `motion` | behaviour |
| --- | --- |
| `'auto'` (default) | a **still** until `size >= AVATAR_LIVE_SIZE` (96, a profile or header slot) or `activity="working"` |
| `'always'` | live at every size |
| `'never'` | always a still |

The OS reduced-motion setting beats all three: a character never moves under it. (The existing
boolean `live` prop is the live-stream ring and badge and is unrelated; the character's motion
is `motion`.)

A live character is one `AgentAvatar`. `activity="working"` plays its Computer episode as soon as
its first frame is up (and again each time `activity` re-enters `'working'`); pass `workingKey`
yourself to own the trigger, and `reactionKey` to replay the authored reaction. Both only act on a
live character.

A **still** is an ordinary image, so a list of dozens of bots costs no canvas per row:

- Stills are drawn once by the same runtime, offscreen, and cached by **content**: a hash of the
  resolved character (so `{ preset }` and the same preset written out are one picture) plus a size
  bucket (64, 128 or 256 CSS px) and the pixel density. Fifty rows share a handful of images.
- Renders are queued **one at a time**; a row scrolled away before its turn takes its render with
  it. Web draws straight into the document; native uses ONE hidden `WebView` that
  `AgentAvatarProvider` mounts only while a render is queued.
- The box is reserved from the first render. Until the still is there the avatar shows its
  initials placeholder at the final size, so nothing jumps; if a still cannot be drawn the
  placeholder stays.
- Stills live in memory for the session (256 entries). Pass `storage` to `BloomProvider` (the
  adapter the theme persists with) or `stillStorage` to `AgentAvatarProvider` and the last 96
  also persist across launches. `localStorage` quotas are small; a PNG at list sizes is about
  7 KB.
- Nothing here opens a socket: only the runtime module (and the renderer's assets) is fetched, and
  only when a character is first drawn.
- **A rendered still is not cheap on a cold start.** It loads the same runtime and assets a live
  avatar does — measured for Alia's character on a cold cache: 31 requests, 16.1 MiB from the
  runtime origin — and only the canvas goes away afterwards.

### A still made ahead of time

An app whose character never changes (its own assistant, say) ships the picture and passes it as
`characterStill`. Wherever the character is still that image is drawn from the first render; the
still cache is not asked, so **nothing of the runtime is fetched**. When the character goes live
(`activity="working"`, a profile size, `motion="always"`) the same image stays under it until the
first frame, instead of the initials.

```tsx
import { ASSISTANT_STILL } from './assistant-still'; // a data: URI, or require('./assistant.png')

<Avatar character={ASSISTANT} characterStill={ASSISTANT_STILL} size={20} activity={activity} />
```

Make the picture with the runtime itself (a paused `portrait`, `reduced: true`) at the largest size
it is shown still: below `AVATAR_LIVE_SIZE` (96), at 2× density. Regenerate it when the
character or the runtime's look changes.

A character avatar is an image named by `alt`, else `name`, else the handle, else "Agent avatar";
`alt=""` makes it decorative.

`AvatarGroupItem` takes the same `kind` and `character`, so a facepile of agents shows stills.

### Where the runtime comes from

`BloomProvider` mounts `AgentAvatarProvider` for you: it renders nothing and loads nothing until a
character is drawn. The runtime URL defaults to `BLOOM_CHARACTER_RUNTIME_URL`
(`https://alia.onl/bloom-character/runtime.mjs`, CORS open, which needs `script-src` to allow
alia.onl under a strict CSP). An app that hosts `assets/character-runtime/` itself passes
`<BloomProvider characterRuntimeUrl="https://app.example/bloom-character/runtime.mjs">`; a nested
`AgentAvatarProvider` still wins for its subtree. An avatar with no provider at all gets the same
default, not a path relative to your host that would answer with HTML.

### Migrating to 10.7

Additive. `Avatar` without `account`/`character` is unchanged.

| Before | After |
| --- | --- |
| `bot.character ? <AgentAvatar character={bot.character} /> : <Avatar source={bot.avatar} />` | `<Avatar account={bot} />` |
| `<AgentAvatarProvider>` mounted per app | `BloomProvider` mounts it; delete yours unless you set a different `runtimeUrl` |
| default runtime URL `/bloom-character/runtime.mjs` on web, none on native | `BLOOM_CHARACTER_RUNTIME_URL` everywhere. Self-hosters pass `characterRuntimeUrl` / `runtimeUrl` (the old default was never a Bloom promise on native) |

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `source?` | `string \| Shapes.ImageSource \| null` | — | Flexible image source. Takes precedence over `uri`. |
| `uri?` | `string` | — | Direct URI string. |
| `variant?` | `string` | `'thumb'` | Rendition forwarded to the `ImageResolver` when `source` is a bare file ID. Defaults to `'thumb'` so avatars never request the full-size original; pass an explicit larger variant when you need a bigger image. Ignored for full URL / `{uri}` sources. |
| `fallbackSource?` | `Shapes.ImageSource` | — | Shown when `source`/`uri` errors. |
| `size?` | `number \| 'xs' \| 'sm' \| 'md' \| 'lg'` | `40` | Diameter in dp, or a named rung (20/24/32/36). |
| `color?` | `'neutral' \| 'blue' \| 'lime' \| 'pink'` | from `name` | Initials disc tint. |
| `initials?` | `string` | first letter of `name` | Explicit fallback text. |
| `alt?` | `string` | — | Accessible description of the photo. |
| `verified?` | `boolean` | `false` | Show a verified badge bottom-right. |
| `verifiedIcon?` | `React.ReactNode` | check icon | Custom badge node. |
| `shape?` | `Shapes.Shape` | `'circle'` | A built-in name or your own `{ d, viewBox }` outline. Anything but `'circle'` needs `react-native-svg`. |
| `style?` | `StyleProp<ViewStyle>` | — | Container style. |
| `placeholderColor?` | `string` | derived | Override placeholder background. |
| `placeholderIcon?` | `React.ReactNode` | initial | Override placeholder icon/letter. |
| `name?` | `string` | account name | Used to derive the initial + a stable tint, and the accessible name of a character. |
| `account?` | `AvatarAccount` | — | `{ kind, avatar, character, username, name }`. A bot with a character draws it; see above. |
| `character?` | `AvatarCharacter \| null` | — | Explicit character. Wins over the account's; `null` opts out. |
| `characterStill?` | `Shapes.ImageSource` | — | The character's picture made ahead of time: drawn wherever it is still, so no runtime loads. |
| `motion?` | `'auto' \| 'always' \| 'never'` | `'auto'` | Still or live. Reduced motion always wins. |
| `activity?` | `'idle' \| 'working'` | — | `'working'` makes the character live and plays its Computer episode. |
| `workingKey?` / `reactionKey?` | `number` | — | Replay the Computer episode / authored reaction when the key changes (live only). |
| `onPress?` | `() => void` | — | Wraps in `Pressable`. |
| `testID?` | `string` | — | |

## Recipes

### Stacked avatars

```tsx
<View style={{ flexDirection: 'row' }}>
  {users.slice(0, 3).map((u, i) => (
    <View key={u.id} style={{ marginLeft: i === 0 ? 0 : -8 }}>
      <Avatar uri={u.avatarUrl} name={u.name} size={32} style={{ borderWidth: 2, borderColor: theme.colors.background }} />
    </View>
  ))}
  {users.length > 3 ? (
    <View style={{ marginLeft: -8, /* counter chip */ }}>
      <Text>+{users.length - 3}</Text>
    </View>
  ) : null}
</View>
```

### Initials-only (no image)

```tsx
<Avatar name={user.displayName ?? 'Anonymous'} size={40} />
```

This is the recommended fallback when you don't have an avatar URL — never show a generic person silhouette unless you also have `placeholderColor` set to something brand-consistent.

### With a status dot

```tsx
<View>
  <Avatar uri={user.avatarUrl} size={48} />
  <View style={{
    position: 'absolute', bottom: 0, right: 0,
    width: 12, height: 12, borderRadius: 6,
    backgroundColor: theme.colors.positive,
    borderWidth: 2, borderColor: theme.colors.background,
  }} />
</View>
```

## Fallback tints keep their hue and clear AA

The four initials tints paint a disc from a theme role (`primary`, `success`,
`negative`, the neutral ramp) and the letter from a stop on the same ramp. The
stop is a PREFERENCE: `legibleStop` walks outward from it along that ramp until
the letter clears 4.5:1 on its own disc, so the hue survives and the letter is
always readable.

It has to walk, because the ramp is rebuilt around a theme role whose lightness
moves with the mode. Measured in dark on `blue`: `pink` **1.24:1**
(`#ffb4ab` on `#ecd8d6`), `lime` 4.29:1, `neutral` 3.19:1 — and
`avatarTintForName` sends a quarter of all fallback avatars to each tint. After:
5.42, 6.09 and 5.85. The discs are unchanged. Gate: `surface-levels.test.ts`.
