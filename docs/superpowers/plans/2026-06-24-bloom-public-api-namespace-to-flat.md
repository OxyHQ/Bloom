# Bloom Public API — Namespace→Flat Implementation Plan (Phase 1A)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert every compound-component family in `@oxyhq/bloom` from namespace exports (`Tabs.Tab`) to flat prefixed exports (`TabsTrigger`), while keeping the six collection families namespaced — so the public API is one consistent shape.

**Architecture:** Each family's source index re-exports its parts under flat prefixed names; the root barrel (`src/index.ts`) stops wrapping them in `export * as X`. The web barrel (`src/index.web.ts`) and the `exports` map are regenerated by the existing `scripts/generate-platform-exports.mjs` — no manual edits to generated files. A barrel-contract test locks the rule in place.

**Tech Stack:** TypeScript, React Native + Web, react-native-builder-bob (build), Jest + ts-jest (test), bun (package manager).

## Global Constraints

- Package manager is **bun** — never npm/yarn. Use `bunx` not `npx`.
- The **six collection families stay namespaced** and MUST NOT be flattened: `Icons`, `Typography`, `Skeleton`, `Grid`, `Code`, `Fonts`.
- **No compatibility shims / no deprecated aliases** — old namespace names are removed outright (AGENTS.md rule + 0.16.x precedent).
- **No `as any`, no `@ts-ignore`, no `var`, no `console.log`, no `!` non-null assertions, no TODO/FIXME.**
- `src/index.web.ts` is **AUTO-GENERATED** — never hand-edit it. Only edit `src/index.ts` then run `bun run generate:exports`.
- Forked families (have a `.web.tsx`) must have **both** `index.tsx` and `index.web.tsx` renamed identically: `Menu`, `Tooltip`, `Select`, `ContextMenu`, `Popover`.
- Each family keeps its existing subpath (`@oxyhq/bloom/tabs`, …) — only the exported **names** change, never the path.
- Verification gate per family: `bun run typescript` AND `bun run test` both green before commit.

### Task 1: Barrel-contract test (the TDD anchor)

This test encodes the rule "only the six collections are namespaces; everything else is
flat". Every later task updates its expectation, watches it fail, then makes it pass.

**Files:**
- Test: `src/__tests__/public-api-contract.test.ts` (create)

**Interfaces:**
- Consumes: the root barrel `../index`.
- Produces three canonical lists later tasks rely on: `ALLOWED_NAMESPACES` (the six collections), `FLATTENED_ROOTS` (the eleven compound roots, which become flat components), `REPRESENTATIVE_PARTS` (one renamed part per family, sanity-checks the rename landed).

> **Why `typeof === 'function'` and not "is it an object":** a `export * as X`
> namespace compiles (under ts-jest/commonjs) to a plain object — but so do many
> legitimate data exports (`Z_INDEX`, `iconSizes`, `STATUS_COLORS`, `tokens`). You
> cannot reliably tell a module namespace from a data object at runtime. The robust
> discriminator is the *other* direction: after conversion, each compound family's
> top-level name is its **root React component (a function)**, never a namespace
> object. So the test asserts the new flat shape positively.

- [ ] **Step 1: Write the test**

```ts
// src/__tests__/public-api-contract.test.ts
import * as Bloom from '../index';

type AnyExports = Record<string, unknown>;
const api = Bloom as AnyExports;

// The ONLY families allowed to remain namespace objects (collections /
// generic-colliding part names). Everything else is flat-with-prefix.
const ALLOWED_NAMESPACES = ['Icons', 'Typography', 'Skeleton', 'Grid', 'Code', 'Fonts'] as const;

// Compound families converted to flat: their top-level name becomes the
// root component (a function), no longer a namespace object.
const FLATTENED_ROOTS = [
  'Tabs', 'Accordion', 'Select', 'Menu', 'ContextMenu', 'Popover',
  'Tooltip', 'SegmentedControl', 'TextField', 'Admonition', 'PromptInput',
] as const;

// One renamed part per converted family — proves the flat rename landed.
const REPRESENTATIVE_PARTS = [
  'TabsTrigger', 'AccordionItem', 'SelectItem', 'MenuItem', 'ContextMenuItem',
  'PopoverTrigger', 'TooltipTrigger', 'SegmentedControlItem', 'TextFieldInput',
  'AdmonitionIcon', 'PromptInputTextarea',
] as const;

describe('public API contract', () => {
  it('keeps the six collection families as namespace objects', () => {
    for (const ns of ALLOWED_NAMESPACES) {
      expect(typeof api[ns]).toBe('object');
    }
  });

  it('exposes each compound family root as a flat component (not a namespace)', () => {
    for (const name of FLATTENED_ROOTS) {
      expect(typeof api[name]).toBe('function');
    }
  });

  it('exposes compound parts as flat prefixed components', () => {
    for (const name of REPRESENTATIVE_PARTS) {
      expect(typeof api[name]).toBe('function');
    }
  });
});
```

- [ ] **Step 2: Run it — expect FAIL**

Run: `bunx jest src/__tests__/public-api-contract.test.ts`
Expected: FAIL — today `Tabs`, `Select`, `Menu`, etc. are still namespace **objects**
(so `typeof` is `'object'`, not `'function'`) and the renamed parts like `TabsTrigger`
do not exist yet (`'undefined'`). The collection assertion already passes.

- [ ] **Step 3: Commit the failing test**

```bash
git add src/__tests__/public-api-contract.test.ts
git commit -m "test(bloom): add public-API namespace/flat contract test (red)"
```
