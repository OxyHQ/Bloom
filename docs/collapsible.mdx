# Collapsible

Use `Collapsible` when an existing control owns whether a body is shown, such as
an option in a radio group. Use `Accordion` for labelled disclosure sections with
their own toggle buttons. Both share the same measured frame and motion owner.

```tsx
import { RadioGroup } from '@oxy.so/bloom/radio';
import { Collapsible } from '@oxy.so/bloom/collapsible';

<RadioGroup
  label="Delivery plan"
  value={plan}
  onValueChange={setPlan}
  options={[
    { value: 'once', label: 'One delivery' },
    { value: 'repeat', label: 'Repeat delivery' },
  ]}
  renderOption={(option, control, { checked, controlRef }) => (
    <View>
      {control}
      {option.value === 'repeat' && (
        <Collapsible open={checked} returnFocusRef={controlRef}>
          <FrequencySelect />
          <TextInput accessibilityLabel="Delivery note" />
        </Collapsible>
      )}
    </View>
  )}
/>
```

Render the owned radio once, unchanged. The body and its interactive controls are
siblings of the radio, never children of its decorative label.

| Prop | Ownership |
| --- | --- |
| `open` | Required controlled visibility; no internal toggle or default state. |
| `appear` | Mounted open, it opens: height and fade run from nothing instead of starting settled. For content that arrives while the person watches (a new row in a thread). Default `false`: open at mount (a history, a restored page) does not move. |
| `transition` | `{ duration, easing? }`, milliseconds and cubic-bezier coordinates, for the height and the fade alike. Defaults to 300ms and `[.42, 0, .58, 1]`. Duration is clamped non-negative; invalid values use the standard motion defaults. |
| `keepMounted` | Default `true`: children stay mounted while shut. `false` unmounts them once the exit finishes and mounts them again on opening, for a closed branch that should cost nothing (a large tree, an empty attachment strip). |
| `returnFocusRef` | DOM or native focusable host to receive focus only when closing content owned it. Accepts `RadioOptionState.controlRef` directly. |
| `className`, `style` | Outer frame, the node its parent lays out. Height clipping and opacity are animated by Bloom. |
| `contentClassName`, `contentStyle` | Natural body; place padding/gaps and content decoration here. |
| `nativeID`, `testID` | Outer host identity. No role or labelled-by relationship is invented. |

Standalone web reveals use a CSS Grid row from `0fr` to `1fr`, so content and width
changes remain intrinsic without a height observer or JavaScript animation loop.
Native and the accordion's spring-driven frame use their existing measured-body
motion. Neither path imposes a fixed maximum height. Children stay mounted so edits and selections
survive closure, unless `keepMounted={false}`. Web uses `inert` and `aria-hidden` immediately. Native disables
pointer interaction and removes descendants from accessibility immediately, then
removes the body from layout when the exit finishes. Live reduced motion cancels
active animation and settles the body immediately. No global `LayoutAnimation`
configuration is changed.

Focus return never overrides deliberate focus outside. On web it includes
logical descendants through React portals and can fall back to the outside
focus captured when opening. Native observes hardware/control focus and the
public currently focused TextInput API; supply `returnFocusRef` there. React
Native does not expose the current VoiceOver/TalkBack cursor, so cursor-only
focus cannot be detected without stealing unrelated accessibility focus.

A nested Bloom `Select` closes its portaled popup when its body becomes hidden;
its selected value survives and its popup stays closed on reopening. A custom
portaled control must likewise coordinate its own open state with visibility.

## `useCollapsibleMotion`

The motion owner behind native `Collapsible` and spring-driven `Accordion`, public for a part that
moves with a reveal it does not draw — a chevron that turns as a body opens, a
header that follows it. Do not rebuild a height-and-opacity reveal on top of it;
render `Collapsible`.

```tsx
import { useCollapsibleMotion } from '@oxy.so/bloom/collapsible';

const { progress, hidden, settled } = useCollapsibleMotion(open, { duration: 200 });
const turn = progress.interpolate({ inputRange: [0, 1], outputRange: ['0deg', '90deg'] });
```

| Argument / field | Meaning |
| --- | --- |
| `open` | Target state. |
| `transition` | A `SurfaceTransition` (default 300ms `[.42, 0, .58, 1]`) or `'spring'`. |
| `kind` | `'trigger'` uses the snappier spring, `'content'` (default) the gentle one; springs only. |
| `useNativeDriver` | Default `false`; only for transform/opacity consumers. |
| `progress` | React Native `Animated.Value`, 0 shut → 1 open. |
| `hidden` | `true` once a closed body has finished leaving. |
| `settled` | `true` once an open body is at rest. |

Live reduced motion settles immediately.

The old pre-1.0 `Collapsible` implementation was removed for a module-scope
Android layout-animation side effect. The controlled API introduced in 7.22 is
a new implementation and does not restore that behavior or the old props.

Standalone web completion follows only its own `grid-template-rows` transition.
Closing makes descendants inert immediately; `keepMounted={false}` removes them
after geometry finishes. Reopening cancels the pending close without replacing
retained children. Reduced motion settles directly. This shares the CSS clock
with docked navigation presence, avoiding a one-frame footer-space jump when an
editor expands as its navigation disappears.
