# SocialButton

A "Continue with …" / "Sign in with …" button for an identity provider. The brand is **named**, not passed as artwork: `brand="google"` supplies the logo, the brand colour and the accessible label together, so a stack of these cannot drift out of sync.

```tsx
import { SocialButton } from '@oxy.so/bloom/social-button';

<SocialButton brand="oxy" action="signIn" onPress={signIn} />   // Sign in with Oxy
<SocialButton brand="google" onPress={signInWithGoogle} />      // Continue with Google
<SocialButton brand="github" appearance="white" />               // outlined, colour mark
<SocialButton brand="apple" iconOnly />                          // circle, logo only
<SocialButton brand="figma" href="https://example.com/auth/figma" />  // a link
```

Providers: `oxy`, `google`, `apple`, `github`, `gitlab`, `microsoft`, `x`, `facebook`, `linkedin`, `discord`, `slack`, `figma`, `notion`, `dropbox`, `spotify`, `twitch`, `reddit`, `tiktok`, `instagram`, `telegram`, `whatsapp`, `amazon`, `bitbucket`, `auth0`, `okta` — also exported as `SOCIAL_PROVIDERS`.

## Wording

`action` picks the verb of the default label — and of the accessible name when `iconOnly`:

| `action` | Label |
| --- | --- |
| `continue` (default) | Continue with Google |
| `signIn` | Sign in with Google |
| `signUp` | Sign up with Google |

The phrase is localised through `BloomProvider locale` (English shown). Pass `children` to write the label yourself.

## Oxy

`brand="oxy"` is Oxy's own mark, drawn two-tone — the mark, and its letters in the colour behind it. It follows Google's treatment: `colorful` is Bloom's **primary button** painted with the theme accent, so it matches the app it sits in; `white` is the secondary button with the mark in the accent; `black` draws it white on near-black. The Oxy SDK's `OxySignInButton` is this button with `action="signIn"`.

SocialButton composes the real `Button`: material, focus, press, disabled and links share its implementation. Provider metadata supplies the logo, label and resolved brand fill/on-fill pair. Scoped `sm`/`md` sizing and unique SVG gradient identifiers are preserved.

## Appearance

| `appearance` | Look |
| --- | --- |
| `colorful` (default) | Saturated brand glass with a white glyph and Button’s shared sheen and interaction tints. |
| `black` | Near-black glass, white label. |
| `white` | The secondary button — surface, 1px border and its hover/press — with the provider's **real multi-colour mark**. What most sign-in screens use. |

Google's `colorful` button is Bloom's **primary button**, material and states included, painted with the theme's accent rather than Google's own `#4285F4` (the two side by side read as a mistake). Its multi-colour G under `white` stays Google's own.

Apple, GitHub and X draw their marks in near-black, which vanishes on a dark surface, so in dark mode the `white` appearance repaints those marks white — the treatment both publish for dark backgrounds. Amazon has no colour mark upstream; its `white` button uses the monochrome glyph tinted with the brand colour.

## Size and shape

| `size` | Height | Width | Padding | Glyph |
| --- | --- | --- | --- | --- |
| `md` (default) | 36 | 300 | 12 | 18 |
| `sm` | 32 | 250 | 10 | 16 |

The fixed width lines a column of providers up without a wrapper; `fullWidth` fills the container instead. `iconOnly` makes it square (a circle — every Bloom button-like control is a full pill). Label is `body-medium` and truncates.

## Custom providers

```tsx
<SocialButton
  brand="custom"
  config={{ label: 'Acme SSO', color: '#7C3AED', icon: <AcmeLogo width={18} height={18} /> }}
/>
```

`color` is a resolved `#rrggbb` or `rgb()` brand fill. The icon is rendered as given — colour it yourself for the appearance.

## Links

`href` makes the button a link, since an OAuth start is a navigation. On web it renders a real `<a href>` (role `link`); on native a press runs `onPress` and then `Linking.openURL(href)`. A disabled button drops its `href`.

## Accessibility

The visible label names the button. With `iconOnly` there is no visible label, so the button is named `"Continue with <Brand>"` — override with `accessibilityLabel`. On web a keyboard user gets a 2px accent `:focus-visible` ring with a 2px offset. `disabled` uses Button’s shared disabled tint, retains its glass and ignores presses.
