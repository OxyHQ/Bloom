# ComposerLoader renderer diagnosis by platform

Evidence for [Bloom #663](https://github.com/OxyHQ/Bloom/issues/663), §8, on Bloom `cfd4e12ebda9ea371b8c925eb00da22eb438610d` (`@oxy.so/bloom@19.7.0`). This records source-level diagnosis and links it to the physical Android measurements already in the audit. Source inspection is not a substitute for optical acceptance on each platform.

## Shared geometry and units

`src/composer-loader/shared.ts` is the geometry authority for web and React Native. `onLayout` supplies measured layout dimensions; the renderers use those values as the SVG `viewBox` width and height with `preserveAspectRatio="none"`. Geometry clamps the requested corner radius to half the shorter side and computes the rounded-rectangle perimeter as `2(w + h) - 8r + 2πr`. The arc becomes a fraction of a normalized 100-unit lap; dash phase is normalized against the measured perimeter. Taper adds fourteen centered dash copies per enabled layer. The ordered layers are bloom, glow, then crisp line. Default Gaussian standard deviations are 14, 6, and 0.5 viewBox units (the crisp layer is at least 0.5 when tapered).

The common source therefore rules out a different perimeter or radius formula between the web and React Native SVG paths. It does not establish pixel equality: the viewBox coordinate systems and platform SVG filter implementations differ, and the Android hardware adapter applies an explicit calibration.

## Renderer findings

| Runtime | Filter units and region | Geometry, clipping, gradient and blend | Finding and remaining limit |
| --- | --- | --- | --- |
| Web (DOM SVG) | `feGaussianBlur` receives the shared standard deviation in the measured CSS-pixel viewBox. Each filter declares `x/y=-50%`, `width/height=200%`. | `pathLength=100` makes dashes use the shared normalized lap. The rounded rect uses the clamped radius. The light sits above the Surface sibling; the light wrapper clips overflow to that radius. A left-to-right object-bounding-box gradient has stops at 0/30/50/70/100%; the midpoint blends the two middle theme colors. `mixBlendMode` is applied to the clipped light wrapper when requested. | Source explains intended units and paint order. WebKit must be visually checked separately; this code inspection does not establish browser optical parity. |
| iOS (React Native SVG) | The iOS fork uses the shared measured layout as `viewBox`, with the same `Filter` region and `FeGaussianBlur` values. Those values are SVG user units; iOS rendering maps viewBox units to the native view. | It uses the same ordered shared strokes, clamped `rx/ry`, normalized perimeter/dash calculation, gradient stops and clipped overlay. Blend is applied to the overlay wrapper. | Source identifies the iOS path and intended geometry. No physical iPhone capture exists in this work, so the renderer's effective filter radius, clipping and blend result on iOS remain unverified. |
| Android SVG fallback | React Native SVG receives the shared geometry/filter values. On supported Android API levels the custom light adapter replaces this SVG paint; older APIs, missing native managers, invalid custom geometry and software hosts retain the SVG fallback. | The SVG fallback groups strokes by semantic layer before applying one blur per layer. It preserves shared viewBox geometry and clip. | Pixel 8a measurements cover the packaged renderer on Android 16/API 36. Other fallback hosts and API 30 physical behavior remain open; do not infer broad performance from the Pixel samples. |
| Android hardware adapter (API 31+) | `android/src/main/java/so/oxy/bloom/ComposerLight.kt` converts layout dimensions, radius and stroke width from dp to physical pixels with display density. It groups strokes into RenderNodes, rasterizes soft layers at quarter resolution, scales blur sigma by density and the layer scale, then converts Gaussian sigma to Android `RenderEffect` radius with `(sigma - 0.5) / 0.57735`. Soft tapered layers use the reviewed 0.7 calibration; bloom-only uses 0.8 alpha. | `PathMeasure` draws the one-dash-per-lap segment using the analytic perimeter converted to physical pixels. A horizontal `LinearGradient` has stops at 0/30/50/70/100%; Android receives the already blended middle color. The parent SVG overlay still owns clipping and optional blend. A synchronous padded bitmap blur is used only for a temporary software canvas capture; a persistently software-rendered host signals fallback and freezes the owner clock. | This is a deliberately calibrated Android renderer, not a pixel-equivalent SVG implementation. API 31+ hardware drawing is the intended path. Physical Pixel 8a evidence exists for Android 16; other GPU/host combinations and API 30 physical rendering remain unverified. |

## Evidence and scope

- The physical Pixel 8a Android 16/API 36 artifact comparison and composer interaction record are in [`composer-loader-pixel8a-2026-11-10`](./composer-loader-pixel8a-2026-11-10/README.md). It identifies a radius mismatch fixed in 17.38.0 and explicitly limits its optical/performance conclusions.
- The narrow/multiline Pixel 8a run is in [`composer-loader-multiline-pixel8a-2026-11-10`](./composer-loader-multiline-pixel8a-2026-11-10/README.md). Its frame, CPU and memory measurements are descriptive; no approved pass budget exists.
- The Android hardware and software-host evidence and remaining limits are recorded in [`composer-loader.mdx`](../../composer-loader.mdx#android-hardware-light-adapter-integration-candidate) and [`composer-loader-android-adapter-2026-11-08.json`](../../benchmarks/composer-loader-android-adapter-2026-11-08.json).
- The source establishes the filter, unit, perimeter, gradient, radius, clipping, blend and stacking choices. Runtime optical confirmation remains separate. In particular, iPhone testing was deferred by the user; this document does not claim iOS visual acceptance or complete §8/R6.
