# Surface backing: numerical prototype, not a contrast guarantee

GoWay candidate 58dd79e measured the dark search placeholder at 4.005:1 on land
and 4.100:1 on sea. Its other 20 selected texts cleared 4.623:1. The owner
currently publishes tint alpha composited over nominal parent fill, while web
paints that tint over a filtered backdrop. TextField derives its placeholder
against an opaque next-level fill. Neither computation describes that painted
map scene. Preserve those negative screenshots in GoWay PR 312.

## Minimal design

Keep one pure filter calculation shared with baked material. This prototype
extracts the existing implementation unchanged into `surface/filter-color.ts`;
the baker retains compatibility exports. `filterColorBounds` adds an internal,
unused interval calculation. It does not change paint, tokens, or foregrounds.

A proposed optional backing range belongs in the existing Surface context:
independent lower/upper sRGB channel bounds, normalized to [0,1], describing
pixels available to the backdrop sampler. A known solid has equal bounds; an
unknown map/image starts at the entire RGB cube. The pure filter propagates that
range; tint alpha composition narrows it. No global registry, sampled average,
per-frame React update, or application-specific color is needed. Theme mode
selects the existing recipe explicitly. CanvasPanel can declare unknown scene
backing; CanvasBackground's name alone cannot assert any known color. Only a
host that really paints an opaque known background can reset uncertainty.

Keep current `solidFill` separate: reduced transparency, increased contrast and
native opaque paint do not receive the web filter. `paint=false`, transparent
paint and explicit caller alpha retain their existing semantics. Existing public
APIs remain compatible; no public prop has been added in this prototype.

A later foreground resolver can use conservative luminance limits for its own
painted body and the semantic quiet-text role. If a range crosses the foreground
luminance, endpoint contrast is insufficient: the worst ratio can be 1 inside
the interval. If no semantic foreground can clear the entire range, report that
failure and require a real known backing, rather than pretending primary text
or a raised arbitrary floor guarantees contrast. This decision is not yet wired.

## Numerical proof and browser check

Run `bun docs/audits/issue-663/surface-backing/probe.ts`. Each affine CSS stage
has extrema at a corner of the incoming box; clamp is monotone. Enumerating all
eight corners at **each** stage includes negative saturation coefficients.
Discarding cross-channel correlation only widens the enclosure. Blur is a
weighted average and stays inside the box if every sampled input is inside it.
The mathematical enclosure, not the finite grid, is the justification.

`numerical.json` checks 35,937 colors in each of four mode/range combinations
(143,748 total), with zero escapes. The restricted mixed-color box illustrates
why evaluating only its lower/upper diagonal is insufficient. Whole-cube body
channel ranges are light [0.3850959, 0.9949041] and dark
[0.12737082575, 0.99577917425], before tint and pixel quantization.

Run `pixels.ts` with `PLAYWRIGHT_PACKAGE_JSON` and `CHROME_PATH` set. It paints
nine flat backdrops per mode including all saturated cube corners, takes a full
viewport screenshot, then samples centers from a fresh canvas loaded with that
PNG. Chromium 1248's observed maximum channel error versus the shared numeric
filter is 0.349/255 light and 0.480/255 dark. Files record the exact browser,
filter strings, inputs, outputs and screenshots. These are filter-body probes,
not a reproduction of complete nested Surface paint. Any eventual guaranteed
range must include quantization slack and be verified in other target engines.

## Limits before production integration

The edge is a separate brightness/mask pass. A body-only range does not cover
text over that edge or a descendant blur sampling the parent's edge. Nested
blur may also sample outside the nominal parent body. To claim enclosure there,
propagate the union of **all** actual sampled layers (including outside-parent
pixels), or conservatively fall back to unknown. Do not reset to parent body
bounds just because the DOM child is visually inside it. This prototype does
not solve that topology or publish an assurance about arbitrary RGB maps.

The inherited `parseLook` is not a general CSS parser: it uses `parseFloat`,
so percentage syntax would be misread. Here its input is exclusively the
numeric string generated by `materialFilter`; no arbitrary CSS is accepted as
proof input. The interval helper rejects unknown stages, non-finite/negative
amounts and invalid bounds. Future integration must keep generated validated
numeric stages, not promote this parser into a general CSS guarantee.

The proof assumes sRGB, the currently supported affine/clamped filter stages,
and ordinary alpha composition. HDR, other blend modes and unknown filters need
an unknown-range result. Native opaque and reduced-transparency paths need
separate regression tests. No GoWay placeholder color has been changed; the
negative remains open. The 20 neighboring text samples must be repeated after
any correction, alongside light/dark land/sea and stronger synthetic backings.

Validation: 18 tests in three suites passed (baked material, material resolver, interval contracts). Source and consumer typechecks passed; consumer gate checked 3,094 source files without Node types and fired its positive control. Biome checked the extracted source. No package-publication or complete Surface pixel-parity claim is made.
