# Glass

Surface defaults to an opaque fill with the shared gradient and rim. Button, Card, Sidebar, Dialog and Bottom Sheet use this solid material with no backdrop blur or refraction. Explicit `Surface material="glass"` remains available for comparison: it adds a translucent tint and a shared web displacement filter. Native glass uses tint/sheen without refraction. See [Surface](./surface.mdx) and [Button](./button.mdx).

The previous standalone `GlassSurface`, `GlassSurfaceProps` and `theme/glass-colors.ts` material have been removed. There is no replacement wrapper to mount around a Button. Existing overlay blur infrastructure remains under `@oxy.so/bloom/glass`: `GlassBlurTargetProvider`, `GlassBlurWindow`, and `useWindowedBlurTarget`.

Light mode retains its bright specular rim. Dark mode uses its own softer sheen and thin top highlight instead of the white inset border. The backdrop distortion uses actual captured pixels, including nearby colours outside the pane; the rim itself is decorative lighting. See the lateral-sampling browser check in [Surface](./surface.mdx).

## Material checks

A translucent fill's label must be measured against the painted composite, across both theme modes and representative backdrops. High-opacity tints usually need the fill's on-colour; clear neutral panes need the theme's text colour. Do not reuse contrast figures from an older alpha or sheen. Prove translucency by measuring how painted pixels move with a changed backdrop, not by reading computed background colour or relying on a failed contrast threshold.

SVG stops require separate `stopColor` and `stopOpacity`: native SVG can discard alpha embedded inside `stopColor`, turning a subtle white/black sheen into an opaque wipe. Keep shadow on the outer control and clip only the inner paint layer; clipping the outer node removes iOS shadows.

## Overlay blur

`expo-blur` couples tint and blur intensity; CSS backdrop blur does not. Native and web therefore require separate visual checks whenever their materials change. Android blur must target content in a separate native window. A BlurView inside its own BlurTargetView can crash in native rendering (recursive RenderNode traversal). Never expose the app-root target directly to an inline control; only `GlassBlurWindow` inside an actual Modal may publish it. The separate-window check in `blur-target.tsx` preserves that boundary.

## Floating islands

`GlassIsland` keeps its grouping and geometry and paints with the same Surface material. Explicit glass groups share one translucent pane with flush controls. Plain sidebar surfaces and navigation rails keep their existing semantics.

GlassIsland defaults to shared solid material and publishes its actual fill and contextual level. `material="glass"` explicitly enables translucent optics and publishes the tint composited against its parent as an estimate. Its ControlSurface material matches the selected material; glass groups pass that option explicitly.
