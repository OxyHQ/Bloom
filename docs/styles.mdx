# Styles

`@oxy.so/bloom/styles` holds the style primitives Bloom itself uses.

```tsx
import { atoms as a, tokens, BREAKPOINTS, web, native, select } from '@oxy.so/bloom/styles';
```

## `atoms`

Utility style objects — `a.flex_1`, `a.flex_row`, `a.align_center`, `a.px_sm`.
They are the inline equivalent of the Tailwind utilities, and they exist
because **a className is inert on web without the consumer's Tailwind
pipeline**. Anything Bloom must draw correctly with or without that pipeline
uses atoms; layout that only apps compose can use classes.

## `tokens`

The t-shirt view of the scales — `tokens.space.lg`, `tokens.borderRadius.xl`.

The numbers themselves live in `design-tokens/scales.ts` and are read from
there by reference, so a rung cannot exist in one spelling and not the other.
They did once diverge: `borderRadius.full` was 999 against `radius-max` 9999,
and each file's comments claimed to match the other.

Prefer the numeric names (`radius-20`) when you are naming a rung in an API —
[`Card`](/docs/bloom/main/card)'s `radius` prop takes those — and the t-shirt
names in ad-hoc inline style.

## `BREAKPOINTS`

The shared widths, so a component and the screen around it agree about when the
layout changes.

## `web` / `native` / `ios` / `android` / `platform` / `select`

Platform-conditional style helpers. Use them for a genuine platform difference
— a shadow, a font smoothing, a scrollbar — and not to work around something
that should be the same on both.

## `webDataSet`

The web-only `dataSet` hook an adopted sheet's selectors hang off, as spread
props. On web react-native-web turns it into a `data-*` attribute; on native it
spreads nothing.

```tsx
<Pressable {...webDataSet({ bloomTrackRow: 'true' })} />
// web:    <div data-bloom-track-row="true">
// native: nothing
```

This is how a component reaches a CSS rule it cannot express inline — a hover
state, a focus ring, a transition. A class never reaches the DOM here, so a
`data-*` attribute is the only hook an
[adopted sheet](/docs/bloom/main/styles) can select on.

## `clamp` / `clamp01`

```ts
clamp(value, min, max)   // held inside [min, max]
clamp01(value)           // held inside [0, 1]; undefined / NaN / ±Infinity → 0
```

Two edges worth knowing, because the copies these replaced disagreed about
them:

- `clamp` resolves an INVERTED range (`min > max`) to `min`. That is what pins
  a dropdown taller than the viewport to the top gutter, so its first rows stay
  reachable instead of its start going off-screen.
- `clamp01` answers `0` for a non-finite value, including `Infinity`, where
  `clamp(v, 0, 1)` would answer `1`. A non-finite share means "not measured
  yet", and a full bar is the wrong thing to draw for that.

## `contrastRatio` / `relativeLuminance` / `readableOn` / `darken` / `darkenUntilContrast`

WCAG maths and the two decisions every surface painted from a computed colour
has to make. `AA_TEXT_CONTRAST` (4.5), `AA_LARGE_TEXT_CONTRAST` (3) and
`AAA_TEXT_CONTRAST` (7) are the bars, named once.

```ts
readableOn(background, ['#ffffff', '#141414'])       // which ink reads on it
darkenUntilContrast(artworkColor, '#ffffff', 7)      // { color, amount } | null
```

`readableOn` takes one surface or several, and picks the candidate whose WORST
contrast across them is highest — text over a gradient has to read at both ends.

`darkenUntilContrast` returns the LIGHTEST shade of a colour on which every
given foreground clears the ratio: the colour itself when it already does, else
pulled toward black in 5% steps. `null` for a colour that does not parse, so a
caller falls back to its own neutral rather than being handed one it did not ask
for.

**Darken the colour; never walk its ramp.** A generated ramp re-derives every
stop's lightness and chroma from the hue, so a near-black input comes back ten
times lighter than it went in and a vivid one has a channel zeroed. Scaling
every channel by the same factor keeps their ratio, which is why a darkened teal
is still teal. Four music surfaces — the lyrics pane, the immersive player, a
generated cover and a browse tile — had five implementations of this between
them, under four names for 4.5.

## `Z_INDEX`

**Within-context values only.** Which overlay paints on top is decided by the
overlay stack, not by a constant: `overlay/stack.ts` ranks surfaces by when
they OPENED, and a per-component z-index answers that question by what a
surface *is*, which leaves some pairings permanently inverted.

Never give an overlay surface a `zIndex` of its own.

## `flatten`

`StyleSheet.flatten` re-exported for code that already depends on the RN
runtime. A raw-DOM web fork should use `flattenWebStyle()` instead — jest's RN
mock stubs `StyleSheet.flatten` as identity, so the array form would survive
and crash the DOM with `Failed to set an indexed property [0]`.
