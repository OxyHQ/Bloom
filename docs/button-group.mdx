# Button.Group

Use the same `Button` alone or inside `Button.Group`. The group owns layout,
dividers, inherited size and the shared surface. Button owns its size recipe,
icons, focus, pointer and keyboard interaction, loading, disabled and toggle states.

```tsx
import { Button } from '@oxy.so/bloom/button';

<Button appearance="outline" tone="neutral" icon={BackIcon} accessibilityLabel="Back" />
<Button.Group accessibilityLabel="Page actions">
  <Button icon={SearchIcon} accessibilityLabel="Search" />
  <Button icon={ShareIcon} accessibilityLabel="Share" />
</Button.Group>
```

Inside a group, buttons default to neutral outline with shared material. Explicit
appearance, tone and material props still win. Grouping does not change button
height, glyph size, label spacing or content density. `xs`, `sm`, `md` and `lg`
use the normal Button scale (24, 32, 36 and 44px at default density).
An explicit button size wins over the group size, then the group's inherited
`BloomScope` size. There is no separate group geometry table.

## Selection

`pressed` and `onPressedChange` control a toggle, both inside and outside groups.
Leave `pressed` unset for an ordinary action. Disabled and loading buttons do
not activate either callback. `onPress` still receives the original event.

```tsx
<Button.Group accessibilityLabel="Range">
  {ranges.map(range => (
    <Button key={range} pressed={value === range} onPress={() => setValue(range)}>
      {range}
    </Button>
  ))}
</Button.Group>
```

One measured selection moves a shared capsule to the actual button bounds.
Multiple selected buttons paint their own states. The measured transition,
reduced motion and disappearance behavior are shared with Bloom's selection motion.

## Menus and popovers

Ordinary buttons support anchored `asChild` triggers, including refs, expanded
state and press cancellation. A wrapper does not require a special group item.

```tsx
<Button.Group accessibilityLabel="Page actions">
  <Popover>
    <PopoverTrigger asChild label="More">
      <Button icon={MoreIcon} accessibilityLabel="More" />
    </PopoverTrigger>
    <PopoverContent label="More">…</PopoverContent>
  </Popover>
</Button.Group>
```

## Group props

| Prop | Default | Behavior |
| --- | --- | --- |
| `orientation` | `horizontal` | Horizontal or vertical layout, without changing button geometry. |
| `size` | inherited, then `md` | Normal Button size, including `lg`. |
| `dividers` | `true` | Inset hairlines between joined controls. |
| `separated` | `false` | Flat segments with a 2px gap in one outer pill; no moving capsule or dividers. Icon segments default to `wide`. |
| `accessibilityLabel` | — | Names the group. |
| `style`, `testID` | — | Group layout and test handle. |

Adjacent buttons default to zero hit slop so targets cannot overlap. Standalone
buttons retain Button's normal touch target. A caller can provide an explicit
hit slop where its layout has room.

## Migration

Replace `ButtonGroup` with `Button.Group` and `ButtonGroupItem` with `Button`,
importing both through `@oxy.so/bloom/button`. Replace item `checked` or `selected`
with `pressed`, and `onCheckedChange` with `onPressedChange`. The old
`@oxy.so/bloom/button-group` entry and item component have been removed.

## The group holds its items

The group keeps `collapsable={false}`. Native renderers must not flatten the
container away from its controls: that previously left an empty named group
beside loose buttons in the mounted accessibility tree. The existing
`ButtonGroup.test.tsx` regression and trigger/material tests cover the new API.
