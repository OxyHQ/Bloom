# ButtonGroup

A row of buttons declared as one control, with one shared glass Surface. Unselected items remain plain; a checked item gains a rounded inset capsule. Dividers separate items by default.

```tsx
import { ButtonGroup, ButtonGroupItem } from '@oxy.so/bloom/button-group';

<ButtonGroup accessibilityLabel="Alignment">
  <ButtonGroupItem onPress={alignLeft}>Left</ButtonGroupItem>
  <ButtonGroupItem onPress={alignCenter}>Center</ButtonGroupItem>
  <ButtonGroupItem onPress={alignRight}>Right</ButtonGroupItem>
</ButtonGroup>
```

## Materials

```tsx
<ButtonGroup accessibilityLabel="Page actions">
  <ButtonGroupItem iconOnly leadingIcon={RiSearchLine} accessibilityLabel="Search" />
  <ButtonGroupItem iconOnly leadingIcon={RiShare2Line} accessibilityLabel="Share" />
</ButtonGroup>
```

Density inherits from `BloomScope`; the material is shared everywhere.

- The GROUP owns the shared material. Unselected items paint `transparent` at rest, and their hover/press states are an alpha of the theme's own `text` — an ink wash, not a fill. That is the one recipe that survives a backdrop Bloom cannot predict: a fixed neutral tuned against the island's fill disappears the moment a photograph moves the pane 40 levels, while a wash of the label's colour keeps the same relation to the label at every composite.
- An inner row clips highlights to the group shape. The outer native host stays unclipped so its shadow remains visible.
- `dividers` defaults to **true**. Separators stop short of the outer rim. Pass `dividers={false}` to hide them.

## Items as triggers

`ButtonGroupItem` declares the props an anchored family's `asChild` trigger merges onto it, so a menu button inside a group is an item OF that group rather than a second control that looks like one:

```tsx
<ButtonGroup accessibilityLabel="Page actions">
  <Popover>
    <PopoverTrigger asChild label="More">
      <ButtonGroupItem iconOnly leadingIcon={RiMore2Line} accessibilityLabel="More" />
    </PopoverTrigger>
    <PopoverContent label="More">…</PopoverContent>
  </Popover>
</ButtonGroup>
```

The item announces its own expanded state on both platforms. A control whose props are a closed list would have dropped `aria-expanded`, `aria-haspopup` and `onLongPress` silently, since all of them are optional — see [Composition](/docs/composition).

## Selection

Use `checked` with `onCheckedChange` for a controlled boolean toggle. `onPress` receives the original press event and can be composed with a toggle callback; disabled items call neither.

`checked` paints an item with its hover fill and announces it as pressed (`aria-pressed` on web, `accessibilityState.selected` on native). Drive it from state for single- or multi-select toolbars; leave every item unselected for a pure action row. For an animated thumb, use `SegmentedControl`.

```tsx
<ButtonGroup accessibilityLabel="Range">
  {ranges.map((range) => (
    <ButtonGroupItem key={range} checked={value === range} onPress={() => setValue(range)}>
      {range}
    </ButtonGroupItem>
  ))}
</ButtonGroup>
```

## Sizes and icons

| | md | sm |
|---|---|---|
| item height | 34 | 30 |
| padding-x | 12 | 10 |
| icon | 20 | 18 |

Text is `body-medium` (Inter 14/20 500) through Bloom's typography `Text` — a bare React Native `Text` falls back to the system font. Pass icon components to `leadingIcon` / `trailingIcon`; `iconOnly` makes a square item that needs `accessibilityLabel`. An app whose own icons take `size`/`color` rather than `width`/`height`/`fill` uses `renderLeadingIcon={({ size, color }) => …}` instead — see [Icons](/docs/icons).

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `ButtonGroup.size?` | `'md' \| 'sm'` | inherited, then `'md'` | Size for every item. |
| `ButtonGroup.dividers?` | `boolean` | `true` | Hairlines between items. |
| `ButtonGroup.accessibilityLabel?` | `string` | — | Names the group. |
| `ButtonGroupItem.onPress?` | `(event) => void` | — | Press handler. Receives the event, so a composed trigger handler can `preventDefault()` it. |
| `ButtonGroupItem.checked?` | `boolean` | `false` | Hover fill + pressed state. |
| `ButtonGroupItem.disabled?` | `boolean` | `false` | Disabled paint, blocks presses. |
| `ButtonGroupItem.iconOnly?` | `boolean` | `false` | Square icon-only item. |
| `ButtonGroupItem.leadingIcon?` / `trailingIcon?` | `BloomIconComponent` | — | Icon components. |
| `ButtonGroupItem.renderLeadingIcon?` / `renderTrailingIcon?` | `BloomIconRenderer` | — | Draw the glyph yourself, handed `{ size, color }` for the current state — for an app's own icon set. Wins over the icon component. [Icons](/docs/icons). |
| `ButtonGroupItem.size?` | `'md' \| 'sm'` | group size | Per-item override. |
| `ButtonGroupItem.hitSlop?` | `number \| {top,bottom,left,right}` | — | Extra touch area. NOT defaulted: items in a group are adjacent, so slop on one overlaps its neighbour. Use it for an item that stands alone in its own island. |
| `ButtonGroupItem.onLongPress?` / `aria-expanded` / `aria-haspopup` / `accessibilityRole` | | — | The trigger contract, set by an anchored family. |

## API migration

Controls use canonical sizes and the shared visual scope. Removed aliases and migration mappings are documented in [Unified component API](/docs/unified-api).

Each `ButtonGroupItem` now composes the actual `Button`, including icon render slots, toggle state, disabled state and trigger events. The group owns joining, dividers and inherited density. The group uses one shared `Surface`. With one checked item, a measured rounded capsule moves behind the plain Buttons and resizes to their actual bounds. It shares the same spring and visibility transition as BottomBar, respects reduced motion, and fades in place when selection disappears. Until layout is available, or when multiple items are checked, each checked Button paints its own material instead. Each platform binding injects its own Surface and Button, so browser packages resolve the web implementations directly.
