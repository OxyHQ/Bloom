# Sidebar

Plain sidebars inherit the enclosing surface. Painted variants publish their resolved fill, and a custom background override supplies that paint rather than sitting underneath it.

The floating dashboard sidebar with its team and account menus. Every row, person and link is a prop; the component owns only interaction state (collapse, search, the two menus).

```tsx
import { Sidebar } from '@oxy.so/bloom/sidebar';
import { RiHomeLine, RiSettings4Line } from '@oxy.so/bloom/icons';

<Sidebar
  items={[{ key: 'home', label: 'Home', icon: RiHomeLine, href: '/', badge: 152 }]}
  secondaryItems={[{ key: 'settings', label: 'Settings', icon: RiSettings4Line, onPress: openSettings }]}
  selected={currentKey}
  onNavigate={(item) => router.push(item.href!)}
  account={{ name: 'Maya Collins', avatar: { initials: 'M' }, users, onAddUser, onManage }}
  team={{ name: 'Design team', email: 'team@example.com', groups, footer: { label: 'Bloom', version: 'v1.0.1' } }}
/>
```

Give it a height (it fills `100%`); its width is its own.

## Primary action

Use `primaryAction` for the sidebar's main command. Bloom reuses `Fab` with its action tone and controlled `collapsed` state,
50px tall and full-width when expanded, a 50px circle with a 26px glyph when collapsed or in
`variant="rail"`. It stays outside the scrolling destinations so long navigation
lists do not push it out of reach. The expanded label follows the sidebar's existing
collapse animation and reduced-motion setting; the button keeps one focus target.

```tsx
import { Sidebar } from '@oxy.so/bloom/sidebar';
import { RiAddLine } from '@oxy.so/bloom/icons/RiAddLine';

<Sidebar
  items={navigation}
  primaryAction={{ label: 'New post', icon: RiAddLine, onPress: openComposer, disabled: saving }}
/>
```

`label` supplies the accessible name in every layout; `icon` is a Bloom icon
component. `onPress` owns the command and is never called while `disabled` is true.
The sidebar does not create a composer or any other application-specific UI.

## Parts

| export | |
| --- | --- |
| `Sidebar` | the rail |
| `SidebarModeSwitcher` | a vertical segmented control of icon + label modes (Search / Computer); the `modes` prop renders it under the header |
| `SidebarItem` | one navigation row, a full pill: rest / hover / selected (solid accent fill with the primary foreground — no gradient, ring or highlight), optional badge (collapsed, it moves over the icon's top-end corner; `collapsedBadge` overrides it there), `collapsed` 36px square |
| `SidebarUserMenu` | the account trigger (2px hover pill outside its box) and its menu |
| `SidebarAccountMenuContent` | that menu's body, for another trigger |
| `SidebarTeamMenu` | the team card and its grouped menu with a version footer |
| `SidebarFolder` | one expandable folder of a `tree` |
| `SidebarPlanCard` | the plan card (avatar, name, plan, action) |
| `SidebarOnboardingCard` | a welcome card with app-owned tasks and an optional guide action |
| `SidebarRailItem` | one `rail` destination: icon on a 48 × 32 pill over a 10px label |
| `SIDEBAR_RAIL_WIDTH` | the rail's width (80) |

## Onboarding

`onboarding` places the same exported `SidebarOnboardingCard` below navigation and
above the tree and custom content, inside the sidebar's existing scroll viewport.
It is absent from a collapsed panel and the navigation rail; a mobile drawer shows
the expanded card.

```tsx
<Sidebar
  items={navigation}
  onboarding={{
    title: 'Welcome to your workspace',
    leading: <ProductMark width={20} height={20} />,
    onPress: openWelcome,
    steps: [
      { key: 'page', label: 'Create a page', completed: hasPages, onPress: createPage },
      { key: 'team', label: 'Invite your team', completed: hasTeammates, onPress: openMembers },
      { key: 'project', label: 'Track a project', completed: hasProject, onPress: openProjects },
    ],
    onSeeAll: openWelcome,
  }}
/>
```

The first two incomplete steps appear in caller order; `visibleCount` changes the
limit. Completion is controlled: pressing a task invokes its callback, and only
updated `completed` data removes it. Omitting `onboarding` hides the entire card,
including when the app decides onboarding is finished. A step with no callback is
static text; `disabled` prevents an available action. The title is independently
clickable only when `onPress` exists. The footer appears only with `onSeeAll`;
its localized “See all” label can be overridden with `seeAllLabel`.

The card uses Bloom's shared card surface, 16px corners, a subtle border and
shadow. Its decorative leading slot accepts a product mark or avatar. Web task
rows are at least 28px high, and native rows at least 44px; labels wrap and grow
with the system font. Actions retain the sidebar's keyboard focus ring. All
product names, task labels, destinations and progress belong to the app.

## Logo

```tsx
<Sidebar
  logo={{ icon: <OxyMark width={28} height={28} />, wordmark: 'Oxy', href: '/', onPress: () => router.push('/') }}
  items={items}
  account={account}
/>
```

- `icon` — the mark, centred in a 36px-high box whose width follows the shared icon lane, so it aligns with navigation at both endpoints. Size it yourself; 24–28px reads right.
- `wordmark` — beside the mark, folded away while collapsed. A string renders as the product name in `headline-semibold`; pass an SVG or image for a drawn wordmark.
- `href` makes it a real anchor on web; `onPress` a button (with both, `onPress` wins so a router can navigate — pass it on native, where there is no anchor). With neither it is decoration, named by `accessibilityLabel` or a string `wordmark`.
- Give a mark, a wordmark or both. Wordmark only disappears when collapsed.

The logo leads the header beside the collapse (or close) control; `account`, if given too, moves to its own row under it. Collapsed, the mark sits above the expand control. `variant="rail"` shows the mark only, centred above the items.

## Team first: a workspace app

By default the account switcher heads the panel and the team is the card at its
foot — a product whose person comes first. A workspace app, where the space you
are in leads, sets `teamPlacement="header"`: the team becomes the switcher at
the top (avatar, name, up/down chevron) and the account the card at the foot
(avatar, name and `email`).

```tsx
<Sidebar
  teamPlacement="header"
  team={{
    name: workspace.name,
    avatar: { source: workspace.avatar, initials: 'A', shape: 'squircle' },
    groups: [
      {
        id: 'workspaces',
        label: 'Your workspaces',
        selection: 'single',
        items: workspaces.map((w) => ({
          key: w.id,
          label: w.name,
          description: w.isPersonal ? 'Personal' : roleLabel(w.role),
          avatar: { source: w.avatar, initials: w.name[0], shape: 'squircle' },
          selected: w.id === workspace.id,
          onPress: () => switchTo(w.id),
        })),
      },
      { id: 'create', items: [{ key: 'new', label: 'Create workspace', icon: RiAddLine, onPress: create }] },
    ],
  }}
  account={{
    name: user.name,
    email: user.email,
    avatar: { source: user.avatar },
    groups: [
      { id: 'me', items: [{ key: 'settings', label: 'Settings', icon: RiSettings3Line, onPress: openSettings }] },
      { id: 'out', items: [{ key: 'out', label: 'Sign out', icon: RiLogoutBoxRLine, tone: 'destructive', onPress: signOut }] },
    ],
  }}
/>
```

- Both menus take the same rows (`SidebarMenuItem`): an `icon` or an `avatar`
  (20px) before the label, an optional `description` under it
  (caption-1-regular, secondary), a `badge`, and `tone: 'destructive'` for sign
  out or leave, in the menus' danger role.
- A `selection: 'single'` group is a choice of one: a radiogroup its label
  names, rows that are radios, and a 20px check on the `selected` one instead of
  a fill.
- `avatar.shape: 'squircle'` draws a team or workspace with `Avatar`'s squircle,
  image and initials alike, so it reads apart from the round people beside it.
- `account.groups` sit after "Users with access" and before the add / manage
  actions. Opened from the card, the account menu heads with the account
  itself, as the team menu always does.
- `SidebarTeamMenu` and `SidebarUserMenu` take `form="switcher" | "card"` on
  their own; the switcher opens top-aligned beside the rail, the card
  bottom-aligned.

## Modes

```tsx
<Sidebar
  modes={[
    { key: 'search', label: 'Search', icon: RiSearchLine, shortcut: '⌥⌃1' },
    { key: 'computer', label: 'Computer', icon: RiComputerLine, shortcut: '⌥⌃2' },
  ]}
  mode={mode}
  onModeChange={setMode}
  items={items}
/>
```

- `toolbar` is a fixed row under the header (logo, account, collapse control) and above the modes: the header stays. `header` replaces the header row instead; `header={false}` draws none. A conversations sidebar puts its search and tools in `toolbar` ([`ConversationSidebar`](./conversation-sidebar.mdx)).
- The default segmented switch between sidebar modes renders under the header and above quick search. Standalone it is `SidebarModeSwitcher` (`modes`, `value`, `onValueChange`).
- Track p4, radius 20, background-tertiary (neutral-200 / neutral-800). Rows are 32 tall and 4 apart: an 18px icon in a 32 box, 4 gap, `body-2-medium`. The selected row's 32px pill — card / neutral-700 with shadow-xs, the sidebar theme toggle's thumb — slides 200ms ease between rows, instantly under reduced motion.
- Rest is text-secondary, selected text-primary. On web a `shortcut` hint (`caption-2`, text-tertiary) appears at the row's end on hover.
- Collapsed, labels and hints collapse and the icons stay pinned. It is a `radiogroup` of `radio` rows, named `"Mode"` unless `modesLabel` / `accessibilityLabel` says otherwise. The sidebar binds the shortcuts itself — see [Keyboard shortcuts](#keyboard-shortcuts).
- For exactly two modes, `modesPresentation="toggle"` uses a 28px `FrostedIconButton` in the expanded header, beside collapse. It keeps the second mode's icon and exposes `aria-pressed`; `modesLabel` supplies a stable accessible name. The tooltip names the destination. Collapsed sidebars center it in its own row. Standalone, use `SidebarModeSwitcher presentation="toggle"`. Three or more modes retain the segmented presentation.


A mode can select an application layout without navigating. For a Standard/Deck
switch, control `mode` with layout state and keep the current route mounted in
the same first panel. Set a stable localized `modesLabel`, such as "Deck mode";
the compact control is a button with pressed state, while segmented modes are
radios. See [Compose application layouts](/docs/bloom/main/compose-layouts).

## Rail

```tsx
<Sidebar
  variant="rail"
  items={[{ key: 'home', label: 'Home', icon: RiHomeLine, activeIcon: RiHomeFill, href: '/' }]}
  secondaryItems={[{ key: 'settings', label: 'Settings', icon: RiSettings3Line, activeIcon: RiSettings3Fill, href: '/settings' }]}
  selected={currentKey}
  onNavigate={(item) => router.push(item.href!)}
/>
```

- An 80px column on background-full with no panel chrome. The primary items are centred vertically in a scroller (px 8, py 24, gap 8); `secondaryItems` sit at the foot.
- Each item (`SidebarRailItem`) is min-height 64, radius 20, py 8: a 48 × 32 pill behind a 22px icon, and 5 below it a one-line 10px label. Selected, the pill takes the accent-500 fill with the primary foreground, the label turns text-primary medium, and `activeIcon` (e.g. the filled glyph) replaces `icon`. Hover fills the pill with background-secondary-hover. A `badge` sits over the pill's top-end corner (top-right in LTR).
- Navigation only: `account`, `team`, `plan`, `tree`, quick search, the theme toggle and collapse belong to the panel and are ignored here. Routing (`href`, `onPress`, `onNavigate`) works as below.
- In `AppShell` the rail stays in flow from `sm`; see `docs/app-shell.mdx`.

## Tree and plan (the AI chat rail)

```tsx
<Sidebar
  items={[{ key: 'new', label: 'New agent', icon: RiAddFill }]}
  tree={{ label: 'Repositories', folders: [{ key: 'web', label: 'web', defaultOpen: true, items: [{ key: 'c1', label: 'coding scenario', meta: 'now' }] }] }}
  selectedTreeItem={chatId}
  onTreeItemPress={(item) => openChat(item.key)}
  plan={{ name: 'Design team', plan: 'Pro Plan', avatar: { initials: 'D', color: 'blue' }, onAction: upgrade }}
/>
```

- The header, collapse control, mode switcher and quick search stay fixed; only destination rows scroll (the shared overlay scrollbar on web, system indicator on native). With a `tree`: the primary rows, then 24 below them the tree — its label (body-medium text-secondary) and, 10 below, the folders 4 apart. The footer gains 12 on top.
- A folder row is p 8 with a 20px folder glyph (open while expanded) and the label; its rows are py 5 / pr 8 / pl 36 with the label and a `meta` chip (radius 4, background-tertiary, px 4 / py 1, caption-1-medium), background-secondary-hover while selected or hovered. A curved 1px icon-quaternary connector drops from the folder glyph into each row. The rows' height and opacity ease open and shut together over 300ms; collapsed rows leave the tab order.
- Quick search filters the tree too: a folder whose label matches keeps every row, otherwise only its matching rows, held open while the query is set. "No results" counts every section.
- The tree hides while collapsed.

### Sections: rows directly, or folders

`tree` takes one section or an array of them, drawn in order 24 apart, each with
its own label and `actions`. A section's `items` are rows listed directly under
its label, before any folders: use them when the section IS the list. Keep
`folders` for collections the user made.

```tsx
<Sidebar
  items={NAV}
  tree={[
    {
      key: 'recent',
      label: 'Recently viewed',
      items: recent.map((home) => ({ key: home.id, label: home.title, meta: home.viewedAgo, href: `/homes/${home.id}` })),
    },
    {
      key: 'saved',
      label: 'Saved',
      actions: <NewFolderButton />,
      folders: savedFolders.map((folder) => ({
        key: folder.id,
        label: folder.name,
        items: folder.homes.map((home) => ({ key: home.id, label: home.title, href: `/homes/${home.id}` })),
      })),
    },
  ]}
  selectedTreeItem={homeId}
  onTreeItemPress={(item, folder) => open(item.key)}
/>
```

- A direct row is a folder row without the connector: the same height, radius, `meta` chip, selection, hover, `actions`, `href`, `onPrefetch` and `onLongPress`, inset 8 (to the folder glyph) instead of 36.
- `onTreeItemPress(item, folder)` gets the row's folder, or `undefined` for a direct row. `selectedTreeItem` matches a key in any section.
- `key` identifies a section among several (defaults to `label`). `items` and `folders` are both optional; a section with neither, or with nothing left after quick search, is not drawn.
- Quick search filters direct rows by their label and folders as above. Collapsed, every section hides, as the single tree did.
- `plan` replaces the team card: radius 12, background-tertiary (the panel colour on a `plain` surface), py 8 / pr 12 / pl 10, a 32px avatar (initials 18.8/22.6 medium), the name (body-medium) over the plan (body-regular text-secondary), and a small secondary button (`actionLabel`, default "Upgrade"). Collapsed, only the avatar.

### A page tree: nested rows, icons and states

A row's own `items` nest it to any depth — pages in pages. The row gains a
disclosure (a chevron that turns 90° open, named "Expand Roadmap" / "Collapse
Roadmap"), its state `open` / `defaultOpen` / `onOpenChange`; children ease
open and shut and are only mounted while shown, so a large closed branch costs
nothing. `expandable` draws the disclosure with no `items` yet, and
`emptyLabel` says what an open, empty row holds ("No pages inside").

```tsx
<Sidebar
  tree={[
    {
      key: 'private',
      label: 'Private',
      collapsible: true,
      open: privateOpen,
      onOpenChange: setPrivateOpen,
      actions: <AddPageButton />,
      actionsVisibility: 'hover',
      emptyLabel: 'No pages yet',
      loading: pages.isPending,
      error: pages.error ? 'Could not load your pages' : undefined,
      items: pages.map(function row(page): SidebarTreeItem {
        return {
          key: page.id,
          label: page.title,
          leading: <PageIcon page={page} />,
          href: `/p/${page.id}`,
          items: page.children.map(row),
          expandable: true,
          emptyLabel: 'No pages inside',
          open: expanded.has(page.id),
          onOpenChange: (open) => toggle(page.id, open),
          actions: <PageRowActions page={page} />,
          actionsVisibility: 'hover',
          draggable: canEdit,
        };
      }),
    },
  ]}
  selectedTreeItem={pageId}
  onTreeItemPress={(item) => router.push(item.href!)}
  onTreeItemDrop={movePage}
/>
```

- Each level starts 16 further in. In a section where any row nests, every row
  keeps the disclosure's 20px lane, so labels align whether or not a row has
  children.
- `icon` (a Bloom glyph, in the row's icon colour) or `leading` (anything — an
  emoji, an image) sits in a 20px box before the label, gap 8.
- `onPress` makes a row an action ("Browse teamspaces"); it runs before
  `onTreeItemPress`.
- `actionsVisibility: 'hover'` — on a row or a section — shows the actions on a
  pointer device only while the row is hovered or holds focus, the way a page
  tree's add and more buttons appear; touch always draws them.
- Quick search keeps a row whose label matches with everything under it, and a
  row with matching descendants with only those, held open while the query is
  set.
- A `collapsible` section's label becomes its disclosure (16px chevron after
  it). `loading` ("Loading…"), `error` (an alert, in the danger role) and
  `emptyLabel` stand in for its rows; a section with no rows and none of these
  is not drawn.

### Moving rows

`onTreeItemDrop` turns dragging on for the rows marked `draggable`. The sidebar
reports where a row landed and the app moves it:

```ts
interface SidebarTreeDrop {
  item: SidebarTreeItem;        // the row moved
  from: SidebarTree;            // its section
  target?: SidebarTreeItem;     // absent: dropped on the section's label
  position: 'before' | 'inside' | 'after';
  section: SidebarTree;         // where it landed
}
```

- **Web:** a draggable row is an HTML drag source and every row a target: the
  top quarter is before it, the bottom quarter after it, the middle inside it
  (halves when the row is not `droppable`). A 2px accent line marks before /
  after and a 2px accent outline inside; a section's label takes a row inside
  the section. The browser scrolls the viewport near its edges.
- **Touch:** a long press (350ms) lifts the row, which follows the finger; a
  tap still opens it and a swipe still scrolls. The finger is hit-tested against
  the rows' frames, read once when the drag starts, and the viewport scrolls
  while the finger rests near its top or bottom. A lifted row let go where it
  was fires its `onLongPress` instead of moving.
- **Keyboard and screen readers:** the focused row answers Alt+Shift+↑ / ↓
  (past a sibling), → (inside the row above) and ← (out of its parent, after
  it) on web; native offers the same as accessibility actions. A move is
  announced ("Roadmap moved").
- The rules hold in every path: a row never lands on itself or inside its own
  descendants, nothing lands in a section with `droppable: false` (a list
  shared with you), nothing lands inside a row with `droppable: false`, and
  nothing lands beside a row with `dropBeside: false` — a container among
  containers (a teamspace's row): anywhere on it is inside.
  Drags span sections, so keys must be unique across the tree: a page listed
  twice (a favourite, and its place) takes two keys, and `selected: true` on
  each copy marks both while it is open. Folders' rows do not move.

## Surface and size: the app's identity

Two apps with the same rows should not look like the same app. That difference is two props, not a fork of this component.

```tsx
<Sidebar surface="card" />                    {/* default: the floating panel */}
<Sidebar surface="plain" size="lg" />      {/* a social reader's nav */}
<Sidebar surface="docked" size="sm" />     {/* a workspace column */}
```

`surface` is the panel's EDGE:

| surface  | what it draws                                                      |
| -------- | ------------------------------------------------------------------ |
| `card`   | shared panel radius (28 by default), a hairline and the panel shadow, on the panel fill       |
| `plain`  | no radius, no border, no shadow — the rows sit straight on the page |
| `docked` | the panel fill, square corners, ONE hairline on the inner edge, full height |

The docked edge is not the card's border: that one is white in light mode, a highlight that reads as an edge only because the card's shadow sits beneath it. A docked column has no shadow, so it takes a real hairline stepped off its own fill (`hairlineOn`).

`size` moves the rows and the panel together — one rung, every measurement, in `SIDEBAR_METRICS`:

| size     | square | glyph | label            | expanded | collapsed |
| -------- | ------ | ----- | ---------------- | -------- | --------- |
| `sm`  | 30     | 18    | `body-2-medium`  | 232      | 46        |
| `md` | 40     | 22    | `headline-medium` | 260      | 56        |
| `lg`  | 44     | 24    | `title-3-medium` | 300      | 60        |

The tree section takes its type, glyph and row inset from the same table (`SIDEBAR_METRICS[size].tree`), one step denser than the rows above it: the section label, row and folder labels, the `meta` chip and the loading, error and empty lines.

| size | label            | meta               | status            | glyph | row inset |
| ---- | ---------------- | ------------------ | ----------------- | ----- | --------- |
| `sm` | `body-2-medium`  | `caption-2-medium` | `body-2-regular`  | 16    | 4         |
| `md` | `body-medium`    | `caption-1-medium` | `body-regular`    | 20    | 5         |
| `lg` | `headline-medium` | `body-2-medium`   | `headline-regular` | 22   | 6         |

The table describes a card without a primary action. Runtime collapsed width is the icon lane plus 7px padding on each side and the borders actually painted: card adds2px, docked1px, plain0px. The lane is the row square, or at least50px when `primaryAction` is present (total66/65/64px respectively). Navigation and search retain their30/40/44px circles, centred in the wider lane; their icons are not enlarged. Logo, collapse control, modes, theme and account controls share that centre. Expanded navigation retains its2px inset, and the primary action uses the same edges. A row outside a sidebar takes `size` itself; inside one it inherits the panel's.

`AppShell` passes both through (`sidebar={{ surface, size }}`) and treats `docked` as what it is — it gives up its start and vertical padding around that column and lets it run the full height, so the hairline is the separator instead of a gutter.

## Right-to-left

The sidebar mirrors with the document (`<html dir="rtl">` on web,
`I18nManager.isRTL` on native): the `docked` hairline is on the END edge
(`borderEndWidth`), so it faces the content in either direction; the collapse
control, its glyph, the folder connector and the account/team menus flip with
it. How direction is read and what an app must set: [`AppShell`, Right-to-left](/docs/bloom/main/app-shell).

Every label it speaks is a prop (`accessibilityLabel`, `collapseLabel`,
`expandLabel`, `closeLabel`, `searchLabel`, `searchButtonLabel`, `filterLabel`,
`clearSearchLabel`, `noResultsLabel`, `account.menuLabel`, `team.menuLabel`);
defaults and what each names: [`AppShell`, Labels](/docs/bloom/main/app-shell).

## Navigation

- `href` rows are links (a real anchor on web). With `onNavigate`, the browser's navigation is prevented and the host routes; without it, the anchor navigates on web and nothing happens natively.
- `onPress` makes a row an action (Settings → a modal) and takes precedence over `onNavigate`.

## Collapse

`collapsed` / `defaultCollapsed` / `onCollapsedChange`. `collapseDisabled` disables the collapse control when a containing layout requires the current width; AppShell sets it while available space requires a collapsed panel. The panel morphs between the size's two widths (260 → 56 at `md` for a card without a primary action) in 300ms while labels, the row-end badges and the shortcut hint collapse (max-width, opacity, 3px blur on web) and the icons stay put. A badge doesn't disappear: collapsed, it fades in over the icon's top-end corner at the small size, capped at `99+` so it fits the square (the expanded row still shows the full count). `mobile` is always expanded and shows a close button. `fluid` fills the container while expanded. Reduced motion snaps.

After expanding, the account trigger's hover pill stays off until the pointer leaves it, so a stationary pointer does not light it up.

On web every control takes the same keyboard focus ring: one stylesheet rule on `[data-bloom-sidebar]:focus-visible` painting `var(--bloom-sidebar-ring)`. A control with the hook but without the variable matches the rule and paints nothing — the collapse button, the `mobile` close button and the flat header's search button shipped that way, focusable and invisible while focused. Each part sets the variable on itself; `SidebarFocusRingWeb.test.tsx` fails for any hooked control that resolves no ring colour.

## Keyboard shortcuts

A mode's or an item's `shortcut` (`⌥⌃1`, `⌘,`, `Ctrl+Shift+H`) is shown on
hover AND bound on web: while the sidebar is mounted, the key does what pressing
the row does — `onModeChange(key)` for a mode, the item's `onPress`, else
`onNavigate(item)` for a link. **Don't add a `keydown` listener for them in the
app**; the label is the single source.

- Modifiers are `⌘ ⌃ ⌥ ⇧` glyphs or `Cmd`/`Ctrl`/`Alt`/`Option`/`Shift` words joined
  with `+`; every modifier must match exactly. Digits and letters match by
  physical key, so `⌥1` works on a Mac, where Option+1 types `¡`.
- `Mod` is the platform's command modifier — ⌘ on Apple platforms, Ctrl
  elsewhere — bound AND drawn that way: `Mod+K` reads `⌘K` on a Mac and
  `Ctrl+K` on Windows (`Mod+Shift+P`: `⌘⇧P` / `Ctrl+Shift+P`).
- `shortcutBinding: 'app'` leaves the binding to the app's own keymap and
  only draws the hint: for a key that must work from inside an editor, where
  the sidebar never acts, or while the navigation sits in a closed drawer.
- Keys typed into an input, a textarea or editable content are ignored.
- One action per key press, however many sidebars render the navigation (in
  flow and in a drawer, or the rail): the first to act marks the event handled,
  and every listener skips a handled event — an app's older binding that calls
  `preventDefault` included.
- Rail items are bound too; the rail draws no hint.

## Quick search

The pill button (or ⌘L / Ctrl+L on web; `searchShortcut={false}` to unbind) opens a field that filters every row by label; "No results" shows when nothing matches. Escape, the clear button, or a press outside the field (web) closes it and clears the query. Activating search on a collapsed rail expands it.

The sidebar's default names and words ("Sidebar", "Quick Search", "No results", "Upgrade", the account menu's rows…) are localised via `BloomProvider locale`; every `*Label` prop still wins.

## Menus

Both menus are `Popover`s: beside the rail (the card bottom-aligned, the switcher top-aligned — whichever identity each is) and below the trigger under `sm`. On native, `Popover` presents as a bottom sheet. `Popover`'s own motion runs here.

## Colour

Panel `backgroundSecondary` (`--surface`) with `borderLight` and the existing three-layer shadow. Rows use `backgroundTertiary`; selected navigation uses the paired `primary`/`primaryForeground` roles, and its badge uses `secondary`/`secondaryForeground`. Initials retain the public names `neutral`, `blue`, `lime`, and `pink`: their colours now come from neutral, primary, success, and tertiary semantic pairs respectively, rather than generated ramps or rotated hues.

### Mode switcher in a collapsed panel

Collapsed segmented modes use the sidebar's icon-square size: 30/40/44px for `sm/md/lg`. The two-mode compact toggle keeps its 28px FrostedIconButton.
The track adds 4px around those squares and stays centered, extending into the
panel's horizontal inset. Its selected thumb remains square, the glyph stays
centered, and hidden labels leave no gap. Expanded mode rows retain their 32px
height.

### Scroll overflow cues

Panel and rail destinations use the shared `ScrollSurface` and its isolated metrics.
Each region paints a 40px fade in its own surface color at an
edge only when more content exists beyond it. The initial content and viewport
measurements reveal the bottom cue before the first scroll. At the top there is
no top fade; at the bottom there is no bottom fade. Content that fits has neither.
Resizing or filtering updates these cues without changing content padding.
The decorative overlays ignore pointer input and are excluded from accessibility.

### Collapse motion

Panel width and horizontal padding, navigation gaps, labels, mode-switcher
geometry, header controls and footer surfaces follow the same 300ms collapse
progress. Reversing the control continues from its current position. Reduced
motion applies the target layout immediately. Mode selection has its own
indicator timing; its position is calculated from the current animated row
height so selection and collapse can happen together.

The panel scroll viewport extends behind the bottom half of the last fixed header control (up to 20px). The top fade begins there, while compensating content padding preserves the initial row spacing. Fixed controls remain above the fade and available throughout scrolling.


### Custom persistent footer

`footer` adds content below the existing bottom controls, outside destination scrolling. Pass a node or `({ collapsed }) => ReactNode`. A rail reports `collapsed: true`; a mobile panel reports `false`, even when its controlled `collapsed` prop is true. Desktop panels report their current rendered state.

```tsx
<Sidebar
  items={items}
  footer={({ collapsed }) => (
    <ProfileButton compact={collapsed} onPress={openAccount} />
  )}
/>
```

`ProfileButton` above is an application component: the app retains authentication, account selection and menu behavior. The slot adds no account behavior and does not replace `account`, theme, secondary navigation, team or plan controls. Omit `account` if your footer replaces the built-in account switcher. Footer content should fit the compact rail width and provide an accessible name when it hides its label.

Navigation items accept `onLongPress` for secondary touch actions, in both panel and rail. Keep the same action available in a keyboard-accessible menu; long press alone is not discoverable or keyboard accessible.

## App-owned history

Use `content` for conversation history or other application-owned rows. It follows
items/tree inside Sidebar's existing scroll viewport; `onScroll` observes that
viewport after its edge fades update. Compose `SidebarItem`/`SidebarFolder` here,
not another scroller. Header, primary action and footer stay fixed. Content remains
mounted while collapsed, but is hidden from focus, pointers and accessibility and
contracts with the panel's animation. `variant="rail"` omits this expanded content.
Quick search only filters built-in rows/tree; use `showSearch={false}` when the
application supplies its own search destination.

### Live application trees

`searchQuery` / `onSearchQueryChange` control the built-in search and let a host
filter additional content or load more history. Uncontrolled search is unchanged.
Tree folders accept `open` / `onOpenChange` for persisted disclosure. Folder and
item `actions` render beside their press targets, so menus never navigate or
toggle the containing row. Items expose `onPrefetch` (pointer/touch entry and
selection) and `onLongPress`; retain a keyboard-accessible menu for touch actions.
Collapsed folders remove both rows and action slots from interaction.

`contentAlignment="center"` centers the logo, destinations, and primary action
as a group in the space **above** the persistent footer, in both panel and rail.
The destination region can still shrink and scroll on short screens. Keep an
account control in `footer`; avoid centering the whole sidebar with `style`,
which also moves its footer. The default `start` preserves existing placement.

## Shared material

Card and docked sidebar surfaces paint the shared Surface material at 90% body opacity with its gradient and rim beneath their contents; plain surfaces and the navigation rail retain their existing fill. The current logo, modes, scoped sizes, tree, custom content, RTL layout, safe edges and scroll behavior are unchanged. Storybook: **Blocks / Sidebar / Glass Panel**.

`header` replaces the account/logo header while keeping it outside the existing destination scroll. A render function receives `{ collapsed }`. `contentPadding` changes the expanded inset and the measured width of app-owned content together; omit it to preserve the size's default inset. `className` reaches the panel's animated layout node. Navigation rows also accept `style` and `className`; collapsed rows retain the sidebar's square geometry.

`SidebarToolbar` composes action slots beside controlled `search` (`value`, `onValueChange`, `open`, `onOpenChange`, optional names and placeholder). Opening search expands it across those slots, focuses its input and removes hidden actions from interaction, accessibility and web tab order. Close and Escape clear the query and restore the search trigger. Leaving the field (blur) closes an empty search too; with text in it, it stays open so the filter is never hidden. The 300ms width and 200ms action fade/transform respect reduced motion. Buttons and fields reuse Bloom's existing bases.

`SidebarItem` accepts `leading` in place of an icon, a secondary `description`, and `selectedAppearance="neutral"` for a tertiary surface instead of the default accent selection. Descriptive rows constrain both text lines for ellipsis and collapse them together. `labelClassName` and `descriptionClassName` reach the text nodes; existing icon-only rows and default selection retain their previous recipe. Press events, native holds, trigger ARIA props and refs reach the host for `asChild` menu composition.

Multi Agent Chat uses these pieces with one sidebar scroll owner. Chrome measured its panel at 260×876px, toolbar at 244×36px, conversation rows at 244×54px and footer actions at 36px. Real pointer checks cover search filtering, close, right-click actions and renaming. Native context-menu hold composition is covered by Jest; device rendering and motion remain separate verification.

### Shared surface paint

The painted host delegates its fill to Surface: a 90%-opacity body with a backdrop blur on web, plus the shared sheen and rim. The host itself stays transparent to avoid painting twice. Explicit alpha colours retain their alpha; descendants receive the corresponding composited fill. Plain or unframed content keeps its existing layout behavior.

### Icon-only navigation rails

`variant="rail"` keeps visible captions and selected pills by default. Use
`railLabels="hidden"` to keep only icons: each destination retains its accessible
name, current-page state, focus ring and browser tooltip. Its minimum hit height
is 48px. `railSelection="icon"` emphasizes the active glyph without a filled
indicator; `activeIcon` can supply a filled counterpart. Hover feedback remains.

`railWidth` owns the rail's layout width (default 80px, minimum 64px). AppShell
measures that natural width, so the content moves with it without consumer
width overrides. These props affect the rail only; the expanded panel and
mobile drawer retain their normal labels and geometry. Standalone
`SidebarRailItem` exposes `labelVisibility` and `selectedAppearance` for the same
choices.
