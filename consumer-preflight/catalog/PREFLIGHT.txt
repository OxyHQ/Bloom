Discovery findings
A. Major setup contradiction: docs/AGENTS and catalog require BloomProvider and
   refer to getting-started for CSS/fonts. getting-started instead prescribes
   BloomThemeProvider + SurfaceProvider and manual inline BLOOM_DIALOG_CSS.
   Packaged provider.mdx supplies BloomProvider import and root contract;
   design-tokens.mdx supplies theme.css import. Getting-started has no @source
   recipe or font setup. Successful setup used Tailwind source scanning knowledge
   unavailable in packaged guide. Fonts were not separately installed/verified;
   screenshot typography is not a font fidelity acceptance.
B. New Vite consumer is not runnable from catalog/getting-started alone. Fixture
   required RN→RNW alias, .web TS/JS extension ordering in BOTH resolver and
   optimizeDeps, JSX loader for dependency .js, global→globalThis, explicit peer
   versions, Expo module-core source entry alias, Babel Reanimated worklet
   transform for installed Bloom and Reanimated JS. None edits package caches.
   Before worklet transform, real browser threw 'Passed a function that is not
   a worklet' from Screen scrolling; typecheck had already passed.
C. Peer manifest accepts expo-blur 15.x via '*', but that installed version lacks
   BlurTargetView needed by candidate bundle. SDK58 peers resolve that. Initial
   Reanimated4.1.1/Worklets0.5.1 host failed browser init; final fixture uses
   supported Reanimated3.19.1. This is fixture compatibility evidence, not a
   claim all Vite/Expo setups fail. Lockfile captures successful dependencies.
D. Scanning the whole 255MB lib tree made this host unresponsive/high CPU;
   explicit lib/module/**/*.js with source(none) and bounded worker counts
   resolved it. Do not infer a measured general performance regression.
E. Conversation ownership row repeats AppShell/Screen advice generically, but
   explicit avoid paragraph correctly prevents wrapping AgentChat twice.
F. Canvas task advertises shared controls in prose but its import list/example
   omits them; canonical guide discovery was necessary. MapLayerPicker example
   uses undefined LAYERS and an ellipsis; simple id/label entries compiled and
   worked. A complete runnable controls example would remove that guess.
